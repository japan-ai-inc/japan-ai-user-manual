# 実行結果の通知を設定する

定期タスクやWorkflowを業務に組み込むと、実行が終わったこと、失敗したこと、確認すべき結果が出たことを、実行履歴を毎回開かずに把握したくなります。本記事では、運用担当者がタスクの**「通知先」**を設定し、実行結果への導線と共有範囲を確認する手順を説明します。

タスクの作成・スケジュール自体は[タスクスケジューラを設定する](../build/configure-task-scheduler.md)、停止・担当交代・履歴の運用は[定期実行を変更・停止・引き継ぐ](change-stop-handover-scheduled-runs.md)を参照してください。

## この記事の範囲

対象は、**「タスク」**で管理するAgentタスクとWorkflowタスクの完了・失敗に関する通知です。通常のタスク設定画面の「通知先」では、通知センター、メール、Slack、Chatworkを複数選択できます。Workflowと従来のタスクスケジューラーは「タスク」に統合されています。

通知は実行の成否を知らせる補助であり、業務処理そのものの成否を保証するものではありません。外部サービスへの送信や更新を伴うタスクでは、通知だけで完了と判断せず、**「実行履歴」**と必要に応じて外部サービス側の結果を照合してください。

> 通知先には実行結果へのリンク、エラー、設定によっては出力内容が含まれます。個人情報、顧客情報、機密情報を扱うタスクでは、受信者・Slackチャンネル・Chatworkルームの閲覧権限を事前に確認してください。

## 始める前に

- 対象の組織、Project、タスク名、実行対象（AgentまたはWorkflow）を確認します。同名の検証用タスクと本番タスクを取り違えないでください。
- 通知を受ける人、確認の一次担当、失敗時の連絡先を決めます。Projectで動くタスクは、通知センターの対象がタスク作成者だけとは限りません。
- 出力本文を通知へ載せてよいか、共有リンクを作成してよいかを業務・情報管理のルールに照らして決めます。
- メール、Slack、Chatworkを使う場合は、送信先情報を安全な経路で用意します。Webhook URLやAPIトークンをチケット、チャット、画面共有へ転記しないでください。
- タスクの作成・更新権限と、通知先の外部サービス側で投稿・受信できる権限を確認します。接続や担当者の変更は[接続の失効・担当者変更に対応する](handle-expired-connections-and-owner-changes.md)も参照してください。

## 通知先と必要な設定

| 通知先 | 画面での設定 | 運用上の確認 |
|---|---|---|
| 通知センター | **「通知先」**で通知センターを選択 | Projectのメンバー構成と各メンバーが結果を閲覧できる範囲を確認します。 |
| メール | メールを選択し、**「メールアドレス」**を入力 | 宛先の誤り、配信制限、共有メールボックスの閲覧者を確認します。複数宛先を指定できます。 |
| Slack | Slackを選択し、**「Slack Webhook URL」**を入力 | Webhook URLが対象チャンネルのものか、チャンネルの公開範囲が適切かを確認します。 |
| Chatwork | Chatworkを選択し、**「Chatwork APIトークン」**と**「Chatworkルーム ID」**を入力 | トークンの有効性、投稿権限、ルームの参加者と閲覧範囲を確認します。 |

複数の通知先を併用できます。例えば、担当者がすぐ気付くために通知センター、運用当番への連絡にメール、チームの監視用にSlackを選ぶ、といった分け方ができます。ただし、同じ出力やリンクが複数の場所に届くため、必要最小限の宛先にします。

## 1. タスクの通知先を設定する

1. ナビゲーションの**「タスク」**を開き、**「使っているもの」**から対象のタスクを選びます。以前のタスクスケジューラー画面を開いた場合は、表示される案内に従って「タスク」へ移動します。
2. 新規タスクでは作成画面、既存タスクでは**「タスクの更新」**を開きます。対象、実行方法、スケジュール、状態を先に確認します。
3. **「通知先」**で、必要な通知先にチェックを付けます。通知センターだけにする場合は追加の宛先入力はありません。
4. メールを選んだ場合は**「メールアドレス」**を入力します。複数の担当者へ送る場合も、不要な全社配信にならないよう宛先を確認します。
5. Slackを選んだ場合は**「Slack Webhook URL」**を入力します。通知用のWebhook URLであることを確認し、ブラウザの履歴、資料、ログなどに残さないよう扱います。
6. Chatworkを選んだ場合は**「Chatwork APIトークン」**と**「Chatworkルーム ID」**を入力します。どちらかが欠けると保存できません。トークンはパスワードと同様に扱い、閲覧できる人を限定します。
7. 必要に応じて、後述する**「通知に出力を表示」**と**「自動共有リンク」**を設定します。
8. **「作成」**または**「更新」**を実行し、タスク詳細で通知先、状態、**「次回実行」**を再確認します。

メール、Slack、Chatworkを選んだのに必要な値が空の場合、タスクは保存できません。通知先のチェックを外すと、その通知先に対応する入力値は設定から外れます。設定の入れ替え時は、以前の宛先に通知が残っていないかを更新後に確認してください。

## 2. 出力表示と自動共有リンクを判断する

### 通知に出力を表示

「通知センター」以外の通知先を選ぶと、**「通知に出力を表示」**を設定できます。有効にすると、通知メッセージにタスクの出力結果を含めます。短い要約を即時に確認したい運用には便利ですが、出力に機密情報や個人情報が含まれる可能性がある場合は、原則として無効にし、権限を確認できる実行結果画面で確認します。

失敗時は、出力の代わりにエラー情報が通知に含まれる場合があります。エラー文にも入力値、対象名、外部サービスの情報が含まれ得るため、通知先の共有範囲を同様に点検してください。

### 自動共有リンク

Agentタスクでは、**「自動共有リンク」**を有効にできます。有効な場合、実行結果の共有リンクが自動生成され、メール、Slack、Chatworkなどの通知本文に共有リンクを載せられます。無効な場合は、共有リンクは通知に追加されません。Workflowタスクでは、この設定項目を同じ画面から利用できることは確認できないため、Workflowの結果共有は実行画面の権限・共有仕様に従って別途確認してください。

> 自動共有リンクは、単なる内部画面への導線ではなく共有用のURLです。有効化前に、リンクを受け取る人が誰か、転送・転載されても問題ないか、タスク出力の共有範囲が業務ルールに適合するかを確認してください。検証用のタスクで一度内容を確認してから本番へ適用します。

## 3. 保存後にテストする

設定しただけでは、外部の宛先に実際に届くか、内容が適切かを判断できません。影響の小さい入力・時間帯で1回確認します。

1. 直近の実行が業務に影響しないことを確認し、必要に応じて一時的な検証用タスクを使います。
2. **「今すぐ実行」**または次回の予定実行後に、**「実行履歴」**で開始時刻、状態、実行結果を確認します。
3. 選択した各通知先で、タスク名、成功または失敗、実行結果へのリンク、必要なら出力の表示を確認します。
4. 自動共有リンクを有効にした場合は、リンク先と共有範囲を確認します。受信者が必要な結果を見られるかだけでなく、見せるべきでない情報が見えないかも確認します。
5. 外部送信・更新をするタスクは、外部サービス側の結果も照合します。通知が届いたことだけで再実行や後続処理を判断しません。
6. 検証のために追加した宛先、Webhook URL、トークン、検証用タスクは、不要になった時点で削除または無効化します。

## 通知が届かない場合

通知がないときは、再実行を連続して行う前に、実行そのものと通知設定を分けて確認します。

| 状況 | 確認・対応 |
|---|---|
| 実行履歴に記録がない | タスクが「有効」か、**「次回実行」**と終了日が正しいか、対象のタスクを見ているかを確認します。 |
| 実行は失敗している | **「実行履歴」**のエラーと対象の接続・権限・入力を確認します。通知の不達だけと決め付けません。 |
| 通知センターに出ない | タスクの「通知先」で通知センターが選ばれているか、Projectの有効なメンバー構成と結果へのアクセス範囲を確認します。 |
| メールが届かない | メールアドレス、迷惑メール・配信ルール、受信側の容量・共有メールボックスの設定を確認します。 |
| Slackに届かない | Webhook URL、投稿先チャンネル、Webhookの有効状態、チャンネル権限を確認します。URLを新規発行した場合はタスク側も更新します。 |
| Chatworkに届かない | APIトークン、ルーム ID、トークンの失効、対象ルームへの投稿権限を確認します。トークンをチャットへ貼り付けて確認しません。 |
| リンクを開けない・内容が期待と違う | 実行結果、タスクの種類、通知を受けた人の権限、共有リンクの有効化、出力表示の設定を分けて確認します。 |

通知送信の失敗は、実行結果の記録後に扱われるため、通知が届かなかったことだけで実行を失敗と断定しません。履歴に成功が残っている場合も、外部宛先の設定不備は別途修正し、重複実行の影響を確認してから再テストしてください。

- [ ] 「通知先」で必要最小限の通知センター、メール、Slack、Chatworkを選んだ
- [ ] メールアドレス、Slack Webhook URL、Chatwork APIトークンとChatworkルーム IDを安全に確認した
