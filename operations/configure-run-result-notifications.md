# 実行結果の通知を設定する

Studio Projectのタスクスケジューラでは、AgentまたはWorkflowの実行結果について通知先を設定できます。通知は実行結果を確認する補助であり、外部サービスへの送信や更新を含む処理の完了を保証するものではありません。

タスクの作成・日時設定は[タスクスケジューラを設定する](../build/configure-task-scheduler.md)、変更・停止・引き継ぎは[定期実行を変更・停止・引き継ぐ](change-stop-handover-scheduled-runs.md)を参照してください。

## 始める前に

- 対象のProject、タスク、実行対象、通知を受ける人を確認します。
- 出力本文や共有リンクを通知に含めてよいか、受信者・Slackチャンネル・Chatworkルームの閲覧範囲を確認します。
- メール、Slack、Chatworkを使う場合は、宛先情報を安全な経路で用意します。Webhook URLやAPIトークンをチャット、チケット、画面共有へ転記しないでください。

## 通知先と必要な設定

対象Projectの**タスクスケジューラ**を開き、**「タスク一覧」**で対象を新規作成または編集します。**「通知先」**では、次の通知方法を複数選択できます。

| 通知先 | 必要な設定 | 確認すること |
|---|---|---|
| 通知センター | なし | Projectメンバーが結果を閲覧できる範囲 |
| メール | メールアドレス | 宛先、配信制限、共有メールボックスの閲覧者 |
| Slack | Slack Webhook URL | 通知先チャンネルとチャンネルの公開範囲 |
| Chatwork | Chatwork APIトークン、ChatworkルームID | トークンの有効性、投稿権限、ルームの参加者 |

## 1. 通知先を設定する

1. 対象Projectの設定で**「タスクスケジューラ」**を開き、**「タスク一覧」**で対象タスクを作成または編集します。
2. 実行対象、入力、実行日時または起動方法、状態を確認します。
3. **「通知先」**で必要な通知先を選びます。通知センターだけを選ぶ場合は、追加の宛先入力はありません。
4. メールではメールアドレス、SlackではSlack Webhook URL、ChatworkではAPIトークンとルームIDを入力します。
5. 通知センター以外を選んだ場合は、必要に応じて**「通知に出力を表示」**を設定します。
6. 作成または更新後に、通知先とタスクの状態を確認します。

複数の通知先を併用できます。ただし、同じ出力やリンクが複数の場所に届くため、必要最小限の宛先にします。必要な値が空の場合、保存できないことがあります。

## 2. 出力表示と自動共有リンクを判断する

### 通知に出力を表示

通知センター以外の通知先を選ぶと、**「通知に出力を表示」**を設定できます。有効にすると、通知にタスクの出力結果を含めます。出力やエラーに機密情報や個人情報が含まれる可能性がある場合は、無効にして実行結果画面で確認する運用を検討してください。

### 自動共有リンク

Agentタスクでは、**「自動共有リンク」**を有効にできます。有効にすると実行結果の共有リンクが自動生成され、メール、Slack、Chatworkなどの通知に含められます。Workflowタスクでは、この設定を同じ画面で利用できることは確認できないため、Workflowの結果共有は実行画面の権限と共有仕様に従って確認してください。

## 3. 保存後に確認する

影響の小さい入力または予定実行で、通知と実行結果を一度確認します。

1. 日時実行タスクでは、必要に応じて**「実行」**から予定時刻を待たずに実行します。無効なタスクやWebhookタスクでは利用できません。外部送信・更新の影響を確認してから実行してください。
2. **「履歴」**で開始時刻、状態、実行結果、エラーを確認します。
3. 選択した各通知先で、タスク名、成功または失敗、結果へのリンク、必要なら出力の表示を確認します。
4. 自動共有リンクを有効にした場合は、リンク先と共有範囲を確認します。
5. 外部サービスを更新するタスクでは、外部サービス側の結果も確認します。

## 通知が届かない場合

通知がない場合は、実行そのものと通知設定を分けて確認します。

| 状況 | 確認・対応 |
|---|---|
| 履歴に記録がない | タスクの状態、実行日時、終了日、対象タスクを確認する |
| 実行が失敗している | 履歴のエラー、接続、権限、入力を確認する |
| 通知センターに出ない | 通知先で通知センターが選ばれているか、Projectメンバーと結果へのアクセス範囲を確認する |
| メールが届かない | メールアドレス、迷惑メール・配信ルール、受信側の設定を確認する |
| Slackに届かない | Webhook URL、投稿先チャンネル、Webhookの有効状態、チャンネル権限を確認する |
| Chatworkに届かない | APIトークン、ルームID、トークンの失効、投稿権限を確認する |
| リンクを開けない・内容が期待と違う | 実行結果、タスクの種類、受信者の権限、共有リンク、出力表示の設定を分けて確認する |

通知が届かなかったことだけで、実行が失敗したとは判断しません。外部宛先を修正して再確認する場合も、重複実行の影響を確認してください。

- [ ] 必要最小限の通知センター、メール、Slack、Chatworkを選んだ
