# MemoryとProject共有情報を管理する

MemoryとProjectの共有情報は、保存目的と共有範囲が異なります。この記事では、**管理者が個人用のMemoryとProject内で共有する情報を区別し、閲覧・変更・削除の影響を確認する手順**を説明します。

Projectの目的、説明、共通指示を整える操作は[Projectの説明・文脈を整える](../build/prepare-project-context.md)を参照してください。組織・Project・Appの権限関係は[組織・Project・Appの権限を理解する](understand-org-project-app-permissions.md)で扱います。

## 始める前に

- 正しい組織、対象Project、変更対象を確認します。
- 閲覧、変更、削除の別と、必要な権限を確認します。
- 既存の本文、対象Agent、影響する利用者を確認します。

> Memoryの画面やAgentの「メモリを使用する」設定は、組織の利用条件や設定によって表示が異なります。画面がない、操作が無効、または保存できないことだけから、情報が存在しない、権限不足である、と断定しないでください。

## 保存先と共有範囲を分ける

前提をAIへ伝える目的でも、保存先を混同すると、個人だけに残したい情報を共有したり、Project全体で使うべき情報が担当者だけに閉じたりします。

| 種類 | 主に保存するもの | 誰が見つけて使う前提か | 管理時の注意 |
|---|---|---|---|
| 自分のMemory | 個人の継続的な好みや担当上の前提 | 原則として本人の利用文脈 | Project共通の業務ルールの置き場所にしない |
| 組織のMemory | 組織で共通に扱う前提 | 許可された利用者・Agent | Project固有の機密事項を登録しない |
| ProjectのMemory | 特定Projectで共有して扱うMemory | そのProjectの利用・管理範囲 | Projectに参加する人や利用するAgentとの関係を確認してから扱う |
| Projectの「説明」 | Projectの目的、対象、利用者、対象外 | Projectを開く人や構築・運用担当者 | Memoryと同じ保存先とは限らない。説明を変えてもMemoryの内容は自動で整理されない |
| 「カスタム指示」などの共通指示 | 用語、出力形式、判断方針、対象外の操作 | 対象Projectで共通に守らせたい方針 | 指示は認可設定ではなく、秘密値や個人の機微情報の保管場所でもない |
| Dataset・Storage・Object | 参照資料、ファイル、構造化した業務データ | 設定されたアクセス範囲の利用者・機能 | Memoryや指示の代わりに、すべての資料を本文へ転記しない |

Memoryは、Agentが対話やタスクで得た事実・文脈を保持し、必要に応じて参照・更新する仕組みです。保存されていても、必ず反映される保証はありません。

## 1. 変更前に共有範囲と影響を確認する

まず、変更対象を次の観点で台帳や運用記録へ整理します。本文そのものをチケットやチャットへ複製する必要はありません。

| 確認項目 | 確認する内容 |
|---|---|
| 保存先 | 自分のMemory、組織のMemory、対象ProjectのMemory、説明、共通指示、資料のどれか |
| 利用範囲 | 個人、組織、どのProject、どのAgent、どの業務で影響し得るか |
| 内容と理由 | 現在も正しいか、重複・矛盾・古い日付・担当名がないか。追加、訂正、統合、廃止のどれか |
| 影響と責任 | Agent・利用者・説明・共通指示への影響、確認者、更新者、見直す契機 |

ProjectのMemoryは対象Projectに紐づく共有情報です。個人用のMemoryを移すと共有範囲が変わるため、健康・人事情報や不要な顧客情報は移しません。

> Projectへの参加、Memoryを閲覧できること、Memoryを編集・削除できること、Agentを設定できることは別の条件です。表示上のロール名だけで変更できると判断せず、対象画面の操作可否と、実際に表示される権限案内を確認してください。

## 2. Memoryの一覧を確認する

組織設定に**「メモリ管理」**が表示される場合は、まず現在の一覧を確認します。

1. 正しい組織を選び、設定から**「メモリ管理」**を開きます。
2. Project外の画面では、表示される場合に**「自分のメモリ」**と**「組織のメモリ」**を切り替えます。組織のMemoryが見えない場合、組織全体に存在しないとは断定しません。
3. 対象Projectの文脈では、**「プロジェクトのメモリ」**として一覧が表示される場合があります。対象Projectを再確認します。
4. **「エージェント名」**、**「メモリ内容」**、**「作成日時」**、**「更新日時」**を確認します。
5. 内容、対象Agent、共有範囲を確認して次の操作を決めます。

誤った顧客情報、古い業務条件、個人情報の混在がないかを確認します。人が確認せずに共有範囲を広げたり、別のProjectへ転記したりしないでください。

## 3. 変更・削除の可否を確認する

### Memoryの変更

Memoryの変更・削除は、対象と権限によって可否が異なります。ProjectのMemoryでは、Projectを更新できる権限が必要です。組織・個人のMemoryは、組織の設定によって、所有者、管理者、または個別に許可された人だけが変更できる場合があります。

1. **「編集」**を選べるか確認します。選べない場合は別のMemoryを作り直しません。
2. 変更前の内容、対象Agent、更新日時を確認します。
3. 内容を、確認済みの事実・適用範囲・例外が分かる文章へ修正します。推測、未確認の数値、期限切れの前提を残さないでください。
4. 保存後、一覧を再表示し、内容と**「更新日時」**を確認します。
5. 影響するAgentで、機密情報を含まない小さな依頼を使い、期待しない参照や古い前提が残っていないか確認します。

この管理画面の手動新規作成は無効で、MemoryはAgentとの対話を通じて作成されます。権限を追加して手動作成を有効にすることはできません。共通方針を保存する場合は、個人・組織・Projectの適切な範囲を確認し、Projectの説明やカスタム指示で管理する情報と区別してください。

### Memoryの削除

削除は元に戻せない旨の確認が表示されます。削除前に、対象が同名の別Memoryではないこと、現在利用するProject・Agent・共通指示と矛盾しないことを確認します。

1. 内容、対象Agent、利用範囲を確認します。
2. 削除理由と、正しい内容が別の保存先にあるかを確認します。
3. 対象行の**「削除」**を選び、確認画面の削除対象を読みます。
4. 確定後、一覧を再表示し、対象が消えたことを確認します。
5. 影響が大きい場合は、関連するAgentと代表的な依頼を確認し、利用者・管理担当者へ変更を伝えます。

> 削除後に元の本文を画面から読み出せる前提にはしないでください。必要な正しい前提を残す場合は、先に保存先と共有範囲を決め、承認された文面を別の適切な場所へ反映してから削除します。会話を削除・新規作成しても、MemoryやProject共有情報が同時に消えるわけではありません。

## 4. Projectの共有情報を見直す

Projectで共有する情報は、説明、共通指示、ProjectのMemory、資料・データで役割を分けます。Memoryの整理だけで、Projectの説明や共通指示まで更新されたとは扱わないでください。

1. 対象Projectの**「プロジェクト設定」→「基本設定」**を開きます。
2. **「プロジェクト情報」**の**「説明」**を確認し、目的、対象利用者、対象業務、対象外が現在の運用と合うか確認します。
3. **「カスタム指示」**が表示される場合は、既存の内容とMemoryに矛盾がないか確認します。保存先・管理方式によって、この欄が表示されない場合があります。
4. 資料や業務データは、Memory本文へ大量に転記せず、実際の保存先とアクセス設定を確認します。
5. 変更した保存先を記録します。

Projectの説明や共通指示の変更手順、保存・キャンセル・削除の違いは、[Projectの説明・文脈を整える](../build/prepare-project-context.md)を正本として確認してください。指示文だけで外部操作の権限を取り消すことはできません。

## 機微情報と共有情報の注意

次の情報は、個人用かProject共有かを問わず、Memoryや説明・指示へ安易に保存しません。

- パスワード、APIキー、トークン、認証コードなどの秘密値
- 特定個人の健康、人事、評価、私生活に関する情報
- 共有が承認されていない顧客情報、契約条件、未公開の営業情報
- 個人のアカウントにしかアクセスできない情報や、異動後に引き継げない情報
- 未確認の事実、推測、期限切れの価格・日付・担当者情報

秘密値はProject Secretなど用途に合う管理機能を使います。手順は[Project Secretを登録・更新・削除する](manage-project-secrets.md)を参照してください。共有情報は最小限にし、正確性と更新責任を確認します。

## 確認できない場合

| 状況 | 確認・対応 |
|---|---|
| 「メモリ管理」が表示されない | 組織の利用条件、正しい組織、対象Project、権限を確認する。表示されないことを未設定の証拠にしない。 |
| 組織またはProjectのMemoryを見られない | 閲覧権限と対象範囲を確認する。個人用のMemoryを共有用として複製して回避しない。 |
| 「編集」「削除」が選べない、または保存に失敗する | 対象の保存先、Project更新権限、個別の操作権限、表示されたエラーを確認する。同じ操作を繰り返さない。 |
| Memoryを手動で新規追加できない | この管理画面では手動作成が無効です。既存Memoryの編集とは区別し、Agentとの対話またはProjectの説明・カスタム指示など、目的に合う保存方法を確認します。 |
| AIが古い情報を使う、または使わない | Memoryだけを原因とせず、対象Agentの設定、共通指示、会話の依頼、資料へのアクセス、保存結果を切り分ける。 |
| 削除してよいか判断できない | 対象Agent・Project・利用者を特定し、正しい代替情報の保存と代表的な確認が済むまで削除しない。 |

問い合わせには、組織名、Project名、保存先、対象Agent、操作日時、表示メッセージ、確認済みの結果を添えます。機密情報やSecretの実値は添付しません。

## 管理チェックリスト

- [ ] 個人、組織、Project、説明、共通指示、資料・データの保存先を区別した
- [ ] 正しい組織・Project・対象Agentと、閲覧・変更・削除の権限を確認した
- [ ] 変更前に、内容の正確性、共有範囲、影響、責任者を確認した
- [ ] 追加・変更・削除の対象範囲と、現在利用できる管理方法を確認した
- [ ] 削除前に、必要な代替情報と影響する利用者・Agentを確認した
- [ ] 説明、共通指示、Memory、資料を別々に保存・確認した
- [ ] 秘密値、個人情報、未承認の業務情報を共有情報へ保存していない
- [ ] 機密情報を含まない代表的な依頼で、変更後の結果を確認した
