# 実行消費と利用状況を確認する

JAPAN AIの利用状況では、Agent、Workflow、モデル、ツールなどを**実行した結果として消費されたクレジット**を確認できます。一方、Appに設定されたシートの料金は、利用人数・購入シート数に基づく別の確認対象です。同じクレジット表記であっても、実行消費とAppのシート料金を混同しないことが重要です。

この記事では、管理者が組織の「クレジット利用状況」で実行消費を確認し、増加の要因を切り分ける方法を説明します。Appの人数・料金・契約上限は[Appの利用人数・料金・契約上限を確認する](check-app-seats-pricing-and-limits.md)、機能ごとの制限や提供条件の参照先は[制限・提供条件の索引](limits-and-availability-index.md)を確認してください。

## この記事の範囲

本記事で扱うのは、組織全体のクレジット利用状況です。月を選び、日別・LLM別・ツール別の表示を切り替えて、利用者ごとの内訳を確認します。

Projectの**「使用量」**画面は、作成済みリソース数、記録済みのクレジット・アクティビティ、ストレージなどを確認する別の画面です。ここでいう「利用上限の計算対象」は組織全体の使用量に占めるProject分であり、Project固有の上限ではありません。Projectの処理が疑われる場合も、組織のクレジット利用状況で利用者・実行種別・日付を絞り、対象のAgent、Workflow、タスク、実行履歴を個別に確認してください。

## 始める前に

- 正しい組織を開いていることを確認します。クレジット利用状況は組織単位の集計です。
- 対象月、確認したい事象の日付、想定する利用者・Agent・Workflowを整理します。月をまたぐ定期実行は、実行された月ごとに確認します。
- 組織の管理者として画面へアクセスできることを確認します。組織の「クレジット利用状況」は管理者向けの画面です。アクセス権が不足すると「クレジット・利用状況へのアクセス権限がありません」と表示されることがあります。
- 数値をAppの月額料金、請求額、契約上限と同一視しないでください。確認目的に応じて、実行消費かシート料金かを先に分けます。

> 「クレジット利用状況」の数値は、利用者が画面を開いた回数やAppをインストールした件数そのものではありません。生成されたテキスト量や使用した機能に応じたクレジット消費を集計する表示です。請求書の金額やAppの契約条件をこの画面だけで確定しないでください。

## 実行消費とAppのシート料金を分ける

確認前に、増加した数値の性質を次のように整理します。

| 確認対象 | 主なきっかけ | 最初に見る画面 | 判断するときの注意 |
|---|---|---|---|
| 実行消費 | Agentの応答、Workflowや定期実行、LLM、ツール、データ連携、SPEECH文字起こしなどの処理 | 組織の「クレジット利用状況」 | 日付、利用者、実行種別、LLM、ツールで原因を絞る |
| Appのシート料金 | 有料Appのインストール、購入シート数の変更、月次更新 | Appの料金・シートに関する画面 | 利用者を削除しても、購入シート数を変更しなければ更新料金が変わらない場合がある |

日別表示には「アプリシート」も表示されるため、クレジットの増加がすべて実行によるものとは限りません。「アプリシート」が増えている場合は、実行の内訳ではなく、[Appの利用人数・料金・契約上限を確認する](check-app-seats-pricing-and-limits.md)で対象App、購入シート数、更新時の条件を確認します。

反対に、「エージェント」「ワークフロー/データ連携」「SPEECH文字起こし」が増えている場合は、実行に伴う消費として利用状況を掘り下げます。表示上の分類は集計用の目安です。単一の実行がどの処理まで行ったかは、対象の実行履歴と併せて確認してください。

## Projectの「使用量」と組織の「クレジット利用状況」を使い分ける

Projectの**「使用量」**では、Project内のページ、Object、Agent、Workflow、Dataset、トリガーなどの作成数、ストレージ、Projectに紐づく記録済みクレジット・アクティビティを確認できます。データソースごとに集計時刻が異なるため、表示値は現在値と一致しない場合があります。記録がない、または0件でも、Projectが未使用とは判断しません。

導入済みAppの「使用量」は、Appの内部リソース一覧を表示せず、クレジット使用量、AIリクエスト、オートメーション実行、ストレージなどの記録値を中心に表示します。Projectの使用量は原因候補の把握に使い、組織全体の実行消費・月別分析は次節の「クレジット利用状況」で確認します。

> Projectのカードに表示されるバーは、記録値と組織全体の利用上限計算対象の比較です。契約上限の残量やAppの人数上限を直接示すものではありません。Projectのリソース数、ストレージ、組織のクレジット、Appのシート料金を同じ数値として扱わないでください。

## 1. 組織の「クレジット利用状況」を開く

1. JAPAN AIで対象組織を選択します。
2. 組織設定から**「クレジット利用状況」**を開きます。
3. 画面上部の月選択で、確認したい月を選びます。まずは現在月ではなく、増加を確認したい月を明示して選択します。
4. 表示される**「利用クレジット」**を確認します。画面の構成によっては、利用可能な残高や付与に関する表示も確認できます。
5. 集計に失敗している場合は、「グラフの読み込みに失敗しました」または「記録がありません」と表示されることがあります。この場合、数値がゼロであると判断せず、後述の対応を行います。

組織の設定や提供条件によって、表示項目、絞り込み項目、利用可能な機能は異なります。画面にない分類を別の数値から推計しないでください。

## 2. 「日別」で増えた日と利用者を確認する

最初は**「日別」**を選び、いつ、どの分類で増えたかを確認します。

1. **「日別」**を選び、**「日毎のクレジット推移」**を確認します。
2. 増加した日の棒を選択し、日付で絞り込みます。日を選択しない場合は、選んだ月全体の集計を確認できます。
3. 一覧で**「名前・メールアドレス」**、**「ワークフロー」**、**「データ連携」**、**「SPEECH文字起こし」**、**「エージェント」**、**「合計」**を確認します。列見出しを使って、消費の大きい利用者や分類を上位から確認します。
4. 必要に応じて名前・メールアドレスで検索します。部署を選べる組織では、対象部署へ絞り込んで比較します。
5. APIからの利用だけを確認する必要がある場合は、**「APIのみ」**を使います。通常の画面操作による利用と混ぜて判断しないでください。
6. 集計結果を共有・保管する必要がある場合は、**「CSVダウンロード」**を使用します。CSVには利用者名やメールアドレスが含まれ得るため、保存先と共有範囲を必要最小限にします。

> 利用者別一覧の「合計」は、選択した月・日・絞り込み条件の集計です。選択条件を変えた数値同士を、そのまま増減比較しないでください。確認した条件を記録してから比較します。

## 3. 「LLM別」と「ツール別」で実行内容を掘り下げる

Agentによる消費が目立つときは、モデルとツールを分けて確認します。

### LLM別を確認する

1. **「LLM別」**を選びます。
2. 一覧とグラフで、LLMごとの**「入力クレジット」**、**「出力クレジット」**、**「利用クレジット」**、**「利用者数」**を確認します。
3. 入力または出力のどちらが増えているか、どのモデルに偏っているかを確認します。
4. 必要に応じて**「CSVダウンロード」**から、**「組織全体」**または**「ユーザー別」**を選びます。ユーザー別のデータは共有範囲を限定します。

入力・出力は「利用クレジット」の内訳です。合計列へさらに加算しません。

### ツール別を確認する

1. **「ツール別」**を選びます。
2. **「ツール」**、**「利用クレジット」**、**「使用量」**、**「単位」**、**「利用者数」**を確認します。
3. 表示されたツールごとの増加を確認します。
4. 高い消費が見つかった場合は、該当するAgentの設定、繰り返し実行、利用者の操作、実行履歴を確認します。

ツール名や単位が表示されない場合は、未使用、対象外、または組織の提供条件による可能性があります。表示だけから利用可否や料金体系を断定しないでください。

## 4. Workflow・自動実行を確認するときの順序

Workflowや自動実行が原因と考えられる場合は、利用状況だけで停止・変更を判断せず、増加日の利用者別内訳、対象のWorkflow・タスク・実行履歴、頻度・終了日・通知先・作成者を順に確認します。

繰り返し実行は消費へ影響する可能性があるため、実行頻度と月間の利用状況を合わせて確認します。設定は[タスクスケジューラを設定する](../build/configure-task-scheduler.md)、変更・停止・引き継ぎは[定期実行を変更・停止・引き継ぐ](change-stop-handover-scheduled-runs.md)を参照してください。

## よくある誤解

- **Appを利用しているので、増加分はすべてApp料金である**：違います。Appのシート料金と、その中で行われたAgentやWorkflowなどの実行消費は分けて確認します。
- **利用者を削除すれば、Appの更新料金も自動で下がる**：違います。利用人数と購入シート数は別に管理される場合があります。[Appの利用人数・料金・契約上限を確認する](check-app-seats-pricing-and-limits.md)を確認します。
- **「LLM別」の入力・出力を「利用クレジット」に足す**：違います。入力・出力はAgent利用内の内訳です。
- **Projectのリソース使用量が少ないので、実行消費も少ない**：判断できません。Projectの作成数・ストレージ・記録済みアクティビティと、組織のクレジット実行消費は別の確認対象です。
- **記録がないため、実行もなかった**：表示の読み込み失敗、選択月・日・絞り込み条件の相違がないかを確認してから判断します。

## 確認できない場合

| 状況 | 確認・対応 |
|---|---|
| 「クレジット利用状況」が表示されない | 正しい組織を選んでいるか、管理者としてアクセスしているかを確認します。組織設定・権限・提供条件により表示が異なるため、管理担当者へ確認します。 |
| アクセス権限がないと表示される | 組織の利用状況を閲覧できる権限を持つ管理者へ依頼します。個人の画面だけで組織全体の消費を推測しません。 |
| 数値が急に増えた | まず日別で日付を特定し、利用者別の分類、LLM別、ツール別の順に確認します。「アプリシート」が原因なら[Appの利用人数・料金・契約上限を確認する](check-app-seats-pricing-and-limits.md)へ戻ります。 |
| Workflowの消費元が分からない | 対象日の利用者別一覧から候補を絞り、Workflow・「タスク」・実行履歴を確認します。推測で複数の自動実行を停止しません。 |
| CSVを共有したい | 利用者名・メールアドレスを含む可能性を確認し、共有先・保存期間・保存場所を必要最小限にします。 |
| グラフや内訳の読み込みに失敗する | 月、日、部署、APIのみなどの絞り込みを記録し、時間をおいて再表示します。継続する場合は、組織名、確認日時、選択条件、表示メッセージ、対象のAgent・Workflowを添えて問い合わせます。 |
