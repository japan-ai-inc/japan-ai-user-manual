# Project・Appの共有接続を設定する

ProjectやAppで同じ外部サービスを使う場合、管理者が**共有接続**を用意し、必要に応じてAppへ割り当てます。

この記事では、共有接続を登録し、Appの「アプリ共通のコネクタ」へ設定する手順を説明します。使い分けは[個人接続・共有接続・Secretを選ぶ](choose-personal-shared-connections-and-secrets.md)、失効や再認証は[接続の失効・担当者変更に対応する](handle-expired-connections-and-owner-changes.md)を参照してください。

## 始める前に

- 正しい組織と対象のProjectまたはAppを確認します。環境を取り違えないでください。
- 接続設定とApp共通の設定を変更できる権限を確認します。対象を開けても、共有接続の作成・割り当てができるとは限りません。
- 接続先、用途、データ、実行範囲を決めます。
- チーム・部門・業務用として承認された外部サービスのアカウントを用意します。個人のアカウントを共有用途に使ってよいかは、外部サービス側の規約と組織の運用を確認します。
- 認証担当者、接続管理者、失効時の連絡先を決めます。

> 共有接続を使う処理は、外部サービスの認証アカウントの権限に影響されます。最小限の権限を持つ業務用アカウントを使い、個人用の権限を安易に共有しないでください。

画面の入口や操作範囲は、組織の設定、権限、Appの構成によって異なります。項目が表示されない場合は、別の接続を作らず管理担当者へ確認してください。

## 共有接続を使う人と、認証アカウントを分けて考える

共有接続では、次の3者を区別します。

| 区分 | 誰か | 確認すること |
|---|---|---|
| 設定する人 | 接続を作成・割り当てる管理者 | 対象Project／App、サービス、接続タイプ、設定結果を管理できるか |
| 利用する人・処理 | Agent、Workflow、業務画面を使う利用者や自動処理 | 共有接続を利用する機能、実行できる操作、利用者のアクセス範囲 |
| 認証されるアカウント | 外部サービスでサインインまたは認証する業務用アカウント | そのアカウントのデータ範囲、実行権限、失効・異動時の管理責任 |

共有接続を設定しても、利用者へ管理権限を付与するものではありません。一方で、利用者が共有接続を使う処理を実行すると、外部サービス側では認証アカウントの権限で参照・送信・更新が行われることがあります。利用者のアクセス権と、外部サービスのアカウント権限の両方を確認します。

## 1. Projectの「コネクタ設定」を開く

1. 対象のProjectを開き、設定画面から**「コネクタ設定」**を開きます。Appに共通の要件がある場合は、対象Appの**「設定」**から接続設定を開けることもあります。
2. **「プロジェクトのコネクタ」**を確認します。ここにある接続が、Project内で共有して使う候補です。
3. 同じサービスの既存接続、名称、認証アカウント、用途、接続タイプを確認します。
4. 組織から利用できる候補が表示される場合は、**「組織共通のコネクタ」**も確認します。ただし、組織共通の候補を選べるか、Projectへコピーされるかは、権限と構成によって異なります。

同じサービスの接続を重ねず、既存接続を確認してから追加してください。

## 2. 共有接続を追加またはコピーする

既存の候補を使えない場合は、Projectへ接続を追加します。

1. **「新しいコネクタ」**を選びます。
2. **「プロジェクト用コネクタ」**を選びます。接続タイプを表示する画面では、**「共有接続」**であることを確認します。
3. 一覧から外部サービスを選びます。表示されないサービスを別のサービスで代用しないでください。
4. 接続名には、用途と認証アカウントを識別できる名称を付けます。例：`営業共有_問合せ対応用`。パスワード、APIキー、トークンなどの秘密値を名前に含めないでください。
5. 外部サービスの認証画面が開く場合は、承認済みの業務用アカウントでサインインし、要求される権限を確認して認証します。
6. Projectへ戻り、「プロジェクトのコネクタ」に接続が表示されること、サービス・名称・接続タイプが意図どおりであることを確認します。

個人の既存接続を候補から使う場合は、**「コピー」**または**「コピーして設定」**が表示されることがあります。コピー元の外部アカウントを共有利用してよいか、担当者変更後も管理できるかを確認してから実行してください。

> 接続名が共有用らしく見えても、外部サービスのアカウント権限まで安全になるわけではありません。認証時のアカウント、OAuthの同意内容、対象データへの権限を確認します。認証情報をチャットや手順書などに貼り付けないでください。

## 3. Appの共有要件へ割り当てる

Appが共有接続を必要とする場合、Projectへの作成だけでは完了しないことがあります。Appの設定で、必要な接続を選択して割り当てます。

1. 対象Appを開き、**「設定」**から接続要件を確認します。
2. **「アプリ共通のコネクタ」**で、未設定のサービスと状態を確認します。状態は**「未設定」**、**「確認中」**、**「設定済み」**、**「無効」**、**「停止中」**などと表示される場合があります。
3. 対象サービスの設定操作を選び、**「このアプリで利用できるコネクタ」**から、手順2で確認した共有接続を選びます。
4. **「設定」**を選び、完了表示を待ちます。組織共通の候補を使う場合は**「組織共通のコネクタ」**から選び、表示された**「コピーして設定」**を確認して実行します。
5. Appの接続要件へ戻り、対象サービスが**「設定済み」**になったことを確認します。

「コネクタは作成されましたが、アプリへの設定に失敗しました」と表示された場合は、同じ接続を作り直さず、作成済みの接続を選択して再設定します。また、「このコネクタの共有範囲がアプリの要件と一致しないため、接続できません」と表示された場合は、個人接続と共有接続、または対象Projectを取り違えていないか確認します。

## Agent・Workflowでどちらの接続が選ばれるか

接続の選択は、画面を操作している人だけでは決まりません。Agent・Workflowの実行場所と、Appが求める接続の種類によって、共有接続と個人接続の扱いが変わります。

| 実行する場面 | 接続の選ばれ方の目安 | 管理者が確認すること |
|---|---|---|
| Project内でAgentやWorkflowをテストする | 個人接続または共有接続が使われる場合があります。 | テスト結果だけで、公開後も同じ接続が使われると判断しない。 |
| 導入済みAppで利用者がAgent・業務画面を操作する | Appの構成により必要な接続が異なります。 | 「接続が必要」などの案内を確認する。 |
| 導入済みAppのWorkflow、自動実行 | 共有接続が必要な場合があります。 | 実行者がいなくても使えるアカウントか、送信先・更新先を確認する。 |

同じ外部サービスでも、AgentとWorkflow、手動実行と自動実行で必要な接続が異なる場合があります。共有接続があっても、すべての利用者の個人認証が不要になるとは限りません。個人接続が必要な利用者には、[自分の外部アカウントを接続する](connect-your-external-accounts.md)を案内してください。

> 自動実行が共有接続を使う場合、実行した利用者本人ではなく、共有の認証アカウントの権限で外部サービスへ処理が及ぶ可能性があります。メール送信、レコード更新、ファイル変更などは、少量の許可済みデータで対象・結果を確認してから利用を広げてください。

## 4. 利用前に動作と管理責任を確認する

設定状態と実際の処理を分けて確認します。

1. 利用予定のAgent、Workflow、またはAppの業務画面を特定します。
2. 許可されたテストデータと、安全な送信先・更新先を用意します。
3. 利用者が行う操作と、自動実行がある場合の処理を、それぞれ小さな範囲で確認します。
4. 外部サービス上で、参照したデータ、送信先、更新先、実行結果が意図どおりか確認します。
5. 接続名、対象、用途、管理責任者、連絡先を記録します。実値は記録しません。

「設定済み」でも外部サービス側の権限不足で失敗することがあります。画面を開けただけで利用開始とせず、代表操作を確認してください。

## うまくいかない場合

| 状況 | 確認・対応 |
|---|---|
| 「コネクタ設定」や「新しいコネクタ」が表示されない | 正しい組織・Projectか、共有接続を管理する権限と機能提供条件があるかを確認する。表示されない機能を個人接続で代用しない。 |
| 「この設定を変更する権限がありません」と表示される | 接続を作成する権限と、App共通の接続を割り当てる権限を確認し、権限を持つ管理者へ依頼する。 |
| Appで「未設定」または「確認中」のまま | 接続を作成しただけで終わらず、Appの「アプリ共通のコネクタ」へ割り当てたか、状態を再表示して確認する。 |
| 共有範囲が一致しないと表示される | 個人接続ではなく共有接続を選んだか、対象Projectの接続か、Appが要求するサービスかを確認する。 |
| 「無効」「停止中」になる | 外部サービスのアカウント、同意、期限、管理状態を確認する。解除・再作成を繰り返さず、失効対応は[接続の失効・担当者変更に対応する](handle-expired-connections-and-owner-changes.md)を確認する。 |
| AgentやWorkflowが失敗する | 実行した機能、個人／共有のどちらが使われる場面か、外部サービス側の権限、対象データ、実行時のエラーを確認する。 |

問い合わせには、組織名、ProjectまたはApp名、接続先サービス、接続名、操作日時、表示された状態・メッセージ、対象のAgent・Workflow、確認済みの操作を添えます。パスワード、APIキー、トークン、認証画面の機密情報は送らないでください。

- [ ] 承認済みの業務用アカウントを選び、最小限の外部サービス権限を確認した
- [ ] 「プロジェクト用コネクタ」と「共有接続」を確認して登録またはコピーした
- [ ] Appでは「アプリ共通のコネクタ」に正しい接続を割り当て、「設定済み」を確認した
- [ ] Agent・Workflow・自動実行の接続選択と、個人接続が必要な利用者を確認した
- [ ] 許可された範囲で外部サービス上の結果を確認した
