# 接続の失効・担当者変更に対応する

外部サービスとの接続は、認証の期限切れ・外部サービス側での解除・アカウントや担当者の変更によって使えなくなることがあります。個人接続と共有接続では、修復する人と引き継ぎ方が異なります。この記事では、利用者と管理者が表示内容から影響範囲を切り分け、接続を安全に修復・引き継ぎする順序を説明します。

- 個人接続を作成・解除・再認証する：[自分の外部アカウントを接続する](connect-your-external-accounts.md)
- 共有接続を設定する：[Project・Appの共有接続を設定する](configure-shared-connections.md)
- 権限やサインイン自体の問題を切り分ける：[権限・認証エラー](../troubleshooting/permission-and-auth-errors.md)
- 定期実行の変更・停止・引き継ぎ：[定期実行を変更・停止・引き継ぐ](change-stop-handover-scheduled-runs.md)

## 始める前に

- 正しい組織、ProjectまたはApp、接続先サービスを確認します。同名のProjectや複数の接続がある場合は、用途も照合します。
- 影響が疑われるAgent、Workflow、App機能、データ連携、トリガー、定期実行を洗い出します。接続名、接続タイプ、認証したアカウント、最終認証日時、発生日時を記録します。
- 外部サービス側で、後任者が使うアカウント、権限、承認済みの引き継ぎ時刻を確認します。パスワード、APIキー、トークンの実値は記録・送付しません。
- 共有接続を変更する場合は、影響する利用者と業務を担当者へ連絡します。変更できる権限がないときは、操作を繰り返さず管理者へ依頼します。

> 接続が表示されていることと、業務処理が成功することは別です。修復後は、許可された小さな操作で、参照先・送信先・更新先を含めて確認してください。

## 症状から原因と対応を分ける

画面に出る文言と対象を確認し、個人接続か共有接続かを先に分けます。「要再認証」は、外部サービスの認証を更新する必要がある状態であり、接続先やアカウントを推測して別の接続へ置き換える合図ではありません。

| 症状・表示 | 主な原因の見方 | 最初の対応 |
|---|---|---|
| 「要再認証」「連携が無効になっています。同じアカウントで再認証してください。」 | 認証が無効になった、または更新が必要な可能性があります。 | 接続名・アカウント・接続タイプを確認し、同じアカウントで「再認証」します。 |
| 「この連携は別のアカウントに紐づいています。同じアカウントで再認証してください。」 | 認証画面で別アカウントを選んだ可能性があります。 | アカウントを切り替えず、既存接続のアカウントを確認します。担当交代なら、後任用の接続として扱います。 |
| 「接続が必要」 | Appまたは機能が利用者本人の接続を求めています。 | 利用者本人が「個人用のコネクタ」を確認し、[自分の外部アカウントを接続する](connect-your-external-accounts.md)に従って対応します。 |
| 共有要件が「無効」「未設定」、または「このアプリを使用するには、管理者による共有認証情報の設定が必要です。」 | App共通の接続が利用できない、または設定されていない可能性があります。 | 利用者は管理者へ連絡し、管理者が対象の共有接続とAppへの設定を確認します。 |
| Gmail／Outlookトリガーで「メール受信エラー」 | 接続の状態、または公開状態の再確認が必要です。 | トリガーの「接続状態を更新」、接続状態、公開状態を順に確認します。 |
| 定期実行の履歴で「タスクの作成者が組織のメンバーではないため実行されませんでした。」 | タスク作成者が組織のメンバーではなくなっています。 | 後任者が実行内容・通知・スケジュールを確認し、[定期実行を変更・停止・引き継ぐ](change-stop-handover-scheduled-runs.md)に従って引き継ぎます。 |

> 「接続済み」「認証済み」でも、外部サービス側のデータ権限、対象フォルダー、送信先などが変われば実行に失敗することがあります。接続だけを原因と決めつけないでください。

## 個人接続を修復・引き継ぐ

個人接続は、利用者本人の外部アカウントで行う認証です。利用者が異動・退職する場合、後任者が前任者の個人接続を引き継いで使える前提にはしません。後任者の業務アカウントと権限が準備できた後、本人が必要な接続を作成します。

### 利用者本人が再認証できる場合

1. 対象のAppまたはProjectで「コネクタ設定」を開き、「個人のコネクタ」または接続を求める案内を確認します。
2. 接続先サービス、「アカウント」、「接続タイプ」が「個人接続」であることを確認します。Appの要件画面では「個人用のコネクタ」と状態も確認します。
3. 「再認証」が表示される場合は選択し、**現在の接続と同じアカウント**で外部サービスの認証を完了します。画面に「再認証」の入口がない場合は、解除・追加を先に行わず担当者へ確認します。
4. 「接続済み」または「認証済み」と表示されることを確認します。
5. 許可された範囲で、失敗していた機能を一度だけ実行し、結果を確認します。

再認証時に別アカウントを選ぶと、既存接続を修復できない場合があります。担当交代で別アカウントを使うなら、旧接続の再認証ではなく、後任者が自分の接続を準備する手順に切り替えます。

### 利用者・担当者が交代する場合

1. 前任者の接続に依存する機能と、外部サービス側のアカウント停止予定を確認します。
2. 後任者を対象ProjectまたはAppの利用者として準備し、必要な外部サービス側の権限を付与します。Studioの利用権限だけでは外部サービス側のアクセスは補えません。
3. 後任者が自分のアカウントで個人接続を作成し、状態を確認します。詳しい操作は[自分の外部アカウントを接続する](connect-your-external-accounts.md)を参照してください。
4. 後任者の立場で、必要なAgent、Workflow、App機能を小さなデータで確認します。
5. 旧接続が不要になったこと、依存する処理がないことを確認してから、前任者本人または管理者が「連携解除」を行います。

> 「連携解除」は認証情報を削除する操作です。データセットの更新設定がある接続を解除すると、更新が行えなくなります。後任の接続で動作確認する前に、旧接続を解除しないでください。

## 共有接続を修復・引き継ぐ

共有接続はProjectまたはAppの共通処理に影響するため、利用者が自分の個人接続で置き換えるものではありません。管理者は、認証したアカウントが引き続き共有利用を許可された業務アカウントか、対象Appの要件と共有範囲に合うかを確認します。

1. 「コネクタ設定」で「プロジェクトのコネクタ」またはAppの「アプリ共通のコネクタ」を開きます。Appで「設定を管理」が表示される場合は、対象の設定を開きます。
2. 接続先サービス、認証したアカウント、接続タイプ、現在の状態を確認します。「無効」「未設定」「停止中」の場合は、表示された案内と対象Appの要件を記録します。
3. 既存接続を修復する場合は、管理権限のある担当者が「再認証」し、外部サービス側で承認された共有用アカウントを使います。「最初に連携したユーザーまたは管理者」に再認証を依頼する案内が出る場合は、その案内に従います。
4. 後任の業務アカウントへ切り替える必要がある場合は、新しい共有接続を準備し、対象Appで「設定」または「コネクタをアプリに設定しました」と確認できるまで設定結果を確認します。具体的な登録・割り当ては[Project・Appの共有接続を設定する](configure-shared-connections.md)を参照してください。
5. 依存するApp・Agent・Workflowを、許可されたデータで確認します。問題がなければ、不要になった旧接続の解除を検討します。

> 共有接続の変更は、同じProjectまたはAppの複数の利用者・自動処理へ影響することがあります。接続の共有範囲がAppの要件と一致しない場合は接続できません。権限不足を避けるために共有範囲をむやみに広げないでください。

## 定期実行・トリガーへの影響を確認する

接続を使うWorkflowトリガーや「タスク」の自動実行は、認証の失効や担当者の退出で停止・失敗する可能性があります。接続を修復しただけで、すべての自動実行が再開したと判断せず、対象ごとに確認します。

- Gmail／Outlookトリガーは「要再認証」や「メール受信エラー」を確認し、認証後に「接続状態を更新」します。画面の案内では、接続後に「公開」するとメール受信が開始されます。必要に応じてWorkflowの公開状態も確認します。
- タスクは作成者に結び付くため、作成者が組織を離れると実行されません。接続の所有者だけでなく、タスクの作成者も確認します。
- 退職・異動の処理では、作成者のタスクに加え、その人の認証情報を使うトリガーも停止する場合があります。後任者が引き継ぐときは、接続、トリガー、タスクを別々に確認します。
- スケジュール、通知先、実行対象、公開済みWorkflow、次回実行、履歴を確認し、変更・再作成・停止の操作は[定期実行を変更・停止・引き継ぐ](change-stop-handover-scheduled-runs.md)に従います。

> 自動実行の確認でメール送信、データ更新、外部への登録が起きる場合があります。実行先と重複実行の影響を確認し、結果が不明なまま同じ処理を繰り返さないでください。

## チェックリスト

- [ ] 対象の組織、Project／App、サービス、影響する機能を確認した
- [ ] 表示されたメッセージ、接続タイプ、認証アカウント、最終認証日時を確認した
- [ ] 個人接続と共有接続を取り違えず、対応する人を決めた
- [ ] 個人接続は本人が同じアカウントで再認証、または後任者が自分の接続を準備した
- [ ] 共有接続は、承認済みの業務アカウントとAppへの設定結果を確認した
- [ ] 旧接続を解除する前に、後任の接続と依存機能を確認した
- [ ] トリガー、タスク作成者、スケジュール、通知先、履歴を確認した
- [ ] 許可された範囲で実行結果を確認し、関係者へ変更内容を連絡した

## うまくいかない場合

再認証できない、接続を変更する権限がない、同じアカウントで認証しても「要再認証」のまま、または自動実行が再開しない場合は、対象を解除・再作成し続けないでください。権限、外部サービス側のアカウント状態、Appへの設定、トリガー・タスクの作成者を分けて確認します。

問い合わせには、組織名、ProjectまたはApp名、接続先サービス、接続タイプ（個人／共有）、接続名、対象機能、操作日時、表示メッセージ、実行履歴の結果、担当交代の有無を添えます。パスワード、APIキー、トークン、認証画面の内容は送らないでください。
