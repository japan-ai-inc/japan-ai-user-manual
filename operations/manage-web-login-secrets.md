# Webログイン用シークレットを管理する

Webログイン用シークレットは、Webサイトへのログインに使うURL、ログインID、パスワードを管理する設定です。この記事では、**管理者がWebログイン用シークレットを登録、更新、削除する手順**と、安全に管理するための確認事項を説明します。

APIキーやトークンをProjectで保存するものではありません。その場合は、[Project Secretを登録・更新・削除する](manage-project-secrets.md)を参照してください。認証情報の種類を選ぶ考え方は、[個人接続・共有接続・Secretを選ぶ](choose-personal-shared-connections-and-secrets.md)で説明しています。

## 始める前に

Webログイン用シークレットは、Webサイトへのログインに使う情報を管理する設定です。接続設定や、人が直接共有するパスワードの保管場所ではありません。

- 正しい組織、Project、対象のAgentまたはAppを確認します。画面の表示は、組織の設定、対象Project、Appの構成、利用者の役割と権限によって異なります。
- 対象サイト、利用目的、ログインする業務用アカウント、管理責任者、パスワード変更時の連絡先を決めます。個人専用アカウントを共通業務に使わないでください。
- Webサイトで自動操作や複数人による利用が許可されているか、利用規約と組織の運用を確認します。MFA、IP制限、端末制限、画像認証などがある場合、登録してもログインできるとは限りません。
- Secretを作成・更新・削除する権限と、対象Projectを操作できる権限を確認します。画面を開けても、操作ごとの権限がなければ登録や変更はできない場合があります。

> パスワード、ワンタイムコード、復旧コード、Cookie、アクセストークンを、Secret名、説明、Agentへの指示、チャット、チケット、画面キャプチャに書かないでください。問い合わせ時も実値やマスク表示の文字列は送信しません。

## Project Secretとの違い

どちらも「シークレット管理」で扱いますが、目的と使われ方が異なります。名前が似ていても、片方をもう片方の代わりに使わないでください。

| 比較 | Webログイン用シークレット | Project Secret |
|---|---|---|
| 主な用途 | Webサイトにログインするための情報 | Projectで使うAPIキー、トークンなどの秘密値 |
| 登録する情報 | 対象WebサイトのURL、ログインID、パスワード | 名前と値 |
| 利用する対象 | Webログインを行うAgentのタスクなど、設定された用途 | Secretを参照するよう設定されたProject内の機能やApp |
| 設定場所 | 「シークレット管理」の「Webログイン用シークレット」 | 「シークレット管理」の「プロジェクトシークレット」 |
| Appへの設定 | Webサイトへのログイン用途として確認します。利用可否は対象機能の案内も確認します。 | 必要な場合はAppの「アプリに必要なシークレット」で選択・紐づけます。 |

> APIキーを使うからという理由だけで、Webログイン用シークレットに登録しないでください。反対に、WebサイトのID・パスワードをProject Secretへ登録して、ブラウザのログインに使えると判断することも避けます。用途が不明な場合は、登録前に対象App・機能の案内と管理担当者へ確認してください。

## 1. 「Webログイン用シークレット」を開く

1. JAPAN AIで対象の組織とProjectを確認します。
2. 設定画面の**「シークレット管理」**を開きます。Appの設定中は、対象Appの設定から開く場合があります。
3. **「Webログイン用シークレット」**を選びます。Project Secretの画面が開いた場合は、タブまたは種類を取り違えていないか確認します。
4. 一覧で**「シークレット名」**、**「作成者」**、**「作成日時」**を確認します。必要に応じて**「シークレット名で検索」**で対象を絞り込みます。

一覧で確認できるのは登録情報であり、パスワードを読み出すための画面ではありません。Webログイン用シークレットがない場合は、「Webログイン用シークレットはありません」と表示されます。

## 2. 新しいWebログイン用シークレットを登録する

1. **「シークレットを作成」**を選びます。
2. **「シークレット名」**に、対象サイトと業務用途を識別できる名前を入力します。名前にログインIDやパスワードを含めません。
3. 表示される共有範囲を確認します。Project内で登録する場合は、対象Projectと、この情報を利用するAgent・Appを取り違えないようにします。個人用または組織全体を選べる画面では、誰の業務に必要な情報か、外部サイトのアカウントを共有利用してよいかを確認して選びます。
4. **「WEB URL」**にログイン対象のURLを入力します。複数のURLを使う場合は、**「追加する」**で必要なURLだけを登録します。ログイン後の任意ページではなく、対象サイトと判別できる適切なURLを指定します。
5. **「ログインID」**と**「パスワード」**に、承認された業務用アカウントの情報を入力します。説明欄を使える場合も、パスワード等の実値は書かず、用途・管理担当・変更時の確認先だけを記載します。
6. 対象組織・Project、サイト、共有範囲、入力したURL、利用目的を再確認し、**「作成する」**を選びます。
7. 一覧にシークレット名が表示されたことを確認します。可能であれば、許可されたテスト用データと操作範囲で、対象Agentの代表タスクを実行します。

> AgentがWebサイトへログインできることは、そのサイト上の操作が承認されていることを意味しません。送信、更新、ダウンロード、削除などを含むタスクは、少量の許可済みデータで対象と結果を確認してから利用を広げてください。

## 3. URL、ログインID、パスワードを更新する

パスワード変更、対象サイトのURL変更、アカウント引き継ぎ、漏えいの疑いがある場合は、速やかに更新します。更新前に、新しい情報が外部サイトで有効であることを確認してください。

1. 対象の行の**「操作」**から**「編集」**を選びます。
2. **「WEB URL」**、**「ログインID」**、**「パスワード」**、必要に応じて**「シークレット名」**と説明を確認・変更します。
3. 編集画面のパスワードは、実値の代わりにマスク表示される場合があります。パスワードを変更しない場合は、その表示を実値としてコピー・入力し直さないでください。変更する場合だけ、新しい実値を入力します。
4. 対象サイト、利用中のAgent・App、切替時刻、失敗時の連絡先を確認して、**「更新する」**を選びます。
5. 更新後、許可された範囲で代表タスクを実行し、ログイン先と処理結果を確認します。反映時点や実行中のタスクへの影響は状況により確認が必要なため、直ちにすべての実行へ反映されるとは判断しないでください。

外部サイトでパスワードを先に失効させると、依存するタスクが失敗する可能性があります。緊急の失効が不要な通常の変更では、新しい情報の登録とテストを終えてから旧情報を無効化します。

## 4. 不要になったシークレットを削除する

削除は復元できません。アカウントを廃止する、別のシークレットへ切り替える、または利用を停止する場合も、先に依存するAgent・App・タスクを確認します。

1. 一覧で対象の**「シークレット名」**、作成者、作成日時を確認します。
2. **「操作」**から**「削除」**を選びます。
3. 確認画面で対象名を読み、「このシークレットは復元できません」という案内を確認します。
4. 代替の設定、依存するタスクの停止または切替、関係者への連絡が完了していることを確認します。
5. **「削除」**を確定し、一覧から対象が消えたことを確認します。

> 不要に見えるSecretでも、定期実行や利用頻度の低いAgentが参照している可能性があります。削除後にログイン失敗が発生した場合、削除した実値を復元できる前提にせず、外部サイトで新しい情報を発行して必要な設定を行ってください。

## 管理チェックリスト

- [ ] Webサイトへの自動操作とアカウント共有が許可されていることを確認した
- [ ] 個人アカウントではなく、承認済みの業務用アカウントを選んだ
- [ ] Webログイン用とProject Secretを用途で区別した
- [ ] 対象組織・Project・Agent・App、URL、共有範囲を確認した
- [ ] Secret名・説明・問い合わせに実値を書いていない
- [ ] MFA、IP制限、端末制限、パスワード変更の影響を確認した
- [ ] 更新前後に、許可された代表タスクでログイン先と結果を確認した
- [ ] 管理責任者、用途、依存する機能、変更日時だけを記録した

## うまくいかない場合

| 状況 | 確認・対応 |
|---|---|
| 「シークレット管理」または「Webログイン用シークレット」が見つからない | 正しい組織・Project・Appを開いているか、機能の表示条件と権限を管理担当者へ確認します。Project Secretで代用しません。 |
| 作成、編集、削除が選べない | 操作別の権限と対象Projectを操作できる役割を確認します。必要以上の権限を自分で付与せず、権限管理者へ依頼します。 |
| 保存できない | シークレット名、WEB URL、ログインID、パスワードの必須項目を確認します。Secret名に使用できない文字や、重複する名前がないかも確認します。実値は問い合わせに貼り付けません。 |
| 登録後もログインに失敗する | URL、ログインID、パスワード、外部サイト側のアカウント状態、MFA・IP制限・端末制限、対象Agentの利用設定を確認します。繰り返し試行してアカウントをロックしないよう注意します。 |
| 更新・削除後にタスクが失敗する | 操作日時、対象のAgent・App・タスク、表示メッセージ、変更内容、外部サイトの状態を記録します。推測でSecretを作り直さず、切替状況と依存する設定を担当者と確認します。 |

問い合わせには、組織名、Project・App名、シークレット名、対象サイト、操作種別、日時、表示メッセージ、影響したタスク、確認済みの内容を添えます。ログインID、パスワード、MFAコード、復旧コード、Cookie、トークン、マスク文字列は添付しないでください。
