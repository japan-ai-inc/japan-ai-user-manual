# 組織・Project・Appの権限を理解する

JAPAN AI Studioでは、組織・Projectを管理する権限と、Appを利用・設定する条件は別です。変更前に、任せる操作範囲を整理します。

この記事は、管理者が組織・Project・Appの権限関係を判断するための説明です。招待・ロール変更・削除は[Project・Appのメンバーを管理する](manage-project-and-app-members.md)、初期設定は[Appの初期設定を完了する](../use/complete-app-setup.md)を参照してください。

## 要点：誰が何をできるか

| 操作 | できる人 |
|---|---|
| Projectのメンバーを招待・ロール変更・削除する | Projectの管理者 |
| Projectのリソース（Agent・Workflow・Pageなど）を作成・更新・削除する | Projectの管理者・編集者 |
| AgentやWorkflowを実行する、多くのリソースを作成する | Projectのメンバー以上 |
| Studio Assistantを使う | 組織で機能が有効になっており、Projectの編集者以上の人 |
| Appをインストール・アンインストールする、「組織のアプリ」タブを開く | 組織の管理者、または`jai.studioapp.install`の権限を持つ人 |
| Appの共有接続・Secret・メンバーを設定する | そのAppの管理者（Appをインストールした人は自動でApp管理者になります） |
| Appに自分で参加する | 組織の管理者のみ（常に管理者として参加します） |

- Studio Projectのロールは「管理者」「編集者」「メンバー」の3つです。**読み取り専用のロール（閲覧者）はありません。** 読み取り専用にしたい場合は、IAMのカスタムロールを作成して割り当てます。
- 編集者はProjectのメンバーを管理できません。
- 有料Appでは、App管理者を含むメンバー1人ごとに1シートを使います。

## この記事の範囲

ここでは、次の3層を区別します。

1. **組織ロール**：組織のメンバーとしての基本ロールです。組織の設定、メンバー、組織全体のリソースに関わる操作の土台になります。
2. **Projectロール**：個別のProjectに参加した人へ付くロールです。Project内のリソースを利用・作成・管理する範囲を決めます。
3. **App固有の条件**：インストール済みAppを開く・利用する・設定するための条件です。Projectへのアクセスに加え、Appのメンバー登録、シート数、接続やSecretが影響します。

個別リソースの設定手順は扱いません。詳細なエラー切り分けは、[権限・認証エラー](../troubleshooting/permission-and-auth-errors.md)を参照してください。

> **組織に所属していること、Projectに参加していること、Appを業務で使えることは同じ状態ではありません。** いずれか一つを満たしていても、別の条件が不足すれば対象の操作はできません。

## まず押さえる権限の全体像

| 層 | 主な管理対象 | 代表的なロール・条件 | 主に管理する人 | この層だけでは決まらないこと |
|---|---|---|---|---|
| 組織 | 組織設定、組織メンバー、組織全体のリソース、Appのインストール | 「管理者」「編集者」「メンバー」、必要に応じてIAMロール | 組織の管理者 | 個別Projectへの参加、Appごとの利用可否 |
| Project | Projectのメンバー、Agent・Workflow・Pageなど | 「管理者」「編集者」「メンバー」、必要に応じてカスタムロール | Projectの管理者 | シート数、外部サービス側の権限、App固有の設定 |
| App | インストール済みAppのメンバー、設定、必要な接続・Secret | Appのメンバー登録、シート数、App固有の要件 | Appの管理者 | 組織全体の管理権限、利用者本人の外部サービス権限 |

IAMは、基本ロールで足りない操作を補う仕組みです。「IAMロール設定」が表示される組織・Projectでは、システムロールと「カスタムロール」が表示されます。

> IAMロールを付けただけで、Projectへ未参加の人を利用者として扱わないでください。対象者のProject参加状況も確認します。

## 組織ロールで決まること

組織ロールは、組織に対する基本的な操作範囲です。基本ロールには「管理者」「編集者」「メンバー」があります。

| 組織ロール | 主にできること | 管理上の考え方 |
|---|---|---|
| 管理者 | 組織と組織全体のリソースを広く管理します。Appのインストール・アンインストールもできます。 | 組織設定やメンバー管理を担当する人に限定します。 |
| 編集者 | IAM管理以外の組織全体のリソースを管理できる範囲があります。 | 管理者と同じ操作が常にできるわけではありません。 |
| メンバー | 許可されたリソースを閲覧・実行する基本となります。 | すべてのProjectやAppへ自動参加するわけではありません。 |

Appのインストールは、組織の管理者のほか、`jai.studioapp.install`の権限をIAMで付与された人も行えます。

## Projectロールで決まること

Projectロールは、対象Project内での役割です。Studio Projectのロールは「管理者」「編集者」「メンバー」の3つで、閲覧者（読み取り専用）のロールはありません。

| Projectロール | Project内の主な範囲 | メンバー管理・Project管理 | 向いている担当 |
|---|---|---|---|
| 管理者 | Projectリソースへのフルアクセスです。 | 設定やメンバー管理を行います。 | Project責任者 |
| 編集者 | Projectリソースを作成・更新・削除します。Studio Assistantを使えます。 | メンバー管理はできません。 | 構築担当 |
| メンバー | AgentやWorkflowを実行できます。多くのリソースを作成することもできます。 | メンバー管理・Project管理はできません。 | 業務利用者 |

「メンバー」は閲覧専用ではありません。内容の確認だけを任せたい人がいる場合は、必要な操作だけを許可したカスタムロールを作成して割り当ててください。

Projectの「管理者」は組織の「管理者」とは別です。組織設定や組織全体の導入まで任せることにはなりません。

最後の管理者を削除・降格・退出させる前に、後任を設定してください。

## App固有の条件を重ねて確認する

Appのメンバーになる方法は次のとおりです。

- **App管理者が追加する**：App管理者が「メンバー」画面から追加します。
- **組織の全メンバーに公開されたAppを開く**：「組織の全メンバーに公開」が有効なApp（無料App）を初めて開いたとき、メンバーとして参加します。
- **組織管理者が自分で参加する**：自分で参加できるのは組織管理者のみで、常に管理者として参加します。有料Appではシートを使います。

Appで実際に業務を行えるかは、次の順で確認します。

1. **組織**：利用者が正しい組織に所属しているかを確認します。
2. **Appのメンバー**：対象Appのメンバーとして追加されているか、目的に合うロールかを確認します。
3. **シート**：有料Appでは、メンバー数がシートの上限に達していないかを確認します。
4. **共有範囲**：App内のAgent、Page、Workflow、Datasetなどが利用者に公開・共有されているかを確認します。
5. **設定と認証**：共有接続、Project Secret、本人の接続、外部サービス側のアクセスが必要かを確認します。共有接続・Secretを設定できるのはApp管理者だけです。

> **Appのメンバーになっても、Appのすべての操作が自動的に可能になるわけではありません。** シート、設定、公開範囲、接続先サービス側の権限も確認します。

## 共有範囲とロールを混同しない

ロールは「その人が変更・実行できる操作の範囲」、共有範囲は「どの人が対象リソースを見つけて利用できるか」の条件です。両方を満たして初めて、期待した操作ができます。

| 状況 | 主な原因 | 確認すること |
|---|---|---|
| Projectに参加済みだが、対象AgentやWorkflowが見つからない | リソースの共有・公開範囲が対象者を含んでいない | 対象リソースの公開状態、共有先、利用権限 |
| リソースは表示されるが、編集できない | ProjectロールまたはIAMの変更権限が不足している | Projectロール、カスタムロール、対象リソースのポリシー |
| Appは開けるが、機能の実行に失敗する | 接続、Secret、外部サービス側の権限、シートなどの設定が未完了 | 表示された案内、Appの設定状態、利用者本人の認証 |
| 共有リンクを受け取ったが開けない | リンクを受け取っただけで、アクセス権が付与されていない | 正しい組織、Project・Appへの参加状態、共有範囲 |

組織全体やProject全体へ共有すると、閲覧できる人が広がります。共有範囲を広げて権限不足を回避せず、必要な利用者・操作・データを先に決めます。

## よくある誤解

- **組織管理者なら、すべてのAppをすぐに利用できる**わけではありません。Appへの参加（有料Appではシートを使います）と接続を確認します。
- **Project管理者なら、組織メンバーや契約も管理できる**わけではありません。
- **編集者ならメンバーを管理できる**わけではありません。メンバー管理はProject管理者の操作です。
- **「メンバー」は閲覧だけの安全なロールである**わけではありません。AgentやWorkflowを実行し、多くのリソースを作成できます。
- **共有リンクを送れば、権限設定は不要**ではありません。

## 期待した操作ができない場合

画面に「メンバー」「IAMロール設定」「設定」が表示されない、または期待した操作ができない場合は、次を確認します。

1. 正しい組織、Project、Appを開いているか確認します。
2. 対象者の組織・Project・Appへの参加状況を確認します。
3. 組織ロール、Projectロール、IAMのどこが不足しているかを分けます。
4. Appではメンバー登録、シート、設定、接続の案内を確認します。
5. 解消しなければ、画面と表示メッセージを添えて管理者へ相談します。Secretの値は共有しません。

## 管理前チェックリスト

- [ ] 組織管理とProject管理が必要な人を分けた
- [ ] 組織ロールとProjectロールを別々に確認した
- [ ] 読み取り専用にしたい人にはカスタムロールを用意した
- [ ] Appの利用条件をメンバー登録・シート・設定・共有範囲に分けた
- [ ] IAMは基本ロールで不足する操作だけに使った
- [ ] 最後のProject管理者を外さないことを確認した
