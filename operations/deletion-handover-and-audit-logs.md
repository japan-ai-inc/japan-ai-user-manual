# 削除・引き継ぎと監査記録を確認する

Project、リソース、メンバー、導入済みAppを終了・削除するときは、操作を確定する前に、依存する処理、アクセス権、必要なデータ、後任者への引き継ぎを確認します。削除、Projectからの退出、リソースのリンク解除、Appのアンインストールは、影響する範囲が異なる操作です。

この記事では、**管理者が削除または担当変更の前後に確認する共通の進め方**、Project内で確認できる「監査ログ」、サポートへ渡す情報を説明します。Appのアンインストール手順は[Appをアンインストールする](../use/uninstall-app.md)、外部サービス接続の担当変更は[接続の失効・担当者変更に対応する](handle-expired-connections-and-owner-changes.md)を参照してください。

## 始める前に：対象操作を取り違えない

最初に、何を終了するのかを決めます。名称が似ていても、次の操作は代用できません。

| 操作 | 主な影響 | 削除前に確認すること |
|---|---|---|
| Projectを削除する | Projectと配下のデータに影響する場合があります。画面上でも「元に戻せません」と案内されます。 | 依存リソース、メンバー、保存が必要なデータ、外部連携、後任者 |
| Projectから退出する | 操作した本人のアクセス権を外します。Projectやリソースは削除されません。 | 自分が最後の管理者ではないこと、後任の管理者 |
| Project内のリソースを削除する | 対象リソースまたはProjectからの参照に影響します。 | 他のProjectとのリンク、Agent・Workflow・Page・自動実行からの利用 |
| メンバーを削除する | 対象ProjectまたはAppへのアクセスを外します。 | 管理者の後任、作成者に結び付く定期実行、個人接続、引き継ぐ業務 |
| Appをアンインストールする | 導入方式に応じてApp、アクセス権、データに影響します。 | Appの確認画面に表示されるデータ・料金・完了状態 |

> 削除できる画面があることは、その操作が安全に完了できることを意味しません。同名のProjectやApp、開発元のProjectとインストール済みApp、リンク解除と元のリソース削除を必ず区別してください。権限不足や確認できない項目がある場合は、削除を確定せず担当者に確認します。

## 1. 削除前に依存関係を棚卸しする

削除対象の一覧だけでなく、その対象を使う人、処理、外部サービスを確認します。削除を実行する人と、業務の責任を引き継ぐ人を分けて記録すると、確認漏れを減らせます。

| 確認領域 | 確認する内容 | 引き継ぎ先に残す情報 |
|---|---|---|
| 利用者・権限 | 「メンバー」で利用者、ロール、最後の管理者を確認する | 後任管理者、必要最小限のロール、利用終了日 |
| 作成物 | Agent、Workflow、Page、Skill、Object、Dataset、Storage、会話や成果物の利用状況を確認する | 継続利用する対象、保存先、所有・編集の担当 |
| 自動実行 | タスク、トリガー、通知先、直近の実行履歴と次回の動作を確認する | 停止または再作成する担当、実行条件、通知先 |
| 接続・認証情報 | 共有接続、個人接続、Project Secret、外部サービス側の権限を確認する | 接続名、用途、認証アカウントの管理者、更新時の連絡先。実値は残さない |
| 外部の影響 | Webhook、外部API、送信先、更新先、外部サービスの契約・通知を確認する | 停止方法、外部側で必要な変更、問い合わせ先 |

リソースによっては、他のProjectからリンクされているため削除できず、先にリンク解除を求められることがあります。逆に、Project内で削除と表示されても、元のリソースではなくProjectからのアクセスだけを外す場合があります。表示された確認文を読み、元データ・参照・利用中の処理のどれに影響するかを確定してください。

> 接続やSecretを先に削除すると、終了対象以外のApp、Agent、Workflowまで失敗することがあります。後任の設定、停止、または代替手順が完了し、許可された範囲で確認できるまで、旧設定を削除しないでください。接続の切替は[接続の失効・担当者変更に対応する](handle-expired-connections-and-owner-changes.md)に従います。

## 2. データの保存・削除・復元可能性を確認する

削除前に、必要なデータを特定し、組織で承認された保存先へ移せるかを確認します。保存対象には、入力データだけでなく、利用者が参照する成果物、ファイル、設定内容、外部サービス上に送信・更新済みの結果が含まれる場合があります。

1. 残すべきデータ、保存の目的、閲覧できる人、保管期限を担当者と決めます。
2. 対象機能が提供する保存・出力方法と、保存先へのアクセスを確認します。必要な内容を保存できない場合は、削除を確定しません。
3. 保存したデータを後任者が開けるか、内容が不足していないかを確認します。機密情報を不要な場所へ複製しないでください。
4. 削除画面の対象名と確認文を読み、影響範囲を再確認してから確定します。
5. 確定後は、一覧、利用画面、必要に応じて外部サービス側を確認し、完了・受付済み・失敗・結果不明を区別して記録します。

Projectの削除画面は元に戻せないことを案内し、削除権限の説明には配下データが削除される場合があると示されています。一方で、削除後のデータ保持期間、物理的な消去時点、すべての種類のデータを利用者が復元できるかは、この画面表示だけでは確定できません。Appのアンインストールも、導入方式によりデータの扱いが異なります。

> 画面から見えなくなったことを、バックアップを含むすべてのデータが消えた証明、または復元できる証明として扱わないでください。保持・完全削除・復元可能性の確認が必要な場合は、対象の組織、ProjectまたはApp、データ種別、削除日時、求める確認内容を明示して問い合わせます。

## 3. メンバーと担当を安全に引き継ぐ

メンバー削除や担当交代では、後任を準備してから前任者のアクセスを外します。最後のProject管理者は削除または管理者以外への変更ができないため、先に後任へ必要な権限を付与し、一覧で反映を確認します。

1. 「メンバー」で前任者・後任者のメールアドレス、ロール、対象ProjectまたはAppを確認します。
2. 後任者を追加し、必要最小限のロールを付与します。後任者が対象を開けることと、必要な外部サービス側の権限を持つことを別々に確認します。
3. 自動実行の作成者、通知先、共有接続の認証アカウント、個人接続、Secretの管理責任者を確認します。前任者の個人接続や認証情報を後任がそのまま使える前提にはしません。
4. 後任者が代表的な利用操作と、必要な自動実行の状態を確認します。外部への送信・更新がある場合は、対象と重複実行に注意します。
5. 引き継ぎ完了、利用終了日、残作業、問い合わせ先を関係者へ共有してから、前任者を削除または役割変更します。

メンバー削除は、Projectやリソースを削除する操作ではありません。ただし、作成者が組織のメンバーでなくなると、定期実行が動かなくなることがあります。権限の変更・削除の詳しい操作は[Project・Appのメンバーを管理する](manage-project-and-app-members.md)を参照してください。

## 4. 「監査ログ」とアクティビティ・実行履歴を使い分ける

Projectの設定で「監査ログ」が表示される場合は、Projectに関する操作履歴を確認できます。表示の有無は組織の設定・権限・提供条件によって異なるため、項目がない場合に別の画面で代用したり、記録が存在しないと判断したりしないでください。

1. 対象Projectの設定から**「監査ログ」**を開きます。
2. **「開始日」**と**「終了日」**を、削除・役割変更・エラーの前後を含む期間に設定します。
3. 必要に応じて**「アクション」**、**「実行者タイプ」**、**「リソース種別」**、**「結果」**で絞り込みます。削除、メンバー追加・削除、ロール変更などを確認できます。
4. 一覧の**「日時」**、実行者、操作、対象リソース、結果、エラーを確認します。必要な行は**「詳細を表示」**で、変更内容、同じ実行に関連する操作、Agentが実行した操作では実行ユーザーの情報を確認します。変更差分がない操作も、詳細を開いて操作の文脈を確認できます。
5. Projectへのリソース追加・削除を確認する場合は、詳細の**「操作の情報」**で、追加または解除の別、指定したリソース、必要に応じて依存リソースと追加結果を確認します。古い記録では、変更前後や依存関係の情報を確認できない場合があります。
6. 確認日時、検索条件、見つかった事実と未確認事項を記録します。監査ログ自体の内容を加工・削除したり、機密情報を広く共有したりしないでください。

アクティビティや実行履歴は、Project内の実行状況を確認する入口です。実行の開始・結果・履歴を調べる目的ではこちらを確認します。削除や権限変更、リソースの追加・解除の操作記録を調べる目的では**「監査ログ」**を優先します。どちらも表示範囲・保持期間・すべての操作の記録を保証するものではないため、必要な記録が見つからない場合は、検索条件と対象期間を添えて問い合わせます。

## 確認できない場合・問い合わせに添える情報

削除が失敗した、完了状態が分からない、監査ログを開けない、必要な記録が見つからない場合は、別の削除操作を繰り返さないでください。対象・権限・依存関係・現在の状態を分けて確認します。

問い合わせには、次を添えます。

- 組織名、対象のProject・App・リソース名、可能なら画面で確認した識別情報
- 操作種別（削除、アンインストール、退出、リンク解除、メンバー削除、ロール変更など）、実行者、操作日時とタイムゾーン
- 影響を受けた利用者、Agent・Workflow・Page・自動実行・外部サービス、および業務影響
- 画面に表示された結果、エラー、削除前後の状態、実施済みの確認・再試行の有無
- 監査ログまたは実行履歴を確認した場合は、対象期間、絞り込み条件、該当する日時・操作・結果
- 必要な確認内容（削除完了、保持・完全削除、復元可能性、アクセス解除、実行停止など）

パスワード、APIキー、トークン、Secretの値、MFAコード、Cookie、業務データの実値、不要な個人情報は送らないでください。詳しい情報の集め方は[問い合わせに必要な情報を集める](../troubleshooting/collect-info-for-support.md)を参照してください。

## 削除・引き継ぎチェックリスト

- [ ] 対象操作を、退出・リンク解除・メンバー削除・Appのアンインストールと区別した
- [ ] 利用者、管理者、依存リソース、自動実行、通知、外部連携を棚卸しした
- [ ] 必要なデータと成果物を、承認された保存先で後任者が確認できる状態にした
- [ ] 保持・完全削除・復元可能性が未確認の事項を、削除完了と取り違えていない
- [ ] 後任の権限、外部サービス側の権限、接続・通知・自動実行を確認した
- [ ] 前任者の個人接続やSecretの実値を引き継ぎ資料に含めていない
- [ ] 「監査ログ」またはアクティビティ・実行履歴で必要な事実を確認し、検索条件を記録した
- [ ] 削除後の状態、残作業、利用者への案内、問い合わせ先を共有した
