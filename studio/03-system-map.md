# 3. 全体構成と機能マップ

### 3.1 階層構造

```
組織 (Organization)
└── プロジェクト (Project)             ← Studio の作業単位
    ├── ワークフロー                   ← ノードで業務を自動化
    ├── エージェント                   ← プロンプト＋スキル
    ├── スキル（ツール）               ← ワークフロー・エージェントが呼び出す機能
    ├── データ連携（ナレッジ）         ← RAG 用データセット
    ├── カスタムオブジェクト           ← 業務データのテーブルと SQL
    ├── ストレージ                     ← プロジェクト内ファイル
    ├── ページ                         ← ノーコード Web 画面
    ├── メンバー / ロール（IAM）       ← アクセス制御
    ├── シークレット                   ← 暗号化された機密情報
    ├── 外部接続 / MCP                 ← 外部 SaaS の認証情報
    └── 設定                           ← スケジューラ・メモリ・API キー・監査ログ
```

### 3.2 モジュール間の関係

```
              ┌──────────────────┐
              │   ワークフロー   │
              └─────────┬────────┘
                        │ ノード経由で呼び出し／参照
   ┌────────┬───────────┼───────────┬────────┬────────┐
   ▼        ▼           ▼           ▼        ▼        ▼
エージェント スキル  データ連携  カスタム   ストレージ ページ
                              オブジェクト         （内蔵）
   ▲                              ▲
   └───── シークレット／外部接続 ──┘
                        ▲
                        │
                  メンバー／ロール（IAM）
                  （横断的に権限制御）
```

- **ワークフロー** は、ノードを通じて他のモジュールを利用します（データ連携ノードで RAG、ツールノードでスキル実行、エージェントノードでエージェント呼び出し、サブワークフローノードで別ワークフロー呼び出し、カスタムオブジェクト SQL ノードで業務データ操作 等）。
- **エージェント** は、スキル・データセット・メモリと組み合わせて動作します。
- **メンバー／ロール（IAM）** は、すべてのモジュールへのアクセス権を横断的に制御します。
- **シークレット／外部接続** は、エージェントやスキルが外部 API を呼ぶ際の認証情報を提供します。
