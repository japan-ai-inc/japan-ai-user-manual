# 15. シークレットマネージャー

### 15.1 概要

外部 API キーや認証情報を **暗号化して保管する** 機能です。設定画面 →「アクセス制御」→「シークレット管理」から利用します。

### 15.2 シークレットの形式

シークレットは柔軟な JSON 構造で保存できます。代表的なパターン:

- API キー単独：`{ "apiKey": "..." }`
- ユーザー名 + パスワード：`{ "username": "...", "password": "..." }`
- OAuth トークン：`{ "accessToken": "...", "refreshToken": "...", "expiresAt": "..." }`
- Bearer / JWT：`{ "token": "..." }`
- 任意のキー・値の組み合わせ

ファイルそのものは現バージョンではサポートしていません。Base64 文字列等として格納する運用が可能です。

### 15.3 主な操作

- シークレットの追加（名前、説明、値）
- 編集・削除
- 値はマスク表示。クリックで開示（権限保有者のみ）
- 利用箇所の確認（参照しているワークフロー・エージェント等）

> **画面プレースホルダー**：`screenshots/15-secrets.png`

### 15.4 スコープと参照

- **プロジェクト単位** のスコープ（プロジェクト内でユニーク）
- 名前は英数字 + ハイフン + アンダースコアを推奨（例：`OpenAI-API-Key`）
- ワークフロー・スキルからは設定 UI でシークレットを選択する形で参照（プロジェクトに紐付くため、URL や ID をハードコードする必要はありません）

### 15.5 権限

| 権限 | 内容 |
|---|---|
| `jai.secret.read` | シークレットの参照（値の閲覧含む） |
| `jai.secret.create` | 新規追加 |
| `jai.secret.update` | 値の更新 |
| `jai.secret.delete` | 削除 |

シークレットへの全操作は **作成者 / 最終更新者・タイムスタンプ** が記録されます。

### 15.6 暗号化

暗号化された値はデータベースに安全に保管され、外部システムからキー素材を取得できない形で運用されます。詳細な実装は導入元にご確認ください。
