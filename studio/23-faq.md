# 23. よくあるご質問（FAQ）

**Q1. プロジェクトはいくつまで作成できますか？**
A. 組織側のプラン・設定により上限が定められている場合があります。上限に達している場合は、「プロジェクト作成」操作時に上限超過のメッセージが表示されます。具体的な上限値については導入元・組織管理者へお問い合わせください。

**Q2. 公開済みのワークフローを以前のバージョンに戻せますか？**
A. 現バージョンでは、過去バージョンへ戻す操作は提供していません。事前に下書きで動作確認を行ったうえで公開してください。なお、ページ機能はバージョン履歴を保持し、アクティブバージョンの切り替えに対応しています。

**Q3. 削除したリソースは復元できますか？**
A. ストレージ上のファイル、カスタムオブジェクト・フィールド・レコードはソフトデリートとして保持され、復元 API による復元が可能です（具体的な保持期間や復元手続きは導入元にご確認ください）。プロジェクト・ワークフロー・エージェントの復元可否は導入元・サポート窓口にご確認ください。

**Q4. 外部の API キーはどのように管理すべきですか？**
A. 直接ワークフローやスキルに記載せず、**シークレットマネージャー** に登録してください。シークレット参照経由で安全に利用できます（[15 章](15-secrets.md)）。

**Q5. 機能が見当たりません（例：カスタムオブジェクトが表示されない）**
A. 一部機能は組織のプラン・機能フラグに依存します（[2.4](02-prerequisites.md)）。組織管理者または導入元にお問い合わせください。

**Q6. ワークフローが想定通り動作しません。どこを見ればいいですか？**
A. ワークフロー詳細の「ログ」タブで、各ノードの入出力・実行時間・トークン使用量・エラーを確認できます。Webhook トリガーの場合は、署名・パラメーター抽出設定もご確認ください。

**Q7. 他のプロジェクトのワークフロー／エージェントを再利用できますか？**
A. 組織共通の **スキル**・**エージェント**・**データセット** をプロジェクトに取り込む形で再利用可能です（組織横断リソースインポート機能の有効化が前提）。詳細は組織管理者にご相談ください。

**Q8. カスタムオブジェクトの SQL でどの程度のクエリが書けますか？**
A. `SELECT`（集計、`GROUP BY`、シングル `JOIN`、サブクエリ、ベクトル検索）、`INSERT`/`UPDATE`/`DELETE`/`UPSERT`、および `CREATE TABLE`/`ALTER TABLE`/`DROP TABLE` の DDL に対応しています。クエリタイムアウトは 30 秒、`UPDATE`/`DELETE` は `WHERE` または `LIMIT` 必須など、[11.7](11-custom-objects.md) の制限が適用されます。

**Q9. レコードへのアクセスを「営業メンバーは自分の担当顧客のみ」のように制限できますか？**
A. 可能です。カスタムオブジェクトのレコード単位 ACL（[11.8](11-custom-objects.md)）で、ロール・ユーザー単位の条件付きルールを設定できます。

**Q10. Webhook トリガーで GitHub や Slack の公式 Webhook を受けられますか？**
A. 可能です。Webhook トリガー設定の「署名検証プロバイダー」で GitHub 形式・Slack 形式・カスタム（HMAC-SHA256）が選択できます（[20.2](20-trigger-reference.md)）。

**Q11. メールを起点にワークフローを動かしたいです。**
A. Gmail / Outlook / Email by JAI のメールトリガーが利用可能です（[20.7](20-trigger-reference.md)）。事前に [外部接続](16-connectors-mcp.md) で対象アカウントを連携してください。

**Q12. 外部ツール（自社の SaaS 等）と連携するにはどうすればよいですか？**
A. 主な選択肢は次のとおりです。

- 汎用 API 呼び出しスキル（HTTP）を利用する
- カスタムスキルを開発する（[9.5](09-skills.md)）
- MCP サーバーを登録する（[16.3](16-connectors-mcp.md)）

選択基準（認証方式、双方向性、運用負荷など）については導入元にご相談ください。
