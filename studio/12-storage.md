# 12. ストレージ

### 12.1 概要

プロジェクト内のファイル・フォルダ管理機能です。サイドバーには「ストレージ（STORAGE）」として表示されます。

- 1 プロジェクト = 1 ストレージルート、その下に任意のフォルダ階層
- パスは `/` 区切り、最大 **10 階層**、パス長最大 1,000 文字
- 内部のストレージバックエンドは Google Cloud Storage 等のクラウドストレージで、ユーザーは意識せず利用できます

### 12.2 主な操作

| 操作 | 内容 |
|---|---|
| アップロード | 単一ファイル／プリサインド URL によるマルチパート分割アップロード |
| ダウンロード | 直接ダウンロードまたは署名付き URL（既定 60 分有効） |
| フォルダダウンロード（ZIP） | 複数ファイルをまとめて ZIP 化（最大 100 MB、トークン 5 分有効） |
| プレビュー | 画像（JPEG/PNG/WebP/GIF/SVG）、PDF、テキスト（plain/JSON/Markdown/CSV）の一部 |
| フォルダ作成 / 削除 | 階層作成、再帰削除 |
| 検索・ソート | 名前・サイズ・更新日時で並び替え |

> **画面プレースホルダー**：`screenshots/12-storage.png`

### 12.3 アップロードの安全管理

セキュリティのため、以下が制限されます。

- 拒否される拡張子（例）：`.exe`, `.bat`, `.sh`, `.ps1`, `.jar`, `.app`, `.deb`, `.rpm`, `.php`, `.jsp` ほか 60 種類以上
- 二重拡張子（例：`document.pdf.exe`）も拒否
- 危険な MIME タイプ（`application/x-jar`, `text/x-php` 等）の拒否
- ファイル名の禁止文字：`/ \ \0`、制御文字、コロン、先頭末尾の空白／ドット

### 12.4 制限値（標準）

| 項目 | 標準値 |
|---|---|
| 1 ファイルの最大サイズ | 約 2 GB |
| プレビュー対象サイズ | 10 MB（テキストは先頭 100 行・1 万文字） |
| プロジェクトあたりのストレージクォータ | 約 10 GB |
| フォルダの最大深さ | 10 階層 |
| パス長 | 1,000 文字 |
| ファイル名最大長 | 255 文字 |
| 署名付きダウンロード URL の有効期限 | 既定 60 分 |
| アップロード署名 URL の有効期限 | 既定 15 分 |
| フォルダ ZIP の最大サイズ | 100 MB |
| アップロード状態 | `pending` → `uploading` → `completed` / `failed` |

> 上限値は契約プランや組織設定により異なります。詳細は導入元にご確認ください。

### 12.5 アクセス制御（ACL）

ストレージは **パスベース** で IAM 評価されます。

| 権限 | 内容 |
|---|---|
| `studio.storage.read` | ファイル一覧・ダウンロード・プレビュー |
| `studio.storage.create` | アップロード |
| `studio.storage.update` | 上書きアップロード |
| `studio.storage.delete` | 削除 |

- フォルダ `/Confidential/` に制限を付けると、その配下すべての子要素も同じ評価対象になります
- 個別ファイル `/Confidential/secret.pdf` にさらに制限を上書きすることも可能です
- 新規作成リソースは親フォルダの権限を継承します

### 12.6 ストレージトリガー

ファイルの作成・更新・削除・移動を起点に、ワークフローを起動できます。

- 監視対象フォルダの指定が必要（フォルダ単位のオプトイン）
- トリガー連鎖の最大深さは 3（無限ループ防止）
- イベントペイロードには `fileAction`, `fileName`, `filePath`, `mimeType`, `fileSizeBytes`, `triggeredBy` 等が含まれます

### 12.7 削除と復元

削除されたファイルは **ソフトデリート** として保持されます。具体的な保持期間や復元手続きは導入元にご確認ください。同名ファイルの再アップロードによる復元動作にも対応します。
