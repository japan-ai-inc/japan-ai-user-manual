# 7. ワークフロー

### 7.1 ワークフローとは

ワークフローは、**入力 → 処理 → 出力** の流れをノードで定義する視覚的な自動化フローです。チャットの応答ロジック、書類処理、Webhook 連携、定期バッチ、メール受信時の処理など、多様な業務を実装できます。

### 7.2 ワークフロー一覧画面

URL: `/{organization_id}/studio/{project_id}/workflows`

| 列 | 内容 |
|---|---|
| 操作 | 削除・コピー・手動実行ボタン |
| ワークフロー名 | 任意の名前 |
| 説明 | 任意の説明 |
| 作成者 | 作成したユーザー |
| 公開 | 公開済み・下書きの状態 |
| 作成日 / 更新日 | タイムスタンプ |
| 有効 | 有効・無効スイッチ（無効化するとトリガーも発火しません） |

> **画面プレースホルダー**：`screenshots/07-workflow-list.png`

### 7.3 ワークフローエディタ

```
┌──────────────────────────────────────────────────────┐
│ 上部ツールバー：[一時保存] [公開] [手動実行] ほか     │
├────────────┬─────────────────────────────┬───────────┤
│ 左パネル   │                              │ 右パネル  │
│ ノードメニュー│       キャンバス（中央）     │  ノード設定 │
│ - トリガー  │   ノードをドラッグ＆ドロップ │ プロパティ │
│ - ブロック  │     線でつないでフロー作成   │           │
│ - プラグイン │                              │           │
├────────────┴─────────────────────────────┴───────────┤
│ 下部パネル：実行ログ／実行履歴（実行時に表示）         │
└──────────────────────────────────────────────────────┘
```

> **画面プレースホルダー**：`screenshots/07-workflow-editor.png`

#### ノードメニュー（左パネル）

タブで切り替えます。

- **トリガー**：ワークフローの起動方法を定義するノード（[20 章](20-trigger-reference.md) 参照）
- **ブロック**：処理を行う基本ノード（[19 章](19-node-reference.md) 参照）
- **プラグイン**：拡張ノード

#### ノード設定パネル（右パネル）

選択中のノードのパラメーターを編集します。各ノードの設定項目は [19 章](19-node-reference.md) を参照してください。

#### 上部ツールバー

- **一時保存**：下書きとして保存
- **公開**：現在のフローを本番として利用可能にする
- **手動実行**：開発中の動作確認

### 7.4 変数の参照

ノード間で値をやり取りするには **変数参照記法** を使用します。基本形は次のとおりです。

```
{{#ノードID.出力名.プロパティ#}}
```

- 例：開始ノードに定義した `question` を LLM プロンプトで使う → `{{#start.question#}}`
- ネスト：`{{#crm_lookup.customer.name#}}`（最大 10 段）
- システム変数：`{{#sys.files#}}`（添付ファイル）
- 環境変数：`{{#env.SOME_VAR#}}`
- 会話変数：`{{#conversation.xxx#}}`

変数が解決できない場合は `null` 相当となります。下流ノードで明示的にハンドリングしてください。

### 7.5 手動実行とデバッグ

「手動実行」ボタンから入力フォームを開き、テスト用のパラメーターを入れて実行できます。

- 実行中、ノードの進行状況がキャンバス上で可視化されます
- 下部パネルには各ノードの **入力 / 出力 / エラー / 実行時間 / 使用トークン数** が時系列で表示されます

> **動画プレースホルダー**：`videos/07-workflow-run.mp4`

### 7.6 公開（パブリッシュ）

「公開」を押すと、確認ダイアログが表示されます。

```
公開確認
公開すると現時点のワークフローが利用可能になります。
以前のバージョンに戻すことはできません。
ワークフローを公開しますか？
[キャンセル] [公開する]
```

- 公開後はトリガー（Webhook URL、スケジュール、メール監視など）が有効化されます
- すでに動作中の実行（ラン）は、その時点のバージョンで完了するまで継続されます
- 以前のバージョンへのロールバックは現バージョンでは提供していません。事前に下書きで動作確認を行ったうえで公開してください。

### 7.7 実行履歴とログ

ワークフロー詳細画面の「ログ」タブで過去の実行履歴を確認できます。

URL: `/{organization_id}/studio/{project_id}/workflows/{workflow_id}/log`

表示項目（例）:

- 実行日時、ステータス（実行中／成功／失敗／キャンセル）、所要時間
- 開始ノードへの入力（`input_data`）、終了ノードからの出力（`output_data`）
- 各ノードの入出力・エラー詳細・LLM トークン使用量

> **画面プレースホルダー**：`screenshots/07-workflow-log.png`

### 7.8 実行時の制限（標準値）

| 項目 | 標準値 | 備考 |
|---|---|---|
| ワークフロー全体の実行時間 | 約 30 分 | プラン・設定に応じて上限が変動します |
| 各ノードの実行時間 | 約 5 分 | コードノードはサンドボックスの上限あり（次項） |
| コードノードの実行時間 | 約 60 秒 | Python3 または JavaScript |
| サブワークフローの再帰呼び出し深さ | 最大 5 | これを超えるとエラー |
| イテレーション並列度 | 最大 10 | 設定で変更可能 |

具体的な数値は契約プラン・組織設定により異なります。詳細は導入元にご確認ください。
