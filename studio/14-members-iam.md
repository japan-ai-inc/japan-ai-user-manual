# 14. メンバーとアクセス制御（IAM）

### 14.1 メンバー管理

設定画面 →「メンバー」から、プロジェクトに参加するユーザーを管理します。

- メンバーの追加・削除
- ロールの変更
- 招待中のステータス確認

> **画面プレースホルダー**：`screenshots/14-members.png`

### 14.2 ロール体系

ロールは **組織レベル** と **プロジェクトレベル** に分かれます。

#### 組織レベルのシステムロール

| ロール | 主な権限 |
|---|---|
| 組織管理者（`jai:global:admin`） | 組織全体・IAM の全権限 |
| 組織編集者（`jai:global:editor`） | 組織内リソースの読み書き・IAM 管理 |
| 組織メンバー（`jai:global:member`） | 読み取り・実行・限定的な作成 |
| 組織 API キー（`jai:global:api_key`） | API 経由のモデル呼び出し・エージェント呼び出し・参照系 |

#### プロジェクトレベルのシステムロール

| ロール | 主な権限 |
|---|---|
| 管理者（`jai:project:admin`） | プロジェクト全権限・メンバー管理・IAM 管理 |
| 編集者（`jai:project:editor`） | リソースの作成・編集・削除・実行 |
| メンバー（`jai:project:member`） | 読み取り・実行・限定的な作成 |

> 現バージョンの Studio プロジェクトでは、上記 3 ロール以外（例：閲覧者）はメンバー招待時に選択できません。プロジェクト外（組織レベル）で参照系のみ付与したい場合は組織側のロール体系で対応します。

### 14.3 リソースポリシー（ABAC 条件付き）

ロールベースの制御に加え、**個別リソースにポリシーステートメント** を付与できます。

ポリシーは次の構造で表現されます。

```json
{
  "sid": "AllowSalesReadOwn",
  "effect": "allow",
  "principals": ["role:sales", "user:u_123"],
  "actions": ["jai.dataset.read", "studio.object.record.read"],
  "conditions": {
    "sourceIp": { "ipMatch": ["10.0.0.0/8"] }
  }
}
```

- 効果：`allow` または `deny`
- 対象アクション：権限文字列のリスト
- 条件：属性ベースの追加条件（IP 制限、時刻範囲、属性一致など）
- リソースポリシーはデータセット、エージェント、ワークフロー、カスタムオブジェクト、モデル等に対して設定可能

### 14.4 JRN（Japan Resource Name）

Studio 内のリソースは JRN という統一フォーマットで識別されます。

```
jai:{組織ID}:project:{プロジェクトID|global}:{リソース種別}:{リソースID}
```

例:

- データセット: `jai:org-123:project:proj-456:dataset:ds-789`
- カスタムオブジェクト: `jai:org-123:project:proj-456:object:obj-789`
- ストレージファイル: `jai:org-123:project:proj-456:storage:res-uuid::path:/folder/file.pdf`
- 組織共通エージェント: `jai:org-123:project:global:agent:ag-456`

### 14.5 監査ログとの関係

IAM 関連の操作（ロールの作成・変更・削除、ロールバインディング、ポリシー変更等）は監査ログとして記録されます。詳細は [18 章](18-api-keys-audit-log.md) を参照してください。

### 14.6 カスタムロール

現バージョンでは、システム提供のロール群を利用する運用を基本としています。カスタムロールの提供状況は導入元にご確認ください。
