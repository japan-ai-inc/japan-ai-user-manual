# Move Your Work Forward from a Page

A Page is a web screen for reviewing information, entering information, and performing business actions. Open a Page prepared in an App or Project, then work according to the guidance on the screen.

**A Page's input fields, buttons, and saving method vary according to how that Page is built.** This article explains the common flow for opening a Page, checking the target, performing an action, and checking the result. Not every Page has the same form or Save button.

Creating Pages, uploading ZIP files, building, publishing, and switching versions are covered in separate articles for creators and administrators.

## Before you begin

- Check the App or Project you will use and the Page name.
- Check the business task you will perform on the Page and which actions you may take, such as viewing, registering, or updating.
- Prepare the information and files needed for the action. Use data approved for business use.
- Know whom to ask if a problem occurs.

If you have not opened an App or Project yet, begin with one of these articles.

- [Open an Installed App and Get Started](open-installed-app.md)
- [Get Started in a Shared Project](start-with-shared-project.md)

> Screen labels and entry points vary by organization configuration, permissions, and App or Project configuration. The following steps describe what to check in a desktop web browser.

## 1. Open the Page to use

### Open it from an App

1. Open the App you will use.
2. If a home Page for business use is displayed directly, check that screen's name and description.
3. If a dashboard is displayed, select the target Page from "Pages."
4. If you cannot see the Page you need, check whether an action such as opening an "All" list is displayed.

When you select a Page on an App dashboard, it may open in a new tab. If the original screen does not change, also check your browser tabs.

### Open it from a Project

1. Open the shared Project.
2. If a home Page opens directly, proceed with the guidance on that screen.
3. On the Project home screen, select the target from "Pages in this Project." In the navigation, use an entry point such as "PAGE."
4. If you cannot find the target Page on the home screen and "View All" is displayed, check the list.

Selecting a Page card and using actions such as editing or access settings in its menu are separate. **For ordinary business use, you do not need to edit the Page itself or change its publication settings.**

### Open it from a link you were given

If you received a Page link from the person in charge, open that link. If you are prompted to sign in, proceed with the account and method you were given.

Even if a link is shared, you do not necessarily have permission to view or operate data. Authentication methods and publication scope also vary by Page. If you cannot open it, ask the person in charge about the target and access conditions.

## 2. Check the screen and target of your action

Before entering or running anything, check the following.

| What to check | What to look for |
|---|---|
| Page name and description | Whether this is the screen for the business task you were given, rather than a different Page with a similar name |
| Displayed data | Whether the customer, opportunity, period, status, and other targets are correct |
| Search and filtering conditions | Whether the intended conditions are used and whether conditions are hiding targets |
| Action description | Whether the action views, registers, updates, sends, or does something else |
| Processing destination | Whether the save location, update target, external-service destination, and similar items are correct |

Specific layouts such as lists and forms vary by Page. If there is no explanation and you do not know what will happen when you select a button, check with the person in charge before taking the action.

**Displaying a Page does not guarantee that you can use all data or features.** Additional permission checks or external connections may be needed when retrieving data or running processing.

## 3. Work according to the screen guidance

### Review information

When a list or search function is available, check and narrow the target by its name, date, status, or other details. If there is an action to open a details screen, select the data you need.

An empty search result does not necessarily mean the data does not exist. Check search conditions, display targets, loading errors, and your viewing scope.

### Enter, register, or update information

When there is a form, proceed in this order.

1. Check the input target. When updating existing data, review the target's name and identifying information.
2. Enter information according to the field descriptions. If required fields or date or number formats are specified, follow those conditions.
3. When using an attachment feature, check the target file and conditions such as the format and size shown on the screen.
4. Review the content and perform the confirmation action specified by that Page.
5. Check the completion display or updated content.

> "Save" and "Register" are examples of action names. Some Pages save automatically and others require explicit confirmation. Do not conclude that an entry was saved merely because you entered it; check the Page's guidance and result.

If an input error is displayed, check the relevant field and explanation. Do not fill a required value with temporary content or select another target when you do not understand the meaning.

### Run AI or business processing

If the Page has a button to make an AI request or call a process such as a Workflow, check the input and processing content before taking the action.

- Check whether it sends information externally or registers, updates, or deletes data.
- While an in-progress indicator is displayed, do not repeatedly select the same confirmation or Run button.
- If you move to an Agent conversation screen, check the request and target Agent.
- Review output text and numbers before using them for business.

Even actions from a Page may affect data shared with other people or external services. Check the processing destination even when you run it only to test it.

## 4. Check the result

**Distinguish between completing screen display, accepting processing, and completing business processing.** How you check the result depends on the action you performed.

| Action performed | Examples of results to check |
|---|---|
| Search for or view information | Whether targets matching the conditions were displayed and you could check required details |
| Register or update data | Completion guidance and registered or updated values. If displayed, a record number or similar identifier |
| Make an AI request | Contents of the response or deliverable. If you also requested an external action, its result |
| Output a file | Completed download, file name, content, and save location |
| Send to or update an external service | Status at the destination, or any available run result or history |

The above are examples of what to check; not every Page has a history or results list. If you cannot determine whether it completed, ask the person in charge how to check.

Even when reloading the screen to check results, first check that there is no unsaved input and no processing with an unclear run status. Closing the screen does not necessarily stop processing.

## 5. Move to another screen or finish work

If a switch menu is displayed at the top of the Page, you can select the Page you need. It is displayed according to settings and Pages you can access, so it is not necessarily displayed for everyone.

If an entry point such as "Back to Studio" or "Back to dashboard" is displayed, use it to return to the App or Project. If no return entry point is available, use the original App or Project tab, or the entry point provided by the person in charge.

Before switching screens or closing a tab, check saved and run results. Browser Back or reload does not necessarily retain input.

> "Download" and similar actions in a Page card's menu are functions for creation and management. Distinguish them from downloading reports or data output within a business screen.

## When there are display or operation problems

| Situation | What users should check |
|---|---|
| You cannot find the Page | Check the App, Project, and Page names and link; display scope; and access permissions. You do not need to create a new Page. |
| Selecting it does not change the screen | Check whether a new tab opened or your browser displayed guidance that it blocked a pop-up. Even when needed, follow organizational policy and do not allow all unrelated sites at once. |
| "Authentication failed" is displayed | Check that you are using the account you were given. If the screen has "Retry," try it after checking unsaved input and run status. If it repeats, contact the person in charge. |
| "Failed to load page" is displayed | If the screen has "Retry," try to restore display. If processing was in progress, first check the result and do not run the same business process repeatedly. |
| "Failed to load Page navigation" is displayed | Check the problem with the Page-switching list separately from the result of business processing on the screen. Retry according to the screen guidance. |
| A configuration error, blank screen, or loading never completes | Record the Page name, date and time, and display content, then tell an administrator. Users should not try to fix it by changing source code or publication settings. |
| The screen opens but retrieving data or running processing fails | Check the displayed message, permissions, and external connection status. Ask the person in charge whether a personal connection or shared setting is required. |

"Retry" for loading the screen frame and rerunning a "Register," "Send," or "Run" action inside a Page are different. Even if communication is interrupted, an update or send may already have completed. **When you do not know whether processing has completed, check before running it again.**

Include the App, Project, and Page names; action you performed; date and time; and displayed message in an inquiry. As URLs may include authentication information, do not forward the browser address-bar content without checking it; use an ordinary guidance link or the target name. Do not send passwords, API keys, tokens, or unnecessary personal information.

## Action-completion checklist

- [ ] I checked the Page I was given and the target of my action.
- [ ] I checked input content and the impact of registration, updates, sends, and similar actions.
- [ ] I performed the required confirmation or run action.
- [ ] I checked the result, update destination, save location, and other outcomes.
- [ ] I did not rerun an unclear result without checking it.
