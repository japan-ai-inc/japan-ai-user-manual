# 用語集

Studioのマニュアルや画面に登場する用語を、用途別にまとめています。分からない言葉が出てきたときや、似た機能の違いを確認したいときに参照してください。

**ここでの定義は、用語を理解するためのものです。機能の利用可否や操作範囲は、提供条件・組織の設定・権限によって異なります。** 操作手順や制限値は、各機能の記事で確認してください。

## 本マニュアルの表記

- 機能名は原則として **Agent、Workflow、Skill、Page、Object、Dataset、Storage** と表記します。画面では日本語名や複数形で表示される場合があります。
- 構築・管理の領域は **Studio Workspace** と表記し、組織やProjectと区別します。
- **App** は、特に断りがない限りStudio Appを指します。
- 「利用者」「作成者」「運用担当者」などは、記事を読む人の役割です。製品のロール名や、付与されている権限を表すものではありません。

## 1. 利用する場所・管理する単位

| 用語・表記 | 意味 | 混同しやすい点 |
|---|---|---|
| **組織（Organization）** | 利用者の所属や、組織としての設定・利用条件などを管理する単位。 | 同じアカウントでも、利用する組織によって見える内容や権限が異なる場合があります。 |
| **Studio Workspace** | Project単位でAgent・Workflow・Pageなどを作成・管理する領域。 | 独立した組織やProjectの別名ではありません。他の画面で「Workspace」が組織を指す場合は、文脈を確認します。 |
| **Project（プロジェクト）** | 業務に必要なリソース、メンバー、設定をまとめる単位。 | 作成者だけの場所ではありません。共有されたProjectを利用者が使うこともあります。 |
| **リソース** | Agent・Workflow・Page・Objectなど、構築や業務利用の対象となる構成要素の総称。 | どのリソースをProjectへ追加・再利用できるかは、対象機能と設定によって異なります。 |
| **Studio App（App／アプリ）** | 画面や処理などを組み合わせ、利用者向けに提供する業務アプリ。配布・インストールして利用する形もあります。 | Page単体と同じ意味ではありません。また、Projectを作るだけで配布や掲載が完了するわけではありません。 |
| **Marketplace（マーケットプレイス）** | 提供されているAppを探し、内容や導入条件を確認する入口。 | 導入済みAppを開く場所とは目的が異なります。すべてのAppがMarketplace経由で提供されるわけではありません。 |

詳しい関係は、[Studio Workspace・Project・App・Marketplaceの関係](studio-concepts.md)で説明しています。

## 2. AI・処理・画面を構成する機能

| 用語・表記 | 意味 | 例・補足 |
|---|---|---|
| **Agent（エージェント）** | 指示や依頼に応じて、AIが回答や処理を行う機能。 | 問い合わせへの回答や報告書の下書きなど。資料検索や外部操作には、利用する機能の設定が必要です。 |
| **モデル／LLM** | 文章の理解・生成など、AgentやWorkflow内のAI処理を担うモデル。LLMは大規模言語モデルの略。 | Agentはモデルそのものではなく、指示や利用するツールなどを含めて構成します。 |
| **プロンプト** | AIへ渡す指示や依頼文。 | Agentの役割を定める指示と、利用者がその都度入力する依頼では、用途が異なります。 |
| **Workflow（ワークフロー）** | 処理の順序や条件を、ノードをつないで定義・実行する機能。 | AI処理、検索、条件分岐、データ操作などを組み合わせます。複数Agentの連結だけに限定されません。 |
| **ノード** | Workflowを構成する処理の単位。 | AIによる生成、条件分岐、ツールの呼び出しなど。前の処理の出力を、次の処理の入力に使う構成もあります。 |
| **変数** | 入力値や処理結果などを、名前で参照するための仕組み。 | 問い合わせ本文や分類結果など。値の型や、どこから参照できるかを確認して使います。 |
| **Skill（スキル）** | Agentが再利用する手順・知識・関連資料などをまとめたもの。 | 報告書の作成ルールなど。内容によってツールやスクリプトを含む場合もあります。 |
| **Tool（ツール）** | 検索、情報取得、データ更新など、特定の操作を実行する機能。 | Skillが仕事の進め方を示すのに対し、Toolは具体的な操作を担います。 |
| **Plugin（プラグイン）** | ツールやSkill、外部接続などを扱う拡張機能・管理領域の名称。 | 画面の「プラグイン」では、ツール・スキル・コネクタを区別します。すべてを同じ種類の実行ツールとは扱いません。 |
| **Page（ページ）** | 情報の表示や入力・操作を行うためのWeb画面。 | 入力フォームやダッシュボードなど。Appの画面を担う構成要素であり、独自開発には技術知識が必要な場合があります。 |

機能の使い分けは、[構成機能の役割](studio-components.md)を参照してください。

## 3. データ・資料・ファイル

| 用語・表記 | 意味 | 例・補足 |
|---|---|---|
| **Object（Custom Object／カスタムオブジェクト）** | 項目を定義し、業務データをレコードとして管理する機能。 | 問い合わせ、商談、タスクなど。本マニュアルでは主に「Object」と表記します。 |
| **フィールド（項目）** | Objectで管理する、データの項目。 | 「問い合わせ番号」「担当者」「対応状態」など。文字列・数値などの型を定義します。 |
| **レコード** | Objectに登録する1件分のデータ。 | 1件の問い合わせが1レコードとなり、その中に担当者や対応状態などの値を持ちます。 |
| **スキーマ** | データの項目・型などを定める構造の定義。 | Objectの設計では、「どんな項目に、どんな値を入れるか」を決めるものです。個々のレコードとは区別します。 |
| **Dataset（データセット）** | AIが必要な情報を検索・参照するためにまとめた資料の集合。 | 製品マニュアルやFAQなど。資料の取り込みと、参照する側の設定が必要です。 |
| **Knowledge／Knowledge Base（ナレッジ／ナレッジベース）** | AIが参照する知識や、そのための資料を指す表現。 | 既存資料ではDatasetに関係する機能の名称として登場します。画面・資料ごとに指す範囲を確認し、常にDatasetと完全に同じ意味とは扱いません。 |
| **RAG（検索拡張生成）** | 関連情報を検索し、その結果を参考にAIが回答を生成する方式。 | Datasetは資料をまとめる機能、RAGは検索結果を回答に利用する方式です。資料全文を毎回読み切ることや、回答の完全性を保証するものではありません。 |
| **Storage（ストレージ）** | ファイルやフォルダを保管・管理する機能。 | PDF、画像、CSV、生成した報告書など。保存しただけでDatasetの検索対象になるわけではありません。 |

> **「タスク」は文脈で意味が変わります。** 業務管理用Objectの1レコード、Agentへ依頼する仕事、またはProjectのタスクスケジューラで管理する実行設定を指す場合があります。記事では「業務タスク」「実行タスク」など、対象を添えて区別します。

## 4. 起動・実行・提供の段階

| 用語・表記 | 意味 | 混同しやすい点 |
|---|---|---|
| **トリガー** | 処理を起動するきっかけや条件。 | 何を処理するかというWorkflowの定義と、いつ・何を受けて起動するかは別に考えます。 |
| **タスクスケジューラ** | Project内のAgentやWorkflowについて、日時・繰り返しなどの実行条件を設定し、タスク一覧や履歴を確認する機能。 | Workflowの構成・公開や開始ノードのイベント設定とは区別します。業務データの「タスク」やProjectの構築用会話とも異なります。 |
| **Webhook（ウェブフック）** | イベントの発生を、HTTPリクエストで指定の受信先へ通知する仕組み。 | 通知を受ける側では、認証・入力内容・起動する処理などの設定が必要です。 |
| **実行／実行履歴** | 定義した処理を動かすこと／その状態や結果などの記録。 | 定義を保存した状態と、処理が実際に動いた結果は別です。失敗や再実行は履歴を確認して判断します。 |
| **下書き／テスト** | 編集中の内容／その内容の動作を確認する操作。 | テストでも、外部送信やデータ更新が起こり得ます。下書きだから影響がないとは限りません。 |
| **公開** | 対象の機能を、所定の手順で利用・提供する状態にすること。 | Workflowの公開、Pageの公開、Appの配布・掲載では意味と手順が異なります。「公開＝インターネット上で誰でも利用可能」ではありません。 |
| **インストール（導入）** | 配布されたAppを、導入先で利用するために取り込むこと。 | 必要な外部接続や利用者設定まで完了しているとは限りません。 |
| **バージョン／リビジョン** | 更新された内容を識別するための版。 | App、Page、SDKなど、何の版を指すかを確認します。名前が同じでも中身や対応条件が異なる場合があります。 |

起動方式の選び方は、[自動実行方式を選ぶ](choose-execution-method.md)を参照してください。

## 5. メンバー・権限・外部接続

| 用語・表記 | 意味 | 注意点 |
|---|---|---|
| **メンバー** | 組織やProjectなどに参加する人。 | 一般的な参加者の意味と、画面上のロール名「Member」は区別します。参加しているだけで、すべての操作が許可されるわけではありません。 |
| **権限／ロール／ポリシー** | 権限は閲覧・実行・更新などの許可、ロールは権限をまとめて割り当てる役割、ポリシーはアクセスの条件や許可・拒否を定めるルール。 | ロール名だけで、すべての対象への操作範囲を判断しないでください。対象リソースと適用される設定を確認します。 |
| **IAM** | 誰が、どの対象に、どの操作を行えるかを管理する仕組み。 | Identity and Access Managementの略。画面にボタンが見えることだけで、実行権限があるとは限りません。 |
| **認証／認可** | 認証は利用する本人や資格情報の確認、認可はその操作を許可するかの判断。 | ログインできても、目的のデータを閲覧・更新できるとは限りません。 |
| **外部接続／コネクタ** | ツールなどから外部サービスを利用するための接続設定。 | どのサービスを、誰のアカウントで、どの範囲まで利用するかを確認します。 |
| **個人接続／共有接続** | 個人で利用する接続／Projectなどの共有用途に用意する接続。 | 共有されるのは接続の利用設定であり、認証情報の値を全員に配るという意味ではありません。実行時に使われるアカウントを確認します。 |
| **Credential（資格情報／認証情報）** | 外部サービスなどへアクセスする際の本人・資格確認に用いる情報。 | APIキー、アクセストークンなど。期限切れや失効により、再認証が必要になる場合があります。 |
| **Secret（シークレット）** | APIキーやパスワードなど、公開せずに管理する機密値。また、その管理対象。 | 画面の「プロジェクトシークレット」など、どの機能の管理対象かを区別します。値を保存することと、ツールの接続を完了することは別です。 |

**Skillの追加、Appのインストール、Secretの登録だけで、必要な権限や外部接続がすべて整うわけではありません。** 実行する人・使う接続・操作する対象を分けて確認します。

## 6. 開発・連携で使う用語

| 用語・表記 | 意味 | 補足 |
|---|---|---|
| **Web UI** | ブラウザから操作する画面。 | フォームや一覧などを使って設定・利用する方法です。 |
| **API** | プログラムから機能を呼び出すためのインターフェース。 | 呼び出し先ごとに、認証方式・入力・応答・制限を確認します。 |
| **SDK** | APIなどをコードから利用しやすくするための開発用ライブラリ。 | Studio SDKとWeb UIは、すべての操作が一対一に対応するとは限りません。利用する版と実行環境を確認します。 |
| **CLI** | ターミナルにコマンドを入力して操作する仕組み。 | StudioのCLIは`jai-studio`です。SDKのコードを書く方法とは操作の入口が異なります。 |
| **Project APIキー** | Projectに関連するAPI利用のための認証情報。 | 秘密として管理します。ブラウザへ配布するコードや、公開資料・ログへ含めないでください。 |
| **Hosted Page／PRS** | Hosted PageはStudioでホストされるPage、PRSはその提供を担うPages Rendering Serviceの略。 | Pageのブラウザ側とサーバー側、外部の開発環境では、利用できるAPIや認証方法が異なります。 |
| **デプロイ** | 作成したコードや成果物を、実行する環境へ配置すること。 | 配置すること、利用者へ権限を与えること、Marketplaceへ掲載することは同じ操作ではありません。 |

> **Public APIとHosted Page向けAPIは、呼び出し先や認証を区別してください。** 同じObjectやStorageを扱う説明でも、そのまま別の実行環境へ転用できるとは限りません。詳細は[実行モード・認証・対応範囲](../development/execution-modes-and-auth.md)で扱います。
