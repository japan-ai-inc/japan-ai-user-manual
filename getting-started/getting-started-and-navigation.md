# 利用開始の前提と基本画面

Studioを使い始める前に、**利用するアカウント・所属組織・対象のAppまたはProject**を確認します。ログインできることと、目的の画面や機能を利用できることは別です。

この記事では、利用開始までの確認事項と、基本画面の見分け方を説明します。Appのインストール、メンバーの招待、機能ごとの操作は、それぞれの詳細記事で扱います。

## 1. 開く前に確認すること

管理者や利用を案内した担当者から、次の情報を確認してください。

| 確認事項 | 確認する内容 |
|---|---|
| アクセス先 | 組織から案内されたログイン先、またはApp・Projectのリンク |
| 利用アカウント | 利用を許可されたメールアドレスと、組織で指定されたログイン方法 |
| 所属組織 | 今回の業務で利用する組織の名前 |
| 利用対象 | App名またはProject名と、最初に使う画面・Agent・Workflowなど |
| 自分の作業 | 利用するだけか、作成・編集・管理も行うか |
| 追加の準備 | 個人の外部アカウント接続や、管理者による初期設定が必要か |

まずはPCのWebブラウザで確認すると、構築・管理のメニューを探しやすくなります。画面幅によってメニューが折りたたまれたり、一部の入口が表示されなかったりする場合があります。これは、すべてのAppがスマートフォンで利用できないという意味ではありません。個別Appの利用環境は、その案内を確認してください。

> 既存のAppやProjectを使うよう案内されている場合、見つからないからといって新しい組織やProjectを作る必要はありません。まず、アクセス先とアカウントを確認します。

## 2. ログインと所属組織を確認する

1. 組織から案内されたアクセス先を開きます。
2. 指定された方法でログインします。ログイン画面が出ずに開いた場合も、利用中のアカウントが正しいか確認します。
3. 組織の選択画面が表示されたら、今回利用する組織を選びます。
4. AppやProjectを開く前に、表示されている組織が案内と一致しているか確認します。

同じ人が複数の組織を利用する場合、選んだ組織によって表示されるAppやProjectが異なることがあります。目的の組織が見つからない場合は、利用アカウントや組織への参加状態を管理者に確認してください。

ログイン方法や追加の認証は、組織の運用に従います。別のログイン方法を自己判断で使っても、同じ所属や権限が引き継がれるとは限りません。

## 3. 目的に合う入口を選ぶ

基本的な入口は、**Apps、Studio Workspace、タスク**です。組織全体のタスクは「その他の機能」から「タスク」を開き、必要に応じてサイドバーへ固定します。AppsやWorkspaceの表示を含め、利用できる入口は提供条件や画面構成によって異なります。

| やりたいこと | 開く場所・確認する対象 |
|---|---|
| 導入済みのAppで業務を進める | Appsから対象Appを探す、または案内されたAppのリンクを開く |
| 共有されたProjectを利用する | 案内されたProjectのリンクを開く。Studio Workspaceの一覧から探す場合も、対象名を確認する |
| Agent・Workflow・Pageなどを作成・管理する | Studio Workspaceで対象Projectを開く |
| 新しいAppの導入を検討する | Apps内のMarketplaceが利用できる場合、その一覧を確認する |
| 組織全体の実行タスクや公開済みWorkflowを確認する | 「その他の機能」から「タスク」を開く。必要に応じてサイドバーへ固定する |

**Appの利用と、Marketplaceからのインストールは別の作業です。** 導入済みAppを使うために、利用者がもう一度インストールする必要があるとは限りません。

共有されたProjectを使う場合も、構築者向けの画面をすべて理解してから始める必要はありません。担当者に案内された機能から利用を始めます。

用語の違いは、[Studio Workspace・Project・App・Marketplaceの関係](studio-concepts.md)を参照してください。

## 4. 基本画面の見方

### Appsの一覧

導入済みAppを探す場所です。Marketplaceや組織内Appの管理に関する表示が加わる場合もありますが、全員に同じタブが表示されるわけではありません。

Appを開くときは、名前と説明を確認します。似た名前のAppがある場合は、案内されたリンクと一致するかを確認してから進みます。

### Studio WorkspaceのProject一覧

作成・管理するProjectを探す入口です。Projectを開いたら、対象の名前を確認します。既存のProjectを利用する目的で来た場合は、新規作成ではなく、そのProjectへのアクセスを確認します。

### App・Projectの内側

開いた先では、画面や処理の内容に応じてメニューが変わります。見た目を完全に同じものとして覚えるのではなく、次の役割を探してください。

| 画面の要素 | 見るポイント |
|---|---|
| 対象名・見出し | どのApp・Project・機能を開いているか |
| ナビゲーション | 利用できるPage、Agent、処理、データなどへの入口 |
| 主な操作領域 | チャット、入力フォーム、一覧、結果など、その機能で作業する場所 |
| 設定への入口 | メンバー・接続・構成などを管理する場所。利用者全員が変更するものではない |
| 状態表示・案内 | 設定不足、読み込み中、権限に関する案内など、次の操作に必要な情報 |

Appでは、用意されたPageやAgent、オートメーションなどが表示されます。Projectでは、リソースや会話などをたどる構成があります。利用者向けのホームPageが開き、構築用メニューが見えない場合もあります。

**画面に機能が見えることと、編集や実行が許可されていることも別です。** 利用できる操作は対象と権限によって異なります。

## 5. 開いたあと、利用できる状態か確認する

### Projectへの参加を案内された場合

Projectを開いた際に、参加を案内する画面が表示される場合があります。対象が案内されたProjectであることを確認し、表示された案内に従ってください。

参加の方法はProjectや組織の設定によって異なります。リンクを知っていれば必ず参加できるわけではありません。参加の案内が出ない、一覧へ戻される、アクセスできない場合は、管理者に参加状態を確認します。

### 外部サービスへの接続が必要な場合

AppやProjectが外部サービスを使う場合、次のような準備が必要になることがあります。

- 利用者本人が、自分の外部アカウントを接続する。
- 管理者が、共有接続や必要な設定を用意する。

利用者本人の接続と、管理者が設定する共有接続を混同しないでください。設定を求められたときは、自分が対応する項目かを確認します。パスワードやAPIキーを、確認のためにチャットへ貼り付けることは避けてください。

接続の説明は[個人接続・共有接続・Secretを選ぶ](../operations/choose-personal-shared-connections-and-secrets.md)、本人の設定は[自分の外部アカウントを接続する](../operations/connect-your-external-accounts.md)で扱います。

## 6. 表示が案内と違う場合

最初に、次の順で確認します。ここでは利用開始時の切り分けだけを行い、権限や設定を自己判断で変更しないようにします。

| 状況 | 最初に確認すること |
|---|---|
| 目的の組織が出ない | ログイン中のアカウントと、組織への参加状態 |
| STUDIO・Workspace・Appsが見つからない | 利用中の組織、画面幅やメニューの開閉、組織での提供条件 |
| AppやProjectが一覧にない | 対象名・案内されたリンク、参加状態、閲覧できる範囲 |
| Projectを開いても参加・アクセスの案内が出る | 自分が利用対象者に含まれているか、参加手続きが必要か |
| 画面は開くが実行・編集できない | 必要な操作権限、機能の有効状態、初期設定や外部接続 |
| 接続元に関する制限が表示される | 組織が指定する利用ネットワーク・アクセス条件 |

解決しない場合は、対象名、発生日時、行おうとした操作、表示されたメッセージを管理者へ伝えます。画面画像を添える場合は、秘密情報や不要な個人情報を隠してください。

## 利用開始の確認リスト

- [ ] 指定されたアカウントでログインしている。
- [ ] 今回利用する組織を確認した。
- [ ] 対象のAppまたはProjectを開けた。
- [ ] 自分が使う画面・Agent・処理を確認した。
- [ ] 参加、権限、初期設定、外部接続について、不明点の確認先が分かる。

ここまで確認できたら、対象に合った操作記事へ進みます。単に試すつもりでも、送信やデータ更新を行う処理は、実行前にその内容を確認してください。
