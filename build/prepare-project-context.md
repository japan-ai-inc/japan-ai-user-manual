# Projectの説明・文脈を整える

Projectを使う人やAIに、目的・用語・作業の前提を伝えます。この記事では、**Projectの説明を整理し、利用できる設定に応じて共通の指示を登録して、保存内容と応答を確認する手順**を説明します。

Projectの作成や名前・アイコンの設定は、[Projectを作成して基本設定する](create-project-and-basic-settings.md)を参照してください。個別の構築依頼は、[Studio Assistantに構築を依頼する](build-with-studio-assistant.md)で扱います。

## 始める前に

- 対象の組織・Projectと、設定を変更できる権限を確認します。
- 既存の説明や指示を読み、変更してよい範囲を担当者と確認します。
- 利用者、対象業務、正しい用語、判断に迷う場合の扱いを整理します。
- 検証に使える、機密情報を含まない入力例を用意します。

> 画面や文脈の管理方式は、組織の設定によって異なります。本記事の「カスタム指示」の操作は、Projectの基本設定にその欄が表示される場合の手順です。欄がないことだけで、権限不足や未設定とは判断しないでください。

## 1. 説明・文脈・指示の役割を分ける

「文脈」とは、AIが依頼の意味を理解するための背景や前提です。すべての環境に「文脈」という独立した入力欄があるわけではありません。

| 情報の置き場所 | 主に書くこと | 混同しないこと |
|---|---|---|
| Projectの「説明」 | 何のためのProjectか、誰が使うか、対象業務と扱う範囲 | 名前だけの補足ではなく、目的が伝わる概要にする |
| 「カスタム指示」が利用できる場合の設定欄 | Projectで共通に守ってほしい用語・出力形式・判断の方針 | Projectの説明とは別に保存する。説明を変更しても、ここに残った古い指示は自動で書き換わらない |
| 個別Agentの指示 | そのAgentが担当する仕事、固有の手順や出力 | Project全体の方針と矛盾する内容を重ねない |
| 会話中の依頼 | 今回の対象、使う資料、作業範囲、期待する結果 | 会話で伝えただけの内容を、Projectの共通設定に保存したと扱わない |
| 業務資料・データ | 詳細な規程、参考資料、更新される業務情報 | 説明欄へ全資料を詰め込まない。資料を置くことと、AIが参照できる設定をすることは別 |

画面や資料に「プロジェクトコンテキスト」と書かれている場合も、現在の環境で何を管理する機能なのか確認します。説明、共通指示、資料、Memoryをすべて同じ保存先・共有範囲だと考えないでください。

**説明や指示を保存することは、AIが毎回すべてを読み、必ず従うことの保証ではありません。** 操作の許可・禁止やデータの閲覧範囲は、権限・接続設定でも管理する必要があります。

## 2. Projectの説明を短く具体的に整える

説明には、初めてProjectを開く人にも用途が分かる内容を書きます。次の項目を短い文章にまとめると、構築や利用の前提がそろいます。

- **目的**：何を支援するか。
- **利用者**：誰が、どの場面で使うか。
- **対象情報**：何を入力・参照する想定か。
- **期待する結果**：何が得られればよいか。
- **対象外**：まだ扱わない業務や、実行しない操作。
- **運用区分**：検証用か、本番業務用か。

### 説明の例

> 営業担当者が商談前の確認事項を整理するための検証用Projectです。利用者が提示した会社情報と商談メモをもとに、事実・未確認事項・質問案を分けた準備メモを作成します。顧客へのメール送信、CRMの更新、契約条件の確定は対象外です。検証には許可されたテストデータのみを使います。

この文章は記載例です。説明に書いただけで、外部システムへの接続や資料参照が設定されるわけではありません。

### 保存する手順

1. 対象Projectを開き、名前と組織を確認します。
2. **「プロジェクト設定」**から**「基本設定」**を開きます。
3. **「プロジェクト情報」**の**「編集」**を選びます。
4. **「説明」**を修正します。名前など、変更する必要のない項目はそのままにします。
5. **「保存」**を選び、更新結果と表示内容を確認します。

作成後の説明は空にできますが、利用者が用途を判断できる概要を残すことをおすすめします。未保存の説明編集を「キャンセル」する場合は、表示される変更破棄の確認を読んでください。

## 3. 共通の指示を整理する

説明が「何のための場所か」を伝えるのに対し、共通の指示では「どう対応してほしいか」を具体化します。

### 書き方の目安

| 項目 | 書き方の例 |
|---|---|
| 用語 | 「顧客」は商談相手の企業を指す。担当者個人を指す場合は「先方担当者」と書く |
| 不明点の扱い | 資料にない金額・日付・契約条件を推測で埋めず、「未確認」と示す |
| 出力形式 | 結論、根拠、未確認事項、次のアクションの順に整理する |
| 対象の確認 | 更新や送信を伴う依頼では、対象・内容・実行範囲を確認する |
| 参照先 | 使うべき資料の名称と基準日を示し、参照できなければその旨を伝える |

### カスタム指示の例

> このProjectでは、商談準備メモの作成を支援してください。
>
> - 入力された事実と提案・推測を分けてください。
> - 金額、日付、契約条件が資料にない場合は「未確認」と記載してください。
> - 出力は「要点」「根拠」「未確認事項」「質問案」の順にしてください。
> - 参照した資料を識別できる場合は、資料名と基準日を添えてください。参照できない資料を読んだと記載しないでください。
> - 会社名や今回の対象が曖昧な場合は、作業前に確認してください。
> - この検証では、外部への送信や既存業務データの更新を行わないでください。

**「更新しない」「送信しない」という指示は、操作権限を取り消す設定ではありません。** 実際に禁止する必要がある操作は、利用するAgent・ツール・接続の権限も担当者に確認してください。

APIキー、パスワード、Secretの値、特定案件の機密情報を共通指示へ貼り付けないでください。自分専用のメモ欄ではなく、Projectの共通設定として内容と共有範囲を確認します。

## 4. 表示される設定方式に合わせて登録する

### 「カスタム指示」が表示される場合

1. 対象Projectの**「プロジェクト設定」→「基本設定」**を開きます。
2. **「カスタム指示」**の現在の内容を確認します。
3. 未設定なら**「カスタム指示を追加」**、登録済みならその欄の**「編集」**を選びます。
4. **「カスタム指示の内容」**に、整理した指示を入力します。登録済みの内容を編集するときは、残すべき方針を消さないよう確認します。
5. **「保存」**を選びます。
6. 保存成功の通知と、表示欄に戻った本文を確認します。必要に応じて設定画面を開き直し、変更が残っていることを確認します。

説明とカスタム指示は別々に保存します。説明欄の「保存」で、編集中のカスタム指示も保存されたとは判断しないでください。

「保存」は、入力エラーがある場合、変更がない場合、必要な権限がない場合などに選べません。**カスタム指示の編集で「キャンセル」を選ぶと、未保存の入力は保存されません。説明編集と同じ破棄確認が必ず出るとは限らないため、必要な下書きを残してから操作してください。**

カスタム指示の入力欄には文字数が表示されます。ただし、文字数表示の範囲内でも保存時にエラーになる場合があります。長文は共通の要点に絞り、保存結果を確認してください。保存できない場合は、入力内容を保全したうえで、操作が追加か編集か、文字数、表示されたエラーを担当者に伝えます。回避のために既存指示を削除して作り直すことは避けてください。

### 「カスタム指示」が表示されない場合

組織の文脈管理方式や、自分の権限・役割によって表示が変わります。

- まずProjectの説明を整理し、保存結果を確認します。
- 管理担当者に、共通の文脈や指示をどの機能・保存先で管理しているか確認します。
- 別の管理機能を利用している場合は、その機能の共有範囲と更新方法に従います。
- 一時的に会話へ必要な前提を添える場合も、共通設定の登録が済んだとは扱わないでください。

欄を表示させるために別画面のURLやAPIで代用したり、同じ指示を複数の場所へ無差別に登録したりしないでください。MemoryやProject共有情報の管理は、[MemoryとProject共有情報を管理する](../operations/manage-memory-and-project-shared-info.md)で扱います。

## 5. 保存内容と実際の応答を分けて確認する

次の2段階で確認します。

### 保存確認

- 正しいProjectの設定を変更したか。
- 説明と指示の双方に、古い目的や対象外の処理が残っていないか。
- 保存成功の通知があり、開き直しても内容が残っているか。
- 追加した文と既存の文に矛盾がないか。

### 応答確認

対象Projectで利用するAgentに、機密情報を含まない小さな依頼を送り、期待する形式と判断になるか確認します。古い会話の前提と切り分けるため、必要に応じて新しい会話でも確認します。新しい会話を使うこと自体が、反映の保証になるわけではありません。

例：

> 次のテスト情報で商談準備メモを作ってください。
>
> 相手先：サンプル商事。相談内容：問い合わせ対応の整理。
>
> 予算、導入希望日、契約条件は提示されていません。
>
> 外部への送信やデータ更新は行わず、メモだけ作成してください。

確認するのは、単にAIが「理解しました」と答えることではありません。

- 指定した見出しや順序で出力されるか。
- 未提示の予算や日付を作り出していないか。
- 事実と提案が区別されているか。
- 読めていない資料を参照済みとしていないか。
- 対象外の操作が実行されていないか。

期待と異なる場合は、対象ProjectとAgent、保存内容、Agent固有の指示、会話中の依頼、資料へのアクセスを確認します。「保存された」と「今回の応答に反映された」は別の確認です。1回の成功を、すべてのAgent・会話・Workflowで同じ結果になる保証とは扱わないでください。

## 6. 前提が変わったら古い記述を見直す

検証から本番運用へ移す、対象業務を広げる、参照資料を差し替えるときは、説明と指示を一緒に見直します。

1. 変更する理由と、影響を受ける利用者・Agentを確認します。
2. 古い記述のどこを置き換えるか決めます。末尾へ追記するだけにせず、矛盾する内容を整理します。
3. 説明・指示をそれぞれ保存します。
4. 代表的な入力で応答と、必要な処理の結果を確認します。
5. 変更点と残っている制約を利用者へ伝えます。

保存済みの共通指示をやめるための「削除」は、未保存入力のキャンセルとは異なります。カスタム指示の削除は、その指示を取り除く操作であり、Project全体の削除や、説明・他の資料をまとめて消す操作ではありません。削除が必要な場合は、担当者と影響を確認してから、対象欄の確認画面に従ってください。詳細な削除・共有情報の運用は[MemoryとProject共有情報を管理する](../operations/manage-memory-and-project-shared-info.md)で扱います。

## うまくいかないとき

| 状況 | 確認・対応 |
|---|---|
| カスタム指示が見つからない | 組織の管理方式と、自分の権限・役割を確認する。非表示だけで未設定と判断しない |
| 説明は編集できるが指示を保存できない | 説明の変更と指示の追加・更新では、必要な権限が異なる場合がある |
| 「保存」を選べない | 入力エラー、変更の有無、権限を確認する |
| 長文の保存に失敗する | 下書きを保全し、要点を整理する。文字数表示だけで保存可能と判断しない |
| 保存したはずの内容が見当たらない | 対象Project、保存通知、説明と指示のどちらを編集したかを確認する |
| AIが指示と違う回答をする | 保存結果、Agent固有の指示、会話の前提、利用する資料を切り分ける |
| 資料を参照していない | 説明に資料名を書いたことと、資料へのアクセスや参照設定を分けて確認する |

問い合わせには、組織名、Project名、編集した欄、追加／更新の別、操作日時、エラー、保存・応答確認の結果を添えます。機密値や顧客情報は含めないでください。
