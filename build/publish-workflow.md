# Workflowを公開する

Workflowを利用者に提供するには、テスト済みの下書きを**公開**します。この記事では、公開前の確認、Workflow編集画面から公開する手順、公開後の確認を説明します。

- 下書きのテスト方法：[Workflowの下書きをテストする](test-workflow-drafts.md)
- 公開済みWorkflowの実行：[公開済みWorkflowを実行する](../use/run-published-workflow.md)

## 公開とは

Workflowの編集内容には、次の3つの状態があります。

| 状態 | 意味 | 利用者への影響 |
|---|---|---|
| 画面上の編集内容 | 編集画面で変更しただけの内容 | 影響しない |
| 下書き（一時保存） | 「一時保存」で保存した構成。テスト実行の対象になる | 通常の利用には影響しない |
| 公開版 | 「公開」で確定した構成。利用者の実行やトリガーの対象になる | 次の実行から影響する |

公開では、**その時点の下書きが公開版になります**。公開版は1つで、公開するたびに最新の内容へ更新されます。

> **公開すると以前の公開版には戻せません。** 確認画面にも「以前のバージョンに戻すことはできません。」と表示されます。戻したい場合に備えて、公開前の構成を記録しておくか、必要に応じて複製を検討してください。

### 公開と表示範囲は別の設定です

「公開」は、どの構成を利用可能にするかを決める操作です。**誰が見られるか（表示範囲）**は、Workflowの基本設定などで管理する別の設定です。

- 公開しても、表示範囲が自動で広がるとは限りません。
- 表示範囲を広げても、未公開の下書きが利用者向けに提供されるわけではありません。
- 組織の全員に共有する場合は、ノードに書いたプロンプト・テンプレート・コードなどの内容も閲覧できるようになります。パスワードやトークンを本文に書かず、連携済みのアカウントを使ってください。

## 始める前に

- 対象の組織・Project・Workflowが正しいことを確認します。
- Workflowを編集・公開できる権限があることを確認します。権限は組織やProjectの設定によって異なります。
- [Workflowの下書きをテストする](test-workflow-drafts.md)の手順で、代表的な入力と分岐をテストします。
- すでに利用されているWorkflowを更新する場合は、利用者・トリガー・連携先への影響を確認し、関係者に知らせます。
- 外部サービスへの送信・更新を含む場合は、公開後に意図せず実行されないよう、トリガーの条件を確認します。

## 1. 公開前に確認する

公開前に、次の点を確認します。

| 確認項目 | 確認内容 |
|---|---|
| テスト結果 | 代表的な入力・分岐・エラー時の結果を確認した |
| チェックリスト | 未接続のノードや未設定の項目が残っていない |
| 開始方法 | 手動・トリガーなど、開始ノードの設定が意図どおり |
| 連携 | 必要な外部サービスとの接続・認証が有効 |
| 出力 | 利用者に返す内容・形式が決まっている |
| 影響範囲 | 更新を知らせる相手と、切り替えのタイミングを決めた |

チェックリストは設定漏れを見つける補助です。指摘がなくても、業務上正しい結果になることの保証ではありません。

組織の設定によっては、ノード設定に不足があると公開時にエラーになり、対象ノードと理由が表示されます。表示された内容を修正してから、もう一度公開してください。

## 2. Workflowを公開する

1. 対象のWorkflowを編集画面で開きます。
2. 画面上部の状態表示が「下書き」または「公開済み」になっていることを確認します。
3. 変更がある場合は、「一時保存」で下書きを保存します。
4. 「公開」を選択します。
5. 「公開確認」で表示内容を確認します。組織全体に共有されているWorkflowでは、共有範囲に関する注意も表示されます。
6. 「公開する」を選択します。
7. 「公開しました」と表示されることを確認します。

公開の確定時にも、画面上の構成が下書きとして保存されてから公開されます。ただし、確定前の保存漏れを防ぐため、手順3で保存しておくことをおすすめします。

### 「公開」を選択できない場合

| 表示・状態 | 考えられる理由 | 対応 |
|---|---|---|
| 「公開する変更がありません」 | 下書きと公開版の構成が同じ | 変更後に一時保存してから公開する |
| 「このワークフローを編集する権限がありません」 | 公開に必要な権限がない | 管理者やProject管理者に確認する |
| 表示がないまま選択できない | 権限や公開状態を読み込み中 | しばらく待ってから画面を再読み込みする |

### 公開に失敗した場合

- 「公開に失敗しました」と表示された場合は、公開版は更新されていない可能性があります。画面の状態表示と実行結果で確認してください。
- ノード名と理由が表示された場合は、該当ノードを修正し、一時保存してから再度公開します。
- 権限に関するメッセージが表示された場合は、管理者に必要な権限を確認します。

## 3. 公開後に確認する

1. 画面上部の状態表示が「公開済み」になったことを確認します。
2. 利用者の画面やトリガーなど、実際の利用方法で実行し、結果を確認します。確認方法は[公開済みWorkflowを実行する](../use/run-published-workflow.md)を参照してください。
3. 関係者に、公開日時・変更内容・問い合わせ先を知らせます。

### トリガーを使うWorkflowの場合

メールなど外部サービスのトリガーを使う場合、公開版の更新と、外部サービス側の登録は別に行われます。

- 「公開しましたが、Outlookトリガーの設定に失敗しました。」のような注意が表示された場合は、公開自体は完了しています。連携を確認して、もう一度公開してください。
- 接続が切れている、または無効な場合、公開後もトリガーが動かないことがあります。公開後に、テスト用のイベントで起動するかを確認してください。
- トリガーの設定方法は、[Workflowトリガーを設定する](configure-workflow-triggers.md)で説明します。

### 実行中・予定済みの処理について

公開後に新しく始まる実行は、更新された公開版を使います。**公開前に開始済みの実行や、すでに受け付けられた処理が、どの版で最後まで動くかは、構成や実行方法によって異なる場合があります。** 利用中のWorkflowを更新する場合は、処理が少ない時間帯を選び、公開後の実行結果を確認してください。

## 4. 公開済みWorkflowを更新する

1. 編集画面で変更します。
2. 一時保存し、下書きをテストします。
3. 変更内容を記録します。
4. もう一度「公開」を実行します。

公開済みのWorkflowを編集している間も、利用者は現在の公開版を使い続けます。**下書きの変更は、公開するまで利用者の実行に反映されません。**

> 本記事はWorkflow編集画面での公開を説明しています。タスク作成用のWorkflowなど、別の画面から公開する場合は、表示名や公開後の影響の説明が異なることがあります。画面の確認メッセージに従ってください。
