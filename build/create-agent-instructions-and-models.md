# Agentを作成して指示・モデルを設定する

Agentに担当させる仕事、回答の進め方、使用するモデルを設定します。この記事では、**Project内にAgentを作成し、名前・説明・指示・モデルを設定して、保存内容と最初の応答を確認する手順**を説明します。

ツール・Skill・Datasetの詳細は[Agentにツール・Skill・Datasetを設定する](configure-agent-tools-skills-datasets.md)、検証と改善の進め方は[Agentをテストして改善する](test-and-improve-agents.md)で扱います。

## 始める前に

- Agentを作成する組織・Projectを確認します。
- Agentの作成・編集が許可されていることを確認します。Projectへの参加や、既存Agentを使えることだけでは、作成・編集できるとは限りません。
- 組織の契約・機能設定・作成数の制限を確認します。作成ボタンが使えない場合は、画面の案内を確認してください。
- 担当業務、期待する出力、対象外の操作を整理します。
- 機密情報や個人情報を含まないテスト用の入力を用意します。

> **Agentの作成・編集には自動保存があります。** 「保存」を押すまで何も作成されない、画面を閉じれば変更を取り消せる、という前提では操作しないでください。検証用の名前を付け、利用状態とアクセス権限も確認します。

Projectの準備は[Projectを作成して基本設定する](create-project-and-basic-settings.md)、Project共通の方針は[Projectの説明・文脈を整える](prepare-project-context.md)を参照してください。

## 1. Agentに担当させる仕事を決める

最初は、1つの目的に絞ります。「営業を全部支援する」より、「商談メモから次回の確認事項を整理する」のように、入力と出力が分かる形にすると確認しやすくなります。

| 決めること | 例 |
|---|---|
| 利用場面 | 商談後、担当者が次回の確認事項を整理する |
| 入力 | 利用者が貼り付けた商談メモ |
| 出力 | 要点・確認済み事項・未確認事項・次回の質問案 |
| 不明点の扱い | 根拠がなければ「未確認」とする |
| 今回は行わないこと | 顧客への送信、CRMの更新、契約条件の確定 |

この例は練習用です。CRM連携や送信機能が自動で設定されることを意味しません。

### 名前・説明・指示を分ける

| 項目 | 役割 | 記載例 |
|---|---|---|
| 名前 | 一覧で用途を見分ける | 商談メモ整理（検証用） |
| 説明 | 利用者に用途や入力内容を伝える | 商談メモをもとに、確認済み事項と次回の質問案を整理します |
| 指示（システムプロンプト） | Agentに役割、手順、出力形式、注意点を伝える | 提示されたメモだけを根拠に、事実と提案を分けて整理する |
| 使用可能なモデル | このAgentのモデル選択の範囲を設定する | まず検証対象のモデル1つに絞る |
| デフォルトモデル | 基準として使用するモデルを設定する | 動作確認したモデルをデフォルトにする |

説明だけに処理手順を書いて済ませず、Agentへの具体的な指示は指示欄へ記載します。Project全体の説明・共通指示と矛盾しないことも確認してください。

## 2. 対象ProjectからAgentを作成する

1. 対象Projectを開き、組織名とProject名を確認します。
2. Project内のAgent一覧を開きます。
3. **「エージェントを作成」**を選びます。
4. 作成画面で名前を入力します。検証中は「検証用」など、用途を見分けられる表記を付けます。
5. 必要に応じてアイコンを設定します。
6. **「基本設定」**の説明欄に、利用者向けの用途と入力内容を記載します。

設定画面の構成は入口によって異なる場合があります。「AI 作成」と「構成」が表示される画面では、入力項目を確認するために「構成」を開きます。「指示」「基本設定」「高度な設定」のタブが表示される画面では、該当するタブを選んでください。この記事では、設定項目を自分で確認しながら入力する方法を扱います。

作成ボタンが使えない場合は、表示された権限・プラン・作成上限などの案内を管理担当者へ伝えます。別のProjectや組織で代わりに作成すると、保存先や利用範囲が変わるため、回避策として無断で切り替えないでください。

## 3. 指示を入力する

**「指示 (システムプロンプト)」**の欄に、Agentがどう仕事を進めるかを書きます。「指示」タブがある場合は、その中を確認します。

### 指示に含める5つの要素

1. **役割**：何の業務を支援するか。
2. **対象情報**：何を根拠にするか。
3. **手順**：どう整理・判断するか。
4. **出力形式**：見出し、順序、粒度。
5. **制約と不明点の扱い**：何をしないか、分からない場合にどうするか。

### 指示の例

次の文章は、前の手順で決めた「商談メモ整理」の記載例です。自社の業務に合わせて調整して入力します。

> あなたは商談メモの整理を支援するAgentです。
>
> 利用者が今回提示したメモを根拠に、次回の商談に向けた確認事項を整理してください。
>
> 手順：
> 1. メモに記載された事実と、利用者の推測・希望を分ける。
> 2. 課題、要望、制約、次回までに確認すべき点を整理する。
> 3. 金額、導入日、決裁者、契約条件が記載されていない場合は「未確認」とする。
> 4. 次回の質問案を作成する。質問案は確認済みの事実と区別する。
>
> 出力は「要点」「確認済み事項」「未確認事項」「次回の質問案」の順にしてください。
>
> 対象の商談を識別できない場合は、先に利用者へ確認してください。
> 根拠のない情報を補完せず、読めていない資料を参照したと記載しないでください。
> この検証では、外部への送信、CRMなどの業務データ更新、契約条件の確定を行わず、整理したメモだけを返してください。

### 指示だけでは設定できないこと

- 「社内資料を調べる」と書いても、資料の参照設定が完了するわけではありません。
- 「外部サービスを使う」と書いても、接続や認証情報は設定されません。
- 「送信しない」と書いても、実際の送信権限を取り消す設定にはなりません。
- 指示を保存しても、常に同じ回答や判断になる保証はありません。

参照先、実行できる操作、アクセス権限はそれぞれ確認します。APIキー・パスワード・Secretの値を指示へ貼り付けないでください。ツールや資料参照を追加する手順は[Agentにツール・Skill・Datasetを設定する](configure-agent-tools-skills-datasets.md)で扱います。

## 4. 使用するモデルを設定する

**「使用可能なモデル」**を開き、デフォルトと選択範囲を確認します。表示される候補は組織のモデル設定などに依存します。他の組織の画面や過去の資料と、同じモデルが必ず並ぶとは限りません。

### まず1つのモデルで確認する場合

1. **「すべてのモデルを許可する」**の状態を確認します。
2. 使用モデルを絞る場合は、このチェックを外します。
3. 設定済みのモデルと、**「デフォルト」**の表示を確認します。
4. 別のモデルを使う場合は、**「モデルを追加...」**から候補を選びます。
5. 追加したモデルの**「デフォルトに設定」**を選びます。
6. 不要なモデルを一覧から外し、検証対象の1つだけが残っていることを確認します。

現在のデフォルトを外したい場合は、先に別のモデルをデフォルトへ変更します。モデル一覧から外す操作は、このAgentの設定を変更するもので、組織全体からモデルを削除する操作ではありません。

### 複数のモデルを候補として残す場合

「モデルを追加...」から必要な候補を追加し、その中からデフォルトを選びます。**複数のモデルを登録しても、この画面の設定だけで比較実行や同時実行が設定されるわけではありません。** 会話側での選択可否や実際の利用状態も確認してください。

### すべてのモデルを許可する場合

「すべてのモデルを許可する」を選び、デフォルトモデルを設定します。この場合も、デフォルトの選択は必要です。

ここでの「すべて」は、組織の制限を解除して未提供のモデルまで使えるようにする操作ではありません。無効化されたモデルや実行が停止されたモデルなどは、候補に出ない場合があります。

### モデル選びのポイント

特定モデルを一律に推奨するのではなく、実際に利用できる候補で確認します。

- 必要な形式で回答できるか。
- 日本語や業務用語を適切に扱えるか。
- 利用予定のツールや入力で動作するか。
- 応答速度や利用コストが運用に合うか。

比較するときは、指示とテスト入力をそろえ、モデルだけを変えると差を確認しやすくなります。モデルの詳細な条件・上限は[Agentの仕様・制限](agent-specs-and-limits.md)で扱います。

## 5. 保存結果と利用状態を確認する

名前・説明・指示・モデルを設定したら、保存状態を確認します。

1. 保存処理中の表示が終わることを確認します。
2. **「保存」**が表示されている場合は選び、保存結果を確認します。
3. **「保存済み」**の表示や成功通知を確認します。**「エラー」**や入力エラーがある場合は、その内容を確認して修正します。
4. 保存が完了してから一覧へ戻り、対象Agentを開き直します。
5. 名前・説明・指示・デフォルトモデル・モデルの選択範囲が残っているか確認します。

**自動保存は、作成画面の変更にも適用されます。** 戻る操作や画面を閉じる操作は、すでに作成されたAgentの削除や、保存済み設定の巻き戻しではありません。途中で中止した場合も、Agentの有無と設定を確認してください。

### 「有効」とアクセス権限を分けて確認する

設定画面にはAgentの**「有効」**を切り替える操作があります。作成直後だから必ず無効・非公開になっているとは考えず、現在の状態を確認します。

- **保存状態**：設定が保存されているか。
- **有効／無効**：Agentを利用するための状態が整っているか。
- **アクセス権限**：誰が利用・編集できるか。

これらは別の確認です。有効にすることを「全員へ公開する操作」、保存することを「自分だけの下書き保存」とは扱わないでください。利用前に、表示されるアクセス権限や管理担当者の案内で、意図した範囲になっているか確認します。

保存エラーが出た場合は、繰り返し別のAgentを作成する前に、対象Agentがすでに存在するか確認してください。必要な入力内容を保全し、エラー表示と保存先を確認します。

## 6. 小さな入力で最初の応答を確認する

設定を保存し、対象Agentが有効で、自分に利用権限があることを確認してから、プレビューなどの利用可能な会話入口で試します。

テスト入力の例：

> 次の商談メモを整理してください。
> サンプル商事では、問い合わせの振り分けを担当者が手作業で行っています。
> 問い合わせ分類を整理したいという相談がありました。
> 予算、導入日、決裁者は確認できていません。
> 外部への送信やデータ更新はせず、メモだけ返してください。

次の点を確認します。

- 指定した4つの見出しで出力されるか。
- メモにある事実と質問案が区別されているか。
- 予算・導入日・決裁者を勝手に補っていないか。
- 外部資料を読んだ、更新したなどと根拠なく記載していないか。
- 対象Agentと使用モデルを取り違えていないか。

プレビューが使えない場合は、保存状態、有効／無効、利用権限、画面のエラーを確認します。表示させるためだけに共有範囲を広げないでください。

最初の1回の成功は、本番利用の承認やすべての入力に対する品質保証ではありません。ここでは基本設定と初回動作を確認し、複数の入力による検証・改善は[Agentをテストして改善する](test-and-improve-agents.md)で進めます。

## うまくいかないとき

| 状況 | 確認・対応 |
|---|---|
| 作成ボタンが使えない | 対象Project、作成権限、契約・機能設定、作成上限と画面の案内を確認する |
| 希望するモデルが候補にない | 組織での提供・有効化・実行可否を確認する。モデル名を指示に書いて代用しない |
| デフォルトモデルを外せない | 別のモデルを追加してデフォルトへ変更してから、元のモデルを外す |
| 変更が保存されない | 入力エラー、保存状態、権限、通信状況を確認する。下書きを保全し、重複作成を避ける |
| プレビューが使えない | Agentの保存・有効状態と、自分の利用権限を確認する |
| 指示どおりの回答にならない | 指示の矛盾、保存内容、選択したAgent・モデル、会話の前提を確認する |
| 資料や外部サービスを使わない | 指示とは別に、参照設定・ツール・接続・権限を確認する |

問い合わせには、組織名、Project名、Agent名、操作日時、エラー表示、期待した結果を添えます。認証情報や機密データは含めないでください。
