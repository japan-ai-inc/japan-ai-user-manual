# 画面からPageを登録・公開する

作成したPageのソースをZIPファイルで登録し、Page一覧・画面表示・アクセス設定を確認して、利用者に提供できる状態にします。この記事では、**ソースを準備する → Pageとして登録する → 表示を確認する → 必要に応じてアクセス設定を保存する → 利用者の入口で確認する**流れを説明します。

AIに画面作成を依頼した場合も、依頼の完了と利用者向けの登録・公開は別の確認です。AIによる作成・修正とプレビューの確認は、[AIにPageの作成・修正を依頼する](ask-ai-to-build-pages.md)を参照してください。

## 始める前に

- 対象の組織・Projectと、登録するPageの用途、利用者、公開するタイミングを確認します。
- PageのソースをZIPファイルとして準備します。ソースの構成、対応条件、容量などの詳細は、[Pageの仕様・制限](page-specs-and-limits.md)で確認してください。
- 対象ProjectでPageを登録・編集できる権限があることを確認します。権限や組織の機能設定によっては、「ZIPをアップロード」やカードのメニューを選択できません。
- 表示確認に使う検証用データ、確認する操作、問題が起きたときの連絡先を決めます。登録・更新・外部送信を行う画面では、実行の影響も確認します。
- 同名のPageがないか、更新なのか新規登録なのかを確認します。同名の場合は、新しいPageを作成するのではなく既存Pageの新しいバージョンとして適用する確認画面が表示されます。

> ZIPを登録しただけで、画面内の業務処理、データ取得、外部連携が正しく動くとは限りません。Pageを開く確認と、利用者が行う操作の確認を分けて実施してください。

## 1. 登録前の確認をする

登録する前に、ソースと公開後の影響を確認します。

| 確認項目 | 確認する内容 |
|---|---|
| 対象 | 正しい組織・Project・Page名か。新規か既存Pageの更新か |
| ソース | 登録するZIPが意図した版か。検証済みの内容だけを含むか |
| 表示名 | Page一覧で利用者が区別できる名称か |
| 動作 | 表示、入力、検索、登録、更新、送信など、今回提供する操作を確認したか |
| データ・接続 | 本番データや外部サービスに影響する操作、必要な権限・接続を把握したか |
| 提供範囲 | サインインの要否、案内する相手、URLを共有する条件を決めたか |

機密情報をソース、画面の初期値、ブラウザで参照できる設定に直接含めないでください。Pageを共有する範囲だけでなく、画面から表示・操作できるデータと外部連携の権限も確認します。

> 同名のPageへの登録は、既存Pageの内容に影響します。確認画面で「新しいバージョンを追加」を選ぶ前に、対象のPage名と変更内容を関係者と照合してください。

## 2. ZIPファイルを登録する

1. 対象Projectを開き、「ページ」を開きます。画面に「ZIPをアップロード」が表示されない場合は、権限または利用条件を確認します。
2. 「ZIPをアップロード」を選択します。
3. 「ページをアップロード」画面で、準備したZIPファイルを選択するか、ドロップします。
4. 選択したファイル名を確認し、「アップロード」を選択します。
5. 「ファイルをアップロードしています」と表示されている間は、画面を閉じずに待ちます。画面を閉じるとアップロードはキャンセルされます。
6. 「アップロードが完了しました。」と表示されたことを確認します。
7. 同名のPageが見つかった場合は、表示される説明を確認します。既存Pageを更新してよい場合だけ、「新しいバージョンを追加」を選択します。

登録後、Page一覧を更新し、対象のPageカードが表示されることを確認します。カードにはPage名、最終更新日、適用中のバージョン情報が表示される場合があります。表示情報は、更新対象を取り違えていないか確認する手掛かりとして使います。

### 登録できない場合

| 表示・状況 | 確認・対応 |
|---|---|
| 「ZIPファイルを選択してください。」 | ZIPファイルを選択し直します。 |
| ZIPの構造や展開内容に関するエラー | ソースの書き出し内容を確認し、条件に合うZIPを準備し直します。詳細な条件は[Pageの仕様・制限](page-specs-and-limits.md)を参照してください。 |
| 「別のアップロードが進行中です。」 | 同じPageへの操作が完了するまで待ってから、もう一度試します。 |
| 「アップロードに失敗しました。再度お試しください。」 | 直ちに繰り返さず、対象Page、ファイル、表示メッセージを記録してから再試行します。繰り返す場合は[Pageのビルド・起動・表示に失敗する](../troubleshooting/page-build-start-display-failures.md)を参照します。 |
| 「ページをアップロードする権限がありません」 | ProjectまたはPageの管理担当者に、必要な権限を確認します。 |

## 3. 登録後のPageを開いて確認する

1. Pageカードで、登録したPageの名前と最終更新日を確認します。
2. Pageカード本体を選択して開きます。カードのメニューは、開く操作とは別です。
3. 読み込み表示の後、画面が表示されることを確認します。エラーが表示された場合は、画面の「再試行」を使う前に、業務処理が実行済みでないかを確認します。
4. 「プレビュー」を利用できる場合も含め、利用者が行う代表的な操作を検証用データで確認します。
5. 登録、更新、送信などを行うPageでは、画面上の完了表示だけでなく、保存先または送信先の結果を確認します。

画面を開けることは、必要なデータ・接続・操作権限がすべて利用可能であることを保証しません。利用時の確認方法は、[Pageから業務を進める](../use/work-with-pages.md)を参照してください。

> 表示エラーの「再試行」と、Page内の「登録」「送信」「実行」などの再実行は別の操作です。処理済みか不明な場合は、同じ業務処理を重ねて実行しないでください。

## 4. Page名・アクセス設定を確認する

Pageカードのメニューから、表示名やアクセス条件を確認・変更できます。これらはソースの登録とは別の設定です。

### Page名とサムネイルを整える

1. 対象Pageカードのメニューを開き、「編集」を選択します。
2. 「ページ名」を確認し、利用者が識別できる名称にします。
3. 必要に応じて、アイコンまたは「画像をアップロード」でサムネイルを設定します。
4. 内容を確認して保存し、「保存しました」と表示されることを確認します。

Page名やサムネイルの変更は、Pageのソース内容や画面内の業務処理を確認する代わりにはなりません。変更後も、対象のPageを開いて確認してください。

### 利用者が開く条件を設定する

1. 対象Pageカードのメニューを開き、「アクセス設定」を選択します。
2. 「アクセスモード」で、利用者に必要な条件を選択します。選択肢には「サインイン必須」「サインイン任意」「匿名アクセス」があります。
3. 組織の設定とPageの状態によって「外部顧客認証」が表示される場合は、必要な外部接続を選択します。選べる接続がない、または組織で無効な場合は保存できません。
4. 「保存」を選択し、「アクセス設定を保存しました。」と表示されることを確認します。
5. 「公開URL」または「アクセスURL」が表示される場合は、共有前に対象Pageとアクセス条件を再確認し、必要な相手だけに案内します。

| アクセスモード | 画面上の説明 | 提供前の確認 |
|---|---|---|
| サインイン必須 | サインイン済みで、Pageへのアクセス権が必要です。 | 対象利用者が必要なアカウントと権限を持つか確認します。 |
| サインイン任意 | 誰でもPageを開け、サインイン済みユーザーはそのまま利用できます。 | サインインしていない場合の表示・操作も確認します。 |
| 匿名アクセス | サインインを求めずに、誰でもPageを開けるようにします。 | URLを知る利用者、表示データ、実行できる処理を慎重に確認します。 |
| 外部顧客認証 | 設定済みの顧客IDプロバイダーで訪問者を認証します。 | この選択肢が表示される場合に限り、認証後の表示と利用者用URLを確認します。 |

> 「サインイン任意」や「匿名アクセス」を選ぶと、Studioにサインインしていない利用者にもURLを共有できる場合があります。公開前に、画面に表示される情報、実行可能な処理、必要な外部接続を必ず確認してください。

## 5. 利用者の入口で公開状態を確認する

設定を保存したら、作成者の画面だけでなく、実際に案内する入口で確認します。

1. Page一覧または共有するURLから対象Pageを開きます。
2. 想定したアクセス条件で開けるかを確認します。別の利用者での確認が必要な場合は、権限のある検証担当者に依頼します。
3. Page名、画面表示、代表的な業務操作、結果の確認先を照合します。
4. 利用者へ、Page名、利用目的、URLまたは入口、利用開始時期、問い合わせ先を案内します。
5. 更新後の切り替えや復元が必要になる可能性に備え、登録した内容と確認結果を記録します。バージョンの詳しい管理は[Pageのバージョンを管理する](manage-page-versions.md)で扱います。
