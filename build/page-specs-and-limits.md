# Pageの仕様・制限

Pageは、Project内で利用するWeb画面です。作成者・開発者は、**Pageのソース一式をZIPで登録**します。Studioは登録されたソースに対して依存関係のインストールとビルドを実行し、Pageとして起動します。登録後は、Pageとして開けること、アクセス条件に合うこと、業務処理の結果が正しいことを確認します。ZIPを受け付けたことや画面が一度表示されたことだけで、データ連携・認証・外部送信まで正しく利用できるとは限りません。

登録・公開の画面操作は[画面からPageを登録・公開する](register-and-publish-pages.md)を参照してください。バージョンの作成・適用の手順は、[Pageのバージョンを管理する](manage-page-versions.md)を参照してください。

## 要点

| 項目 | 決まり |
|---|---|
| 登録するもの | 完成済みのビルド成果物ではなく、Pageの**ソース**。ルートに`package.json`とロックファイル、静的なPageなら`index.html`を置きます。 |
| Studioが行うこと | ロックファイルに応じてBun／Node.js／静的配信を選び、依存関係のインストールと`build`スクリプトを実行し、Node.jsまたはBunのサーバーとして起動します。 |
| 拒否されるZIP | Next.jsのビルド成果物をアップロードしたもの、ルートに`package.json`も`index.html`もないもの。 |
| 表示までの時間 | 登録・更新後、初回表示まで数分（最大15分程度）かかることがあります。その間はビルド中の画面、失敗時はビルド失敗の画面が表示されます。 |
| サーバー処理 | `process.env.PORT`で待ち受けます。SSRの最初の応答には約60秒の制限があります。 |
| 秘密値 | ブラウザへ送るファイルに入れません。サーバー側の環境変数として、ルートの`.env`／`.env.production`から`${secret:Secret名}`で参照します。 |

## この記事の範囲

この記事は、StudioからZIPを登録するPageについて、登録時に確認される条件、ビルドと実行の条件、アクセスモード、バージョン、上限をまとめます。個別Pageの画面設計、データ操作、外部サービスへの接続設定、サーバー処理の作り方は対象外です。ソースの構成やフレームワークの設定（basePathなど）は[Pageのソース構成とランタイム](../development/page-source-structure-and-runtime.md)、サーバー処理と環境変数は[Pageのサーバー処理・環境変数・Secret参照](../development/page-server-env-and-secrets.md)を参照してください。

## 仕様

| 項目 | 仕様 | 補足 |
|---|---|---|
| 登録する形式 | 「ZIPをアップロード」では、ZIPファイルを1件選びます。ZIP以外、複数選択は受け付けられません。 | ファイル名の拡張子とZIPの形式が確認されます。 |
| ZIPの中身 | Pageのソース一式を入れます。ルートに`package.json`とロックファイル（Node.js／Bunのプロジェクト）、または`index.html`（静的なPage）が必要です。どちらもない場合は登録できません。 | Next.jsの`next build`などで生成したビルド成果物をアップロードすると拒否されます。ビルドはStudio側で実行されるため、ソースを登録してください。 |
| ZIP内のファイル | ZIP内の通常ファイルがPageのファイルとして扱われます。パスに現在・親ディレクトリを表す要素が含まれるZIPは、構造エラーになります。 | 親フォルダーが1つだけで、その配下に全ファイルがあるZIPは、親フォルダーを除いた構成として扱われます。不要な親フォルダーを重ねないようにしてください。 |
| 登録対象外の内容 | `__MACOSX`、`node_modules`、`.git`、`.DS_Store`、`.jai-studio`、`__staging`、`__upload-lock.json`、`__backup`、`__versions`を含むパスは登録対象から除外されます。さらに、ZIPの最上位（単一の親フォルダーで包むZIPではその直下）の`.next`、`dist`、`build`、`out`、`.cache`、`coverage`、`.turbo`、`.vercel`、`tmp`、`temp`も除外されます。 | 依存関係とビルド出力はStudio側で作られるため、`node_modules`やビルド出力フォルダーをZIPに含める必要はありません。 |
| 空または無効なZIP | ZIPが完全に空の場合は「ZIPファイルに有効なファイルが含まれていません。」と表示されます。ファイルがすべて除外対象のフォルダーにある場合は「ZIPファイルの構造が正しくありません」と表示されます。 | ZIPの最上位にソースが置かれているか確認し、作り直します。 |
| Page名 | 新規登録時のPage名は、ZIPファイル名から拡張子を除いた文字列を基にします。 | 同名のPageが1件見つかり、更新権限がある場合は、確認後に「新しいバージョンを追加」として登録します。表示名を変更しても、登録済みのファイル内容は変わりません。 |
| ランタイムとビルド | ロックファイルに応じてBun、Node.js、静的配信のいずれかが選ばれます。Node.js／Bunのプロジェクトでは、依存関係のインストールと`package.json`の`build`スクリプトが実行され、Node.jsまたはBunのサーバーとして起動します。 | 登録・新しいバージョンの適用のたびにビルドが行われます。ビルド中は専用の画面が表示され、初回表示まで数分（最大15分程度）かかることがあります。ビルドに失敗するとビルド失敗の画面が表示されます。 |
| サーバー処理の実行条件 | サーバーは`process.env.PORT`で指定されたポートで待ち受けます。`PORT`、`NODE_ENV`、`PRS_*`などの予約キーは、Pageの環境変数として渡されません。`/api/v1/*`や`/api/storage`などのパスはプラットフォームが使用します。 | SSRの最初の応答には約60秒の制限があります。 |
| 静的なPage | `index.html`をルートに置いたPageは静的に配信されます。 | 存在しないパスへのアクセスは`index.html`にフォールバックし、`<base href>`は自動で挿入されます。 |
| ブラウザで動く部分 | 画面用のファイル（HTML、JavaScript、CSS、初期表示データなど）は、利用者のブラウザに届く前提で扱います。 | パスワード、APIキー、トークン、Project Secretの値を含めないでください。公開範囲にかかわらず同じです。 |
| 環境変数と`.env` | 直接アップロードしたPageでは、ルートの`.env`と`.env.production`だけが読まれます。それ以外の`.env.*`は無視されます。 | 環境変数はサーバー側の処理で`process.env`から読みます。 |
| Project Secret | `.env`に`${secret:Secret名}`と書くと、同じProjectの同名のProject Secretがそのまま解決され、サーバー側の環境変数として渡されます。直接アップロードでは、Secretを紐づける画面はありません。 | Project Secretを読めるのは、Pageのサーバー環境変数とAPI呼び出しノードだけで、Agentからは読めません。接頭辞による拒否や「シークレットを選択」の操作は、Appの公開・インストールの流れにだけあります。**Secret値をブラウザへ返す、画面に表示する、ブラウザ側の変数・ログ・配布ファイルに入れる処理は行わないでください。**詳しくは[Pageのサーバー処理・環境変数・Secret参照](../development/page-server-env-and-secrets.md)と[Project Secretを登録・更新・削除する](../operations/manage-project-secrets.md)を参照してください。 |
| アクセスモード | 「アクセス設定」では「サインイン必須」「サインイン任意」「匿名アクセス」を選べます。組織の設定とPageの状態によっては「外部顧客認証」も表示されます。 | 「サインイン必須」はサインインとPageへのアクセス権が必要です。「サインイン任意」と「匿名アクセス」は誰でもPageを開けるため、表示データと実行できる処理を個別に確認します。外部顧客認証は、設定済みの顧客IDプロバイダーを使う場合だけ選択できます。接続は少なくとも1件、最大の件数は画面で提示される範囲で設定します。 |
| 共有URL | 「サインイン任意」「匿名アクセス」では公開URLが表示されます。外部顧客認証ではアクセスURLが表示されます。 | 公開URLは`/p/{token}`の形式です。`/app/...`のURLを組み立てたリンクは正しく機能しないため、画面に表示されたURLを使ってください。URLを知る人が到達できる前提で、利用者、表示情報、実行権限を確認してから案内します。 |
| バージョン | 新規登録時に最初のバージョンが作られます。新しいZIPを既存Pageへ登録すると、現在のPageコンテンツが新しい版に切り替わります。過去版は「復元して適用」で再度適用できます。 | 現在のPageは常に1つの「適用中」の版を参照します。名前・説明の編集はコンテンツを切り替えません。詳細な手順は[Pageのバージョンを管理する](manage-page-versions.md)で確認してください。 |

## 上限・制限値

| 対象 | 上限・制限値 | 条件 |
|---|---:|---|
| ZIPファイルのサイズ | 100MB以下 | 「ZIPをアップロード」と「新しいバージョンをアップロード」の両方で、圧縮後のZIPに適用されます。100MBを超えると登録できません。 |
| ZIPエントリ数 | 5,000件以下 | ファイルとフォルダーの合計です。ZIPの中央ディレクトリの件数と、展開処理時の件数の両方で確認されます。 |
| 展開後の合計サイズ | 200MB以内 | 登録対象として展開されるファイルの合計です。ZIP圧縮後のサイズとは別に確認されます。 |
| 同時に選べるZIP | 1件 | アップロード画面で選択できるファイル数です。複数のZIPをまとめて登録することはできません。 |
| 初回表示までの時間 | 最大15分程度 | 登録・更新後のインストールとビルドを含みます。この間はビルド中の画面が表示されます。 |
| SSRの最初の応答 | 約60秒 | サーバーを起動してから最初の応答を返すまでの制限です。 |
| 組織のPage数 | 組織単位の上限あり | Page一覧画面の使用量バーに、現在の数と上限が表示されます。 |
| Project Secret名 | 64文字以下 | 先頭は英小文字、以後は英小文字・数字・アンダースコアだけを使います。空文字、UUID形式の名前は受け付けられません。 |
| Project Secret値 | 8,192文字以下 | 空の値は登録・更新できません。値は画面の一覧・詳細でマスクされます。 |
| Pageの環境変数の値 | 1値あたり4,096バイト以下 | Project Secretとして保存できる値でも、4,096バイトを超えるとPageの起動時に失敗します。日本語などのマルチバイト文字は1文字が複数バイトになります。 |

## よくある誤解

### ローカルでビルドした成果物をZIPにして登録する

逆です。Studioが登録されたソースに対してインストールとビルドを実行します。ルートに`package.json`とロックファイル（静的なPageなら`index.html`）を置いたソースをZIPにします。Next.jsのビルド成果物をアップロードすると拒否されます。

### サインイン任意と匿名アクセスは同じである

どちらも誰でもPageを開ける選択肢ですが、画面上の説明は異なります。サインイン任意ではサインイン済みの利用者はそのまま利用し、匿名アクセスではサインインを求めません。いずれも公開URLを共有する前に、Page内に表示される情報と実行できる操作を確認します。

### Secretを隠した変数名にすればクライアント側に置いてよい

変数名を変えても、ブラウザへ送られた値は利用者や開発者ツールから取得され得ます。Secret値は`.env`の`${secret:Secret名}`でサーバー側の環境変数として受け取り、配布物、ブラウザ用設定、画面、ログに含めないでください。Project Secretの管理画面で値がマスクされることと、Page側で値を露出しないことは別の確認です。

### 新しい版をアップロードしたら、すぐに利用者へ案内してよい

アップロード後にはインストールとビルドが実行され、表示まで最大15分程度かかることがあります。ビルドが成功しても、認証・データ取得・更新・外部送信の成功までは保証されません。適用中の版を確認したうえで、想定した権限・利用者の入口から代表操作と結果を検証してください。

## うまくいかない場合

次のような場合は、推測してZIPを作り替えたり、公開設定を緩めたりしないでください。

- ZIPの構造、容量、エントリ数、展開後サイズに関するエラーが出る。
- ビルド失敗の画面が表示される、または15分程度を過ぎてもビルド中の画面のままになる。
- 登録後に白い画面、読み込みエラー、必要なファイルの読み込み失敗が起きる。
- アクセスモードの選択肢、公開URL、外部顧客認証が表示されない。
- Secretを必要とする処理を安全に設定する方法が分からない。
- 適用中の版、Page名、対象Project、実行結果が分からない。

対象の組織・Project・Page名、ZIPファイル名、発生日時、表示メッセージ、再現手順、確認済みの操作を記録します。Secret値、パスワード、APIキー、トークン、認証情報を問い合わせに添付しないでください。ビルド・表示の対応は[Pageのビルド・起動・表示に失敗する](../troubleshooting/page-build-start-display-failures.md)、Secretの設定は[Project Secretを登録・更新・削除する](../operations/manage-project-secrets.md)を参照します。
