# Pageの仕様・制限

Pageは、Project内で利用するWeb画面です。作成者・開発者は、ブラウザで動作する画面ファイルをZIPで登録し、登録後にPageとして開けること、アクセス条件に合うこと、業務処理の結果が正しいことを確認します。ZIPを受け付けたことや画面が一度表示されたことだけで、データ連携・認証・外部送信まで正しく利用できるとは限りません。

登録・公開の画面操作は[画面からPageを登録・公開する](register-and-publish-pages.md)を参照してください。バージョンの作成・適用の手順は、[Pageのバージョンを管理する](manage-page-versions.md)を参照してください。

## この記事の範囲

この記事は、StudioからZIPを登録するPageについて、登録時に確認される条件、アクセスモード、バージョン、および確認済みの上限をまとめます。個別Pageの画面設計、データ操作、外部サービスへの接続設定、サーバー処理の作り方は対象外です。

提供条件は組織の機能設定、権限、Pageの種類によって変わります。ここに書かれていないパッケージ管理、特定フレームワーク、ビルドコマンド、実行時間、通信量の上限を、利用可能または不可能と断定しません。

## 仕様

| 項目 | 仕様 | 補足 |
|---|---|---|
| 登録する形式 | 「ZIPをアップロード」では、ZIPファイルを1件選びます。ZIP以外、複数選択は受け付けられません。 | ファイル名の拡張子とZIPの形式が確認されます。登録前に、配布する成果物だけをZIPにまとめてください。 |
| ZIP内のファイル | ZIP内の通常ファイルがPageのファイルとして扱われます。パスに現在・親ディレクトリを表す要素が含まれるZIPは、構造エラーになります。 | 親フォルダーが1つだけで、その配下に全ファイルがあるZIPは、親フォルダーを除いた構成として扱われます。不要な親フォルダーを重ねないようにしてください。 |
| 登録対象外の内容 | `__MACOSX`、`node_modules`、`.git`、`.DS_Store`、`.jai-studio`、`__staging`、`__upload-lock.json`、`__backup`、`__versions`を含むパスは登録対象から除外されます。さらに、ZIPの最上位（単一の親フォルダーで包むZIPではその直下）の`.next`、`dist`、`build`、`out`、`.cache`、`coverage`、`.turbo`、`.vercel`、`tmp`、`temp`も除外されます。 | 除外される名称に依存して配布内容を構成しないでください。登録後は必ず実際のPageを開き、必要なHTML、JavaScript、CSS、画像などが読めることを確認します。Pageのソース領域に生成される設定・キャッシュなどの一時ファイルは、ZIPへ含める成果物として扱わないでください。 |
| 空または無効なZIP | ZIPが空、または除外後に登録できるファイルがない場合は登録できません。 | 「ZIPファイルに有効なファイルが含まれていません。」または構造に関するメッセージを確認し、成果物を作り直します。 |
| Page名 | 新規登録時のPage名は、ZIPファイル名から拡張子を除いた文字列を基にします。 | 同名のPageが1件見つかり、更新権限がある場合は、確認後に「新しいバージョンを追加」として登録します。表示名を変更しても、登録済みのファイル内容は変わりません。 |
| 実行・ビルド | StudioへのZIP登録は、ZIPを展開してファイルを配置する処理です。登録画面で任意の依存関係インストールや任意のビルドコマンドを指定する項目は確認できません。 | ローカルで必要な成果物を作成してから登録します。新しいバージョンの適用後にはPageの再ビルド要求が行われますが、完了表示だけで画面や業務処理の正常性を保証するものではありません。 |
| ブラウザで動く部分 | ZIPに含める画面用ファイルは、利用者のブラウザに届く前提で扱います。 | HTML、JavaScript、設定ファイル、初期表示データに、パスワード、APIキー、トークン、Project Secretの値を含めないでください。公開範囲にかかわらず同じです。 |
| Project Secret | Project SecretはProject単位で管理する機密値です。作成・参照・更新・削除にはそれぞれ権限が必要で、機能が有効な組織でのみ管理できます。値は暗号化して保存され、管理画面の一覧・詳細では実値ではなくマスク値が返ります。 | ZIPを登録する通常のPage登録処理には、Secret名や値を指定する入力はありません。**Secret値をブラウザへ返す、画面に表示する、ブラウザ側の変数・ログ・配布ファイルに入れる処理は行わないでください。**Pageからの安全な参照方式、サーバー処理への受け渡し、必要な設定は本記事の範囲外です。[Pageのサーバー処理・環境変数・Secret参照](../development/page-server-env-and-secrets.md)および[Project Secretを登録・更新・削除する](../operations/manage-project-secrets.md)で確認してください。 |
| アクセスモード | 「アクセス設定」では「サインイン必須」「サインイン任意」「匿名アクセス」を選べます。組織の設定とPageの状態によっては「外部顧客認証」も表示されます。 | 「サインイン必須」はサインインとPageへのアクセス権が必要です。「サインイン任意」と「匿名アクセス」は誰でもPageを開けるため、表示データと実行できる処理を個別に確認します。外部顧客認証は、設定済みの顧客IDプロバイダーを使う場合だけ選択できます。接続は少なくとも1件、最大の件数は画面で提示される範囲で設定します。 |
| 共有URL | 「サインイン任意」「匿名アクセス」では公開URLが表示される場合があります。外部顧客認証ではアクセスURLが表示される場合があります。 | URLを知る人が到達できる前提で、利用者、表示情報、実行権限を確認してから案内します。URL共有は、Page内のデータ操作を安全にする代わりにはなりません。 |
| バージョン | 新規登録時に最初のバージョンが作られます。新しいZIPを既存Pageへ登録すると、現在のPageコンテンツが新しい版に切り替わります。過去版は「復元して適用」で再度適用できます。 | 現在のPageは常に1つの「適用中」の版を参照します。名前・説明の編集はコンテンツを切り替えません。詳細な手順は[Pageのバージョンを管理する](manage-page-versions.md)で確認してください。 |

## 上限・制限値

次表は、登録処理または画面表示で値を確認できたものだけです。契約・組織ごとのPage数上限は機能制限として判定されますが、この時点で一律の数値を確認できないため、表には載せません。

| 対象 | 上限・制限値 | 条件 |
|---|---:|---|
| ZIPファイルのサイズ | 100MB以下 | 「ZIPをアップロード」と「新しいバージョンをアップロード」の両方で、圧縮後のZIPに適用されます。100MBを超えると登録できません。 |
| ZIPエントリ数 | 5,000件以下 | ファイルとフォルダーの合計です。ZIPの中央ディレクトリの件数と、展開処理時の件数の両方で確認されます。 |
| 展開後の合計サイズ | 200MB以内 | 登録対象として展開されるファイルの合計です。ZIP圧縮後のサイズとは別に確認されます。 |
| 同時に選べるZIP | 1件 | アップロード画面で選択できるファイル数です。複数のZIPをまとめて登録することはできません。 |
| Project Secret名 | 64文字以下 | 先頭は英小文字、以後は英小文字・数字・アンダースコアだけを使います。空文字、UUID形式の名前は受け付けられません。 |
| Project Secret値 | 8,192文字以下 | 空の値は登録・更新できません。値は画面の一覧・詳細でマスクされます。 |

## よくある誤解

### ZIPをアップロードすればStudioが任意の開発環境でビルドしてくれる

確認できる登録処理は、ZIPのサイズ・構造・展開内容を検査し、ファイルを配置するものです。任意のパッケージマネージャー、言語ランタイム、ビルドコマンドを選ぶ機能は確認できません。必要な成果物を作成したうえで登録し、実際に開いて確認してください。

### サインイン任意と匿名アクセスは同じである

どちらも誰でもPageを開ける選択肢ですが、画面上の説明は異なります。サインイン任意ではサインイン済みの利用者はそのまま利用し、匿名アクセスではサインインを求めません。いずれも公開URLを共有する前に、Page内に表示される情報と実行できる操作を確認します。

### Secretを隠した変数名にすればクライアント側に置いてよい

変数名を変えても、ブラウザへ送られた値は利用者や開発者ツールから取得され得ます。Secret値を配布物、ブラウザ用設定、画面、ログに含めないことが必要です。Project Secretの管理画面で値がマスクされることと、Page側で値を露出しないことは別の確認です。

### 新しい版をアップロードしたら、すぐに利用者へ案内してよい

アップロード後には再ビルド要求が行われますが、表示・認証・データ取得・更新・外部送信の成功までは確認していません。適用中の版を確認したうえで、想定した権限・利用者の入口から代表操作と結果を検証してください。

## 確認できない場合

ブラウザへSecret値を渡さないためのPage記述の完全な要件、対応するサーバーランタイムの全体像、利用できる言語・フレームワーク・パッケージマネージャー・ビルドコマンド、実行時間・通信量・組織別のPage数の一律上限は本記事では扱いません。これらを本記事の仕様として扱わないでください。

次のような場合は、推測してZIPを作り替えたり、公開設定を緩めたりしないでください。

- ZIPの構造、容量、エントリ数、展開後サイズに関するエラーが出る。
- 登録後に白い画面、読み込みエラー、必要なファイルの読み込み失敗が起きる。
- アクセスモードの選択肢、公開URL、外部顧客認証が表示されない。
- Secretを必要とする処理を安全に設定する方法が分からない。
- 適用中の版、Page名、対象Project、実行結果を確定できない。

対象の組織・Project・Page名、ZIPファイル名、発生日時、表示メッセージ、再現手順、確認済みの操作を記録します。Secret値、パスワード、APIキー、トークン、認証情報を問い合わせに添付しないでください。ビルド・表示の対応は[Pageのビルド・起動・表示に失敗する](../troubleshooting/page-build-start-display-failures.md)、Secretの設定は[Project Secretを登録・更新・削除する](../operations/manage-project-secrets.md)を参照します。
