# Objectの仕様・制限

Objectは、業務データを「レコード」と「フィールド」で管理する機能です。作成前に、名前の付け方、フィールド型、入力条件、リレーション、CSVによるデータ操作の条件を確認しておくと、運用開始後の修正や取込エラーを減らせます。

この記事は、Objectの構造とデータ操作の仕様・制限をまとめたリファレンスです。設計と作成は[Objectの構造を設計する](design-object-structure.md)、日常のレコード操作は[Objectのデータを閲覧・更新する](../use/view-and-update-object-records.md)を参照してください。

## この記事の範囲

ここでは、標準のObject画面で確認できる次の内容を扱います。

- Object名・フィールド名、表示名、説明の入力条件
- 「フィールド型」「任意入力を許可」「ユニーク制約」「バリデーションルール」などの構造上の制約
- 「リレーション」と参照先の条件
- レコードの表示、CSVの「エクスポート」「CSVからインポート」、削除に関する確認事項
- 画面で選択できる件数・ページ・ルールの上限

契約プランごとの提供条件、個別環境で有効な機能、外部API・SQLからの詳細な利用条件はここでは確定しません。画面に表示されない機能は、権限または組織・Projectの設定によって利用できない場合があります。

## 基本仕様

| 項目 | 仕様 | 補足 |
|---|---|---|
| Object名 | 必須です。先頭は英字にし、英数字とアンダースコアを使えます。スペース、アンダースコア以外の記号は使えません。 | Objectを識別する名称です。既存のObjectと同じ名前は使えません。 |
| 表示名 | 画面に表示する名称です。 | Objectとフィールドのどちらにも設定できます。利用者に分かる業務用語を使います。 |
| 説明 | Objectの用途を記載できます。 | フィールドの「説明」には、値の意味や入力時の注意を記載します。AIエージェントがフィールドを理解するためにも使用されます。 |
| フィールド名 | 必須です。先頭は英字にし、英数字とアンダースコアを使えます。スペース、アンダースコア以外の記号は使えません。 | 同じObject内では同じフィールド名、および同じ表示名のフィールドは作成できません。 |
| フィールド型 | 「テキスト」「数値」「真偽値」「日時」「配列」「JSON」「自動採番」を選べます。 | 「自動採番」は数値フィールドとして扱われます。型は、保存したい値の意味に合わせて選択します。 |
| 「任意入力を許可」 | オンでは空欄を許可し、オフでは必須フィールドになります。 | 既存レコードに空欄がある場合、必須への変更はできません。 |
| 「ユニーク制約」 | レコード間で値が重複しないようにします。 | 既存レコードに重複値がある場合は設定できません。利用前に重複を解消します。 |
| デフォルト値 | 型に合う値を設定できます。 | 「現在時刻を自動取得」は、レコード追加時に時刻を入力します。 |
| 「自動採番」 | 1から開始し、レコード追加時に常に1ずつ増えます。手動編集はできません。 | 削除済みの番号は再利用されません。 |
| 最大文字数 | 「テキスト」型のフィールドだけに設定できます。 | 数値型などには設定できません。文字列の長さを制限したい場合に使います。 |
| 数値の下限・上限 | 「数値」型のフィールドだけに設定できます。下限は上限以下にします。 | 範囲外の既存データがあると、範囲の変更はできません。 |
| 「バリデーションルール」 | 文字数制限、数値範囲、正規表現、許可する値、配列要素数、日時範囲、カスタムを組み合わせて設定できます。 | 型に対応しないルールは設定できません。同じ種類のルールは1つだけです。 |

## リレーションの仕様

「リレーション」は、別のObjectのレコードに紐付けるための設定です。参照先オブジェクトと参照先フィールドの両方を選択する必要があります。

| 項目 | 仕様 | 補足 |
|---|---|---|
| 参照先フィールド | 「ユニーク制約」のあるフィールドだけを選択できます。 | 同じ値を複数のレコードが持つフィールドは参照先にできません。安定した識別子を用意してください。 |
| 型 | 参照先のデータ型と一致している必要があります。 | 参照元と参照先で異なる型を組み合わせることはできません。 |
| 使用できない型 | 「配列」と「JSON」はリレーションに使用できません。 | 複数値や任意構造を持つフィールドを参照先・参照元にしたい場合は、構造を見直します。 |
| 「ユニーク制約」との併用 | 同じフィールドに「ユニーク制約」と「リレーション」は同時に設定できません。 | 参照する側のフィールドに一意性が必要か、別フィールドへ分けるべきかを検討します。 |

リレーションを設定しても、参照先の閲覧・更新権限が自動で付与されるわけではありません。参照元と参照先の「アクセス設定」をそれぞれ確認してください。

## 上限・制限値

次の数値は、実装で確認できる値だけを示します。数値の記載がない項目は、この資料では上限を断定しません。

| 対象 | 上限・制限値 | 条件・注意 |
|---|---:|---|
| Object名・Objectの表示名・フィールド名・フィールドの表示名 | 255バイト | UTF-8のバイト数です。日本語など複数バイトの文字では、文字数と一致しません。 |
| Objectの説明 | 1,000バイト | UTF-8のバイト数です。 |
| テキスト型フィールドの「最大文字数」 | 1〜65,535 | 整数で指定します。「テキスト」型だけが対象です。 |
| レコード一覧の表示件数 | 30、50、100件／ページ | 標準のObject画面の選択肢です。未指定・不正な値は30件になります。CSV出力の上限とは別です。 |
| CSVの「CSVからインポート」 | 1回につき1,000レコードまで | ヘッダー行を除く件数です。CSV形式で、ヘッダーが現在のフィールド構成・順序と一致する必要があります。 |
| CSV取込・出力時の内部処理単位 | 1,000レコード | CSV出力は次のカーソルがある間、1,000件ずつ取得します。出力全体を1,000件に制限する値ではありません。 |
| レコードのアクセスルール | 1 Objectあたり最大100個の原子ルール | 画面上の1つのルールグループが複数の原子ルールに展開される場合があります。新規作成で合計100個を超えると拒否されます。 |
| レコードの変更履歴一覧 | 1〜200件／取得 | 履歴が利用できるObjectでの1回の取得件数です。画面上の保存期間を示す値ではありません。 |
| レコードのアクセスルールの優先度 | 1以上の整数 | 小さい値が優先されます。上限100という一律の入力制限は確認できません。 |
| レコードのアクセスルールの条件 | 1〜20件／ルール | UI経由の作成・更新に適用されます。 |
| レコードのアクセスルールの割り当て対象 | 1〜200件／ルール | 「ロール」「メンバー」「エージェント」から選択します。 |

既存の「レコードのアクセスルール」を編集するときは、現在のフィールド定義を読み込んでから条件を確認します。保存済みの条件を画面で表現できない場合は、条件部分が読み取り専用で表示されることがあります。この場合は、条件を推測して作り直さず、対象フィールドとルールを確認し、必要に応じて一覧を開き直してから編集します。

## データ操作の仕様

### CSVの「エクスポート」と「CSVからインポート」

「エクスポート」は、閲覧権限があるObjectで利用できます。出力するCSVには先頭列として「レコード ID」が含まれ、その後にフィールドの表示名（表示名がない場合はフィールド名）が並びます。値にカンマ、二重引用符、改行が含まれる場合はCSV用にエスケープされます。

「CSVからインポート」は、Objectを更新できる権限が必要です。CSVファイルのみ選択でき、空行は除外して読み込みます。ヘッダーは、現在のフィールド構成と**列数・順序・名称が完全に一致**している必要があります。テンプレートに含まれる「レコードID」列を使うと、既存のレコードを識別して更新できます。IDがない場合でも、ユニークなフィールドの値で既存レコードを一意に特定できると更新対象になります。特定結果が矛盾する行は取り込まれません。

取込時には、必須、フィールド型、ユニーク制約などが行ごとに確認されます。取込結果の作成・スキップ・失敗の件数と、該当行を確認してください。入力値やフィールド構成を直してから再取込し、同じデータを重複登録しないようにします。

### 削除と復元

Object、フィールド、レコードの削除には、それぞれの削除権限が必要です。フィールドを削除すると、そのフィールドに保存されているレコードのデータも削除されます。削除する前に、CSVでの出力、参照中のPage・Agent・Workflow、リレーション、業務上必要な履歴への影響を確認してください。

画面には「ゴミ箱へ移動」と「完全に削除」の案内が表示される場合があります。「ゴミ箱へ移動」では、30日後に完全に削除され復元できなくなる案内です。フィールド単体の復元は利用できません。

## よくある誤解

### 表示名に日本語を使えるなら、フィールド名にも使える

表示名は利用者向けの名称です。一方、フィールド名とObject名は英字で始め、英数字とアンダースコアだけで付けます。画面用の分かりやすい名称は「表示名」に設定してください。

### リレーションを設定すれば、参照先のデータを誰でも見られる

リレーションはデータを紐付ける設定です。アクセス権を引き継ぐ設定ではありません。参照先のObject・フィールド・レコードを閲覧または更新できるかは、別途「アクセス設定」で決まります。

### 「自動採番」は削除した番号を詰め直す

「自動採番」は削除済み番号を再利用しません。番号に欠番があっても異常ではありません。連続した帳票番号など、別の運用要件がある場合は管理方法を事前に検討してください。

### CSVの出力は画面に表示しているページだけが対象

「エクスポート」は、画面の30・50・100件という表示件数とは別に、ページをたどってレコードを出力します。一方で「CSVからインポート」は1回あたりのレコード数に上限があります。

### 削除したフィールドはいつでも元に戻せる

フィールド単体の復元は利用できません。フィールドを削除すると保存済みの値にも影響します。不要な列を非表示にしたいだけの場合は、表示フィールドの設定を使い、フィールド削除を選ばないでください。

## 確認できない場合

画面にボタンや設定が表示されない、取込・出力・削除・復元ができない場合は、次を順に確認します。

1. 対象のProject、Object、レコードを取り違えていないか確認します。
2. 自分に必要な閲覧・作成・更新・削除・管理の権限があるか、Project管理者または組織の管理者に確認します。
3. ObjectがAppから提供されている場合は、構造を変更できる対象か確認します。
4. CSVでは、最新のテンプレートを出力し、ヘッダー、列順、必須項目、型、1回のレコード数を見直します。
5. 制約を変更できない場合は、既存レコードの空欄、重複、文字数、数値範囲など、表示された検証結果を解消します。
6. 削除後の対応が必要な場合は、削除対象、削除日時、必要なレコード、エラー表示を添えて管理者に相談します。削除前に、業務への影響を確認してください。

問い合わせ時は、ProjectとObjectの名称、操作した日時、対象を識別できる情報、エラーメッセージ、CSVならヘッダーを共有します。個人情報や機密情報を含む値・ファイルは必要以上に共有しないでください。
