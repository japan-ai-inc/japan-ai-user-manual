# 既存リソースをリンク・解除する

すでに組織または公式で用意されているリソースをProjectで使うときは、**コピーを作るのではなく、元のリソースへのリンクを追加する**方法があります。この記事では、リンクで何が共有されるか、コピーとの違い、Projectからリンクを解除する手順と確認事項を説明します。

リンクできる画面・種別は組織の機能提供や権限によって異なります。現行の画面では、エージェント、ワークフロー、ナレッジ（Datasetを含む）、スキルを選択できます。Object、Storage、Pageなども同じ手順でリンクできるとは限りません。

- DatasetをProject内で新規に準備する方法：[Datasetを準備して参照させる](prepare-and-reference-datasets.md)
- Workflowを自分のProjectで構成する方法：[Workflowのノードを構成する](configure-workflow-nodes.md)
- Agentの設定を行う方法：[Agentを作成して指示・モデルを設定する](create-agent-instructions-and-models.md)

## リンク・コピー・削除の違い

まず、目的に合う操作を選びます。特に「Projectに見えるようにする」ことと、「別の編集可能な作業用コピーを作る」ことを混同しないでください。

| 操作 | 作られるもの | 元のリソースとの関係 | Project内での扱い |
|---|---|---|---|
| リンク（画面上は「追加」） | 元への参照 | 元はそのまま残る。更新の反映範囲・時点はリソース種別ごとに確認する | リンク元のリソースは読み取り専用。元の場所で編集する |
| コピー | 新しいリソース | 元とは別のリソースになる | コピー後の変更が元へ反映されるとは限らない。少なくともWorkflowの「コピー」は新しいWorkflowを作成する操作 |
| リンク解除（画面上は「リソースの削除」） | Projectからの参照を削除 | **元のリソースには影響しない** | このProjectからアクセスできなくなる。元を削除する操作ではない |

リンクは、同じリソースを複数のProjectで使いたい場合に適しています。一方、Projectごとに設定や構成を変えたい場合は、リンク元を更新すると他のリンク先にも影響し得るため、リンクのまま変更を始めないでください。対象機能に「コピー」がある場合も、コピーされる設定の範囲を確認してから使います。

> **リンクは独立した複製ではありません。** Project内で「読み取り専用」と表示されたリソースを編集したい場合は、Project外の元のリソースを開いてください。リンク元の更新を各Projectでいつ・どこまで利用できるかは、対象のリソース種別で確認してください。

## 始める前に

- 対象の組織、Project、追加したいリソースが正しいことを確認します。
- Projectを更新できる権限があり、対象画面に「追加」が表示されることを確認します。表示されない場合は、権限または組織の機能提供条件を確認してください。
- リンク元の管理者に、更新・廃止・削除の担当者と連絡方法を確認します。
- そのリソースを他のProjectと同じ内容で使いたいのか、Project固有に変更したいのかを決めます。
- Workflowを追加する場合は、使用するAgent・Workflow・Skillなどの依存リソースも確認します。

> 元のリソースの削除は、リンク先が残っていると制限される場合があります。不要になったからといって、元を先に削除しないでください。利用中のProjectを確認し、必要なリンクを解除してから削除の可否を確認します。

## 1. 追加先の種別を開く

1. 対象のProjectを開きます。
2. 追加したい種別の一覧を開きます。たとえば、エージェント、ワークフロー、Dataset、またはスキルの一覧です。
3. 一覧にある既存のProject内リソースと、今回追加したい組織・公式のリソースを区別します。
4. **「追加」**を選び、**「リソースを追加」**を開きます。

「追加」が表示されない、または「追加可能なリソースがありません」と表示される場合があります。対象リソースがすでにProjectに追加されている、対象のスコープではない、無効・削除済みである、または権限・提供条件を満たさない可能性があります。別の画面から同じ結果を得ようとして新規作成や削除を行わず、対象・権限・元の状態を確認してください。

## 2. リンクするリソースを選ぶ

1. **「リソースを追加」**で、必要に応じて種別のタブを選びます。
2. **「リソースを検索...」**で名前を確認し、対象を選択します。
3. 必要に応じて、ソースの表示が**「公式」**または**「組織」**であることを確認します。
4. 複数の候補がある場合は、名前だけでなく用途・管理者・更新状況を確認して選びます。
5. **「追加を確認」**を選びます。

確認画面では、選択したリソースとソースを見直します。エージェントを選んだ場合に表示される**「カスタム設定もインポート」**は、個人設定（モデル、指示など）をこのProjectにコピーする選択です。リンクそのものと同じ意味ではないため、必要性を確認してから選択してください。

### Workflowの依存リソースを確認する

選択したWorkflowが他のリソースを必要とする場合、確認画面に**「依存リソースの自動追加」**が表示され、必要なエージェント・Workflow・スキルが自動追加の対象として示されます。選択したWorkflowだけを追加できるとは限りません。

「スキップされた依存リソース」が表示された場合は、理由を確認します。アクセス権限がない、リソースが見つからない・削除されている・無効である、Project固有であるなどの理由により、必要な依存先を追加できないことがあります。この状態で追加を続ける前に、Workflowが目的どおりに使えるかを元の管理者と確認してください。

## 3. 「追加」でリンクを確定し、利用できる状態を確認する

1. 確認画面の選択内容、自動追加される依存リソース、スキップされた依存リソースを確認します。
2. 問題がなければ**「追加」**を選びます。
3. **「○件のリソースを追加しました」**、またはスキップ件数を含む完了表示を確認します。
4. 一覧に対象が表示されることを確認します。
5. 対象を開き、必要に応じて実行・参照の確認をします。リンク元での更新が業務に与える影響も、管理者と共有します。

リンクしたリソースをProject内で開くと、**「読み取り専用」**と表示されることがあります。この場合、Project内では編集できず、元のリソース側で編集します。元を更新する権限がない場合は、Project内で編集可能になるとは考えず、元の管理者へ変更を依頼してください。

## 4. 不要になったリンクを解除する

リンク解除は、Projectから元へのアクセスを外す操作です。元のリソースや、他のProjectのリンクを削除する操作ではありません。

1. 対象のProjectで、リンクを解除したいリソースの一覧を開きます。
2. 対象の名前・種別・利用中のWorkflowなどを確認します。WorkflowやAgentから参照されていないか、利用者への影響がないかを確認してください。
3. 対象の操作から**「リソースの削除」**を選びます。
4. 確認画面の「削除すると、このプロジェクトからリソースへのアクセスが削除されます。元のリソースは影響を受けません。」という注意を確認します。
5. 対象名が正しいことを確認し、**「削除」**を選びます。
6. 一覧から対象がなくなり、このProjectで使えない状態になったことを確認します。

> Project Builderエージェントや、配布によって管理されているリソースなどは、リンク解除できない場合があります。また、リンクを解除したエージェントがProjectの既定であった場合は、既定エージェントの状態も確認してください。解除できない場合に、元のリソースを削除して解決しようとしないでください。

## うまくいかないとき

| 状況 | 確認・対応 |
|---|---|
| 「追加」が表示されない | Projectの編集権限、対象画面、組織の機能提供条件を確認する |
| 追加したい候補がない | 種別・検索条件・ソースを確認する。すでに追加済み、Project固有、無効・削除済み、権限不足の可能性を確認する |
| 自動追加・スキップの表示が出た | Workflowの依存リソースとスキップ理由を確認する。必要な依存先がないまま利用を始めない |
| Project内で編集できない | 「読み取り専用」の表示を確認し、元のリソース側で編集する。元の管理者へ依頼する |
| 元のリソースを削除できない | 利用中のProjectへのリンクが残っていないか確認し、影響を確認してからリンク解除する |
| リンク解除できない | 対象が既定・予約・配布管理のリソースではないか、権限と利用中の依存関係を確認する |

問い合わせには、組織名、Project名、対象リソースの名前と種別、操作した画面、表示されたメッセージ、依存リソースの追加・スキップ状況を添えます。リソースの本文、認証情報、Secretの値は含めないでください。

## チェックリスト

- [ ] リンクとコピーが別の操作であり、リンクが元への参照であることを確認した
- [ ] 元の更新がリンク先にも影響し得ることを、元の管理者・利用者と確認した
- [ ] 対象の種別、名前、ソース、管理者を確認してから「追加」した
- [ ] Workflowでは自動追加される依存リソースとスキップ理由を確認した
- [ ] 「読み取り専用」のリソースをProject内で編集しようとしていない
- [ ] リンク解除前に、Project内の利用者・Workflow・Agentへの影響を確認した
- [ ] リンク解除後に、元のリソースが残っていることと、Project側の表示を確認した
