# Projectを作成して基本設定する

Studioで業務の仕組みを作り始めるときは、作業場所となるProjectを準備します。この記事では、**Studio WorkspaceからProjectを作成し、名前・説明・メンバーを確認して、構築を始められる状態にする手順**を説明します。

Projectの作成は、MarketplaceのAppをインストールする操作とは異なります。共有されたProjectを使うだけの場合は、新しく作成せず、[共有されたProjectで利用を始める](../use/start-with-shared-project.md)を確認してください。

## 始める前に

- 作成先の組織と、Projectを作成できる権限を確認します。
- 同じ目的のProjectがすでにないか、担当者や一覧で確認します。
- 誰が何のために使うか、最初にどこまで作るかを決めます。
- 最初に参加するメンバーと、必要な役割を確認します。自分だけで準備し、他のメンバーの追加を後にする進め方もあります。
- 検証用の場合は、本番業務用と見分けられる名前と、利用してよいテストデータを用意します。

> 以下はWebブラウザのWorkspace一覧から作成する手順です。メニュー・操作権限・作成上限は、組織の設定や契約によって異なります。表示されない機能を別の画面やURLで代用せず、管理担当者に確認してください。

## 1. 作成先を確認して「作成」を開く

1. JAPAN AIにログインし、作成先の組織を確認します。
2. **Studio Workspace**を開き、Project一覧へ進みます。
3. 一覧で同じ目的のProjectを確認します。名前で検索する場合は、関連する業務名やチーム名も確認してください。
4. **「作成」**を選び、**「プロジェクトを作成」**画面を開きます。

一覧には、アクセスできるProjectや、組織の設定に応じて表示対象となるProjectが出ます。検索で見つからないことだけでは、組織内に存在しないと断定できません。

「作成」を選べない場合は、ボタン付近の案内や使用状況を確認します。作成権限、契約上の利用可否、組織のProject数の上限などが関係します。上限を空けるために既存Projectを独断で削除しないでください。

入口が分からない場合は、[利用開始の前提と基本画面](../getting-started/getting-started-and-navigation.md)を参照してください。

## 2. 名前・説明・アイコンを設定する

作成画面で基本情報を入力します。**作成時はプロジェクト名と説明の両方が必要です。** 空欄や空白だけの状態では、セットアップへ進めません。

| 項目 | 入力する内容 | 例・注意点 |
|---|---|---|
| プロジェクト名 | 業務や利用チームが分かる名前 | `営業部_商談準備_検証`など。本番用と検証用を区別する |
| 説明 | 対象業務、利用者、使用する情報、達成したいこと | 最初に作る範囲と、まだ実行しない操作も書く |
| アイコン | 一覧などで見分けるための画像。必要に応じて設定 | 画面に案内される条件に従う。設定しなくても作成できる |

### 説明の例

> 営業チームが商談前の情報を整理するための検証用Projectです。提供された会社情報と商談メモから、確認事項と質問案を作成します。最初はテストデータのみを使い、メール送信やCRMの更新は行いません。

「プランを立てて作成」を選ぶ場合、説明はプランニング画面の入力欄に下書きとして入ります。通常の「作成」では構築依頼は送信されないため、いずれの場合も「営業支援」だけでなく、対象と目的を具体的にします。ただし、**説明に「更新しない」と書くことは、操作権限や接続設定による制限の代わりにはなりません。**

APIキー、パスワード、Secretの値などは、名前や説明に入力しないでください。外部サービスへの接続や機密値の登録は、専用の設定として扱います。

## 3. メンバーと役割を確認する

作成画面のメンバー一覧を確認します。

1. 自分が含まれていることを確認します。この作成画面では、自分が管理者として初期設定されます。
2. 最初から一緒に作業する人がいる場合は、表示される候補から追加します。
3. **追加した人の役割を、1人ずつ確認します。** この画面では追加時に管理者が初期選択されるため、そのまま確定せず、担当に合う役割へ変更してください。
4. 名前・メールアドレスを確認し、誤って追加した人を取り除きます。

この候補選択は、表示される組織メンバーをProjectに追加する操作です。候補にいない人へ、ここから任意のメールアドレスで組織招待できるとは限りません。

作成時には少なくとも1人の管理者が必要です。組織の管理者とProjectの管理者を混同せず、必要以上の権限を付けないようにします。実際にできる操作は、役割だけでなく組織やProjectの権限設定にも依存します。

メンバー追加・変更・削除の詳細は、[Project・Appのメンバーを管理する](../operations/manage-project-and-app-members.md)で扱います。

## 4. 作成方法を選ぶ

入力内容とメンバーを確認したら、作成方法を選びます。通常の**「作成」**と、**「プランを立てて作成」**が表示されます。

| 進めたいこと | 操作 | 確認すること |
|---|---|---|
| 作業場所だけ準備して、構築は後で行う | 「作成」を選ぶ | Projectを作成してProjectへ進む。プランニングは始まらない |
| AIと構築プランを相談してから進める | 「プランを立てて作成」を選ぶ | Projectの作成後、「プロジェクトプラン: ＜プロジェクト名＞」へ進む |
| 名前や説明を見直す | 「キャンセル」して入力を見直す | 作成前の入力を閉じる操作であり、作成済みProjectの削除ではない |

テンプレートが選べる環境でも、作成方法の選択をテンプレートのインストールや公開と混同しないでください。

### 基本設定だけを終える場合

**「作成」**を選び、作成後にProjectを開いて基本設定を確認します。この操作では構築プランは作成・実行されません。後からAIへ構築を依頼する場合は、[Studio Assistantに構築を依頼する](build-with-studio-assistant.md)を参照してください。

### AIとプランを立ててから構築する場合

**「プランを立てて作成」**を選ぶと、Project作成後に**「プロジェクトプラン: ＜プロジェクト名＞」**へ進みます。そこで相談内容を送信し、提示されたプランを確認します。

| プランニング画面で行うこと | 操作 | 確認すること |
|---|---|---|
| プランを実行せずProjectへ進む | 「スキップ」を選び、確認画面で進む | プランを実行せずにProjectへ移動する |
| AIに構築を依頼する | プランを確認・相談し、「承認」の確認画面で実行へ進む | 単なる保存ではなく、プランの実行が始まる |
| Projectの設定を見直す | 「戻る」で設定画面へ戻り、修正後に「保存して続行」 | プランニングへ戻った後も内容を確認する。メンバー変更は作成後の管理画面で確認する |
| 今回の作成自体を取りやめる | セットアップ画面を閉じる際の中止確認を読む | 作成されたProjectを削除する操作であり、後で続けるための一時保存ではない |

「戻る」後の画面でメンバーを変更しても、「保存して続行」では反映されません。メンバーの追加・削除・役割変更は、セットアップを終えてからProjectのメンバー管理画面で行ってください。

### プランニングをスキップする場合

1. **「スキップ」**を選びます。
2. **「プランニングをスキップしますか？」**の確認を読みます。
3. 確認画面で進むと、プランを実行せずにProjectへ移動します。

### プランを承認して実行する場合

目的・入力情報・期待する結果・実行してよい範囲を相談し、提示されたプランを確認します。**「承認」後の実行確認を確定すると、エージェントが実行を開始します。** 外部への送信や既存データの変更などが含まれる場合は、実行してよい内容か確認してから進めてください。

実行開始は構築完了を意味しません。処理結果と作成された内容の確認は、[Studio Assistantに構築を依頼する](build-with-studio-assistant.md)で扱います。

> **「スキップ」と「中止」は異なります。** 中止の確認画面には「プロジェクトとすべてのデータが削除されます」と表示されます。これは「プランを立てて作成」後のセットアップを中止する場合の操作です。Projectを残して後から構築したい場合は、中止を確定せず「スキップ」を使ってください。

## 5. 作成後の基本設定を確認・修正する

Projectを開けたら、対象の名前を確認し、Project内の**「プロジェクト設定」**から**「基本設定」**を開きます。

### 名前と説明を変更する

1. **「プロジェクト情報」**の**「編集」**を選びます。
2. プロジェクト名と説明を修正します。
3. **「保存」**を選び、更新結果を確認します。
4. 表示された名前・説明が意図した内容になっているか確認します。

作成時は名前と説明の両方が必要ですが、作成後の編集では説明を空にできます。運用上は、利用者が目的を判断できる説明を残すことをおすすめします。プロジェクト名は空にできません。

未保存の変更がある状態で「キャンセル」を選ぶと、変更の破棄を確認する画面が表示されます。これは**未保存の編集を取りやめる操作**で、作成時のセットアップ中止によるProject削除とは異なります。

### アイコンを変更する

「プロジェクトのアイコン」の画像アップロード操作を使い、画面に案内される画像を選びます。アイコンの変更は名前・説明の保存とは別に処理されるため、アップロード結果と表示を確認してください。

「編集」や画像の操作を選べない場合は、Projectの設定変更権限を確認します。Projectを開けることと設定を変更できることは同じではありません。

## 6. 構築を始める前に確認する

基本設定の完了と、業務で使える仕組みの完成を分けて確認します。

- 正しい組織に作成され、Projectを開けること。
- 名前・説明から、用途と検証用／本番用の区別が分かること。
- 意図したメンバーと役割になっていること。セットアップ中に設定画面へ戻った場合も、保存後の状態を確認すること。
- 通常作成で構築を後にしたのか、プランニングでスキップしたのか、承認して実行を開始したのかが明確なこと。
- AIの構築を実行した場合は、作成されたリソースや未完了事項を確認すること。

Projectを作成しただけで、必要なAgent・Workflow・Pageなどがすべて完成するわけではありません。外部接続、Secret、ホームPage、公開や配布の準備も、必要に応じて別に行います。

## うまくいかないとき

| 状況 | 確認・対応 |
|---|---|
| Workspaceや「作成」が見つからない | 組織、提供条件、作成権限を確認する。共有Projectの利用だけなら新規作成は不要 |
| 「作成」を選べない | ボタン付近の案内、契約上の利用可否、組織の作成上限、権限を確認する |
| 「作成」または「プランを立てて作成」を選べない | 名前・説明が入力され、空白だけになっていないか確認する。入力エラーがあれば修正する |
| 追加したい人が候補にいない | 組織と候補の表示を確認し、組織への所属・招待状況を管理担当者へ確認する |
| プランニングを開始できない | 「プランを立てて作成」を選んだ場合の画面か、エラー内容を確認する。作業場所だけ残す場合は、表示されている「スキップ」を利用する。中止による削除と混同しない |
| 作成や保存の結果が分からない | 同じ操作を連続で確定せず、一覧や設定を再確認する。Projectがすでに作成されている可能性も確認する |
| 「編集」を選べない | 対象Projectの設定変更権限を確認する。画面の閲覧権限だけでは変更できない場合がある |

問い合わせには、組織名、Project名、操作した画面、日時、表示されたエラー、一覧や設定の再確認結果を添えます。APIキーやパスワードなどの機密値は含めないでください。

## 完了チェック

- [ ] 作成先の組織と、既存Projectの再利用可否を確認した
- [ ] Projectを作成し、名前・説明・必要なアイコンを確認した
- [ ] 初期選択に任せず、メンバーと役割を確認した
- [ ] 「作成」と「プランを立てて作成」の違いを確認し、プランニングを使った場合はスキップ・承認実行・中止の違いを理解して進めた
- [ ] Projectを開き、基本設定の保存結果を確認した
- [ ] 構築・接続・テストなど、次に行う作業が決まっている
