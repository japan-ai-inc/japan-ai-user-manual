# Datasetを準備して参照させる

**Dataset**は、業務資料や外部データを取り込み、AgentやWorkflowからRAG検索で参照するためのデータのまとまりです。この記事では、Datasetの作成、データの取り込み、同期・再読み込み、Agentへの設定、参照結果の確認までを説明します。

- AgentにDatasetを設定する方法：[Agentにツール・Skill・Datasetを設定する](configure-agent-tools-skills-datasets.md)
- Datasetの仕様・制限：[Datasetの仕様・制限](dataset-specs-and-limits.md)
- 資料が回答に反映されない場合：[Agentがデータを参照しない](../troubleshooting/agent-not-using-data.md)

## DatasetとRAG参照とは

Datasetに取り込んだデータは、AgentまたはWorkflowが質問や処理の内容に関連する情報を探すために使えます。画面では「データ連携」に、**「エージェントやワークフローからデータセットのRAG検索が可能です。」**と説明されています。

RAG参照は、質問に関連する情報を検索して回答に利用する仕組みです。Datasetを設定しても、毎回すべての資料の全文が回答に使われるわけではありません。特定の契約書の全条項を漏れなく確認するような用途では、対象ファイルと確認範囲を明示した別の手順を設計してください。

| 用途 | Datasetが向く例 | 事前に決めること |
|---|---|---|
| 社内問い合わせ | 規程、FAQ、製品資料をもとに回答する | 正本の資料、更新担当、対象利用者 |
| 業務支援 | 手順書や過去事例を探して回答案を作る | 回答に含めてよい情報、確認者 |
| Workflow処理 | 入力内容に関係する資料を検索して後続の処理に渡す | 検索結果を使う処理と、失敗時の扱い |

Datasetは通常のファイル保管場所とは目的が異なります。資料を保管しただけではRAG参照には使えず、Datasetへ取り込んで処理が完了していることを確認する必要があります。

## 始める前に

- 対象の組織・Project・Datasetが正しいことを確認します。
- Datasetの作成、編集、データ追加に必要な権限があることを確認します。権限や表示される操作は、組織の設定によって異なる場合があります。
- 取り込む資料について、正本・更新担当者・更新時の連絡先を決めます。古い版や同内容の資料を混在させないでください。
- 個人情報、機密情報、第三者の情報を取り込む場合は、共有範囲と社内ルールを確認します。
- Agentに設定する場合は、テスト用の質問と、その答えの根拠になる資料箇所を用意します。

> **Datasetを共有する範囲と、Agentを共有する範囲は分けて確認してください。** 非公開のDatasetが接続されたAgentを共有する場合、他の利用者もDatasetの内容を閲覧できる可能性がある旨の警告が表示されます。

## 1. Datasetを作成する

1. 対象の組織またはProjectで「データ連携」を開きます。
2. 「データセット一覧」で「データセット作成」を選択します。
3. 「データセット名」に、用途と資料の範囲が分かる名前を入力します。例：「人事規程_2026年度版」のように、版や対象を区別できる名前にします。
4. 表示される場合は「共有設定」を確認します。組織のDatasetでは、「非公開（自分のみ）」または「共有（組織全体または指定した部署）」を選べます。Projectでは、「作成者のみアクセス可能」または「プロジェクトメンバー全員がアクセス可能」と表示される場合があります。
5. 表示される場合は「部署設定」または「共有部署」で、参照を許可する部署を確認します。
6. 「追加する」を選択します。

作成できない、またはボタンが選択できない場合は、権限が不足している可能性があります。組織またはProjectでDatasetを作成・更新できる権限を確認し、管理者またはProject管理者に相談してください。

### 名前と共有範囲の決め方

| 項目 | 決め方 | 例 |
|---|---|---|
| 名前 | 資料の用途・対象・版が分かるようにする | 「営業提案資料_現行版」 |
| 非公開 | 作成者だけで準備・検証する場合 | 公開前の資料を確認中 |
| 共有 | 利用者や作成者が共通で参照する場合 | 部署共通の業務手順書 |
| 共有部署 | 参照してよい部署だけに絞る場合 | 人事部向けの規程資料 |

> Datasetを共有すると、選択した範囲で資料が参照可能になります。資料そのものの共有可否だけでなく、Agent経由で質問した場合に見せてよい内容かも確認してください。

## 2. データを取り込む

作成直後にデータ追加画面が表示されない場合は、対象Datasetを開き、「データアップロード」を選択します。データの詳細画面に「データがまだありません」と表示されるときも、「データアップロード」から追加できます。

1. 「データアップロード」を選択します。
2. 取り込み元を選び、資料または取得対象を指定します。画面では、PCからのファイル、Web上のURL、設定済みの外部データ連携などを選べる場合があります。
3. ファイル名、URL、対象フォルダなど、選んだ取り込み元で必要な項目を確認します。
4. 「アップロードする」などの実行操作を選択します。
5. Datasetのデータ一覧に戻り、追加したデータの「ステータス」を確認します。
6. 「完了」になったことを確認してから、参照テストへ進みます。

取り込みは完了まで時間がかかる場合があります。「保留中」「進行中」「更新」と表示されている間は、処理中として扱います。「失敗」「コンテンツなし」「読み取り不能」と表示されたデータは、そのままでは期待どおりに参照できない可能性があります。資料、取得元へのアクセス、対応形式を確認し、必要に応じてデータを見直してください。

> 同じ資料を繰り返し登録すると、古い版と新しい版のどちらを参照すべきか判断しにくくなります。更新時は、既存データを置き換えるのか、版として残すのかをあらかじめ決めてください。形式・容量・件数などの条件は、[Datasetの仕様・制限](dataset-specs-and-limits.md)を確認してください。

### PDFを取り込む場合

「AI OCR for PDF」が表示される場合は、PDF内の画像をAIモデルで検出・処理する設定です。表示の有無は組織の設定によって異なる場合があります。この設定はDataset作成後にも変更できます。PDF 1ページごとにクレジットを利用します。

AI OCR for PDFを無効にすると、以後アップロードするPDFはアップロード時に選んだ抽出方法で処理され、外部連携で取り込むPDFはテキスト抽出で処理されます。すでに取り込み済みのデータには影響せず、設定変更による再処理は行われません。既存の抽出結果を変える必要がある場合は、設定変更だけで完了したとは扱わず、対象データの更新方法を画面の案内と担当者に確認してください。専用の処理方式が設定されたDatasetでは、AI OCR for PDFを変更できない場合があります。

## 3. 同期・再読み込みを設定する

外部のWebまたは外部APIを取得元とするDatasetでは、必要に応じて最新データを取り込むための設定を確認します。

1. 「データセット一覧」で対象Datasetを選択します。
2. 「詳細設定」を開きます。
3. 「更新頻度」を確認し、必要な頻度を選びます。
4. 「更新する」を選択し、次回の更新後にデータ一覧の状態を確認します。

「更新頻度」は自動更新の頻度を設定する項目です。**PCからアップロードしたファイルは自動更新の対象外**です。PC上の資料を更新した場合は、更新後のファイルをDatasetへ取り込む操作が必要です。

Project内の「データ連携」では、Projectにリンク済みのDatasetを一覧から確認し、必要なDatasetを取り込む操作があります。Project外のDatasetを参照候補へ加えただけでは、そのDatasetを利用できるとは限りません。リンク後に、一覧と参照権限を確認してください。

すぐに取得元の内容を更新したい場合は、「データセットを再読み込み」を選択できます。再読み込みは、取得元（Webまたは外部API）から最新データを再取得して再インデックスする操作です。更新中は再読み込みできません。

> 取得元の変更が直ちにDatasetへ反映されるとは限りません。自動更新・再読み込みの後は、データ一覧の状態と、代表的な質問での参照結果を確認してください。外部連携の認証が切れている場合は更新できないことがあります。

## 4. Agentに参照させる

Datasetの処理が「完了」になったら、Agentへ設定します。

1. 対象Agentの設定を開きます。
2. 「データ連携」を開きます。
3. 「データセットを選択」で、準備したDatasetにチェックを付けます。
4. 不要なDatasetが選ばれていないことを確認します。
5. 「適用」を選択します。
6. Agentの「データ連携」欄にDataset名が表示され、Agent設定が保存されたことを確認します。

複数のDatasetを選択できる場合でも、最初は業務に必要なものだけに絞ることをおすすめします。類似資料や古い資料を同時に選ぶと、回答の根拠を確認しにくくなります。詳しい設定手順は[Agentにツール・Skill・Datasetを設定する](configure-agent-tools-skills-datasets.md)を参照してください。

## 5. 参照結果をテストする

1. 対象Agentを開きます。
2. Datasetに含まれる情報で、答えを事前に確認できる質問を入力します。
3. 回答の内容と、表示される場合は「回答のデータ参照先」を確認します。
4. 資料の原文と照合し、必要な資料が使われているか、古い資料が混ざっていないかを確認します。
5. 想定と異なる場合は、質問、Agentの指示、Datasetの選択、データ一覧のステータス、共有範囲を順に確認します。

| 確認すること | 例 |
|---|---|
| 質問との対応 | 資料にある用語・条件を含めて質問したか |
| 取り込み状態 | 対象データが「完了」になっているか |
| 資料の正しさ | 現行版の資料だけが入っているか |
| Agent設定 | 対象Datasetが「データ連携」で選択されているか |
| 共有範囲 | 質問者・Agent利用者に適切な範囲か |

回答が資料と異なる、または資料を参照しない場合は、すぐに資料が存在しないと判断せず、Datasetの状態と設定を確認してください。切り分けは[Agentがデータを参照しない](../troubleshooting/agent-not-using-data.md)で扱います。
