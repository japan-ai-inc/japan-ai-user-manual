# Agentにツール・Skill・Datasetを設定する

Agentに、業務に必要な機能と参照情報を組み合わせます。この記事では、**作成済みのAgentへツール・Skill・Datasetを設定し、保存・認証・利用者のアクセス・実際の動作を確認する手順**を説明します。

Agentの作成、指示、モデルの設定は[Agentを作成して指示・モデルを設定する](create-agent-instructions-and-models.md)を参照してください。ここでは既存のツール・Skill・Datasetを選ぶ操作を中心に扱い、新規作成や詳細な接続設定は別記事で説明します。

## 始める前に

- 設定する組織・Project・Agentと、Agentを編集できる権限を確認します。
- 既存の設定と、このAgentを利用している人・業務を確認します。稼働中のAgentへ試験的な機能を無断で追加しないでください。
- 何を読み取り、何を出力し、何を変更してよいかを決めます。
- 利用予定のSkillの内容・共有範囲と、Datasetの資料・更新状況を確認します。
- 外部サービスを使う場合は、接続に使うアカウントと操作可能な範囲を確認します。
- 機密情報を含まないテスト用の入力と、期待する結果を用意します。

> **Agentの設定には自動保存があります。** 特にプラグインの追加・解除は、選択画面を閉じる前でも保存対象になります。「閉じる」を変更の取り消しとして使わないでください。Datasetの選択確定とは操作が異なります。

画面構成や候補は、組織の設定、Project、アクセス権限、提供状態によって異なります。この記事はパソコンの画面を中心に説明しています。

## 1. 必要な機能と参照情報を分ける

| 設定するもの | 主な役割 | 設定前に確認すること |
|---|---|---|
| ツール | 検索、ファイル処理、外部サービスへのアクセスなどの操作を行う | 読み取りか更新か、認証が必要か、対象データへアクセスできるか |
| Skill | 再利用する手順や知識をAgentに利用させる | 内容が目的に合うか、必要なツールや接続があるか、利用者が使える共有範囲か |
| Dataset | 業務資料を参照するための情報源を設定する | 正しい資料か、更新・取り込みが済んでいるか、利用者に参照が許可されているか |

Agent設定では、ツールとSkillを**「プラグイン」**から追加します。Datasetは**「データ連携」**から選びます。機能の役割と画面上の名称を対応させて操作してください。

### 最初は目的に必要なものだけを選ぶ

例えば「社内のFAQをもとに回答案を作る」Agentなら、まず対象のFAQを含むDatasetを確認します。回答の構成や確認手順を共通化したい場合は、内容を確認したSkillを追加する方法があります。外部検索やメール送信が不要なら、用途が分からないまま追加しないでください。

この例は構成の考え方であり、特定のFAQ用Skillや接続がすべての組織へ提供されていることを意味しません。

**指示に機能名を書くだけでは、ツールの設定や認証は完了しません。** また、プラグインを追加しただけで、すべての会話で必ず実行されると考えないでください。必要な操作と参照情報を指示でも伝え、結果を確認します。

## 2. 対象Agentの設定を開く

1. 対象の組織・Projectを開きます。
2. Agent一覧から、設定するAgentの編集画面を開きます。
3. Agent名と既存の指示を確認します。
4. 「構成」や「指示」など、設定項目が表示される領域を開きます。
5. **「プラグイン」**と**「データ連携」**を確認します。

会話画面で一時的に機能を選ぶ操作と、Agent自体の設定を編集する操作を混同しないでください。本記事はAgent設定画面での操作です。

編集できない場合は、利用権限と編集権限を分けて確認します。既存Agentと会話できることだけでは、そのAgentの構成を変更できるとは限りません。

## 3. ツールを追加する

1. **「プラグイン」**欄の**「追加」**を選びます。
2. 検索欄へ、使いたい機能やプラグインの名称を入力します。
3. 必要に応じて「公式一覧」「プロジェクト」「組織で作成」「自分で作成」など、表示される分類を切り替えます。
4. 候補の名前、説明、「ツール」「スキル」の表示、提供範囲を確認します。
5. 目的に合う候補の**「追加」**を選びます。
6. 選択画面を閉じ、Agentのプラグイン欄に追加した項目が表示されていることを確認します。
7. Agentの保存状態と、認証に関する案内を確認します。

名称が似ていても、対象サービスや読み取り・更新の範囲が異なる場合があります。名前だけで選ばず、説明と利用目的を照合してください。

### 追加画面を閉じても、変更は取り消されない

プラグインの「追加」や「削除する」は、Agentフォームの選択内容をその都度変更します。選択画面を閉じる操作は、その変更を取り消す操作ではありません。

誤って追加した場合は、対象を確認してAgentの設定から外し、その後の保存結果を確認します。追加する前の設定内容を把握しておくと、戻す対象を判断できます。

### 候補が見つからない場合

- 検索語を短くし、分類の絞り込みを確認します。
- 正しいProject・組織で操作しているか確認します。
- 担当者に、提供状態、選択画面への掲載、共有範囲、利用権限を確認します。

検索結果に出ないことだけで、未契約、機能の不存在、削除済みのいずれかに断定しないでください。

## 4. Skillを追加し、共有範囲を確認する

Skillも「プラグイン」→「追加」から選びます。「スキル」と表示される候補について、内容と用途を確認して追加してください。

確認したいのは、次の点です。

- どの依頼に使うSkillか。
- どのような手順や出力を想定しているか。
- 外部サービスの操作や、追加の認証が必要か。
- 自分だけでなく、Agentを使う人も利用できるか。
- Agentの既存の指示と矛盾しないか。

詳細を開く導線が表示されている場合は、内容の確認に使います。Skillの新規作成・改修は[Skillを作成して利用する](create-and-use-skills.md)で扱います。

### 非公開Skillの警告が出た場合

自分用の非公開Skillを、他の人が使うAgentへ設定すると、共有範囲に関する警告が表示される場合があります。**Agentを共有することと、Skillを共有することは別の設定です。** 作成者が使えたからといって、他の利用者も使えるとは限りません。

1. 警告の対象になっているSkillを確認します。
2. Skillに含まれる内容と、想定する利用者を確認します。
3. 共有してよいか、所有者・管理担当者と判断します。
4. 共有が許可されている場合だけ、画面の「公開範囲の変更が必要です」などの案内から、対象Skillと範囲を確認して保存します。公開範囲の選択肢では、組織内で利用できる範囲と自分のみの範囲を見分けます。
5. 共有するAgentで利用するSkillは、自分のみの範囲のまま残さないことを確認します。保存に失敗した場合は、どのSkillまで変更されたかを開き直して確認します。
6. 共有できない場合は、利用者が使える別のSkillへ置き換えるか、Agentの構成を見直します。

**公開範囲の変更は、このAgent内だけの表示調整ではなく、Skill自体の設定変更です。** 警告を消すためだけに公開範囲を広げないでください。Skillを共有しても、外部サービスの認証情報まで利用者へ提供されたとは扱いません。

「アクセスできないプラグイン」が表示された場合は、対象の所有者や管理担当者に確認します。単なる読み込み途中と区別し、候補が取得できない原因を確認してから対応してください。

## 5. 必要な認証・接続を確認する

外部サービスを使うプラグインには、**「認証が必要」**と表示される場合があります。追加操作と認証操作は別です。

1. どのサービスへ、誰のアカウントで接続するか確認します。
2. 「認証が必要」が表示され、接続が許可されている場合は、その案内から認証画面を開きます。
3. 対象アカウントと求められる権限を確認して、認証を進めます。
4. 管理者への連絡を求める案内がある場合は、担当者へ設定を依頼します。
5. Agent設定へ戻り、認証表示と保存内容を確認します。
6. 許可されたテストデータを使い、実際の読み取りなどで動作を確かめます。

画面の認証済み表示だけでは、対象のファイルやレコードを読み取れること、必要な更新を実行できることまでは確認できません。期限切れ、接続先の権限、対象データへのアクセスなどは、実際の操作で確かめる必要があります。

個人接続と共有接続のどちらを使うか、他の利用者にも個別認証が必要かは、接続の方式によって異なります。作成者の接続で全員が使えるとは説明しないでください。

APIキー、パスワード、Secretの値をAgentの指示やSkill本文へ貼り付けないでください。認証情報の管理は[個人接続・共有接続・Secretを選ぶ](../operations/choose-personal-shared-connections-and-secrets.md)で扱います。

## 6. Datasetを選ぶ

資料を参照させる場合は、**「データ連携」**からDatasetを選択します。

1. 対象Agentの**「データ連携」**欄を開きます。
2. **「データセットを選択」**画面で、目的のDatasetを探します。
3. 対象のチェックを付けます。すでに選択されているDatasetも確認してください。
4. 参照させないDatasetのチェックは外します。
5. 画面下部の選択件数などを確認し、**「適用」**を選びます。
6. Agentの「データ連携」欄へ戻り、選択した名前とAgentの保存状態を確認します。

**選択画面で「適用」することと、Agent設定の保存が成功することは別の確認です。** 選択を確定せず「キャンセル」や閉じる操作をした場合、その選択変更はAgentへ適用されません。プラグイン選択画面と同じ挙動ではありません。

ここで選ぶのは、Agentに設定する参照情報です。資料を名前で指定するだけの操作や、会話へのファイル添付とは分けて考えます。

### 選択前後に確認すること

- 正しい業務・組織・版の資料が入っているか。
- 更新した資料の取り込みや同期が済んでいるか。
- テストに使う質問の答えが、その資料に含まれているか。
- 利用者に参照を許可してよい資料か。
- 古い版や類似資料を重複して選んでいないか。

Datasetを選んでも、元の資料の取り込みが完了したり、参照権限が新たに付与されたりするわけではありません。新規作成のボタンが表示されても、作成できるかどうかは権限などに依存します。資料の準備や取り込みは[Datasetを準備して参照させる](prepare-and-reference-datasets.md)を参照してください。

### 全文を漏れなく読む用途とは分ける

Datasetを設定したことは、毎回すべての資料の全文が回答に使われることを意味しません。関連する情報を探して回答する用途と、「契約書の全条項を漏れなく点検する」などの網羅的な確認は分けて設計してください。

網羅的な処理では、対象ファイルを明示し、内容を取得・確認できた範囲を検証する別の手順が必要です。ファイル添付の場合も、添付しただけで全文確認済みとは判断しません。

## 7. 指示を整え、小さな入力で確かめる

設定した機能や資料を、どの場面でどう使うか指示に書きます。説明のないままプラグインを増やすより、役割を明確にして動作を確認します。

### 指示の例

> 対象のFAQ資料を参照し、利用者の質問に対する回答案を作成してください。
> - 資料に根拠がない内容は推測で補わず、未確認と伝えてください。
> - 出力は「回答案」「確認できた根拠」「追加確認事項」に分けてください。
> - 参照できない資料を読んだことにしないでください。
> - この検証では、外部への送信や業務データの更新は行わないでください。

これは指示の記載例です。Datasetの選択やツールの認証を代わりに行うものではありません。また、「更新しない」という指示は、接続先の更新権限を取り消す設定ではありません。

### 段階を分けて確認する

| 確認段階 | 確認する内容 |
|---|---|
| 設定 | 必要なプラグイン・Datasetが選択され、不要な項目がない |
| 保存 | 保存エラーがなく、設定画面を開き直しても内容が残る |
| アクセス | 想定利用者がAgent・Skill・資料を利用でき、必要な接続がある |
| 動作 | 小さな入力で期待する資料や機能が使われ、結果が正しい |

最初は、資料に答えがある質問と、答えがない質問を試します。外部サービスの接続を含む場合は、許可されたテスト対象を読み取るなど、影響の小さい操作から確認します。

AIが「参照しました」「実行しました」と返しただけで完了とせず、回答の根拠、表示される実行結果、対象データを確認してください。送信・更新を伴う試験は、対象と内容について承認を得てから行います。検証でツールを使う場合も、実操作として扱ってください。

詳細なテスト設計は[Agentをテストして改善する](test-and-improve-agents.md)で扱います。

## 8. 不要な設定を外す

### ツール・Skillを外す

プラグイン欄の対象カードにある解除アイコン、または追加画面の対象にある「削除する」を使い、保存後に対象が外れていることを確認します。

この操作は**Agentからの設定解除**です。Skillそのものの削除、外部サービスの接続解除、実行済み処理の取り消しとは異なります。

### Datasetを外す

「データ連携」を開いて対象のチェックを外し、「適用」を選びます。Agentの保存結果も確認してください。Datasetの選択解除と、元資料やDataset自体の削除は別の操作です。

設定を外しただけで、過去の会話や出力に含まれる情報が消える、他の経路からの利用も禁止されるとは考えないでください。利用を禁止する必要がある場合は、共有・権限・接続の管理も担当者に確認します。

## うまくいかないとき

| 状況 | 確認・対応 |
|---|---|
| ツールやSkillが見つからない | 検索・分類、組織・Project、掲載状態、共有範囲を確認する |
| 追加できない | 提供状態や画面の警告、必要な権限を確認する。候補に表示・選択できることと、他の環境でも利用できることは分けて確認する |
| 「認証が必要」が残る | 認証したサービスとアカウント、接続結果を確認する |
| 認証済みなのに処理できない | 対象データへのアクセス、接続先の権限、有効期限、実行エラーを確認する |
| 作成者だけSkillを使える | AgentとSkillそれぞれの共有範囲、利用者ごとの接続を確認する |
| Datasetが設定に反映されない | 「適用」の実施とAgentの保存結果を分けて確認する |
| 資料と違う回答になる | Datasetの版・取り込み状態、指示、質問、実際の参照内容を確認する |
| 保存エラーが出る | エラー内容を確認し、必要な入力と権限を見直す。保存成功前に完了と扱わない |

問い合わせには、組織名、Project名、Agent名、対象プラグイン・Dataset名、操作日時、エラー、どの段階まで確認したかを添えます。認証情報や資料の機密内容は含めないでください。
