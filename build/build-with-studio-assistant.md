# Studio Assistantに構築を依頼する

Studio Assistantに業務の目的や条件を伝え、Project内の構築を相談します。この記事では、**要件を伝える → 計画を確認する → 実行する → 変更結果を確かめる**という進め方を説明します。

AIから「完了」と返答があっても、業務で使えることの確認は別に必要です。作成された内容、保存・公開の状態、テスト結果を確認してから利用を始めてください。

## 始める前に

- 作業先の組織・Projectを確認します。新しく作成する場合は、[Projectを作成して基本設定する](create-project-and-basic-settings.md)を先に進めます。
- Studio Assistantの利用と、対象リソースの作成・変更に必要な権限を確認します。Projectを開けるだけで構築できるとは限りません。
- 最初に実現したい業務を1つに絞り、利用してよいテストデータを用意します。
- 既存Projectを変更する場合は、変更してよい対象と、触れない対象を担当者と確認します。
- 外部接続やSecretが必要な場合は、設定する担当者を決めます。APIキーやパスワードをチャット本文に貼り付けないでください。

> 表示されるAgent、メニュー、構築できる機能は、組織・Projectの設定や権限によって異なります。以下では、Project作成直後のプランニングと、作成済みProjectでの通常の会話を分けて説明します。

## 1. 構築を依頼する会話を開く

### Projectを作成した直後の場合

[Projectを作成して基本設定する](create-project-and-basic-settings.md)で**「プランを立てて作成」**を選ぶと、**「プロジェクトプラン: ＜プロジェクト名＞」**の画面へ進みます。ここでは構築支援用のAgentが選ばれ、作成時の説明が入力欄に下書きとして入ります。

説明は、この時点ではまだ送信されていません。対象業務、入力情報、完成形、作業範囲を補足し、必要であれば設計書やモックなどの資料を添付してから送信してください。この画面では、通常のチャットと異なりAgent・モデル・ツールの切り替え操作が表示されません。

### 作成済みProjectで始める場合

1. Studio Workspaceから、作業するProjectを開きます。
2. Projectのチャット入力欄、または表示されている**「新規タスク」**から会話を始めます。
3. **選ばれているAgentを確認します。** Agent選択メニューが表示され、利用可能な候補にStudio Assistantがある場合は、それを選びます。候補が多く検索欄が出ている場合は、名前で探します。
4. 構築支援用のAgentを選べない場合は、そのProjectで利用できるかを管理担当者に確認します。

初期選択のAgentは、設定や利用権限によって別のAgentになることがあります。**Project内のすべての会話がStudio Assistantとの会話とは限りません。** 通常の業務用Agentに、構築権限がある前提で依頼しないでください。

Projectを開いたときに業務用Pageが表示される場合は、用意されている戻り導線などから構築側の画面へ進みます。入口が分からない場合は、管理担当者に確認してください。

### 途中の作業を続ける場合

Project内の最近の会話や会話一覧から、前回の作業を開きます。対象Project、Agent、最後に実行した内容を確認し、**完了済みの作業を最初から繰り返すのではなく、残っている作業を指定**してください。

作成直後のプランニングで承認して実行へ進むと、実行用の会話へ移動します。再開時は、相談だけを行った会話と、実際に構築を実行した会話を取り違えないようにします。会話の閲覧・追記ができる範囲は権限によって異なります。

## 2. 目的・入力・完成条件を伝える

「営業向けのアプリを作って」だけでなく、誰が何を入力し、どのような結果を得たいかを伝えます。

| 伝える項目 | 書く内容 |
|---|---|
| 利用者と目的 | 誰の、どの作業を支援するか |
| 入力・参照情報 | 入力する項目、使ってよい資料、テストデータの場所 |
| 欲しい結果 | 回答、保存する情報、画面など、利用者が受け取るもの |
| 最初に作る範囲 | 今回完成させる最小限の機能 |
| 変更の範囲 | 新規作成か既存修正か。対象の名前と、変更しないもの |
| 接続・実行の条件 | 必要な外部サービス、設定の担当者、送信・更新の可否 |
| 完成の判定 | どの入力を使い、何を確認できればよいか |

### 最初の依頼例

> このProjectで、営業担当者が商談前に質問案を作る仕組みを検討してください。
>
> 入力は会社名、商談の目的、担当者が入力する商談メモです。出力は確認事項と質問案で、不明な情報は推測せず「要確認」と示してください。
>
> 最初は、会話から入力して結果を受け取る最小構成にします。専用画面やCRM連携は今回は作りません。検証用の架空データだけを使います。
>
> まず不足している情報を質問し、必要な構成、作成・変更する対象、テスト方法を含む計画を提案してください。この依頼では構築を実行せず、メール送信、CRM更新、既存リソースの削除も行わないでください。

これは依頼の書き方の例であり、標準提供のAppや、すべての環境で同じ構成を作れることを示すものではありません。

**「まだ実行しない」という依頼は、権限や接続設定による制御の代わりにはなりません。** とくに通常の会話では、すべての変更に専用の承認画面が出ると考えず、検証用Project・データ・必要最小限の権限で進めます。

## 3. 計画を読み、実行する範囲を決める

提案された計画について、次の点を確認します。

- 目的と利用者が依頼内容に合っているか。
- Agent、Workflow、Object、Pageなど、何を作成・変更するのかが分かるか。
- 既存のリソースを再利用するのか、新しく作るのかが明確か。
- 必要な情報・接続・権限がそろっているか。人が設定する項目が分かれているか。
- メール送信、データ更新、削除、公開、自動実行などが意図せず含まれていないか。
- 完成後の確認方法と、今回実施しない範囲が明確か。

不明点があれば、実行前に修正を依頼します。

> 今回はAgentの作成と会話テストだけにしてください。Page、定期実行、外部サービス連携は次の段階に分けます。変更対象とテスト項目を、この範囲で書き直してください。

計画を変更した場合は、**最後に合意した内容**を確認してください。承認ボタンが押せることだけで、計画の内容や安全性まで確認済みとは判断できません。

## 4. 実行へ進む

### 作成直後のプランニング画面から実行する

1. 最新の計画を読み、実行してよい範囲か確認します。
2. **「承認」**を選びます。
3. **「承認して実行しますか？」**の確認内容を読み、実行する場合だけ確定します。
4. 実行用の会話へ移動したら、進行状況、質問、エラーを確認します。

確認を確定すると、エージェントによる計画の実行が始まります。**承認は、計画を保存するだけの操作ではありません。**

プランニング中に添付した資料は、承認して実行へ進む際に実行側でも参照できるよう引き継がれます。ただし、添付や引き継ぎだけで内容の読込・設定反映まで完了したとは判断せず、実行後に利用状況を確認してください。

応答中や計画の保存・同期中などは、承認を選べない場合があります。回答に計画が書かれていても、実行に必要な保存が完了しているとは限りません。押せない状態が続く場合は、会話の案内や保存状態を確認し、必要に応じて計画の保存を依頼します。

> **構築を後にする場合は「スキップ」と「中止」を区別してください。** スキップは計画を実行せずProjectへ進みます。一方、セットアップの中止確認には、Projectとデータを削除する旨が表示されます。作業場所を残したい場合に、中止を一時保存の代わりに使わないでください。詳細は[Projectを作成して基本設定する](create-project-and-basic-settings.md)を参照してください。

### 作成済みProjectの通常の会話で実行する

通常の会話に、作成直後と同じ「承認」ボタンや計画保存の仕組みが必ずあるわけではありません。確認した計画を示し、実行してよい対象を文章で明確にします。

> 合意した計画のうち、Agentの作成だけを実行してください。対象はこの検証用Projectです。既存リソースの削除、外部送信、CRM更新、自動実行の登録は行わないでください。完了後に作成した対象と、未実施のテストを一覧にしてください。

不足する接続や権限が案内された場合は、正規の設定手順で準備します。エラーを回避するために、機密値を会話へ貼り付けたり、意図せず広い権限を付けたりしないでください。

## 5. 返答ではなく、変更された内容を確認する

実行後は、次の順序で確認します。

1. 会話で、完了した作業・失敗した作業・未実施の作業を確認します。
2. 作成・変更したリソースの名前や場所を確認します。
3. Projectの該当リソース一覧、または表示されているリソースパネルから対象を開きます。
4. 設定や内容が、合意した計画に合っているか確認します。
5. テストを行い、結果を確かめます。

リソースの表示方法は画面設定によって異なります。チャットに説明やコード、ファイルが出ただけで、Projectへの登録・保存・公開まで完了したとは判断しないでください。

| 対象の例 | 確認すること |
|---|---|
| Agent | 名前、指示、参照する情報やツールが意図した内容か。テストの依頼に対応できるか |
| Workflow | 処理の順序、入力・出力、分岐、外部操作が計画どおりか。下書きテストと公開状態を区別する |
| Object・Storage | 保存先、項目やデータ、ファイルが正しいか。検証データが本番用に混ざっていないか |
| Page | ソース作成だけでなく、登録・起動・表示・必要な業務操作を確認できるか。公開状態と閲覧範囲も確認する |
| 外部連携・自動実行 | 接続先、実行主体、送信・更新対象、起動条件が合意した範囲か |

すべての対象を一度に構築する必要はありません。今回作ったものだけを確認し、必要に応じて次の機能を追加します。

### テストは小さな入力から始める

架空データや許可された検証データを使い、通常の入力に加えて、必須情報がない場合や想定外の入力も確認します。外部サービスを使うテストは、テスト目的でも送信・更新などが発生し得るため、対象と影響を確認してから実行します。

AIにテスト結果を報告してもらう場合は、「実施したテスト」「未実施のテスト」「確認できなかった項目」を分けるよう依頼してください。報告だけでなく、実際の画面・保存結果・出力も確認します。

## 6. 修正を依頼し、残作業を引き継ぐ

修正は、対象と期待する違いを絞って依頼します。

> 作成した商談準備Agentについて、商談メモが空のときは質問案を推測せず、メモの入力を求めるように修正してください。他の設定は変更しないでください。変更前後の違いと、再テストの結果を報告してください。

失敗した場合は、最初からすべてを作り直す前に、途中まで保存された内容や外部操作の結果を確認します。再実行すると同名リソースが増えたり、同じ操作が重複したりする可能性があります。

停止操作やブラウザを閉じることを、**実行済み変更の取り消し**と考えないでください。戻す必要がある場合は、対象ごとの変更履歴・版管理・復旧方法を確認します。

最後に、次の情報をまとめておくと続きの作業を始めやすくなります。

- 作成・変更した対象と、開く場所。
- 実施したテストと結果、未実施のテスト。
- 未設定の接続や権限、手作業で残っている項目。
- 公開・配布・業務利用を開始してよいか、誰が判断するか。

Project内で構築できたことと、業務利用・Marketplace配布の準備ができたことは別です。

## うまくいかないとき

| 状況 | 確認・対応 |
|---|---|
| Studio Assistantを選べない | Projectと利用権限を確認する。初期選択が別Agentなら、構築用Agentを利用できるか管理担当者へ確認する |
| セットアップの初期化に失敗する | 表示されたエラーを確認し、画面に「再試行」がある場合に利用する。中止による削除と混同しない。通常の「作成」ではプランニング画面は開かない |
| 「承認」を選べない | 応答中・保存処理中か、計画を保存できているか確認する。連続操作で進めようとしない |
| 承認したが実行画面へ進まない | 実行用の会話が作られていないか確認し、結果不明のまま何度も承認しない。解決しなければ問い合わせる |
| 「完了」と言われたが対象が見つからない | 対象Project、リソース名、保存・登録の成否、閲覧権限を確認する。返答やファイル生成だけを登録完了と扱わない |
| 一部の処理で失敗した | 保存済みの内容と未完了部分を分け、原因を解消して必要な範囲だけ再実行する |

問い合わせには、組織・Project、会話の場所、操作日時、依頼した範囲、表示されたエラー、確認した保存結果を添えます。秘密情報や不要な業務データは含めないでください。

## 完了チェック

- [ ] 正しいProjectと構築支援用Agentで依頼した
- [ ] 目的・入力・完成条件・変更しない範囲を伝えた
- [ ] 最新の計画を確認し、実行する範囲を決めた
- [ ] 計画への承認、実行開始、構築完了を区別した
- [ ] 作成・変更された対象を実際に開いて確認した
- [ ] テスト結果と、未実施・未確認の項目を分けた
- [ ] 残作業と公開・業務利用の判断担当者を明確にした
