# Storageの仕様・制限

Storageは、Projectで使うファイルとフォルダを保存・参照する場所です。本記事では、通常のStorage画面でファイルを扱う際に確認する仕様、上限、操作上の制約をまとめます。アップロードの手順は[Storageのファイルを利用する](../use/use-storage-files.md)、フォルダ構成の設計は[Storageのフォルダ構成を整える](organize-storage-folders.md)を参照してください。

- [Storageのファイルを利用する](../use/use-storage-files.md)
- [Storage API](../api/storage-api.md)
- [Hosted PageのStorage API](../page-runtime/hosted-page-storage-api.md)

## この記事の範囲

ここで扱うのは、Projectの通常の「ストレージ」画面における、ファイル・フォルダの作成、アップロード、検索、プレビュー、ダウンロード、移動、名前変更、削除です。

StorageトリガーはStorage上の変化を利用しますが、Workflowの設定機能です。本記事では起動対象になる変化と絞り込み条件だけを整理し、設定・公開・テストの手順は[Workflowトリガーを設定する](configure-workflow-triggers.md)を参照します。

Appが管理するファイル、API、Hosted Page内の操作、組織・Projectごとの権限や保存容量は対象外です。表示される操作や利用できる容量は、権限・機能設定・契約内容によって異なります。

## 通常機能の仕様

| 項目 | 仕様 | 補足 |
|---|---|---|
| 保存単位 | ファイルとフォルダをProject内で管理します。フォルダを開き、現在の場所に「フォルダ作成」または「ファイルアップロード」を行います。 | 一覧には「ファイル名」「アップロードしたユーザー」「変更日」「ファイルサイズ」などが表示されます。 |
| アップロード | 複数ファイルを選択してアップロードできます。ファイルをドロップしてアップロードできる画面もあります。 | 選択後は「アップロード開始」を行います。ダイアログが閉じたことではなく、「待機中」「アップロード中」「完了」「失敗」の状態や一覧で結果を確認してください。 |
| 受け付ける形式 | 既定の許可形式には、画像、動画、音声、テキスト、PDF、Word、Excel、PowerPoint、JSON、XML、ZIP・RAR・7z・TAR・GZIPなどがあります。 | 許可形式は環境設定で変更できます。ここにない形式を必ず拒否する、またはここにある拡張子なら必ず受け付ける、とは限りません。拡張子だけの書き換えで回避しないでください。 |
| 検索 | 「ファイル名で検索」で、現在開いている場所の一覧を絞り込みます。 | 検索結果がない場合も、Project全体に存在しないとは限りません。現在のフォルダと検索語を確認します。 |
| プレビュー | 「プレビュー」は、対応する画像、PDF、テキスト形式で利用できます。対応外の場合は「このファイル形式はプレビューに対応していません」と表示され、ダウンロードして確認します。 | PDFは先頭ページ、テキストは内容の一部を確認する用途です。プレビューの可否とアップロード可否は別です。 |
| ダウンロード | 個別ファイルをダウンロードできます。フォルダまたは選択した複数項目は「ZIPでダウンロード」できます。 | フォルダが空の場合はZIPを作成できません。取得後は内容と対象範囲を確認してください。 |
| パスの利用 | ファイルまたはフォルダで「パスをコピー（エージェントで使用可能）」を選べます。 | コピーした値は、同じProjectでAgentに対象を示すときに使えます。パスを知っているだけで閲覧権限が与えられるわけではありません。 |
| 同名時の処理 | 同じ場所に同じ名前のファイルがあると「ファイルが既に存在します」が表示されます。 | 「置き換え」は既存ファイルを新しいファイルで置き換えます。「両方保持」は新しいファイル名に番号を加えます。既存ファイルが「アップロード中」の場合は、完了を待ちます。 |
| 名前変更 | ファイル・フォルダで「名前を変更」を利用できます。ファイルは拡張子を保ったまま名前部分を変更します。 | 同名があると競合を解決する必要があります。変更後の名前・パスを、参照しているAgent、Workflow、Pageで確認してください。 |
| 移動 | ファイル・フォルダを「移動」できます。移動先に同名項目がある場合は、置き換えまたは両方保持を選びます。 | 同じ場所は移動先に選べません。複数項目の操作では、一部だけ失敗する場合があります。 |
| 削除 | ファイルを「削除」できます。フォルダを削除すると、配下のファイルとフォルダも対象になります。 | 通常画面では「この操作は元に戻せません」と表示され、復元操作は提供されません。削除前に配下と参照元を確認してください。 |
| 組織ドライブの他者作成項目 | 組織ドライブでは、非管理者が他者作成の完了済みファイルを削除しようとすると、画面側で削除を止めます。フォルダを含む削除はサーバー側でも項目ごとに権限確認されます。 | 一括削除では項目ごとに成功・失敗が返り、権限がない項目は「Permission denied」となる場合があります。フォルダに対する作成者・管理者ごとの詳細な許可条件は、この資料では断定しません。 |
| アプリ管理のファイル | 「インストール済みアプリ」と表示されるアプリ管理のシードファイルは読み取り専用です。 | 通常の「名前を変更」「移動」「削除」の対象にできません。変更が必要な場合は、アプリの更新またはアンインストールについて担当者に確認します。 |

## 上限・制限値

以下は、指定時点の実装で数値を確認できる値だけです。組織・Projectに割り当てられる保存容量は契約・設定で変わるため、固定値としては記載しません。

| 項目 | 仕様 | 補足 |
|---|---|---|
| 1ファイルの最大サイズ | 既定値は**2GB**です。 | 環境設定で変更できます。実際にアップロードできるかは、この値に加えて組織に設定された保存容量の残りと権限により決まります。 |
| 名前の長さ | ファイル名・フォルダ名は、前後の空白を除いて**1〜255文字**です。 | 空白だけ、`/`、制御文字、`.`・`..`、予約された名前は使えません。名前は前後の空白を除いて扱われます。 |
| プレビュー対象の最大サイズ | **10MB**までです。 | これはアップロード上限ではなく、プレビュー生成の上限です。10MBを超えるファイルはダウンロードして確認します。 |
| テキストのプレビュー | 最大**100行**かつ最大**10,000文字**までです。 | 対応テキスト形式のプレビューで表示する範囲です。ファイル全体の内容確認にはダウンロードを利用します。 |
| フォルダ／複数選択のZIPダウンロード | 既定値は合計**100MB**までです。 | フォルダ配下、または選択対象のファイル合計サイズが対象です。環境設定で変更できます。空のフォルダはダウンロードできません。 |
| 一括削除 | 1回に最大**100件**です。 | ファイルとフォルダを合わせた選択数です。結果は一部成功・一部失敗になる場合があります。 |

ファイル保存容量とデータ保存容量は、組織ごとの設定値と現在の使用量で判定されます。一律の容量値は確認できないため、画面に表示される上限・残量を確認してください。

プレビューに対応するMIMEタイプは、JPEG、PNG、WebP、GIF、SVG、PDF、TXT、JSON、Markdown、CSV、XMLです。画像・PDFは表示用の画像として、テキストはテキストとして確認します。Office文書、動画、音声、圧縮ファイルなどは通常のアップロード対象であっても、プレビュー対象ではありません。

## Storageトリガーで対象にできる変化

ストレージトリガーでは、「対象フォルダ」と「サブフォルダも含める」を指定し、次の「イベントタイプ」を1つ選択します。

| 項目 | 仕様 | 補足 |
|---|---|---|
| フォルダ：新規作成 | 対象フォルダ内でフォルダが新規作成されたときに起動します。 | ファイル属性がないため、ファイル名・拡張子・ファイルサイズのフィルターは使えません。 |
| ファイル：新規アップロード | 対象フォルダ内へ新しいファイルが追加されたときに起動します。 | ファイルの追加を入力として使う場合は、出力用フォルダを対象外にすることを検討します。 |
| ファイル：更新 | 既存ファイルが更新されたときに起動します。 | 同名時に「置き換え」を選ぶ運用では、更新イベントになることを前提にテストします。 |
| ファイル：削除 | ファイルが削除されたときに起動します。 | 削除後に元ファイルの内容を読む設計にはしません。 |
| フィルター | ファイル名は「一致」「含む」、拡張子は「末尾一致」、ファイルサイズは「以上」「以下」で絞り込めます。 | 複数のフィルターは、グループ内ではor、グループ間ではAndとして組み合わせます。ファイルサイズの値の単位はバイトです。 |

トリガーを有効にするにはWorkflowの公開が必要です。対象フォルダ、サブフォルダの扱い、イベントタイプ、フィルターを設定した後、実際のファイル操作で起動結果を確認してください。

## よくある誤解

### Storageへ置けば、すべてのAgentやDatasetが自動で読める

Storageへの保存、会話への添付、Datasetへの取り込みは別の操作です。Agentで使う場合は「パスをコピー（エージェントで使用可能）」で対象を指定し、必要な権限と利用可能な機能があることを確認します。Datasetの検索対象にしたい場合は、Dataset側の取り込み・同期設定が必要です。

### プレビューできない形式は、アップロードもできない

プレビュー対象は限定されています。プレビューできない場合でも、通常の許可形式であり、保存容量・権限などの条件を満たしていればアップロードやダウンロードはできます。逆に、プレビューが表示されたことだけで、ファイルの内容や全ページを確認したことにはなりません。

### 「両方保持」は、常に同じ名前の別版を残す

「両方保持」では、新しいファイルまたは項目に番号が追加されます。既存のパスを参照しているAgentやWorkflowが、新しい番号付きの項目を自動的に参照するとは限りません。保存後の実際の名前と参照先を確認してください。

### 名前変更・移動をしても、参照先は自動で追従する

Storage画面からは、すべての参照先が自動更新されることを確認できません。参照中のAgent、Workflow、Page、利用手順を確認し、変更後に利用者の操作と自動実行の両方をテストしてください。

### 削除はごみ箱からすぐ戻せる

通常画面には復元操作がありません。削除の確認画面でも元に戻せない旨が表示されます。不要と確定するまで、削除ではなく移動や保管を検討してください。

## 確認できない場合

アップロードできない、操作が表示されない、保存容量が不足した、またはプレビュー・ZIPダウンロードに失敗した場合は、次を順に確認します。

1. 対象のProject、現在のフォルダ、ファイル名、ファイルサイズを確認します。
2. 一覧の「待機中」「アップロード中」「完了」「失敗」と、表示されたエラーを確認します。
3. 「置き換え」か「両方保持」かを判断できない場合は、既存ファイルの変更日・サイズ・用途を確認し、更新担当者へ相談します。
4. 名前変更・移動・削除の前後では、参照しているAgent、Workflow、Pageで実際に使えることを確認します。
5. 解決しない場合は、Project名、フォルダ、ファイル名、操作日時、行った操作、画面の表示またはエラーを添えて管理者・担当者へ連絡します。機密情報や一時的なダウンロードURLは不要な範囲へ共有しません。

契約・設定に依存する保存容量、権限、許可形式は、画面に表示される情報と管理者の案内を正とします。固定の数値として推測しないでください。
