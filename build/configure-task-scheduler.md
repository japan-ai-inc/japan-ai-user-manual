# タスクスケジューラを設定する

Studioでは、従来のWorkflowとタスクスケジューラが**「タスク」**にまとまりました。タスクを使うと、Agentタスクや公開済みWorkflowを、定められた日時・繰り返し・各Workflowの開始トリガーで実行し、設定や履歴を一か所で管理できます。

この記事では、「タスク」ページで実行対象を見つけてタスクを作成し、スケジュール・通知・実行結果を確認する流れを説明します。

旧Workflow／旧タスクスケジューラーのURLを開ける環境では、「タスク」への移行案内が表示される場合があります。移行期間中に旧画面を開けても、日常の作成・実行・設定・履歴確認は、以下の「タスク」ページを入口にします。

- 自動実行方式の選び方：[自動実行方式を選ぶ](../getting-started/choose-execution-method.md)
- Workflowの開始トリガーを設定する：[Workflowトリガーを設定する](configure-workflow-triggers.md)

## タスクスケジューラとは

「タスク」は、以前のWorkflow一覧とタスクスケジューラに分かれていた作成・利用・管理の入口です。ナビゲーションの**「その他の機能」**から**「タスク」**を開けます。よく使う場合はサイドバーに固定できます。

| タブ | 主な用途 |
|---|---|
| **使っているもの** | 自分が利用するタスクの状態、実行、履歴、設定を確認する |
| **探す** | 同僚が公開したWorkflowやAgentタスクの定義を探し、自分用のタスクを作成する |
| **作る** | AgentタスクまたはWorkflowを作成・編集・公開する |

「タスク」は実行を管理する入口であり、Workflowの開始ノードで設定するイベントトリガーを置き換えるものではありません。日時・繰り返しで動かすAgentタスクと、Workflowに設定されたメール受信・Webhookなどの開始トリガーは、対象や設定方法が異なります。

| 実行方法 | 主なきっかけ | 設定・確認する場所 |
|---|---|---|
| Agentタスクのスケジュール | 日時、繰り返し、文字起こしの完了（利用できる場合） | 「タスク」の作成・設定画面 |
| Workflowタスク | Workflowに定義された開始トリガー | Workflowの開始ノード。自分用タスクの状態・接続・入力は「タスク」で確認 |

## 始める前に

- 実行するAgentまたはWorkflowと、対象の組織・Projectを確認します。
- Workflowを使う場合は、作成者が公開済みであり、自分に利用が許可されていることを確認します。
- 実行・作成・Workflowの作成または公開に必要な権限を確認します。組織の設定や権限により、表示できるタブや操作は異なります。
- 接続、必須入力、Webhookシークレットが必要なWorkflowでは、それらを用意します。未設定のままではタスクを作成できない、または有効にできない場合があります。
- 外部サービスへ送信・更新する処理では、繰り返し実行や手動実行で重複しても問題ないかを確認します。

## 1. 「タスク」を開き、実行対象を選ぶ

1. ナビゲーションの**「その他の機能」**から**「タスク」**を開きます。
2. 既に作成したタスクを確認・変更する場合は、**「使っているもの」**を選びます。
3. 公開済みの定義から自分用のタスクを作る場合は、**「探す」**を選び、名前・説明で検索します。
4. 新しいAgentタスクまたはWorkflowを作る場合は、**「作る」**で**「新規作成」**を選び、**「新規エージェントタスク」**または**「新規ワークフロー」**を選びます。

Agentタスクを作るときは、名前、説明、Agent、プロンプト、既定のスケジュール、公開範囲、組織での実行を設定します。保存しただけでは、公開済みの定義を使う利用者には反映されません。利用させる準備ができたら公開し、公開範囲を確認してください。

Workflowを作る場合は、キャンバスでノードと開始方法を設定します。Workflowの構成・テスト・公開は、[Workflowのノードを構成する](configure-workflow-nodes.md)〜[Workflowを公開する](publish-workflow.md)を参照してください。

## 2. 公開済みの定義からタスクを作成する

「探す」で対象を選び、**「タスクを作成」**を選択します。同じ定義から複数のタスクを作ることもできます。作成画面では、少なくとも次を確認します。

| 項目 | 確認すること |
|---|---|
| 名前 | 一覧で区別できる名前になっているか |
| 実行対象 | 実行するAgentまたはWorkflowが意図どおりか |
| 接続 | 必要な接続が「接続済み」か。再認証が必要な接続がないか |
| 入力項目 | 必須の入力項目と初期値が業務に合うか |
| Webhookシークレット | 署名を検証するWebhookでは、送信元と同じシークレットを安全に入力したか |
| 通知先 | 成功・失敗を誰が受け取るか |
| 状態 | 作成後すぐに有効にするか |

Workflowから作るタスクでは、Workflowの開始トリガーやスケジュールを作成者側で管理している場合があります。この場合、作成画面に**「この定義の実行タイミングは作成者が決めており、変更できません。」**と表示されます。日時やイベントの種類を自分の判断で置き換えるのではなく、必要に応じてWorkflowの作成者に変更・再公開を依頼してください。

必要な接続、必須入力、Webhookシークレットがそろわないと、タスクを作成できないことがあります。表示された不足項目を解消してから作成します。Webhook URLやシークレット、接続の認証情報を、チャット・チケット・画面共有に転記しないでください。

## 3. スケジュールを設定する

日時・繰り返しを設定できるタスクでは、**「頻度」**と**「実行日時」**を確認します。設定できる候補はタスクの種類によって異なります。

| 繰り返し | 実行のされ方 |
|---|---|
| 繰り返さない | 指定日時に1回実行する |
| 1時間ごと | 1時間ごとに実行する |
| 毎日 | 指定した時刻に毎日実行する |
| 平日 | 平日の指定時刻に実行する |
| 1週間ごと／1ヶ月ごと | 指定した曜日または日を基準に繰り返す |
| カスタム | 実行する曜日と繰り返し間隔を指定する |

カスタムの繰り返し間隔は、10・15・20・30分、または1・2・3・4・6・8・12・24時間から選択します。繰り返しを終わらせる必要がある場合は、**「終了日」**を設定します。

タスクに保存されているタイムゾーンと、**「次回実行」**の表示を必ず確認してください。指定時刻に開始することや、その時刻までに完了することは保証されません。締め切りがある業務では余裕を持って設定します。

> トリガーで動くWorkflowタスクには、編集できるスケジュールがありません。イベントによる開始条件は、Workflowの開始ノードで確認します。

## 4. 通知を設定する

作成画面または既存タスクの**「設定」**で、**「通知」**を設定します。通常、次の通知方法を複数選択できます。

| 通知先 | 追加で必要な設定 |
|---|---|
| 通知センター | なし |
| メール | メールアドレス |
| Slack | Slack Webhook URL |
| Chatwork | Chatwork APIトークン、Chatworkルーム ID |

外部の通知先を選ぶと、**「通知に出力を表示」**を設定できます。出力やエラーには機密情報が含まれることがあるため、通知先の閲覧範囲を確認し、必要最小限にします。通知の詳しい設定と運用は、[実行結果の通知を設定する](../operations/configure-run-result-notifications.md)を参照してください。

## 5. 作成後に「使っているもの」で確認する

作成後は**「使っているもの」**で対象の行を確認します。一覧には、名前、作成元、状態、実行、次回実行、前回の結果が表示されます。

1. 状態が**「有効」**になっていることを確認します。組織で停止中の場合は、ここで有効にしても実行されません。
2. スケジュールがあるタスクでは、**「次回実行」**が意図どおりか確認します。
3. 接続・入力・Webhookシークレットが不足している場合は、状態に表示される**「接続が必要」**、**「入力が必要」**、**「Webhookシークレットが必要」**を確認し、**「設定」**で解消します。
4. 必要に応じて行のメニューから**「実行」**を選び、開始するトリガーを選択して1回実行します。手動実行は実際の処理を起動するため、外部送信・更新の影響を確認してから行います。
5. **「履歴」**で対象タスクの実行結果を確認します。すべての自分のタスクをまとめて確認する場合は、**「実行履歴（全タスク）」**を使います。

## 実行されなかった・失敗した場合

まず「使っているもの」の状態、設定、履歴を確認します。代表的な表示と対応は次のとおりです。

| 表示・状態 | 対応 |
|---|---|
| **「有効にすると実行できます」** | タスクを有効にする前に、必要な入力・接続・通知先を確認します。 |
| **「組織で停止中のため実行できません」** | 組織側で実行が停止されています。管理者に確認します。 |
| **「このタスクはまだ実行できません。次の設定を完了してください: …」** | 表示された接続、入力、Webhookシークレットなどを設定します。 |
| **「タスクを実行できませんでした。」** | 履歴、対象のAgent・Workflow、接続、入力、組織の利用条件を順に確認します。 |
| **「このワークフローは組織で停止中のため、タスクを作成できません。」** | Workflowの作成者または管理者に、組織での実行状態を確認します。 |

Workflowのノード、入力、出力を詳しく調べる場合は、[Workflowの実行履歴でデバッグする](debug-workflow-run-history.md)を参照してください。失敗した処理に外部への送信や書き込みが含まれる場合は、履歴と処理先を確認するまで繰り返し実行しないでください。

## 作成後の変更・停止

「使っているもの」の対象行で**「設定」**を開くと、タスク名、通知、状態、入力、接続、スケジュールなど、画面で編集できる項目を変更できます。Workflow自体が持つ開始トリガーでは、**「ワークフロー自体のトリガーです。ワークフローを公開すると更新されるため、変更はワークフローで行ってください。」**と表示されます。この場合は、Workflowを編集・テスト・公開して変更します。

一時的に止めるときは状態を**「無効」**にします。不要になったときは**「このタスクを削除」**を使います。タスクを削除しても、通常は元のWorkflowや他のタスクには影響しません。ただし、Workflowの開始トリガーや外部システムのWebhook設定が残っている可能性があるため、自動実行全体を止める場合は両方を確認してください。

変更・停止・担当交代の手順は、[定期実行を変更・停止・引き継ぐ](../operations/change-stop-handover-scheduled-runs.md)を参照してください。
