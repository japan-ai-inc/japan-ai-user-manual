# タスクスケジューラを設定する

Studio Projectでは、Projectの設定にある**タスクスケジューラ**で、AgentまたはWorkflowの実行タスクを作成・管理します。この記事では、日時実行の設定、通知、実行履歴の確認を扱います。

- 自動実行方式の選び方：[自動実行方式を選ぶ](../getting-started/choose-execution-method.md)
- Workflowのイベント起動：[Workflowトリガーを設定する](configure-workflow-triggers.md)

## タスクスケジューラの範囲

対象Projectの設定で「タスクスケジューラ」を開きます。画面には**「タスク一覧」**と**「履歴」**のタブがあります。

| 対象 | 設定する場所 | 使い分け |
|---|---|---|
| 日時・繰り返しで起動するタスク | タスクスケジューラのタスク一覧 | 実行日時、繰り返し、終了日、通知先を設定する |
| Workflowのイベント起動 | Workflowの開始ノード | Webhookなど、イベントを受けて起動する条件を設定する |

タスクスケジューラはProject単位の設定です。Workflowの開始ノードに設定するイベント起動を置き換えるものではありません。

## 始める前に

- 対象のProject、実行するAgentまたはWorkflow、利用する接続と入力を確認します。
- 外部サービスへ送信・更新する処理では、定期実行や「実行」による重複の影響を確認します。
- タスクの作成・更新・削除、実行に必要なProject権限を確認します。表示される操作は権限によって異なります。

## 1. タスクを作成する

1. 対象Projectの設定で**「タスクスケジューラ」**を開き、**「タスク一覧」**を選びます。
2. **「新規作成」**を選びます。
3. 実行対象としてAgentまたはWorkflowを選び、名前、必要な入力、接続を確認します。
4. 日時実行では、実行日時と繰り返しを設定します。Workflowを対象にする場合は、Workflowの入力も確認します。
5. 通知先を設定し、内容を確認して作成します。

Studio Projectで選べる起動方法はタスクの種類によって異なります。日時実行はAgentとWorkflowで使えます。WebhookはWorkflowを対象とするタスクで設定できます。文字起こし完了の起動は、Studio Projectのタスク作成画面では選択できません。

必要な入力が不足すると保存できず、実行対象側の接続が使えないと実行に失敗する場合があります。Workflowを対象とするWebhookタスクでは、保存後に生成・表示されるWebhook URLを使用します。このURLはSlack通知用のWebhook URLとは別です。Webhook URLや接続の認証情報をチャットやチケットへ転記しないでください。

## 2. 日時と繰り返しを設定する

日時実行では、実行日、時刻、繰り返しを設定します。繰り返しには、繰り返さない、毎時、毎日、平日、毎週、毎月、カスタムが表示されます。

カスタムでは実行する曜日と間隔を設定します。間隔は10・15・20・30分、または1・2・3・4・6・8・12・24時間から選びます。繰り返しを終了する場合は終了日を設定します。

この画面の実行時刻は日本時間（JST）で設定します。ブラウザのタイムゾーンが日本時間と異なる場合の警告と、保存後の次回実行を確認してください。指定時刻に開始することや、その時刻までに完了することは保証されません。締め切りがある業務では余裕を持って設定します。

## 3. 通知を設定する

作成または編集画面の**「通知先」**で、通知センター、メール、Slack、Chatworkを選択できます。メールにはメールアドレス、Slack通知にはSlack Webhook URL、ChatworkにはAPIトークンとルームIDが必要です。

通知センター以外を選ぶと、**「通知に出力を表示」**を設定できます。出力やエラーには機密情報が含まれることがあるため、宛先と表示範囲を必要最小限にします。詳しい運用は[実行結果の通知を設定する](../operations/configure-run-result-notifications.md)を参照してください。

## 4. 作成後に確認する

**「タスク一覧」**で、対象のタスクの状態、実行日時、繰り返し、通知先を確認します。必要に応じて、操作メニューから編集、削除、または**「実行」**を選べます。

「実行」は、日時実行タスクで予定時刻を待たずに実際の処理を開始します。無効なタスクやWebhookタスクでは利用できません。外部への送信・更新がある場合は、入力と処理対象を確認してから実行してください。

実行結果は**「履歴」**で、日時、状態、結果、エラーの詳細を確認します。Workflowの実行結果は、表示されるリンクからWorkflowの結果を開ける場合があります。失敗した処理に外部送信や書き込みが含まれる場合は、処理先も確認してから再実行を判断してください。

## 5. 変更・削除

タスク一覧の編集で、名前、実行対象、入力、通知先、日時・繰り返し、終了日などを見直します。Agent／Workflowの種類と、スケジュール／Webhookなどの起動方法は、作成後には切り替えられません。変更前後に、直近の予定実行と外部処理への影響を確認してください。

不要になったタスクを削除する前には、履歴を残す必要、Webhookの呼び出し元、関連するWorkflowの開始ノードを確認してください。タスクを削除しても、対象のAgentやWorkflow自体を削除する操作ではありません。Studio Projectのこの画面で、既存タスクを一時停止・再開する操作は確認できていません。予定実行を止める必要がある場合は、削除による影響と代替手順を確認してください。
