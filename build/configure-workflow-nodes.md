# Workflowのノードを構成する

Workflowで行う仕事を、小さな処理に分けてつなぎます。この記事では、**Project内でWorkflowを作成し、ノードを追加・接続・設定して、処理の骨格を下書きとして保存する手順**を説明します。

ノード間で値を渡す具体的な操作は[Workflowの変数・分岐を設定する](configure-workflow-variables-and-branches.md)、実行による検証は[Workflowの下書きをテストする](test-workflow-drafts.md)で扱います。この記事の完了は、業務利用できることや公開済みであることを意味しません。

## 始める前に

- 対象の組織・Projectと、Workflowを作成・編集できる権限を確認します。
- 既存Workflowを変更する場合は、利用者と変更の影響を確認します。初めての練習には、検証用のWorkflowを使います。
- 入力する情報、処理の順序、最後に返す結果を決めます。
- 使用するモデル、Agent、Dataset、ツールなどが利用可能か確認します。
- 外部サービスを操作する場合は、接続に使うアカウントと読み取り・更新の範囲を確認します。

> **Workflowのノード編集では、画面に変更が見えていることと、下書きが保存されたことを分けて確認します。** Agent設定の自動保存と同じだと思い込まず、区切りごとに「一時保存」を選び、成功を確認してください。

画面の配置、追加できるノード、利用できる操作は、組織の設定や権限によって異なります。以下はパソコンの編集画面を中心にした説明です。

## 1. 入力・処理・出力に分ける

ノードは、Workflowを構成する処理の単位です。画面上では「ブロック」と表示される場合もあります。ノードを結ぶ線は、処理のつながりを表します。

最初は分岐や繰り返しのない、小さな流れを設計します。

### 構成例：商談メモを整理する

> 開始 → LLM → 終了

| 役割 | この例で行うこと | 設定時に決めること |
|---|---|---|
| 開始 | 商談メモを受け取る | 利用者が入力する情報と、その用途 |
| LLM | メモを要点・未確認事項・次の質問に整理する | モデル、指示、参照する入力 |
| 終了 | 整理した結果を返す | 返す値と、その名前 |

これは設計例であり、ノードを置くだけで完成するテンプレートではありません。開始で受け取ったメモをLLMへ渡し、LLMの結果を終了の出力に設定する必要があります。

**接続線と、値の受け渡しは別の設定です。** 線がつながっていても、前のノードの結果が次のプロンプトや入力欄へ自動的に入るとは限りません。

### ノードを選ぶ目安

| やりたいこと | ノードの候補 | 注意点 |
|---|---|---|
| 入力を受け取る | 開始 | 最初は手動実行を想定した入力から整理する |
| 文章の要約・分類・生成を行う | LLM | モデルとプロンプト、入力の参照を設定する |
| 作成済みAgentに仕事を依頼する | Agent | 対象Agent、入力、利用権限を確認する。モデル固定のAgentは既定モデルで実行され、変更できない |
| Datasetから情報を参照する | データ連携 | Datasetと検索に使う情報を設定する。全資料を必ず網羅する処理とは考えない |
| 外部サービス等の機能を使う | ツール | 対象の操作、入力、認証、外部への影響を確認する |
| 条件によって経路を分ける | IF ELSE、質問分類 | 分岐条件だけでなく各経路の接続・出力を設定する。詳細は[Workflowの変数・分岐を設定する](configure-workflow-variables-and-branches.md)で扱う |
| 最終結果を返す | 終了 | 出力名と、返したい値の参照先を設定する |

候補には、このほかにもコードやテンプレート処理などがあります。最初からすべてを使う必要はありません。選択画面に表示される候補と、必要な入力項目を確認して選びます。

## 2. Workflowを作成する

1. 対象の組織・Projectを開き、Workflowの一覧へ進みます。
2. **「新規作成」**を選びます。
3. **「ワークフローを作成」**の画面で、**「名前」**を入力します。
4. **「説明」**に、目的・入力・出力・検証用であることを記載します。
5. 表示される有効化などの設定を確認し、作成を確定します。
6. 編集画面が開いたら、Workflow名と作業対象を確認します。

例：

- 名前：商談メモ整理（検証用）
- 説明：入力された商談メモを要点・未確認事項・次の質問に整理する検証用Workflow。外部への送信やCRMの更新は行わない。

名前を空のままでは作成できません。作成操作が使えない場合は、対象Project、権限、画面の案内を確認してください。

「表示範囲」の選択は、開いている場所によって表示されない場合があります。**表示範囲・有効化・処理内容の公開は別の確認事項です。** Workflowを作成しただけで、公開や外部サービスの認証まで完了したとは扱いません。

入力欄へAPIキー、パスワード、トークンを貼り付けないでください。ノード内のプロンプトやコードも含め、Workflowの内容を誰が閲覧できるか確認します。

## 3. 初期構成と編集画面を確認する

初期構成には、**「開始」→「LLM」→「終了」**のノードと接続線が用意されています。保存済みWorkflowを開いた場合は、その下書きの構成が表示されます。新規作成時と同じ構成に戻す必要はありません。

各ノードを選択すると、そのノードの設定領域が開きます。ノードごとに入力項目は異なります。

確認する場所は、次の3つです。

| 場所 | 確認すること |
|---|---|
| ノードが並ぶ編集領域 | 必要な処理があるか、どの順に接続されているか |
| 選択したノードの設定領域 | 入力、モデル、指示、参照先、出力などが意図どおりか |
| Workflowの操作領域 | 一時保存、チェックリスト、公開状態など |

ノードを動かして見やすく並べられますが、**位置を入れ替えるだけでは処理順の変更になりません。** 順番を変える場合は、接続線と入力の参照先を確認します。「自動レイアウト」が表示される場合も、配置を整える機能として使い、業務ロジックの修正とは区別します。

## 4. 必要なノードを追加する

初期構成で目的を満たす場合は、ノードを追加せず、設定から始めてかまいません。

### 接続済みの2つのノードの間へ追加する

1. 追加したい位置の接続線を確認します。
2. 接続線上の**「＋」**を選びます。見つけにくい場合は線にポインターを合わせます。
3. 表示された候補から、追加するノードの種類を選びます。検索欄がある場合は名称で探します。
4. 追加後に、前のノード → 新しいノード → 次のノード、という接続になっているか確認します。
5. 新しいノードを選び、必要な設定を入力します。

途中へノードを挿入した場合、接続が組み替えられても、後続ノードの入力参照が新しい処理結果へ置き換わったとは限りません。挿入した処理を本当に後続で使うには、参照先も見直します。

### 次の処理を追加する

選択したノードの設定に**「次のブロックを追加」→「ブロックを追加」**が表示される場合は、そこから次のノードを選べます。次のノードがすでにつながっている場合などには、同じ追加ボタンが表示されないことがあります。

編集領域の別の場所に「ノードを追加」が表示される環境もあります。すべての画面に同じ追加ボタンがあるとは限らないため、表示されている入口を使います。

### 追加する前に外部への影響を確認する

ツールやAgentを組み込む場合は、読み取りだけか、送信・登録・更新を行う可能性があるかを確認します。構成を確認するためだけに「実行」や「公開」を選ばないでください。実行時には接続先で処理が行われる可能性があります。

## 5. ノードを接続する

接続線がない場合は、前のノードの出力側の接続点から、次のノードの入力側の接続点へドラッグします。

1. どの処理から、どの処理へ進めたいか決めます。
2. 出力側と入力側の接続点を確認してつなぎます。
3. 接続線が残っていることを確認します。
4. 開始から結果を返すところまで、意図した経路をたどれるか確認します。

ノードの種類によって、接続点の位置や数が異なります。分岐ノードでは、それぞれの分岐に対応した接続点を使います。詳しい分岐構成は[Workflowの変数・分岐を設定する](configure-workflow-variables-and-branches.md)で扱います。

### つなげない場合

次を確認します。

- 出力同士、入力同士をつなごうとしていないか。
- 同じノード自身へ線を戻そうとしていないか。
- 「終了」の後ろや「開始」の手前へ接続しようとしていないか。
- 前の処理へ戻る線によって循環を作ろうとしていないか。
- 繰り返し処理の内側・外側をまたぐ、許可されない接続になっていないか。
- 実行中など、編集できない状態ではないか。

繰り返したい処理がある場合も、後ろから前へ線を引けば実現できるとは考えないでください。繰り返し用の構成を検討します。

**接続できたことは、データの型や設定が正しいことの保証ではありません。** 後続ノードが必要とする情報を受け取れるかは、設定とテストで別途確認します。

## 6. 各ノードの中身を設定する

ノードを順に選び、「何を受け取り、何を行い、何を返すか」を確認します。名前や説明を編集できる場合は、「要点を整理」「回答案を作成」のように役割が分かる表現にします。

### 開始：受け取る情報を整理する

商談メモ整理の例なら、利用者が渡すメモを入力として定義します。「入力フィールド」で必要な情報を設定します。入力の種類や変数の指定は[Workflowの変数・分岐を設定する](configure-workflow-variables-and-branches.md)で詳しく説明します。

この段階で、自動実行のためのトリガーを追加する必要はありません。イベント起点・定期実行などの設定は[Workflowトリガーを設定する](configure-workflow-triggers.md)で扱います。

### LLM：モデルと指示を設定する

利用できるモデルを選び、処理の目的と出力形式を指示します。初期表示のままにせず、モデルとプロンプトの双方を確認してください。

指示の例：

> 渡された商談メモだけを根拠として、内容を「要点」「未確認事項」「次回の質問案」に整理してください。記載されていない金額・期限・担当者は推測しないでください。外部への送信やデータ更新は行わず、文章を返してください。

これは指示文の例です。別途、開始ノードの入力をプロンプトで参照する設定が必要です。「渡された商談メモ」と書いただけで、入力変数が結び付いたことにはなりません。

LLMノードと、作成済みAgentを呼ぶAgentノードは別の種類です。Agentの名前・指示・ツールがLLMノードへ自動で引き継がれるとは考えないでください。

### Agent：既定モデルと実行条件を確認する

Agentノードでは、対象Agentと依頼文に加え、前段から渡すファイルを選択できます。モデルが固定されているAgentは、そのAgentの既定モデルで実行されます。モデルを変更できるAgentでは、モデルを未選択にするとAgentの既定モデルを使い、必要な場合だけノード側でモデルを指定します。

ノード側で選べるモデルは、選択したAgentのモデル設定と利用可能なモデルにより異なります。Agentを切り替えた後は、前のAgent用に選んだモデルを引き継がず、既定モデルと選択可能な候補を確認してください。温度は0.0〜2.0、タイムアウトは60〜1,200秒で設定できます。

Agentの出力には、応答、ファイル、ツール呼び出しの情報が含まれる場合があります。後続ノードや終了ノードで何を使うかは、変数候補から確認して設定します。

### 終了：返す結果を設定する

最終結果の名前と、返したい値を指定します。商談メモ整理の例なら、LLMが作成した文章を出力に指定します。

終了ノードにつながっているだけでは、必要な結果がすべて出力されるとは限りません。出力の参照先を確認し、名称変更やノード差し替えの後は選び直しが必要でないか確認します。

### 設定欄を閉じることと保存を分ける

ノード設定で入力した内容は、編集中の構成へ反映されます。設定欄を閉じる操作を「入力のキャンセル」と考えないでください。一方で、編集中の構成に反映されたことだけでは、サーバーへの下書き保存を確認したことになりません。

## 7. 不要なノードや接続を整理する

不要なノードは、対象を確認してノードの操作メニューから削除できます。種類や状態によっては削除できないノードがあります。特に、手動の開始ノードを不要だと判断して無理に消そうとしないでください。

接続線だけを取り除く場合は、その線の削除操作を使います。ノード全体の削除とは分けて操作します。

削除・差し替え・複製の後は、次を確認します。

- 必要なノードや線まで消えていないか。
- 開始から結果までの経路が切れていないか。
- 残ったノードが、削除前のノードや出力を参照していないか。
- 複製したノードに、以前の参照先や接続先が残っていないか。

誤操作に気付いたときは、編集画面に表示される「元に戻す」などを確認します。ただし、編集の取り消しと、実行済みの外部操作を取り消すことは別です。削除した構成が必ず自動修復されるとも考えないでください。

## 8. チェックリストを確認して一時保存する

1. Workflowの**「チェックリスト」**を開きます。
2. 未接続、モデル・プロンプトの未設定、参照先の不備など、表示された項目を読みます。
3. 対象項目を選び、該当するノードの設定を確認します。
4. この段階で直せる不備を修正します。変数や分岐など後で設定する部分は、未完了として記録します。
5. **「一時保存」**を選びます。
6. 保存成功の通知を確認します。保存失敗や権限のエラーが出た場合は、完了と扱わないでください。
7. 成功を確認した後、必要に応じて編集画面を開き直し、ノード・線・設定が残っていることを確認します。

チェックリストは設定の見直しを助ける機能であり、業務結果が正しいことや、外部サービスの操作が成功することを保証するものではありません。指摘がなくても、実行による確認は必要です。

### 「一時保存」と「公開」を混同しない

| 操作・状態 | この段階での扱い |
|---|---|
| 基本設定の作成・変更 | 名前や説明などを登録する操作。ノード構成の保存とは分けて確認する |
| ノード設定の編集 | 編集中の構成を変更する操作。保存成功の確認が必要 |
| 一時保存 | ノードと接続を下書きとして保存する操作 |
| 公開 | 処理内容を利用可能な版として公開する別の操作。検証と影響確認を済ませてから行う |
| 表示範囲・利用権限 | 誰が見たり操作したりできるかの設定。下書き／公開済みとは別 |

**本記事では「公開」を選ばず、下書きの保存までで止めます。** 既存の公開済みWorkflowを編集している場合も、一時保存を公開版の更新と取り違えないでください。公開の詳細は[Workflowを公開する](publish-workflow.md)で扱います。

## うまくいかないとき

| 状況 | 確認・対応 |
|---|---|
| 新規作成や編集ができない | 組織・Project・権限と画面の案内を確認する |
| 追加したいノードが見つからない | 検索語、候補の分類、組織の提供設定を確認する |
| ノードを並べ替えたが順番が変わらない | 位置ではなく接続線と参照先を確認する |
| 線をつなげない | 入出力の向き、循環、開始・終了、繰り返し範囲、実行状態を確認する |
| 後続へ結果が渡らない | 接続だけでなく、入力変数・プロンプト・出力の参照を確認する |
| 削除後に警告が残る | 残ったノードが削除した出力を参照していないか確認する |
| 一時保存に失敗する | 表示されたエラーと権限を確認し、変更内容を保全する。保存前に再読み込みしない |
| 保存したが業務利用できない | 下書きの保存、公開、利用権限、認証を分けて確認する。確認せず公開し直さない |

問い合わせには、Workflow名、Project名、該当ノード、操作日時、接続と設定の状況、エラーを添えます。認証情報や機密データは含めないでください。
