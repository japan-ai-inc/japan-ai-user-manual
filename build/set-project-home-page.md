# ProjectのホームPageを設定する

Projectを開いた利用者に、最初に業務用のPageを表示したい場合は、ホームPageを設定します。ホームPageを設定すると、Projectの通常のダッシュボードではなく、選択したPageが最初に開きます。入力フォーム、受付画面、業務の入口となる案内画面などを最初に見せたい場合に利用します。

この設定は、Pageの登録・公開やアクセス条件の設定とは別です。先に利用するPageを用意し、表示・操作を確認してからホームPageに設定してください。Pageの登録とアクセス設定は、[画面からPageを登録・公開する](register-and-publish-pages.md)を参照してください。

## 始める前に

- 対象の組織・Projectと、ホームにするPageを確認します。ホームPageにするPageは、対象Projectに存在し、削除されていない必要があります。
- Projectの設定を編集できる権限があることを確認します。Projectを開けるだけでは、ホームPageを変更できるとは限りません。
- 利用者が最初に行う作業、表示するデータ、問い合わせ先を、Page内または案内文で分かるようにします。
- Pageの表示、入力、登録、送信など、利用者が行う代表的な操作を確認します。ホームPageに設定しても、Page内の処理や外部連携が正しく動くことは保証されません。
- Pageのアクセス設定と、利用者ごとの閲覧権限を確認します。ホームPageの設定は、Pageを閲覧できる人を追加する設定ではありません。

> ホームPageを設定すると、Projectを開いた利用者には通常のProjectナビゲーションが表示されない場合があります。構築用のメニューを隠したいのか、利用者がほかの画面へ戻れる必要があるのかを、設定前に決めてください。

## 1. ホームにするPageを準備する

まず、対象ProjectでPageを登録し、利用者向けの表示を確認します。Pageがまだない場合は、先に[画面からPageを登録・公開する](register-and-publish-pages.md)を実施してください。

| 確認項目 | 確認する内容 |
|---|---|
| 対象Page | Project、Page名、表示するバージョンが意図したものか |
| 利用者の入口 | 最初に読ませる説明、入力項目、操作の順番が分かるか |
| データと処理 | 表示する情報、登録・更新・送信先、外部接続の影響を確認したか |
| 権限 | 想定利用者がPageを閲覧・実行できるか。ホーム設定だけで権限が変わらないことを確認したか |
| 戻り方 | 通常のProject画面へ戻る必要がある利用者と、戻る入口を表示する範囲を決めたか |

> 検証用Page、編集中のPage、利用者に見せてはいけないデータを含むPageは、ホームPageに設定しないでください。設定後にProjectを開く利用者へ最初に表示されます。

## 2. 「プロジェクト設定」を開く

1. 対象のProjectを開きます。
2. Project内の「プロジェクト設定」を開きます。
3. 「基本設定」を開きます。
4. 「ホームページ設定」が表示されることを確認します。

「ホームページ設定」が表示されない場合は、Page機能が利用可能か、対象Projectの設定編集権限があるかを確認します。設定欄が表示されても、選択欄が操作できない場合は、権限またはPage一覧の読み込み状態を確認してください。

## 3. 「ホームページ」で最初に開くPageを選ぶ

1. 「ホームページ設定」の説明を確認します。ここでは「プロジェクトを開いたときに最初に表示するページ」を選択します。
2. 「ホームページ」の選択欄を開きます。
3. 一覧から、利用者に最初に見せるPageを選択します。
4. 「更新しました」と表示されることを確認します。
5. いったんProjectを開き直し、選択したPageが最初に表示されることを確認します。

選択できるのは、対象ProjectにあるPageです。存在しないPageや削除済みのPageをホームPageとして保存することはできません。Page一覧の読み込みに失敗した場合は、「ページ一覧の読み込みに失敗しました」と表示されるため、「再試行」で一覧を取り直してから選択してください。

ホームPageの選択は、選択時に更新されます。別途「保存」ボタンを探すのではなく、成功または失敗のメッセージと、開き直したときの表示を確認してください。更新に失敗した場合は、画面上の選択が元に戻るため、通信状態、権限、対象Pageを確認してから再試行します。

### ホームPageを設定しない場合

「ホームページ」で「デフォルト (ダッシュボード)」を選択すると、ホームPageの指定を解除できます。解除すると、ホームPageに関連する「Studioに戻る」ボタンの表示設定やページナビゲーションの設定も解除されます。解除後は、Projectの通常のダッシュボードが最初に表示されることを確認してください。

## 4. 「Studioに戻る」ボタンの表示を決める

ホームPageを選択すると、「「Studioに戻る」ボタンの表示」を設定できます。これは、ホームPage上から通常のProject画面へ戻るボタンを、誰に表示するかを決める設定です。

| 選択肢 | 利用場面 |
|---|---|
| 「全ユーザー」 | 利用者も通常のProject画面へ戻る必要がある場合 |
| 「編集権限を持つユーザー」 | 構築・管理を行う人だけが通常画面へ戻ればよい場合 |
| 「非表示」 | 利用者には業務用Pageだけを案内したい場合 |

1. 「「Studioに戻る」ボタンの表示」を開きます。
2. 想定する利用者に合う選択肢を選びます。
3. 「更新しました」と表示されたことを確認します。
4. 必要に応じて、編集権限を持つ利用者と持たない利用者の両方で、ボタンの表示を確認します。

> 「非表示」にすると、ホームPageから通常のProject画面に戻るボタンは表示されません。利用者がほかのPageや機能へ進む必要がある場合は、Page内の案内や次の「ページ切り替え」の設定を先に確認してください。

## 5. 必要な場合だけ「ページ切り替え」を設定する

組織の機能設定でページナビゲーションが有効な場合は、「ページナビゲーション」に「ページ切り替えを有効にする」が表示されます。これはホームPageのヘッダーから移動できるPageを選ぶ設定です。表示されない場合は、この設定を利用できないため、ホームPageと戻るボタンの確認までで完了です。

1. 「ページ切り替えを有効にする」をオンにします。
2. 「表示するページを選択」で、利用者に案内するPageを選びます。選択できるのは最大100件です。
3. 更新完了を確認します。
4. ホームPageを開き、ヘッダーから選択したPageへ移動できることを確認します。

ページナビゲーションは、Pageの閲覧権限を変更しません。利用者に閲覧権限がないPageは、選択していてもその利用者が移動できるPageとして表示されません。また、設定したPageが削除された場合は、残っている利用可能なPageだけを対象に確認し、設定を見直してください。

## 6. 利用者の状態で確認する

設定者の画面だけでなく、実際の利用者に近い状態で確認します。

1. 対象Projectを開き直します。
2. ホームPageが最初に表示されることを確認します。
3. 表示する情報、入力欄、主要な操作、処理結果の確認先を確認します。
4. 「Studioに戻る」ボタンとページ切り替えを設定した場合は、想定した利用者にだけ必要な入口が表示されることを確認します。
5. 閲覧権限の異なる利用者で確認できる場合は、Pageを開けるか、ナビゲーションに不要なPageが出ていないかを確認します。

設定されたホームPageが削除されるなどして取得できない場合、Projectを開いたときは通常のダッシュボード表示へ切り替わります。一方、Pageへの閲覧権限がない、認証に失敗する、またはPageの読み込みに失敗する場合は、ホームPageの表示エラーになることがあります。利用者に代替のURLや設定変更を求める前に、Pageのアクセス設定、利用者の権限、認証状態、Pageの存在を確認してください。
