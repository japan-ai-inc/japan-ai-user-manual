# Workflowの実行履歴でデバッグする

Workflowが期待どおりに動かないときは、**実行履歴**で各ノードの入力・出力を確認し、問題のある箇所を特定します。この記事では、履歴の探し方、詳細の読み方、原因の絞り込み、失敗した実行の再実行を説明します。

- 下書きのテスト：[Workflowの下書きをテストする](test-workflow-drafts.md)
- 利用者として結果を確認する場合：[公開済みWorkflowを実行する](../use/run-published-workflow.md)

## 2つの履歴を使い分ける

Workflowの履歴は、確認したい版によって見る場所が異なります。

| 見る場所 | 対象 | 主な用途 |
|---|---|---|
| 編集画面の「実行履歴」 | 編集画面から実行した下書きのテスト | 公開前の動作確認 |
| **「タスク」＞「使っているもの」**の「履歴」 | 作成したタスクの実行 | タスク単位の実行結果の確認 |
| Workflowの実行ログ | 公開版の実行を管理者が確認する場合 | 公開後の不具合調査 |

> 編集画面でのテスト実行は、公開版やタスクの履歴とは区別して確認します。どの履歴に表示されるかは、実行した入口・権限・Workflowの構成により異なります。
>
> 旧WorkflowページのURLを開ける環境では、「タスク」への移行案内が表示される場合があります。旧画面を主要な履歴確認の入口としては扱わず、まず「タスク」または編集画面から、確認したい実行に対応する履歴を開いてください。

## 始める前に

- 調べたい実行の、おおよその日時・実行者・起動方法（手動／トリガー）を確認します。
- 実行履歴を閲覧できる権限があることを確認します。見られる範囲は組織やProjectの設定によって異なります。
- 実行の入力・出力には、メール本文や顧客情報などの機密情報が含まれることがあります。画面共有やファイルの受け渡しの範囲に注意してください。

## 1. 対象の実行を探す

### タスクから確認する場合

1. ナビゲーションの**「その他の機能」**から**「タスク」**を開きます。
2. **「使っているもの」**で対象のタスクを探します。状態、実行、次回実行、前回の結果を照合します。
3. 対象行のメニューから**「履歴」**を選びます。自分のタスクをまとめて調べる場合は、**「実行履歴（全タスク）」**を選びます。
4. 状態、日時、対象タスクを照合して、調べる実行を特定します。

### Workflowの実行ログから確認する場合

Workflowの公開版の実行を管理者として調べる場合は、「タスク」の**「作る」**で対象Workflowを確認し、利用できる場合は**「実行履歴」**を開きます。実行ログには、公開済みWorkflowの実行が表示されます。

実行者が「自動実行」と表示される実行は、トリガーやスケジュールなど、人が直接操作していない起動です。

## 2. 実行の詳細を読む

対象の実行を選ぶと「ログの詳細」が開きます。

| 表示 | 確認すること |
|---|---|
| 概要 | ステータス、経過時間、クレジット、エラーメッセージ |
| 結果 | Workflowの最終出力 |
| ステップ | 実行されたノードの順序と、各ノードの入力・出力 |

### ステータスの読み方

- **成功**：処理が最後まで完了したことを示します。**業務上正しい結果であることの保証ではありません。** 出力の内容も確認してください。
- **失敗**：途中のノードでエラーが発生しました。エラーメッセージと、ステップでの失敗箇所を確認します。
- **部分的成功**：一部の処理が完了していない可能性があります。どのノードまで期待どおりかをステップで確認します。
- **停止**：途中で停止されました。停止前に完了した処理が残っている場合があります。

## 3. 問題のあるノードを特定する

ステップを最初のノードから順に確認し、**値が最初に想定と異なったノード**を探します。エラーが出たノードより前に、原因があることがよくあります。

1. 開始ノードの出力（入力値やイベントの情報）が想定どおりか確認します。
2. 次のノードの入力に、前のノードの出力が正しく渡っているか確認します。
3. 各ノードの出力が、次の処理に必要な形式になっているか確認します。
4. 最初に想定と異なったノードを、修正の対象にします。

### よくある原因

| 症状 | 考えられる原因 | 確認先 |
|---|---|---|
| 入力が空になっている | 変数の参照先の誤り、別の経路の変数を参照している | [Workflowの変数・分岐を設定する](configure-workflow-variables-and-branches.md) |
| 想定と違う分岐に進んだ | 条件の演算子・値の誤り、「含む」の部分一致 | [Workflowの変数・分岐を設定する](configure-workflow-variables-and-branches.md) |
| AIの出力形式が崩れる | 指示の不足、出力形式の指定が曖昧 | 該当ノードのプロンプト |
| 外部サービスでエラー | 連携の失効、権限不足、相手先の制限 | 連携の状態・管理者 |
| トリガーで起動しない | 未公開、連携の失効、絞り込み条件 | [Workflowトリガーを設定する](configure-workflow-triggers.md) |
| タスクが実行できない | 無効、組織で停止中、接続・入力・Webhookシークレットの不足 | 「タスク」＞「使っているもの」の状態と「設定」 |

## 4. 実行データを保存する

詳細画面から、実行データをJSON形式でダウンロードできる場合があります。管理者や開発担当へ調査を依頼するときに添付すると、状況を正確に伝えられます。

> ダウンロードしたファイルには入力・出力がそのまま含まれます。保存先と共有相手に注意してください。

## 5. 失敗した実行を再実行する

トリガーなどイベントで起動した実行が失敗した場合、詳細画面に「再実行」が表示されることがあります。

1. 失敗の原因（連携の失効など）を先に解消します。
2. 「再実行」を選択します。
3. 確認画面の内容を確認し、「再実行する」を選択します。
4. 「再実行を開始しました」と表示されたら、一覧で新しい実行の結果を確認します。

- 再実行は、**保存された入力**で実行されます。入力を変更することはできません。
- 失敗前に完了していた書き込み（Objectへの保存など）がある場合、**再実行によってデータが重複する可能性があります。** 対象データを確認してから実行してください。
- 「再実行」は、失敗した実行のうち、イベントで起動した実行にだけ表示される場合があります。手動で実行した失敗をやり直す場合は、通常の実行画面または「タスク」の**「実行」**から改めて実行します。

## 6. 修正して確認する

1. 編集画面で、特定したノードを修正します。
2. 一時保存し、問題が起きた入力に近い値でテストします（[Workflowの下書きをテストする](test-workflow-drafts.md)）。
3. テスト結果を編集画面の「実行履歴」で確認します。
4. 問題が解消したら公開します（[Workflowを公開する](publish-workflow.md)）。
5. タスクまたは公開後の実行ログで、公開版の実行結果を確認します。

> 修正を公開しても、すでに失敗した実行の結果は変わりません。必要に応じて再実行や、手動での実行を行ってください。
