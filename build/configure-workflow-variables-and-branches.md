# Workflowの変数・分岐を設定する

Workflowのノードをつなぐだけでは、使いたい値が各処理へ渡るとは限りません。この記事では、**開始時の入力を定義し、前段の値を後段から参照して、条件に応じた接続先を設定する手順**を説明します。

ノードの追加・接続は[Workflowのノードを構成する](configure-workflow-nodes.md)を参照してください。ここでは設定と下書き保存までを扱います。実行結果の確認は[Workflowの下書きをテストする](test-workflow-drafts.md)で行います。

## 始める前に

- 対象の組織・Project・Workflowと、編集権限を確認します。
- 稼働中のWorkflowを変更する場合は、利用者と影響範囲を確認します。
- 入力する値、処理に使う値、最後に返す値を整理します。
- 外部送信・更新を行わない練習用の構成と、機密情報を含まない入力を用意します。
- ノードの名前を見て、役割と参照元を区別できる状態にします。

本記事はパソコンの編集画面と、手動開始のWorkflowを中心に説明します。トリガー由来の入力や利用できる候補は、構成・提供状態によって異なります。

> **入力欄の「保存」と、Workflow全体の「一時保存」は別です。** 入力項目やノード設定を編集した後は、Workflowの「一時保存」の結果まで確認してください。画面内で値が変わっただけでは、下書き保存の完了とは扱いません。

## 1. 変数名・表示名・値を区別する

変数は、Workflowの入力やノードの処理結果を参照するための項目です。

| 項目 | 役割 | 例 |
|---|---|---|
| 変数名 | 設定内で値を識別する名前 | `request_text` |
| ラベル名 | 入力する人に見せる名称 | 依頼内容 |
| 説明 | 入力する内容や注意点 | 要約したい依頼文を入力してください |
| 実際の値 | 実行時に入力・生成される内容 | 来週の説明会に向けて確認事項を整理したい |
| 参照元 | どのノードの値を使うか | 開始ノードの `request_text` |

同じ変数名が複数のノードに見える場合は、名前だけで判断せず、**参照元ノードと項目の組み合わせ**を確認します。

### 接続線と変数参照は別々に設定する

- **接続線**：処理をどのノードへ進めるかを表します。
- **変数参照**：そのノードで、どの値を使うかを指定します。

例えば「開始 → LLM → 終了」と接続しても、LLMのプロンプトに開始入力を指定することと、終了ノードにLLMの出力を指定することは、別途確認が必要です。

## 2. 開始ノードに入力フィールドを追加する

1. 手動開始の**「開始」**ノードを選択します。
2. **「入力フィールド」**の**「追加」**を選びます。
3. フィールドタイプ、変数名、ラベル名、説明を入力します。
4. 必要に応じて最大長・初期値・必須の設定を確認します。
5. 入力フィールドの画面で**「保存」**します。
6. 開始ノードの一覧に追加した項目が表示されていることを確認します。

### 練習用の入力例

| 項目 | 設定例 |
|---|---|
| フィールドタイプ | 段落 |
| 変数名 | `request_text` |
| ラベル名 | 依頼内容 |
| 説明 | 要約したい依頼文を入力してください。機密情報は入力しないでください |
| 最大長 | 想定する依頼文が収まる値を画面で設定 |
| 初期値 | 練習では空欄 |
| 必須 | 入力を必ず求める場合は有効 |

これは設定例です。初期値や上限を全Workflow共通の仕様として示しているわけではありません。

### 名前と型の注意

- 変数名・ラベル名・説明は入力が必要です。
- 変数名には空白を含めず、先頭をアンダースコアにしないでください。
- 同じ開始ノード内では、区別しやすい変数名を付けます。
- この入力画面では「段落」と「ファイルリスト」を選びます。数値や真偽値の専用入力が必ずあるとは考えないでください。
- 「段落」に数字を書いても、後段で数値として扱えると決めつけないでください。参照候補に表示される型を確認します。
- ファイルリストは、ファイルそのものと抽出した本文を区別します。本文を使いたい場合は、抽出処理や受け側の対応を確認します。

初期値を設定する場合は、入力省略時の意図と一致するかを確認します。必須・初期値・空欄を組み合わせた挙動は、後続のテストで確かめてください。

## 3. LLMへ開始入力を渡す

1. 開始ノードからLLMノードへ接続されていることを確認します。
2. LLMノードを選び、利用するモデルを確認します。
3. **「プロンプト入力」**へ処理の指示を記載します。
4. 値を挿入したい位置で半角の **`/`** を入力します。
5. 変数候補から、開始ノードの `request_text` を選択します。
6. 挿入された変数表示の参照元・項目を確認します。

例えば、次のように指示を組み立てます。

> 次の依頼内容を、要点・確認事項・次の行動の3項目で整理してください。入力にない日付や担当者は補わず、未確認としてください。
>
> 依頼内容：ここへ「開始 / request_text」を候補から挿入

最後の行は操作位置を示す説明です。**「ここへ挿入」という文章や、変数名の文字列をそのまま貼るのではなく、画面の候補から変数を選んでください。**

変数名を普通の文章として書いただけの状態と、変数が挿入された状態を区別します。前段の接続や項目名を変更した場合は、選び直す必要がないか確認してください。

### 変数が候補に出ないとき

| 確認すること | 見直し方 |
|---|---|
| 前段につながっているか | 画面上で左に置くだけでなく、接続線を確認する |
| 入力・出力が定義されているか | 参照元ノードの設定を開く |
| 受け側が扱える型か | 文字列・数値・ファイル・配列などを区別する |
| 繰り返しの内側か外側か | その場所で使える値と参照範囲を確認する |
| 古い参照が残っていないか | 変数名変更・ノード置換後は、現在の候補から選び直す |

参照候補は接続関係や受け側の設定に応じて作られます。すべてのノードの出力が、どこからでも選べるわけではありません。旧資料にある参照名を推測して手入力するより、現在の候補を使ってください。

## 4. 終了ノードで返す値を指定する

1. 処理ノードから**「終了」**へ接続します。
2. 終了ノードを選び、**「出力変数」**を開きます。
3. **「追加」**で出力項目を作成します。
4. 変数名に、例えば `result` を入力します。
5. **「変数を選択」**から、対象LLMノードの `text` を選びます。
6. 出力名だけでなく、参照先が正しいことを確認します。

この例では、LLMの文章出力を `result` という名前で返す設定にします。LLMが生成したすべての情報が自動的に最終出力へ含まれる、と考えないでください。

不要な出力を外す場合は、その値を利用するPageや別処理がないか確認します。公開済みWorkflowの出力名変更は、呼び出し側にも影響する可能性があります。

## 5. IF ELSEで条件分岐を設定する

決まった値や条件で経路を分けたい場合は、**「IF ELSE」**を使います。ここでは、依頼内容に特定の語が含まれるかで処理先を分ける設定例を扱います。

### 例：依頼内容に「至急」が含まれるかで分ける

1. 開始ノードの後に「IF ELSE」を追加し、接続します。
2. IF ELSEの設定を開き、**「条件を追加」**を選びます。
3. 開始ノードの `request_text` を選択します。
4. 比較演算子を**「含む」**にします。
5. 比較する値に `至急` を入力します。
6. ノード上の**「条件」**側の接続点から、優先確認用の処理へ接続します。
7. **「それ以外」**側の接続点から、通常確認用の処理へ接続します。
8. 各処理で使う入力変数と、その先の出力を確認します。

「条件」の線をつなぐだけでは、「それ以外」の接続も完了したことにはなりません。両方の経路を確認してください。

この例は、文字列を条件とする練習です。「至急ではありません」にも「至急」という文字が含まれます。**文字の一致と、文章の意味・業務上の緊急度は同じではありません。** この条件だけで実際の優先度を確定しないでください。

### 文字列と数値で選べる条件が異なる

| 対象の型 | 主な演算子 | 注意 |
|---|---|---|
| 文字列 | 含む、含まない、で始まる、で終わる、である、でない、空、空でない | 部分一致と一致判定を区別する |
| 数値 | =、≠、>、<、≥、≤、空、空でない | 数字を含む文章ではなく、数値型の候補か確認する |

現在のIF ELSEの変数選択は、文字列・数値を中心に扱います。ファイルやオブジェクトを直接選んで、同じ演算子を使えるとは限りません。

「空」など値の有無を調べる演算子は、通常の値比較とは分けて設定します。空文字・空白だけの入力・値そのものがない場合を同じものと考えず、必要なケースをテストしてください。演算子を変更した後は、比較値が残っていないか、必要な値が抜けていないかも確認します。

## 6. 条件の組み合わせと追加分岐を使い分ける

### 同じ分岐へ進む条件を増やす

同じケース内で「条件を追加」し、条件が複数になると表示される **AND／OR（and／or）** の切替を確認します。

- **AND**：すべての条件を満たす場合に、そのケースへ進むための設定。
- **OR**：いずれかの条件を満たす場合に、そのケースへ進むための設定。

例えば「至急を含む」と「見積を含む」を組み合わせる場合、両方が必要なのか、片方だけでよいのかを先に決めます。条件を増やした後にAND／ORを確認しないと、意図と異なる対象まで含む可能性があります。

### 異なる処理先を追加する

別の経路を増やす場合は、**「追加条件を追加」**を使います。追加したケースごとに、対象変数・演算子・比較値・接続先を設定します。

| 操作 | 目的 |
|---|---|
| 同じケース内の「条件を追加」 | 1つの分岐を判定する条件を増やす |
| 「追加条件を追加」 | 別の条件を持つ分岐先を増やす |
| 「それ以外」の接続 | 条件に該当しない入力の処理先を用意する |

複数ケースに当てはまる入力も用意し、期待する経路を確認します。最初は重複しない条件で組み立てると、確認しやすくなります。画面の並びだけから、業務上の優先順位が正しく実現できたとは判断しないでください。

## 7. 質問分類と使い分ける

文章の内容をモデルに分類させたい場合は、**「質問分類」**も候補になります。

| ノード | 設定の考え方 | 向いている例 |
|---|---|---|
| IF ELSE | 変数・演算子・比較値を指定する | 決まった文字列や数値条件で振り分ける |
| 質問分類 | モデル・入力変数・分類項目・必要に応じた指示を設定する | 依頼文を「製品の質問」「利用方法の質問」などに分類する |

質問分類では、モデルを選び、分類対象の入力変数と分類項目を設定し、各分類の接続点から処理先へつなぎます。必要に応じて高度な設定の指示を整えます。

IF ELSEと同じ「それ以外」の端点があるとは考えないでください。対象外・判断しにくい入力をどの分類で扱うかも設計し、テストで確認します。モデルによる分類は、正解率や毎回の一致を保証するものではありません。

## 8. 分岐の後も、使える値を確認する

分岐した構成では、候補に見える値が、その実行経路で必ず生成されるとは限りません。

- 分岐先のノードが、どの開始入力・前段出力を使うか確認します。
- 別の分岐でしか生成されない値を、当然に存在する前提で参照しないでください。
- 複数の分岐を同じノードへ接続しても、結果を自動的に統合できたとは考えないでください。
- 最終出力で返したい値が、各経路で用意されるかを確認します。
- ケースやノードを削除・置換した場合は、接続線と変数参照の両方を見直します。

複雑な合流を一度に作るより、まず各分岐の入力・処理・出力を整理し、1経路ずつ実行結果を確認する方針にします。

## 9. チェックリストを確認して一時保存する

1. 参照元・参照先・型・条件・接続先を見直します。
2. **「チェックリスト」**を開き、変数が見つからない、条件が未設定、ノードが未接続などの指摘を確認します。
3. 指摘された項目を修正します。後で設定するものは未完了として記録します。
4. **「一時保存」**を選び、成功表示またはエラーを確認します。
5. 保存が成功してから開き直し、入力項目・変数参照・条件・接続先が残っていることを確認します。

チェックリストの指摘がなくても、業務上正しい結果になるとは限りません。また、一時保存は公開ではありません。本記事では「公開」を実行せず、次の下書きテストへ進みます。

### 次の記事で確認する入力例

| ケース | 確認すること |
|---|---|
| 通常の入力 | 指定した変数が処理に使われ、期待する出力が返るか |
| 条件に一致する入力 | 意図した分岐へ進むか |
| 一致しない入力 | 「それ以外」など、想定した処理へ進むか |
| 「至急ではありません」などの文章 | 文字一致の条件が業務目的に合っているか |
| 空欄・初期値を使う入力 | 必須・初期値・空判定が期待どおりか |
| 複数ケースに一致する入力 | 想定した経路が選ばれるか |
| 数値の境界値 | `>` と `≥` などの違いが正しく設定されているか |

この表はテスト観点の提案です。自動テストが登録されたことや、実行確認が完了したことを意味しません。

## 困ったとき

| 症状 | 最初に確認すること |
|---|---|
| 入力フィールドを保存できない | 変数名・ラベル名・説明、画面の入力エラー |
| 変数が候補にない | 前段との接続、出力定義、型、繰り返し内外の範囲 |
| 変数名がそのまま文章に出る | 普通の文字列ではなく、候補から変数を挿入したか |
| 意図した分岐へ進まない | 対象変数、比較値、型、AND／OR、分岐端点の接続 |
| 最終出力が足りない | 終了ノードの出力名・参照先と、参照元が通る経路 |
| 変更が保存されていない | 入力画面の保存だけでなく、一時保存が成功したか |

解決しない場合は、Workflow名、ノード名、入力例、期待する経路、表示されたエラーを担当者へ伝えます。APIキーや不要な個人情報は含めないでください。
