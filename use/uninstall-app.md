# Appをアンインストールする

使わなくなったAppを終了するときは、利用者・データ・自動実行・料金への影響を確認してからアンインストールします。この記事では、**導入方式を見分け、必要な引き継ぎを終えてから削除し、完了を確認する手順**を説明します。

**アンインストールは、自分だけがAppから退出する操作ではありません。** 対象Appの利用終了に関わる操作です。Marketplaceから導入したAppの確認画面では、Appとデータの削除、メンバーのアクセス権解除、元に戻せないことが案内されます。

設定エラーや更新不具合の解消が目的の場合は、先に[Appの初期設定を完了する](complete-app-setup.md)や[App更新の変更点と再設定を確認する](check-app-updates.md)を確認してください。再インストールすれば以前のデータや設定が戻る、という前提で削除しないでください。

## 始める前に

- 対象の組織・App・提供元を確認します。同名のAppや、開発元のProjectと取り違えないようにします。
- Appの利用を終了する承認と、操作できる権限を確認します。
- 利用者へ終了予定を伝え、処理中の業務や引き継ぎが残っていないか確認します。
- 必要なデータ・ファイル・成果物の保存先と、保存してよい範囲を確認します。
- 自動実行、通知、他のシステムからの呼び出しなど、終了に伴う対応を確認します。
- Appの料金と、別途契約している外部サービスの費用を分けて確認します。

> 以下はWebブラウザでの操作を中心に説明します。表示項目・操作権限・削除時の案内は、組織の設定や導入方式によって異なります。確認画面を開くことと、最後の「アンインストール」で確定することを区別してください。

## 1. 終了する対象と導入方式を確認する

最初に、何を終了したいのかを整理します。

| 目的・導入方式 | 進め方 |
|---|---|
| 自分だけがAppの利用をやめたい | 退出やメンバー変更を確認する。App全体のアンインストールとは分ける |
| Marketplaceから導入したAppを終了したい | この後のMarketplace向け手順へ進む |
| 組織内self-installで導入したAppを終了したい | 本記事の「組織内self-installの場合」を確認する。データの案内はMarketplace版と異なる |
| JAPAN AIによる配布・管理など、別の方式で導入されたApp | 表示される案内に従い、配布担当者やJAPAN AIへ依頼する |
| 作成中のProjectやAppの掲載を取り下げたい | 導入済みAppのアンインストールとは別の操作として確認する |

Appを開けること、Appの設定を変更できること、組織のAppをアンインストールできることは、同じ権限ではありません。Marketplace導入の終了操作には、組織のApp管理に必要な権限が確認されます。「App管理者だから必ず削除できる」とは判断せず、操作できない場合は権限のある担当者へ依頼してください。

## 2. 削除前の引き継ぎを終える

確認画面で確定する前に、次の項目を確認します。

| 確認対象 | 終了前に行うこと |
|---|---|
| 利用者 | 誰が利用しているかを確認し、終了後の代替手順・問い合わせ先を伝える |
| 業務データ | 必要な情報を特定し、許可された方法で保存・移行する |
| ファイル・成果物 | 後から参照する必要があるものを、承認された保存先で確認できる状態にする |
| 実行中の処理 | 未完了の処理と外部サービスへの反映状況を確認する |
| 定期実行・通知・外部呼び出し | このAppへの依存を確認し、必要な停止・切り替えを担当者と調整する |
| 接続・Secret | 他の用途と共有していないかを確認し、終了後の整理担当者を決める |
| 料金・契約 | Appの終了時の案内と、外部サービスなど別契約の終了条件を確認する |

データの保存は、Appが提供する機能や組織で認められた方法で行います。すべてのAppに一括エクスポートや復元機能があるわけではありません。必要なデータを保存できない場合は、削除を確定する前に管理者・提供元へ相談してください。

**データが内部で保持される場合でも、利用者が後から取り出したり復元したりできるとは限りません。** 一方、アンインストールをもって、監査記録や外部サービス上の情報を含むすべてのデータが即時・物理的に消去された、とも扱わないでください。保持期間や完全削除の確認が必要な場合は、対象データを明示して問い合わせます。

接続やSecretを先に削除して、他のAppや業務まで止めないようにしてください。認証情報そのものを引き継ぎ資料やチャットへ貼り付ける必要はありません。

## 3. Marketplaceから導入したAppをアンインストールする

### 対象Appの確認画面を開く

1. 正しい組織でStudioのApp一覧を開きます。
2. 対象Appのメニューに「アンインストール」が表示される場合は、選択します。
3. Appの設定から操作する場合は、設定画面に表示される「アンインストール」を選びます。
4. 開いた確認画面のApp名が、終了したいAppと一致していることを確認します。

権限に応じて「組織のアプリ」から操作できる場合もあります。入口が複数あっても、確認画面で対象を必ず確認してください。ボタンが見つからない場合は、別のAppや開発元Projectを削除して代用せず、導入方式と権限を確認します。

### 削除と料金の案内を読む

確認画面では、Appとデータの削除、メンバーのアクセス権解除、操作を元に戻せないことを確認します。表示される人数も、影響確認の材料にしてください。

利用人数に応じて料金が発生するAppでは、次の料金案内が表示されます。

> 今後の更新料金は発生しません。当月分は返金されません。

この案内は、そのAppの更新料金についてのものです。過去の利用分、すでに確定した費用、JAPAN AIの他の契約、外部サービスの料金まで取り消されるとは解釈しないでください。料金案内が表示されないことだけを根拠に、関連費用がすべてゼロになるとも判断しないでください。

料金・契約上限の詳細は、[Appの利用人数・料金・契約上限を確認する](../operations/check-app-seats-pricing-and-limits.md)で扱います。

### App名を入力して確定する

1. データ保存・引き継ぎ・利用者への案内が終わっていることを最終確認します。
2. 確認画面で求められるApp名を、表示どおりに入力します。
3. 「アンインストール」を選択して確定します。
4. 処理結果を確認します。

入力した名前が表示名と一致しないと、確定できません。App名が変更されたという案内が出た場合は、最新の名前と対象を確認し直してください。

確定前に中止する場合は「キャンセル」を選びます。**受付後に画面を閉じても、受付済みのアンインストールを取り消したことにはなりません。** 処理中は連続操作を避け、結果が分からないときは次の手順で状態を確認してください。

## 4. 組織内self-installの場合

組織内self-installにも、導入済みApp側のアンインストール操作があります。ただし、Marketplace導入とは別の管理経路であり、必要な権限やデータの扱いを同じものとして説明しないでください。

1. 開発元Projectではなく、終了したい**インストール済みApp**を開きます。
2. App一覧のメニューまたはApp設定に表示される「アンインストール」を選びます。
3. 確認画面のApp名と、次の趣旨の案内を確認します。
   - インストール済みAppとアクセス権を削除する
   - 開発元Projectは残る
   - 顧客データには既存の保持ルールが適用される
4. 必要なデータの保存・引き継ぎを確認したうえで、求められるApp名を入力して確定します。
5. App一覧へ戻った後も、現在の状態を確認します。

「開発元Projectは残る」は、導入先で増えたデータや設定が開発元へ戻る、という意味ではありません。保持ルールの対象・保存先・後から参照できる範囲が不明な場合は、確定前に担当者へ確認してください。

操作に失敗したという案内でも、処理が完了している可能性があります。再試行する前に、現在の状態を確認します。Marketplace向けの「受付済み」「再試行」の表示が、self-installでも同じ形で出るとは限りません。

## 5. 受付と完了を区別して確認する

**Appが開けなくなったことや、一覧へ戻ったことだけでは、削除完了の確認にはなりません。** Marketplace導入では、先に利用が無効化され、後続の削除処理が未完了のまま残る場合があります。このMarketplace向けの操作では、App設定から一覧へ戻る動作が、未完了の応答でも発生する場合があります。

| 結果・表示 | 次の対応 |
|---|---|
| 「アプリをアンインストールしました」などの完了案内 | 一覧の最新状態を確認し、終了結果を記録する |
| アンインストール中 | 操作を重ねず、処理結果を確認する |
| 受付済み・アンインストール未完了 | 完了とは扱わず、案内を確認して同じ対象の「再試行」を使う |
| デプロイ中 | デプロイの完了を確認してから再試行する |
| 常時起動ページに関する案内 | 常時起動ページの停止と削除完了をJAPAN AIサポートへ依頼する |
| データ削除が未完了 | 案内に従って再試行し、解消しなければサポートへ連絡する |
| 通信エラーなどで結果が不明 | 正しい組織で一覧や詳細を開き直し、現在の状態を確認してから次の操作を決める |

受付済みのMarketplace導入を再試行する場合は、App名の再入力が求められないことがあります。これは新たな導入を削除する操作ではなく、受付済みの削除を完了させるための操作です。

一覧に見当たらない場合も、組織・検索条件・表示権限が違う可能性があります。結果が確定できないまま再インストールしたり、別の画面から削除を繰り返したりしないでください。

## 6. 終了後の確認と周知を行う

完了を確認したら、終了日時、対象App、確認した結果、残作業を記録し、利用者へ共有します。

- 必要な保存データ・成果物を、引き継ぎ先で参照できるか
- 他のシステムに、終了したAppを呼び出す設定が残っていないか
- 外部サービス側の通知・接続・契約に、別途整理が必要か
- 未完了処理や問い合わせが残っていないか
- 利用者へ、代替手順と問い合わせ先を伝えたか

実行済みの外部操作が、Appのアンインストールによって取り消されるとは限りません。送信済み通知、登録済みデータなどの扱いは、必要に応じて対象サービスの担当者と確認してください。

データ・権限・監査記録の詳しい整理は、[削除・引き継ぎと監査記録を確認する](../operations/deletion-handover-and-audit-logs.md)で扱います。

## うまくいかないとき

- **「アンインストール」が表示されない**：対象の組織、導入方式、操作権限を確認します。Appの利用権限だけでは操作できない場合があります。
- **JAPAN AIへの問い合わせが案内される**：その導入の管理担当者へ依頼します。他の削除機能で代用しないでください。
- **Appが使えないのに未完了と表示される**：利用停止と削除完了を分けて確認します。
- **再試行しても完了しない**：対象、表示された案内、受付済みかどうか、実施済みの確認をサポートへ伝えます。

問い合わせには、組織名、App名、導入方式、操作日時、画面の表示、再確認・再試行の結果を添えます。APIキー、Secretの値、パスワード、業務上の機密データは添えないでください。

## 完了チェック

- [ ] 終了対象と導入方式を確認し、退出・Project削除・掲載取り下げと区別した
- [ ] 利用者への案内、必要なデータ保存、業務の引き継ぎを終えた
- [ ] データ・アクセス権・料金について、対象方式の確認画面を読んだ
- [ ] 正しいApp名でアンインストールを確定した
- [ ] 受付済み・利用停止・結果不明を、削除完了と取り違えていない
- [ ] 完了結果を確認し、残作業がある場合は担当者を決めた
- [ ] 利用者へ終了結果と代替手順を共有した
