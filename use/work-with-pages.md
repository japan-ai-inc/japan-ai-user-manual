# Pageから業務を進める

Pageは、情報の確認や入力、業務上の操作を行うためのWeb画面です。AppやProjectに用意されたPageを開き、画面の案内に沿って作業します。

**Pageの入力項目・ボタン・保存方法は、そのPageの作りによって異なります。** この記事では、Pageを開き、対象を確認して操作し、結果を確認する共通の流れを説明します。すべてのPageに同じフォームや保存ボタンがあるわけではありません。

Pageの作成、ZIPのアップロード、ビルド、公開、バージョンの切り替えは、作成者・管理者向けの別記事で扱います。

## 始める前に

- 利用するAppまたはProjectと、Pageの名前を確認します。
- そのPageで行う業務と、閲覧・登録・更新など自分が行ってよい操作を確認します。
- 操作に必要な情報やファイルを用意します。業務で利用を許可されたデータを使ってください。
- 問題が起きたときの確認先を把握します。

AppやProjectをまだ開けていない場合は、次の記事から始めます。

- [導入済みAppを開いて利用を始める](open-installed-app.md)
- [共有されたProjectで利用を始める](start-with-shared-project.md)

> 画面の表記や入口は、組織の設定・権限・AppやProjectの構成によって異なります。以下はPCのWebブラウザで確認する流れです。

## 1. 利用するPageを開く

### Appから開く

1. 利用するAppを開きます。
2. 業務用のホームPageが直接表示された場合は、その画面の名前や説明を確認します。
3. ダッシュボードが表示された場合は、「ページ」から目的のPageを選びます。
4. 目的のPageが見えていなければ、「すべて」など一覧を開く操作が表示されているか確認します。

AppのダッシュボードでPageを選ぶと、新しいタブで開く場合があります。元の画面に変化がないときは、ブラウザのタブも確認してください。

### Projectから開く

1. 共有されたProjectを開きます。
2. ホームPageが直接開いた場合は、そのまま画面の案内へ進みます。
3. Projectのホーム画面では「このプロジェクトのページ」、ナビゲーションでは「PAGE」などの入口から対象を選びます。
4. ホーム画面に目的のPageが見当たらず、「全て見る」が表示されている場合は、一覧を確認します。

Pageのカードを選ぶ操作と、カードのメニューにある編集・アクセス設定などの操作は別です。**通常の業務利用では、Page自体の編集や公開設定を変更する必要はありません。**

### 案内されたリンクから開く

担当者からPageのリンクを受け取っている場合は、そのリンクを開きます。ログインを求められたら、案内されたアカウントと方法で進めてください。

リンクが共有されていても、閲覧やデータ操作の権限が付与されているとは限りません。認証方法や公開範囲もPageによって異なります。開けない場合は、担当者に対象とアクセス条件を確認します。

## 2. 画面と操作対象を確認する

入力や実行の前に、次の点を確認します。

| 確認するもの | 見るポイント |
|---|---|
| Pageの名前・説明 | 案内された業務の画面か。似た名前の別Pageではないか |
| 表示されているデータ | 対象の顧客・案件・期間・状態などが合っているか |
| 検索・絞り込み条件 | 意図した条件か。条件によって対象が隠れていないか |
| 操作の説明 | 閲覧、登録、更新、送信など、何を行う操作か |
| 処理先 | 保存先、更新対象、外部サービスの送信先などが正しいか |

一覧やフォームなどの具体的な構成はPageごとに異なります。説明がなく、ボタンを押すと何が起きるか分からない場合は、操作前に担当者へ確認してください。

**Pageが表示されたことは、すべてのデータや機能を利用できることの保証ではありません。** データ取得や処理の実行時に、追加の権限確認や外部接続が必要になる場合があります。

## 3. 画面の案内に沿って作業する

### 情報を確認する

一覧や検索機能が用意されている場合は、対象の名前・日付・状態などを確認して絞り込みます。詳細画面を開く操作がある場合は、目的のデータを選びます。

検索結果が空でも、データが存在しないとは限りません。検索条件、表示対象、読み込みエラー、閲覧できる範囲を確認します。

### 入力・登録・更新する

フォームがある場合は、次の順で操作します。

1. 入力対象を確認します。既存データを更新する場合は、対象の名前や識別情報を見直します。
2. 項目の説明に従って入力します。必須項目や日付・数値の形式が指定されていれば、その条件に合わせます。
3. 添付機能を使う場合は、対象ファイルと画面に示された形式・容量などの条件を確認します。
4. 内容を見直し、そのPageで指定された確定操作を行います。
5. 完了表示や更新後の内容を確認します。

> 「保存」「登録」などは操作名の例です。自動保存するPageも、明示的な確定が必要なPageもあり得ます。入力しただけで保存されたと判断せず、そのPageの案内と結果を確認してください。

入力エラーが表示されたら、該当する項目と説明を確認します。意味が分からないまま必須値を仮の内容で埋めたり、別の対象を選んだりしないでください。

### AIや業務処理を実行する

AIへの依頼や、Workflowなどの処理を呼び出すボタンが用意されている場合は、入力と実行内容を確認してから操作します。

- 外部への送信、データ登録・更新・削除を伴うか確認します。
- 実行中の表示が出ている間は、同じ確定・実行ボタンを繰り返し押さないようにします。
- Agentの会話画面へ移動した場合は、依頼内容と対象Agentを確認します。
- 出力された文章や数値は、業務で使う前に内容を確認します。

Pageからの操作でも、他の人と共有するデータや外部サービスに影響する場合があります。「動作確認のつもり」で実行する場合も、処理先を確認してください。

## 4. 結果を確認する

**画面の表示完了、処理の受付、業務処理の完了を区別します。** 結果の確認方法は、行った操作に合わせます。

| 行った操作 | 確認する結果の例 |
|---|---|
| 情報の検索・閲覧 | 条件に合う対象が表示されたか。必要な詳細を確認できたか |
| データの登録・更新 | 完了の案内と、登録・更新後の値。表示される場合はレコード番号など |
| AIへの依頼 | 回答や成果物の内容。外部操作も依頼した場合は、その操作結果 |
| ファイルの出力 | ダウンロード完了、ファイル名、内容、保存場所 |
| 外部サービスへの送信・更新 | 送信先・更新先での状態、または確認できる実行結果・履歴 |

上記は確認対象の例であり、すべてのPageに履歴や結果一覧が備わっているわけではありません。完了したか判断できない場合は、担当者に確認方法を尋ねてください。

結果を確認するために画面を再読み込みする場合も、未保存の入力がないこと、実行済みか不明な処理がないことを先に確認します。画面を閉じても処理が停止するとは限りません。

## 5. 別の画面へ移る・作業を終える

Pageの上部に切り替えメニューが表示される場合は、目的のPageを選べます。切り替えは設定とアクセスできるPageに応じて表示されるもので、全員に必ず表示されるわけではありません。

「スタジオに戻る」「ダッシュボードに戻る」などの入口が表示される場合は、そこからAppやProject側へ戻ります。戻る入口がない場合は、元のApp・Projectのタブや、担当者から案内された入口を使ってください。

画面を切り替える前やタブを閉じる前に、保存・実行結果を確認します。ブラウザの「戻る」や再読み込みで入力内容が保持されるとは限りません。

> Pageカードのメニューにある「ダウンロード」などは、作成・管理用の機能です。業務画面の中で出力した報告書やデータをダウンロードする操作とは区別してください。

## 表示・操作に問題がある場合

| 状況 | 利用者が確認すること |
|---|---|
| Pageが見つからない | App・Project・Pageの名前とリンク、表示範囲、アクセス権を確認する。新しいPageを作る必要はありません。 |
| 選んでも画面が変わらない | 新しいタブが開いていないか、ブラウザにポップアップを止めた案内がないか確認する。必要な場合も組織の方針に従い、無関係なサイトまで一括で許可しない。 |
| 「認証に失敗しました」と表示される | 案内されたアカウントで利用しているか確認する。画面に「再試行」があれば、未保存の入力や実行状況を確認したうえで試す。繰り返す場合は担当者へ連絡する。 |
| 「ページの読み込みに失敗しました」と表示される | 画面の「再試行」があれば表示の回復を試す。処理の途中だった場合は、先に結果を確認し、同じ業務処理を重ねて実行しない。 |
| 「ページナビゲーションの読み込みに失敗しました」と表示される | Page切り替え一覧の問題と、表示中の業務処理の結果を分けて確認する。画面の案内に従って再試行する。 |
| 設定エラー、白い画面、読み込みが終わらない | Page名・発生日時・表示内容を記録し、管理者へ伝える。利用者がソースや公開設定を変更して直そうとしない。 |
| 画面は開くがデータ取得や実行に失敗する | 表示されたメッセージ、権限、外部接続の状態を確認する。個人接続と共有設定のどちらが必要かは担当者へ確認する。 |

画面枠の読み込みに対する「再試行」と、Page内の「登録」「送信」「実行」などの再実行は別です。通信が途切れても、すでに更新や送信が完了している可能性があります。**処理済みか分からないときは、再実行する前に確認してください。**

問い合わせには、App・Project・Pageの名前、操作内容、発生日時、表示メッセージを添えます。URLに認証用の情報が含まれる可能性があるため、アドレス欄の内容を無確認で転送せず、通常の案内リンクや対象名を使ってください。パスワード・APIキー・トークンや、不要な個人情報は送らないようにします。

## 操作完了の確認リスト

- [ ] 案内されたPageと操作対象を確認した。
- [ ] 入力内容と、登録・更新・送信などの影響を確認した。
- [ ] 必要な確定・実行操作を行った。
- [ ] 結果、更新先、保存先などを確認した。
- [ ] 不明な実行結果を、確認せずに再実行していない。
