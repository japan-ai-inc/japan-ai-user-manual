# Appの初期設定を完了する

Appをインストールした後は、必要な接続・秘密情報・利用者の準備を整え、業務で使えるか確認します。この記事では、**初期設定を進める順序と、利用開始を判断するための確認事項**を説明します。

**「インストール済み」「設定済み」「業務で使える」は別の状態です。** Appを開けても、一部の機能に必要な設定が残っている場合があります。また、設定画面の完了表示だけでは、全利用者の認証や外部サービス上のアクセス、業務処理の成功まで確認したことにはなりません。

接続の登録・変更、Secretの操作、メンバー追加の詳しい手順は、それぞれの管理記事で扱います。すべてのAppで同じ設定が必要なわけではありません。表示された要件とApp固有の案内に従い、必要な項目だけ進めてください。

## 始める前に

- 対象の組織・Appと、インストール済みであることを確認します。
- 初期設定を行う担当者と、業務利用を開始してよいか判断する担当者を決めます。
- 利用する外部サービス、接続に使うアカウント、必要な情報を用意します。
- 利用予定者と、その人たちに許可する操作範囲を確認します。
- 利用人数や接続先サービスに伴う費用・承認条件を確認します。
- 動作確認用のデータと、実施してよい操作を決めます。

インストール結果が分からない場合は、[MarketplaceからAppをインストールする](install-marketplace-app.md)で状態を確認してください。設定不足を解消するために、最初からインストールし直す必要があるとは限りません。

> 以下はPCのWebブラウザでの標準画面を中心に説明します。表示項目や操作できる範囲は、組織の設定・権限・Appの構成によって異なります。ここにある順序は確認の進め方であり、全Appに共通する一括設定ウィザードではありません。

## 1. Appを開き、残っている設定を確認する

1. 正しい組織で、対象のAppを開きます。
2. 「要設定」「設定を確認」などの案内がある場合は、その内容を確認します。
3. Appの設定で「コネクタ」「シークレット管理」など、必要な項目を確認します。
4. 各項目の状態と、誰が対応するかを整理します。

Marketplaceの詳細画面に「セットアップを完了」という入口が表示される場合は、そこから設定へ進めます。どの画面から入った場合も、対象Appが正しいことを確認してください。

| 表示・状態の例 | 判断と次の対応 |
|---|---|
| 未設定 | 必要な接続やSecretの割り当てを確認する |
| 確認中 | 判定が終わったか確認する。設定済みとは扱わない |
| 無効・停止中 | 対象項目の説明を確認し、担当者へ対応を依頼する |
| 設定済み | その項目の設定状態を確認できた状態。後で実際の利用も確認する |
| 設定確認不可・読み込み失敗 | 要件がないとは判断せず、再表示や担当者への確認を行う |
| 設定変更の権限がない | 操作権限のある担当者へ依頼する |

設定の案内があっても、App全体が利用不能とは限りません。未設定の項目に依存する機能だけが使えない場合があります。ただし、業務に必要な機能が動くかを確認せず、全機能が使えると案内しないでください。

## 2. 必要な設定を種類ごとに分ける

まず、共通設定と利用者本人の設定を分けます。

| 設定の種類 | 確認すること | 主な対応者 |
|---|---|---|
| App共通のコネクタ | Appが使う外部サービスと、割り当てる共有接続が合っているか | 共有接続を管理できる担当者 |
| 個人用のコネクタ | 各利用者が自分のアカウントで認証する必要があるか | 利用者本人 |
| Project Secret | Appが必要とする秘密情報を、指定された項目へ割り当てているか | Secretを扱う権限のある担当者 |
| メンバー・アクセス権 | 誰がAppを開き、どの操作を行えるか | メンバー・権限を管理できる担当者 |
| App固有の準備 | 対象データ、保存先、業務条件などの指定が必要か | App固有の案内で指定された担当者 |

同じ外部サービスを使っていても、個人用とApp共通の接続は置き換え可能とは限りません。自分の接続が動いていることを理由に、他の利用者やApp共通の接続も準備できたとは判断しないでください。

## 3. App共通の接続とSecretを整える

### App共通の接続を確認する

「コネクタ」にあるApp共通の要件を確認し、権限のある担当者が必要な接続を設定します。

確認するポイントは次のとおりです。

- Appが必要とするサービスと、選ぶ接続のサービスが一致しているか
- 接続先のアカウント・組織・業務データが意図したものか
- その接続をAppで共有して使うことが承認されているか
- 接続を登録しただけでなく、Appの必要な項目への設定も完了しているか

**「コネクタが作成された」と「Appに設定された」は別です。** 作成後にAppへの設定失敗が表示された場合は、作成済みの接続と現在の状態を確認し、画面の案内に従って対応します。原因を確認せず同じ接続を作り続けないでください。

具体的な設定操作は、[Project・Appの共有接続を設定する](../operations/configure-shared-connections.md)で扱います。

### Project Secretを確認する

AppからAPIキーやトークンなどを参照するために、Project Secretの設定が求められる場合があります。「シークレット管理」の中で、**「プロジェクトシークレット」と「Webログイン用シークレット」を区別**して確認してください。

- Appに必要なSecretの項目・名前を確認します。
- 必要な値を、承認された方法で用意します。
- 指定された設定画面で、既存のProject Secretを選んで必要な項目へ割り当てるか、新規のSecretを作成して割り当てます。
- 保存や紐づけの結果を確認し、未設定・無効のまま残っていないか確認します。

Secretを一覧へ保存しただけでは、Appが必要とする項目への割り当てが終わっていない場合があります。名前が似ている別のSecretや、別環境の値を選ばないようにしてください。

秘密情報の値を、チャット本文、手順書、問い合わせのスクリーンショットへ貼り付ける必要はありません。確認のために値を表示させたり、他の利用者へ配ったりせず、指定された設定画面で扱います。

具体的な操作は、[Project Secretを登録・更新・削除する](../operations/manage-project-secrets.md)で扱います。Webログイン用のSecretとは別の設定です。

### 共通設定を再確認する

設定後はAppの設定画面や詳細画面を開き直し、状態を確認します。コネクタを設定できても、Secretなど別の種類の設定が残っていないか確認してください。

設定を変更できない項目は、項目名と状態を担当者へ伝えます。対応できないことを理由に、共有範囲や権限を無断で広げないでください。

## 4. 利用者のアクセスと個人接続を確認する

### 利用者がAppを開けるようにする

業務で使う人を確認し、必要なメンバー設定・アクセス権を整えます。

- 組織に所属していることと、対象Appを利用できることを区別します。
- 管理者自身が開けるだけでなく、予定する利用者も開けるか確認します。
- 利用に必要な権限を設定し、不要な管理・編集権限まで付与しないようにします。
- メンバー追加に料金確認が出る場合は、人数・費用・承認を確認してから進めます。

メンバー操作は[Project・Appのメンバーを管理する](../operations/manage-project-and-app-members.md)、人数と料金の判断は[Appの利用人数・料金・契約上限を確認する](../operations/check-app-seats-pricing-and-limits.md)で扱います。

### 個人用の接続を本人が確認する

Appが個人用のコネクタを必要とする場合は、各利用者が自分のアカウントで必要な認証を行います。管理者が自分のアカウントを接続しても、他の利用者全員の認証が完了するわけではありません。

「接続が必要」と表示される場合は本人が対応し、設定後に状態を確認します。「共有コネクタを利用」など別の状態が表示される場合は、どの接続を使う想定なのかを確認してください。個人用接続が必要な場面で、管理者のアカウントや秘密情報を利用者へ共有して代用しないでください。

本人による接続操作は、[自分の外部アカウントを接続する](../operations/connect-your-external-accounts.md)で扱います。

## 5. App固有の準備と動作確認を行う

App固有の案内に、対象データ・保存先・業務条件などの準備がある場合は、その手順に従います。すべてのAppに共通する設定として、不要なObject・Dataset・接続を追加する必要はありません。

準備が整ったら、業務で使う人の立場で、許可された範囲の小さな確認を行います。

1. 確認する業務操作と、期待する結果を決めます。
2. テスト用または確認を許可されたデータを用意します。
3. 利用者がAppを開き、対象機能を操作します。
4. エラーの有無だけでなく、参照したデータ・出力内容・保存先を確認します。
5. 設定不足や権限不足があれば、対象項目を特定して担当者へ戻します。

メール送信、外部データの登録・更新、ファイルの上書きなどが含まれる場合は、確認操作でも実際の業務に影響します。実行先と許可範囲を確認し、Appに検証用の方法がある場合はその案内に従ってください。全Appにテストモードがあるとは限りません。

**画面を開けたことだけを動作確認の完了にしないでください。** たとえば資料を検索するAppなら、意図した資料を参照できるか、結果の内容が妥当かまで確認します。外部サービスの認証や設定の表示が正常でも、対象データへのアクセスや個別の処理に失敗する場合があります。

## 6. 利用開始の範囲を決め、担当者へ引き継ぐ

Marketplaceの詳細画面にある「セットアップは完了しています」という表示は、App共通の接続・Secretなどの設定確認として読み取ります。**その表示だけで、各利用者の個人接続や、すべての業務操作の成功まで確認済みとは扱わないでください。**

必要な設定と動作確認が終わったら、次の情報を利用者・運用担当者へ案内します。

- 利用する組織・Appと、その入口
- 利用開始してよい機能と、確認した操作
- 利用者本人が行う接続などの作業
- 未対応の項目と、使わないようにする機能
- 接続の失効やエラーが起きたときの問い合わせ先

一部の設定を残して利用を始める場合は、未設定項目に依存する機能を明示し、担当者が利用範囲を判断します。全体を「設定完了」と案内するのではなく、確認済みの範囲と残作業を分けて伝えてください。

## うまくいかないとき

| 状況 | 最初に確認すること |
|---|---|
| 設定画面や項目が見当たらない | 対象の組織・App、操作権限、Appの要件。表示されないだけで設定不要とは判断しない |
| コネクタを作成したのに未設定のまま | Appの必要な項目への設定結果と、設定失敗の案内 |
| Secretを保存したのに未設定のまま | Project Secretの種類と、Appの必要項目への紐づけ |
| 管理者は使えるが他の人は使えない | メンバー・アクセス権、本人の接続、外部サービス側のアクセス範囲 |
| 設定状態を確認できない | 読み込みエラーや確認不可の案内。状態を再取得し、解消しなければ担当者へ確認 |
| 設定済みなのに業務操作が失敗する | 使用しているアカウント、対象データ、App固有の準備、実行時のエラー |
| 接続が無効・停止中になる | 接続管理者へ状態と発生時点を伝える。解除・再作成を繰り返さない |

問い合わせには、組織名、App名、設定項目名、表示状態、操作日時、確認した操作を添えます。Secretの値や認証情報そのものは送らないでください。

## 完了チェック

- [ ] 対象の組織・Appと、設定担当者を確認した
- [ ] 必要な共通コネクタとProject Secretの設定結果を確認した
- [ ] 読み込み失敗・確認不可を、設定不要や完了と取り違えていない
- [ ] 利用予定者のアクセスと、必要な本人の接続を確認した
- [ ] App固有の準備を確認した
- [ ] 許可されたデータで必要な業務操作を確認した
- [ ] 利用開始してよい範囲、残作業、問い合わせ先を共有した
