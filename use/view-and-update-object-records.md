# Objectのデータを閲覧・更新する

Objectは、顧客・案件・タスクなどの業務データを、決められた項目で管理する機能です。1件のデータを「レコード」、名前・状態・期限などの項目を「フィールド」と呼びます。

この記事では、既存のObjectから対象レコードを探し、内容を確認して、許可された項目を更新する流れを説明します。新しいObjectの作成、フィールドの追加・削除、アクセス設定の変更は扱いません。

**レコードの値を変える操作と、Objectの構造を変える操作は別です。** 例えば「タスクの期限を変更する」はデータ更新、「期限という項目を追加する」は構造の変更です。

## 始める前に

- 利用するProjectまたはAppと、Objectの名前・用途を確認します。
- 対象レコードを識別できる情報を用意します。名前だけでなく、管理番号や取引先なども確認できると取り違えを防げます。
- 閲覧だけか、更新・新規登録も行うのか、自分が行ってよい操作を確認します。
- 更新によって通知やWorkflowなどの後続処理が動く業務では、その影響を担当者に確認します。

まだ利用先を開けていない場合は、次の記事から始めてください。

- [導入済みAppを開いて利用を始める](open-installed-app.md)
- [共有されたProjectで利用を始める](start-with-shared-project.md)

> 以下はPCのWebブラウザで使う標準のObject画面を中心に説明します。表示される項目・操作は、権限、組織の設定、Objectの構成によって異なります。App内の独自Pageでは、入力・保存方法が異なることがあります。

## 1. 対象のObjectを開く

### Projectから開く

1. 案内されたProjectを開きます。
2. 「OBJECT」や「オブジェクト」など、Object一覧への入口を開きます。
3. 一覧でObjectの名前と説明を確認し、対象を開きます。
4. 表示された画面が、目的のObjectのレコード一覧であることを確認します。

フィールド設定の画面ではなく、業務データが並ぶ画面を使ってください。既存レコードを閲覧・更新するだけなら、フィールドの定義を変更する必要はありません。

### AppのPageから使う

顧客一覧やタスク管理などのPageが用意されている場合は、担当者から案内されたPageを使います。**App利用者に、Object一覧への直接アクセスが用意されているとは限りません。**

Page内の「保存」「更新」などの操作は、そのPageの案内に従います。後述する標準画面のダブルクリックや自動保存を、独自Pageにもそのまま当てはめないでください。

- [Pageから業務を進める](work-with-pages.md)

## 2. 対象レコードを探す

標準のレコード一覧では、検索条件や表示フィールドを使って、確認する範囲を絞れます。

### 検索条件を指定する

1. 「検索条件」を開きます。
2. 「フィールド名」で検索対象の項目を選びます。
3. 「演算子」で、一致や部分一致など、目的に合う比較方法を選びます。
4. 必要な「値」を入力して「検索」を選びます。
5. 表示されたレコードの内容を確認します。

例えば、管理番号が分かっている場合は、その項目と一致条件で探します。氏名や会社名で探す場合は、似た名前のレコードが混ざっていないか確認してください。選べる条件や入力形式は、項目の種類によって異なります。

見つからない場合は、検索条件のクリア、対象Object、入力した値を確認します。複数ページに分かれているときはページ切り替えも確認してください。

**検索結果が空でも、データが存在しないとは限りません。** 検索条件や閲覧範囲によって見えていない可能性があります。確認できないまま同じデータを新規登録しないでください。

### 表示する項目を調整する

「表示フィールドを選択」が利用できる場合は、確認したい項目を表示します。例えば、名前に加えて管理番号・担当者・状態を表示すると、対象を照合しやすくなります。

表示する列の選択と、フィールドの削除は別の操作です。列を隠すために「フィールド削除」やObjectの設定変更を行わないでください。

## 3. レコードの内容を確認する

1. 一覧の管理番号・名前などを照合します。
2. 詳細を開く矢印などが表示されていれば、対象レコードの詳細を開きます。
3. 更新前の値と、変更する必要がある項目を確認します。
4. 関連レコードへのリンクがある場合は、関連先が正しいか確認します。

一覧の長い文章は省略表示されることがあります。「全て表示」や詳細画面を使い、省略部分を見落とさないようにしてください。

> 標準の一覧でも、行をダブルクリックしたときの動作は画面構成によって異なり、詳細表示を開く場合と編集状態になる場合があります。閲覧だけが目的の場合は、詳細を開く操作を使い、編集状態になっていないか確認します。

関連レコードを開けない場合は、関連先の状態や閲覧権限を確認します。リンクがあることだけで、関連先の全データを閲覧・更新できるわけではありません。

## 4. 許可された項目を更新する

### 詳細画面で1項目を編集する

標準の詳細画面では、編集可能な項目の値をダブルクリックすると入力状態になります。

1. 対象レコードと項目を再確認します。
2. 変更したい値をダブルクリックします。
3. 入力欄に新しい値を入力、または候補から選択します。
4. 入力内容を見直してから、編集欄の外へ移ります。
5. 更新処理が終わり、「レコードを更新しました」と表示されることを確認します。
6. 表示された値が意図どおりか確認します。

**標準の詳細画面では、値を変更して編集欄から離れると保存処理が始まります。画面全体の「保存」ボタンを押す方式ではありません。** 他の項目を確認しようとクリックした場合も、保存が始まることがあります。

未保存の変更を取り消したい場合は、編集中のキャンセル操作を使います。すでに保存された値は、キャンセルでは元に戻りません。入力ミスを保存した場合は、現在の値と業務上の影響を確認してから修正します。

### 一覧で行を編集する

行のメニューに「編集」が表示されている場合は、そこから編集を開始できます。画面によっては詳細画面が開きます。

その場で行が入力状態になった場合は、対象の項目を変更して内容を確認します。標準の行編集では、編集行の外へ移ると保存処理が始まります。処理完了と更新後の値を確認してください。

変更を取り消す操作で確認画面が表示された場合は、破棄する内容を確認して選択します。保存中に別の操作を繰り返したり、完了確認前に画面を閉じたりしないでください。

### 入力時に確認すること

| 項目の種類・条件 | 確認すること |
|---|---|
| 必須項目 | 空欄のままになっていないか |
| 数値 | 桁、単位、許容範囲が業務ルールに合っているか |
| 日付・日時 | 対象の日付や時刻、画面に表示される形式が正しいか |
| 選択項目・真偽値 | 目的の候補やオン／オフを選んでいるか |
| 関連項目 | 同じ名前の別レコードを選んでいないか |
| 重複を許さない項目 | 管理番号などが、既存レコードと重複していないか |

入力エラーが出た場合は、メッセージで示された項目を修正します。システム項目など、通常の編集対象にならない項目もあります。編集できない項目を変えるために、フィールド定義やアクセス設定を変更しないでください。

## 5. 必要な場合だけ新しいレコードを登録する

新規登録が業務上必要で、操作が許可されている場合に行います。

1. 同じデータがすでに登録されていないか確認します。
2. 対象Objectの「レコード新規作成」を選びます。
3. 表示された項目に必要な情報を入力します。
4. 初期値が入っている項目も、今回の登録内容に合っているか確認します。
5. 登録ボタンを選び、作成完了の表示を確認します。
6. 一覧または詳細で、登録したレコードを確認します。

項目によっては値が自動設定されます。画面に入力欄がない項目や、自動生成される番号を無理に指定する必要はありません。

検索条件をかけたままでは、新しいレコードが一覧に出ない場合があります。作成直後に見つからなくても、登録ボタンをもう一度押す前に検索条件と登録結果を確認してください。

## 6. 更新後の状態を確認する

更新完了の表示に加えて、次を確認します。

- 対象のレコードを変更できている。
- 変更した項目が意図した値になっている。
- 関係のない項目を誤って変更していない。
- 必要な場合は、一覧や詳細を開き直しても更新後の値が表示される。

更新した状態や担当者が検索条件に合わなくなると、レコードが一覧から外れることがあります。削除されたと判断する前に、条件を解除して探してください。

「変更履歴」が利用できる場合は、変更の確認に役立ちます。ただし、すべての環境で履歴の閲覧・復元ができるとは限りません。復元は、現在のデータを変更する操作なので、単なる履歴閲覧と区別します。

外部連携や自動処理の結果も必要な業務では、担当者から案内された確認先でチェックします。Objectの更新成功と、後続処理の成功は同じではありません。

## うまく操作できないとき

| 状況 | まず確認すること |
|---|---|
| Objectが見つからない | Project／App、対象名、案内された入口、参加状態・アクセス範囲 |
| レコードが表示されない | 検索条件、ページ、閲覧範囲。ゴミ箱との切り替えがある場合は表示先も確認 |
| 項目が見えない | 表示フィールドの設定、Objectの構成、閲覧上の制限 |
| 編集・新規作成ができない | 操作権限、システム項目などの編集制約、ボタン付近の案内 |
| 必須・型・日付などのエラー | メッセージで指定された項目と入力形式 |
| 値が重複しているというエラー | 同じ管理番号などの既存データがないか。制約を外して対処しない |
| 他のユーザーまたは処理による更新が通知される | 最新データを再読み込みし、変更済みの内容を確認してから必要な修正だけを行う |
| 保存に失敗した／完了したか分からない | 現在の保存状態を確認。再読み込み前に必要な入力内容を控え、二重登録や古い値の上書きを避ける |

同時更新の通知が出たときは、古い画面の内容をそのまま繰り返し送信しないでください。自分以外の利用者だけでなく、AgentやWorkflowなどの処理が更新している場合もあります。

担当者に相談するときは、次の情報をまとめます。

- Project／AppとObjectの名前
- 対象レコードを識別できる番号や、共有してよい範囲のURL
- 行いたかった操作と対象項目
- 発生日時とエラーメッセージ
- 編集前後に確認できた状態

機密情報を含む値や画面を、必要以上に共有しないでください。

## 操作時の注意

- **閲覧できることと、更新・登録・削除できることは別です。** ロール名だけで操作範囲を判断せず、実際の権限と業務ルールを確認します。
- 値を変更するつもりで、Objectやフィールドの削除を選ばないでください。
- CSV取込、一括削除、復元などは複数データや現在の状態に影響します。通常の1件更新の代わりには使わず、別途決められた運用手順に従います。
- 画面を閉じることを、保存の取り消しや処理停止の方法として使わないでください。

## 完了の目安

- [ ] 正しいObjectとレコードを特定できた。
- [ ] 許可された項目だけを変更した。
- [ ] 更新・登録の完了と、保存後の値を確認した。
- [ ] 不明なエラーや競合を残したまま、再操作していない。
