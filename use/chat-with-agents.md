# Agentと会話して結果を確認する

Agentに依頼や質問を送り、回答・処理結果・成果物を確認するまでを説明します。Appから使う場合も、共有されたProjectから使う場合も、**利用するAgentと対象データを確認してから依頼する**ことが基本です。

この記事では、既存のAgentとの会話を扱います。Agentの作成、指示・ツール・モデルの設定変更は行いません。

## 始める前に

- 利用するAppまたはProjectと、Agentの名前・用途を確認します。
- 依頼する業務と、使ってよい情報・ファイルを用意します。
- 外部サービスの検索・登録・送信などを行う場合は、利用する接続と操作範囲を確認します。
- アクセスや接続の問題について確認できる担当者を把握します。

まだ利用先を開けていない場合は、次の記事から始めてください。

- [導入済みAppを開いて利用を始める](open-installed-app.md)
- [共有されたProjectで利用を始める](start-with-shared-project.md)

> 画面の表記・配置・利用できる操作は、組織の設定、Agent、権限などによって異なります。以下はPCのWebブラウザで確認する流れです。

## 1. 利用するAgentを選ぶ

### Appから始める

1. 利用するAppを開きます。
2. ダッシュボードやナビゲーションの「エージェント」から、案内されたAgentを探します。
3. 名前と説明を確認し、そのAgentを選びます。
4. 会話の入力画面で、利用するAgentが目的に合っていることを確認します。

業務用のホームPageが開いた場合は、Page内に用意された会話の入口や担当者の案内に従います。すべてのAppに、同じAgent一覧が表示されるわけではありません。

### Projectから始める

1. 共有されたProjectを開きます。
2. ホーム画面のAgent、または「AGENT」などの入口から対象を探します。
3. 名前と説明を確認し、対象Agentの利用画面へ進みます。

ホーム画面のチャット入力欄にそのまま依頼することと、指定されたAgentを選ぶことを同じ操作だと決めつけないでください。担当者からAgentが指定されている場合は、そのAgentを使います。

**Agentを使うために、Agentの設定を編集する必要はありません。** 目的のAgentが見つからない、利用できない場合は、名前・参加状態・実行権限を担当者に確認してください。

## 2. 目的と条件を添えて依頼する

入力欄には、少なくとも「何をしてほしいか」「何を対象にするか」「どの形で返してほしいか」を書きます。

| 書く内容 | 例 |
|---|---|
| 目的 | 顧客への回答案を作る |
| 対象・範囲 | 添付したFAQのうち、契約更新に関する説明を使う |
| 出力形式 | 結論、根拠、確認事項の3項目でまとめる |
| 守ってほしい条件 | 資料にないことは推測せず「要確認」とする |
| 実行してよい範囲 | 下書き作成だけを行い、メール送信やデータ更新はしない |

例えば、資料を添えて回答案を作るなら、次のように依頼します。

> 添付の「契約更新FAQ.pdf」を使い、顧客からの「更新手続きは何が必要ですか？」という質問への回答案を作ってください。結論・根拠・確認事項に分け、根拠となる見出しや箇所を示してください。資料に書かれていないことは「要確認」とし、メール送信はしないでください。

この例は依頼の書き方です。指定した形式、引用箇所の提示、ファイルの読み取りが必ず成功することを保証するものではありません。結果を確認し、必要に応じて補足します。

外部への送信やデータ更新を依頼するときは、送信先・更新対象・実行範囲を明確にしてください。「下書き」と「送信」、「更新案の提示」と「実データの更新」は区別します。

## 3. 必要なファイルを添付する

資料を使ってほしい場合は、添付操作が利用できることを確認して、送信前にファイルを追加します。

1. 入力欄付近の「＋」など、ファイル追加の入口を開きます。
2. 対象のファイルを選びます。
3. 添付欄に表示されたファイル名と、アップロードの状態を確認します。
4. 誤ったファイルがあれば、送信前に添付欄から外します。
5. アップロードが完了し、エラーがないことを確認します。
6. メッセージに、どのファイルをどの目的で使うかを書きます。

対応形式、添付可能な件数や容量は、利用するAgentや設定などによって異なります。画面の案内に従ってください。読み取り専用の会話では、添付や送信ができない場合があります。

**ファイルを選んだことと、アップロードが完了したことは別です。** 送信できない場合は、処理中や失敗した添付がないか確認します。また、添付できたことだけで、資料の全文や画像・表を正確に読み取れたとは判断しないでください。

複数資料を使う場合は、例えば「規程Aを優先し、資料Bとの違いを確認する」のように、資料の役割を指定すると対象を整理しやすくなります。

> ローカルファイルの添付、Datasetの参照、外部サービスからの取得は別の方法です。ファイル名やURLを書くだけで、Agentがその情報へアクセスできるとは限りません。資料を参照できない場合は、[Agentがデータを参照しない](../troubleshooting/agent-not-using-data.md)で確認します。

## 4. 送信し、進行状況を確認する

1. Agent、依頼文、添付ファイル、操作対象を見直します。
2. 「送信」または送信アイコンを選びます。
3. 自分の依頼が会話に表示されたことを確認します。
4. 応答や処理状況を確認し、追加の質問や確認が出た場合は内容を読んで対応します。

キーボードでの送信方法は設定によって異なります。Enterキーが常に改行になる、または常に送信になると決めつけず、画面の案内を確認してください。

送信ボタンが使えない場合は、添付の処理中、入力内容、会話の読み取り専用状態、利用するAgent・モデルの状態などを確認します。処理中に追加の指示を送れる場合もありますが、最初の操作では、結果を確認してから次の依頼に進むと状況を把握しやすくなります。

外部アカウントの接続を求められた場合は、自分で設定する個人接続か、管理者が用意する共有設定かを確認します。認証情報を依頼文へ貼り付けるのではなく、指定された設定画面を使ってください。

> 通信が途切れたり応答が止まったりしても、同じ依頼をすぐに再送しないでください。登録・更新・送信を伴う処理では、すでに操作が完了している可能性があります。会話の結果と実際の更新先を確認してから判断します。

## 5. 回答と実行結果を確認する

AIの回答が表示されたら、そのまま採用する前に、依頼の目的と照らし合わせます。

| 確認対象 | 確認すること |
|---|---|
| 回答内容 | 質問に答えているか。重要な条件や例外が抜けていないか |
| 数字・日付・名称 | 元資料や業務データと一致しているか |
| 根拠 | 引用や参照先がある場合、実際にその内容を裏付けているか |
| 不明点 | 推測や未確認事項が、事実と区別されているか |
| 外部操作 | 対象サービスで、指定した登録・更新・送信が完了しているか |
| 生成物 | 求めた形式・内容のファイルや文書を実際に開けるか |

「実行しました」という文章だけで、外部操作の成功を確定しないでください。処理結果の表示や、権限のある更新先で確認します。逆に、応答が見えないだけで未実行と決めつけないことも重要です。

回答の根拠が分からない場合は、同じ会話で「どの資料のどの箇所を根拠にしましたか」と確認します。ただし、追加回答も確認対象です。重要な判断では、提示された根拠を元資料で照合してください。

### 成果物のファイルを受け取る

ファイルが出力された場合は、会話内のファイルカードやダウンロード操作を確認します。

1. ファイル名・形式を確認します。同名の修正版がある場合は、どの応答で作成されたものかも確認します。
2. プレビューやCanvasが利用できる場合は、開いて内容を確認します。
3. 必要なファイルをダウンロードし、組織で認められた場所へ保存します。
4. 保存したファイルを開き、内容・形式・欠落の有無を確認します。

表示やプレビューの方法は、ファイルの種類と利用できる機能によって異なります。**本文にファイル名が書かれているだけでは、受け取れるファイルが添付されているとは限りません。** カードやリンクが見当たらない場合は、「作成したファイルを、この会話で受け取れる形で共有してください」と依頼します。

Canvasで内容を変更した場合も、以前ダウンロードしたファイルが自動的に置き換わるとは考えず、必要な版を確認して保存してください。保存エラーが表示されている場合は、保存済みと判断しないようにします。

## 6. 同じ会話で修正する・履歴から再開する

### 続きの依頼や修正をする

同じ資料や回答の修正を続ける場合は、その会話に追加の依頼を書きます。何を残し、何を変えるかを具体的に伝えてください。

> 先ほどの回答案の「結論」はそのままにし、「確認事項」を箇条書きにしてください。新しい事実は追加しないでください。

別の顧客・案件・目的へ移る場合は、新しい会話に分けると対象を整理しやすくなります。新しい会話では、前の会話の資料や判断が自動的に引き継がれると考えず、必要な情報を改めて指定します。

### 過去の会話を開く

1. 利用していたApp・Projectを開きます。
2. Appの「チャットルーム」や、Project内の会話一覧・履歴の入口を開きます。
3. 検索や絞り込みが表示される場合は、対象の会話を探します。見つからない場合は、検索条件や表示対象を見直します。
4. 会話を開き、前回の依頼・結果・Agentを確認してから続けます。

共有された会話を読めても、追加入力が許可されているとは限りません。また、Projectに参加しているだけで、全員の会話をすべて見られるとは限りません。

会話のリンクを他の人へ送る場合は、共有範囲と、その中の資料・個人情報・機密情報を確認してください。リンクを送るだけで相手に閲覧権限が付くとは限りません。

## うまく進められないとき

| 状況 | 最初に確認すること |
|---|---|
| Agentが見つからない・使えない | App・Project、Agent名、参加状態、実行権限 |
| ファイルを添付できない | 対応形式・画面の制限案内・アップロード状態・会話の操作権限 |
| 送信できない | 入力内容、添付の完了、処理状況、読み取り専用表示、画面のエラー |
| 資料に基づかない回答になる | 指定したAgentと資料、添付の成否、参照設定や外部接続 |
| 外部操作が失敗する | 必要な接続・権限・対象データ。再実行前に処理済みかを確認する |
| 成果物を開けない・取得できない | 会話内のファイルカード、エラー表示、ファイル名。必要なら共有し直すよう依頼する |
| 過去の会話が見つからない | 組織・App・Project、検索条件、共有・アーカイブ等の表示対象 |

解決しない場合は、Agent名、対象のApp・Project、発生日時、操作内容、表示メッセージを担当者へ伝えます。パスワードやAPIキー、不要な個人情報は送らないでください。

## 操作完了の確認リスト

- [ ] 目的に合うAgentを選んだ。
- [ ] 対象資料・出力形式・実行範囲を指定した。
- [ ] 添付を使う場合は、ファイル名とアップロード完了を確認した。
- [ ] 回答の内容と根拠を確認した。
- [ ] 外部操作や成果物は、文章だけでなく実際の結果を確認した。
- [ ] 不明な処理結果を、確認せずに再実行していない。
