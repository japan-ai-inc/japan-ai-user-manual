# 導入済みAppを開いて利用を始める

管理者や担当者から案内されたAppを開き、自分が使う画面や処理に進むまでを説明します。**Appが導入されていること、自分にアクセス権があること、必要な接続が整っていることは、それぞれ別の確認事項です。**

この記事の対象は、すでに導入されたAppを利用する人です。Appの新規インストールや共有設定の変更は行いません。Projectの作成や、Agent・Workflowの編集も不要です。

## この操作でできるようになること

- 自分が利用するAppを、一覧または案内されたリンクから開く。
- 参加や設定の案内が出たときに、自分で進めるか担当者に確認するかを判断する。
- App内のPage・Agent・公開済みWorkflowなど、目的の機能に進む。

## 始める前に

次の情報を用意してください。

| 確認事項 | 確認する内容 |
|---|---|
| 利用先 | 組織名とApp名。案内されたリンクがあれば、そのリンク |
| アカウント | 組織で利用を許可されたログインアカウント |
| 最初の作業 | 開くPage、利用するAgent、実行する処理など |
| 設定の担当者 | アクセス権や共有接続について確認できる管理者・担当者 |

ログインや組織の選択がまだの場合は、[利用開始の前提と基本画面](../getting-started/getting-started-and-navigation.md)で先に確認します。

> 画面の表記や表示項目は、組織の設定・権限・画面構成によって異なります。以下は、PCのWebブラウザで確認する流れです。

## 1. 導入済みAppを探す

### Appsの一覧から探す

1. 今回利用する組織を開きます。
2. ナビゲーションから「Apps」を開きます。「STUDIO」の配下に表示される場合もあります。
3. タブが表示されている場合は、導入済みAppの利用側である「マイアプリ」を選びます。
4. 「アプリ名で検索」に、案内されたApp名を入力します。
5. 名前と説明を確認し、目的のAppを選びます。

管理権限によって、カード形式だけでなく管理用の一覧が表示される場合があります。「開く」が表示されている場合は、その操作から進めます。

**「マイアプリ」は、組織内に導入されたAppをすべて見せる一覧とは限りません。** 検索して見つからない場合は、検索語を消して一覧を確認し、それでも見つからなければ、案内されたリンクや自分の参加状態を確認します。

「マーケットプレイス」は新しいAppを探して導入を検討する場所です。導入済みAppが見つからないという理由だけで、再インストールを行わないでください。

### 案内されたリンクから開く

1. 管理者や担当者から案内されたAppのリンクを開きます。
2. ログインを求められた場合は、指定されたアカウントを使います。
3. 開いたApp名と利用する組織が、案内と一致することを確認します。

一覧に表示されていない場合でも、案内されたリンクからアクセス状態を確認できます。ただし、**リンクを持っているだけでアクセス権が付与されるわけではありません。**

## 2. 参加の案内が出た場合だけ、内容を確認する

すでに利用できる状態なら、そのままAppの画面が開きます。参加操作が不要な人もいます。

「参加」「参加する」が表示された場合は、次の順で確認してください。

1. 参加先が、案内されたApp・Projectであることを確認します。
2. 参加の説明を読み、付与される役割が自分の担当と合っているか確認します。
3. 案内された役割と一致していれば、参加を確定します。
4. 参加後にAppが開くことを確認します。

> **「管理者として参加しますか？」と表示された場合は、通常利用のための確認とは区別してください。** 管理を担当するよう案内されていなければ、いったん戻り、担当者へ利用者としての追加方法を確認します。使い始めるために全員が管理者になる必要はありません。

Appの画面でProjectへの参加を求められる場合があるのは、Appを構成するリソースやメンバーをProject単位で管理しているためです。新しいProjectを作成する操作ではありません。

参加のボタンがない、操作できない、アクセスエラーになる場合は、管理者に追加を依頼します。App名・利用アカウント・表示された案内を伝えてください。

## 3. 開いた画面から、使う機能を選ぶ

Appを開いた直後の画面には、主に次の違いがあります。

| 最初に開く画面 | 進め方 |
|---|---|
| App専用のホームPage | 画面内の説明に沿って、案内されたフォーム・一覧・業務メニューを使います。 |
| PageやAgentなどが並ぶダッシュボード | 目的に合う項目を選びます。すべての項目を順に操作する必要はありません。 |

ホームPageが開いた場合、ダッシュボードと同じメニューが見えなくても、それだけで異常とは限りません。「ダッシュボードに戻る」が表示される場合はそこから戻れますが、全員に表示されるとは限りません。

ダッシュボードやApp内のナビゲーションでは、次のような入口を探します。Appに用意されている機能や権限によって、表示は異なります。

| やりたいこと | 主な入口 | 次の操作記事 |
|---|---|---|
| 業務画面で入力・確認を進める | 「ページ」、または最初に開いたホームPage | [Pageから業務を進める](work-with-pages.md) |
| AIに依頼する・質問する | 「エージェント」 | [Agentと会話して結果を確認する](chat-with-agents.md) |
| 前の会話を確認する・続ける | 「チャットルーム」 | [Agentと会話して結果を確認する](chat-with-agents.md) |
| 用意されたWorkflowを実行する | 「オートメーション」内の対象Workflow | [公開済みWorkflowを実行する](run-published-workflow.md) |

App内の「オートメーション」には、Workflowや実行タスクが表示される場合があります。処理名と説明を読み、担当者から案内された対象を選んでください。初回利用のために自動実行の設定を変更する必要はありません。

ObjectのデータやStorageのファイルを使う場合は、そのAppで用意されたPageや操作導線に従います。どのAppにも、Object・Storageを直接操作するメニューがあるわけではありません。

## 4. 接続や設定を求められたら、担当を分ける

Appを開けても、外部サービスへの接続や共有設定が不足していると、一部の機能が利用できない場合があります。

| 求められていること | 対応する人・進め方 |
|---|---|
| 自分の外部アカウントの接続・再認証 | 本人が、Appで案内された接続画面から設定します。利用するサービスとアカウントを確認してください。 |
| 共有コネクタやProject Secretの設定 | 設定を担当する管理者に依頼します。他の利用者にも関係するため、自己判断で置き換えません。 |
| どちらか分からない | 表示されたメッセージを担当者に伝え、自分が行う設定かを確認します。 |

必要な個人接続があるAppでは、Appの「設定」から接続を確認できる構成もあります。具体的な認証手順は、[自分の外部アカウントを接続する](../operations/connect-your-external-accounts.md)で扱います。

「未設定の項目があります」「設定を確認」などの案内が出ても、App全体が利用できないとは限りません。反対に、**案内が出ないことだけで、必要な設定がすべて完了しているとも判断できません。** 設定の案内は権限によって表示が異なります。

パスワード・APIキー・認証トークンは、チャットや問い合わせ本文に貼り付けず、指定された設定画面で扱ってください。

## 5. 最初の操作と結果を確認する

使う機能が分かったら、そのAppの案内と対応する操作記事に沿って進めます。

1. 処理の対象と、入力する情報を確認します。
2. 外部への送信やデータの更新を伴う場合は、送信先・更新対象・実行範囲を確認します。
3. 許可された入力で操作を行います。
4. 画面の結果や状態を確認します。処理によっては、実行履歴や外部サービス側の反映も確認します。

**Appを開けたことや、ボタンを押せたことは、処理が完了したこととは別です。** AIの回答は内容を確認して利用し、送信や更新は意図した対象に反映されたかを確認してください。

結果が表示されない場合も、処理が動いていないとは限りません。送信・更新を伴う操作は、履歴や反映状況を確認してから再実行します。

## 開けない・利用を始められないとき

| 状況 | 最初に確認すること |
|---|---|
| Appsが見つからない | 利用する組織、メニューの表示、画面幅。PCでも見つからなければ管理者に利用条件を確認します。 |
| マイアプリに対象がない | 検索語を消し、App名・利用アカウント・参加状態を確認します。組織で未導入とは即断しません。 |
| 参加を求められる | 説明された役割を確認します。管理者参加が意図と違う場合は、利用者としての追加を依頼します。 |
| カードを選べない・「開く」が使えない | アクセス権やAppの状態を確認してもらいます。再インストールでは解決しない場合があります。 |
| リンクを開くと一覧へ戻る・エラーになる | 案内されたリンクが現在も有効か、対象Appが利用可能かを担当者に確認します。 |
| Appは開くが特定の処理が失敗する | その操作の権限、個人接続、共有設定、入力条件を確認します。 |

解決しない場合は、App名、発生日時、行った操作、表示メッセージをまとめて担当者に伝えます。スクリーンショットには、秘密情報や不要な個人情報が写らないようにしてください。

詳しい切り分けは[表示されない・参加できない](../troubleshooting/not-visible-cannot-join.md)で扱います。

## 利用開始の確認リスト

- [ ] 指定された組織・アカウントで、目的のAppを開けた。
- [ ] 参加が必要な場合、意図した役割で参加した、または担当者へ追加を依頼した。
- [ ] 最初に使うPage・Agent・Workflowなどが分かった。
- [ ] 個人接続と管理者の共有設定を区別できた。
- [ ] 最初の操作を行う前に、対象と影響、結果の確認方法を確認した。
