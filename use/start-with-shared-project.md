# 共有されたProjectで利用を始める

担当者から共有されたProjectを開き、用意されているPage・Agent・Workflowなどを使い始めるまでを説明します。**Projectは、作成者だけが使う場所ではありません。利用者は、既存のProjectで許可された機能を使えます。**

この記事では、新しいProjectやAppの作成は行いません。メンバーの追加や権限の変更、機能の構築手順も対象外です。導入済みAppを使う場合は、[導入済みAppを開いて利用を始める](open-installed-app.md)を参照してください。

## この操作でできるようになること

- 共有リンクや一覧から、目的のProjectを開く。
- 参加やアクセスの案内に応じて、必要な確認を行う。
- Project内の既存リソースから、担当する業務に必要な機能を選ぶ。

## 始める前に

共有した担当者から、次の情報を確認してください。

| 確認事項 | 確認する内容 |
|---|---|
| 利用先 | 組織名、Project名、共有リンク |
| 利用アカウント | 組織で利用を許可されたアカウント |
| 利用する機能 | Page・Agent・Workflowなどの名前と、最初に行う作業 |
| 自分の操作範囲 | 閲覧だけか、実行・入力・更新も行うか |
| 問い合わせ先 | Projectの管理者、または利用を案内した担当者 |

ログインや所属組織の確認は、[利用開始の前提と基本画面](../getting-started/getting-started-and-navigation.md)で説明しています。

> **リンクの共有と、アクセス権の付与は別です。** 組織に所属していても、そのProjectや個々の機能を利用できるとは限りません。共有した担当者に、利用者としての追加が必要か確認してください。

## 1. 共有されたProjectを開く

### 共有リンクから開く

1. 担当者から案内されたリンクを開きます。
2. ログインを求められたら、指定されたアカウントでログインします。
3. 利用する組織とProjectが、案内と一致することを確認します。
4. ホーム画面や、案内されたPage・Agentなどが開いたら、その対象を確認して利用へ進みます。

リンクがProject全体ではなく、個別のPageや会話などを指している場合は、その画面が直接開くこともあります。対象が分からなければ、担当者にProject名と機能名を確認してください。

### Studio Workspaceの一覧から探す

共有リンクがない場合や、あとからProjectを開き直す場合は、一覧から探します。

1. 今回利用する組織を開きます。
2. ナビゲーションの「Workspace」など、Studio Workspaceへの入口を開きます。「STUDIO」の配下に表示される場合もあります。
3. 「プロジェクト名で検索」に、案内されたProject名を入力します。
4. 名前と説明を確認し、対象のProject名のリンクから開きます。

「参加中のプロジェクト」「すべてのプロジェクト」のタブが表示される場合もあります。タブは全員に必ず表示されるものではなく、**「すべてのプロジェクト」に見えていることも、利用できることの保証にはなりません。**

Project名がリンクになっていない、または「未参加」と表示される場合は、次の参加・アクセス確認へ進みます。検索して見つからない場合は、検索語を消して確認し、それでも見つからなければ担当者にリンクと参加状態を確認してください。

> 既存のProjectを利用するために、新規作成や複製を行う必要はありません。別のProjectを作っても、共有元のデータやアクセス権は引き継がれるとは限りません。

## 2. 参加・アクセスの案内を確認する

すでに利用できる場合は、参加操作をせずに画面が開きます。案内が表示された場合だけ、内容を確認してください。

| 表示・状態 | 対応 |
|---|---|
| Projectや目的の画面がそのまま開く | 対象を確認し、利用する機能へ進みます。 |
| 「参加」「参加する」が表示される | 参加先と説明を読み、自分に案内された役割と一致するか確認します。 |
| 「未参加」で、参加操作ができない | 担当者に、利用者としての追加や必要な権限を依頼します。 |
| 一覧に戻る、アクセスできない | アカウント・組織・リンク・参加状態を確認します。画面の変化だけで原因を断定しないでください。 |
| 接続元の制限が表示される | 組織で指定されたネットワークなど、利用条件を確認します。 |

参加確認には、「このプロジェクトに管理者として参加しますか？」など、**管理者としての参加を示す説明**が表示される場合があります。通常の利用者登録と同じものだと思って進めないでください。

- 管理を担当するよう案内されていて、対象と役割が一致する場合は、参加を確定し、Projectが開くことを確認します。
- 利用だけを担当する場合や、役割が不明な場合は、「戻る」「キャンセル」などでいったん戻り、担当者に追加方法を確認します。

全員が管理者になる必要はありません。また、Projectに参加したあとも、閲覧・実行・編集・削除がすべて許可されるとは限りません。

## 3. 最初に開いた画面を確認する

Projectを開いた直後の画面は、設定によって異なります。

### 業務用のホームPageが開いた場合

入力フォームや一覧など、利用者向けのWeb画面が開きます。画面内の説明に従って、担当者に案内された操作へ進んでください。

ホームPageでは、通常のProjectナビゲーションが非表示になる場合があります。構築用のメニューが見えなくても、それだけで不具合ではありません。Projectの画面に戻る入口も、設定や権限によっては表示されません。

目的の操作が見つからない場合は、担当者に利用する画面を確認します。メニューを出すために、URLの書き換えやProject設定の変更を行う必要はありません。

### Projectのホーム画面が開いた場合

Project名や説明、チャットの入力欄、Agent、Page、共有された会話などを確認します。表示内容はProjectの構成や提供条件によって異なります。

利用するAgentやPageが指定されている場合は、その対象を選びます。最初に見えたチャット入力欄へ依頼することと、指定のAgentを選んで依頼することを、同じ操作だと決めつけないでください。

## 4. 目的に合う既存の機能へ進む

Project内のナビゲーションには、「AGENT」「PAGE」「WORKFLOW」「OBJECT」「STORAGE」「DATASET」などの入口があります。画面によって日本語表記になる場合もあります。

すべての機能を順に開く必要はありません。担当者に案内された対象から利用を始めます。

| やりたいこと | 探す入口・対象 | 次の操作記事 |
|---|---|---|
| 用意された業務画面で入力・確認する | ホームPage、または「PAGE」などにある対象Page | [Pageから業務を進める](work-with-pages.md) |
| AIに依頼する・質問する | ホーム画面のAgent、または「AGENT」の対象Agent | [Agentと会話して結果を確認する](chat-with-agents.md) |
| 共有された会話を確認する | Projectホームの共有された会話、または案内された会話リンク | [Agentと会話して結果を確認する](chat-with-agents.md) |
| 用意された処理を実行する | Project内の「ワークフロー」で対象の公開済みWorkflowを確認するか、担当者が案内した実行用のリンクを開く | [公開済みWorkflowを実行する](run-published-workflow.md) |
| 業務データを閲覧・入力・更新する | 「OBJECT」の対象Object、またはそのデータを扱うPage | [Objectのデータを閲覧・更新する](view-and-update-object-records.md) |
| ファイルを取得・保存する | 「STORAGE」の対象ファイルやフォルダ | [Storageのファイルを利用する](use-storage-files.md) |

この表は入口の見分け方です。表示される項目や利用できる操作は、機能の有効状態、Projectの構成、権限によって異なります。

**利用することと、作成・編集することを区別してください。** 通常の業務利用で、Agentの指示を書き換えたり、Workflowの下書きテスト・公開操作を行ったりする必要はありません。編集画面が開いてしまい、どこから利用するか分からない場合は、対象の利用方法を担当者へ確認します。

## 5. 接続と操作対象を確認して、最初の作業を行う

外部サービスを利用する機能では、自分のアカウント接続や、管理者による共有設定が必要な場合があります。

- **自分の外部アカウント接続を求められた場合**：利用するサービスとアカウントを確認し、案内された認証画面で設定します。詳しい手順は[自分の外部アカウントを接続する](../operations/connect-your-external-accounts.md)で扱います。
- **共有接続やSecretなどの設定が必要な場合**：Project管理者へ確認します。別の人の認証情報を受け取ったり、共有設定を自己判断で置き換えたりしないでください。

接続の準備が整ったら、最初の作業を行います。

1. 対象のPage・Agent・Workflowと、処理するデータを確認します。
2. メール送信、データ更新、ファイル保存などを伴う場合は、送信先・更新先・保存先を確認します。
3. 業務で利用を許可された入力を使い、必要な操作を行います。
4. 結果、処理状態、保存先などを確認します。

画面が開けることだけでは、その処理の実行権限や接続が整っているとは限りません。また、AIの回答が表示されたことと、外部サービスでの更新が完了したことも別です。

エラーや応答の途切れが起きた場合は、すぐに同じ処理を繰り返さず、履歴や更新先を確認してください。送信・登録などの重複を避けるため、実行済みか不明な場合は担当者へ確認します。

## うまく始められないとき

| 状況 | 最初に確認すること |
|---|---|
| Projectが一覧にない | 組織、検索語、共有リンク、利用アカウント、参加状態 |
| 名前は見えるが開けない | 未参加表示、利用者としての追加、アクセス権 |
| 他の人とメニューが違う | ホームPageの設定、利用する機能、権限の違い |
| Projectは開くが特定の機能を使えない | その機能の閲覧・実行権限、公開状態、必要な接続 |
| 共有された会話やデータが見つからない | 対象の名前・リンク、共有範囲、閲覧権限 |
| 画面の読み込みに失敗する | 表示されたエラーと発生日時。読み込み失敗を、Projectが存在しないことの根拠にしない |

問い合わせる際は、Project名、対象機能名、利用アカウント、行った操作、発生日時、表示メッセージを伝えます。パスワード・APIキー・トークンは送らず、画面画像の不要な個人情報や機密情報も隠してください。

## 利用開始の確認リスト

- [ ] 案内された組織・Projectを開けた。
- [ ] 参加や権限の案内を確認し、自分の役割に合う方法でアクセスしている。
- [ ] 利用するPage・Agent・Workflowなどの名前と入口が分かる。
- [ ] 個人接続と共有設定のどちらが必要か確認した。
- [ ] 最初の操作について、結果や更新先を確認できた。
