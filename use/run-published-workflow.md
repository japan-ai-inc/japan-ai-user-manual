# 公開済みWorkflowを実行する

担当者が業務利用向けに用意したWorkflowに必要な情報を入力し、実行結果を確認するまでを説明します。Workflowは、あらかじめ定義された処理を順番や条件に沿って進める機能です。

**「実行を開始できたこと」と「目的の業務が完了したこと」は別です。** 状態表示だけでなく、出力内容や、登録・送信などの処理結果まで確認してください。

この記事では、利用者が画面から実行する操作を扱います。Workflowの作成・編集・公開、トリガーや定期実行の設定は行いません。

## 始める前に

- 利用するAppまたはProjectと、Workflowの名前・用途を確認します。
- 担当者から、業務で使用してよい版と利用入口の案内を受けます。
- 必要な入力値、ファイル、処理対象の期間・レコードなどを用意します。
- 外部サービスへの送信やデータ更新がある場合は、対象・送信先・実行してよい範囲を確認します。
- 実行権限や接続設定の問題について相談できる担当者を把握します。

まだ利用先を開けていない場合は、次の記事から始めてください。

- [導入済みAppを開いて利用を始める](open-installed-app.md)
- [共有されたProjectで利用を始める](start-with-shared-project.md)

> 画面の表記・配置・利用できる操作は、組織の設定、権限、Workflowの構成によって異なります。以下はPCのWebブラウザで確認する流れです。実行ボタンが見えることだけで、公開や業務利用の確認が済んでいるとは判断しないでください。

## 1. 利用するWorkflowを開く

### Appから開く

1. 利用するAppを開きます。
2. ダッシュボードやナビゲーションの「オートメーション」から、目的のWorkflowを探します。
3. 名前・説明が目的の処理と合っていることを確認します。
4. 対象のカードや「実行する」から、入力・実行画面へ進みます。

App内の「オートメーション」には、Workflow以外に実行タスクが並ぶ場合があります。名前が似ていても、別の実行対象を選ばないようにしてください。

業務用のホームPageが開くAppでは、Pageに用意された入口や担当者の案内に従います。すべてのAppに同じ一覧が表示されるわけではありません。

### Projectから開く

1. 共有されたProjectを開きます。
2. Project内のワークフロー一覧を開きます。
3. 目的のWorkflowと公開状態を確認します。
4. 対象行の「手動実行」から入力画面を開きます。操作メニューに表示される場合は、メニューから選びます。

Workflowを編集することと、一覧から手動実行することは別の操作です。通常の業務利用では、編集画面で処理内容を変更したり、公開し直したりする必要はありません。

案内されたリンクから開く場合も、表示されたApp・Project・Workflowの名前を確認してください。

### 利用する版に迷ったとき

Appに配布されたWorkflowと、Project内で作成・更新されるWorkflowでは、実行対象の管理方法が異なる場合があります。**利用者が編集画面のテスト実行で代用するのではなく、担当者が案内した利用入口を使います。**

「公開済みのはずなのに入力項目が違う」「更新前と処理内容が変わった」などの疑問があれば、実行前に担当者へ確認してください。公開作業は[Workflowを公開する](../build/publish-workflow.md)で扱います。

## 2. 実行方法と入力項目を確認する

実行画面で、Workflowの名前・説明と、今回必要な情報を確認します。

- Appでは「実行に必要な情報」などの欄が表示されます。
- Projectの実行画面では「入力」などのタブが表示される場合があります。
- 実行方法を選ぶ欄がある場合は、担当者から案内された方法を選びます。
- 入力不要のWorkflowでは、入力欄が表示されない場合があります。

複数の実行方法があると、選択によって入力項目が変わります。**実行方法を切り替えた後は、入力値をもう一度確認してください。**

画面にAIモデル、完了通知先、Webhook URLなどの設定情報が表示されても、利用者が編集できる入力項目とは限りません。「開発者が設定した項目です。変更できません。」などの案内がある項目は、必要に応じて担当者へ変更を依頼します。

> 画面からの実行と、イベントやスケジュールによる自動実行は別です。この操作を行うだけで、定期実行の開始・変更・停止が完了するわけではありません。違いは[自動実行方式を選ぶ](../getting-started/choose-execution-method.md)で確認できます。

## 3. 必要な情報を入力する

項目名・説明・必須表示に従って入力します。

| 入力欄の例 | 確認すること |
|---|---|
| テキスト・長文 | 対象名、依頼内容、処理する範囲に不足がないか |
| 数値 | 単位、桁、対象件数などが説明に合っているか |
| 選択肢 | 初期選択のままでよいか、今回の業務に合っているか |
| URL | 目的の資料や対象を指しているか、指定された種類のURLか |
| ファイル | 正しい版・対象期間のファイルか、アップロードが完了しているか |
| JSONなどの構造化入力 | 担当者の入力例・形式に合っているか |

これは入力欄の例で、すべてのWorkflowに同じ項目があるわけではありません。前回の値や初期値が表示されている場合も、そのまま使ってよいか見直します。

### ファイルを使う場合

1. 対象のファイル入力欄を確認します。
2. 画面で許可されている方法で、ファイルを選択するかURLを入力します。
3. 表示されたファイル名・件数と、アップロードの完了を確認します。
4. エラーが出た場合は、形式・容量・件数などの案内を確認します。

対応形式、最大容量・件数、ローカルファイルとURLのどちらを使えるかは、入力欄の設定によって異なります。添付できたことだけで、すべての内容を正しく読み取れるとは判断しないでください。

パスワードやAPIキーなどを、用途の説明がない自由入力欄へ貼り付けないでください。接続・シークレットの設定不足が表示された場合は、AppやProjectの管理者に確認します。

### 入力例

例えば「売上集計レポート」というWorkflowに、対象期間・売上ファイル・出力形式の欄が用意されている場合は、期間とファイル内の日付を揃えて入力します。

- 対象期間：集計したい月
- 売上ファイル：その月の対象データを含むファイル
- 出力形式：画面で選択できる形式から選ぶ

この例は、入力内容の整合を確認する考え方です。標準で同名のWorkflowや同じ入力欄が用意されていることを示すものではありません。

## 4. 実行する

1. Workflow、実行方法、入力値、ファイルを見直します。
2. 登録・更新・送信を行う場合は、対象と実行範囲を再確認します。
3. 画面の「実行する」などの実行ボタンを1回押します。
4. 入力エラーが表示されたら、指摘された項目を修正します。
5. 実行が始まったら、状態や結果画面を確認します。

アップロード中、実行中、無効化されている場合、または実行権限がない場合などは、実行できないことがあります。ボタン付近や画面内のメッセージを確認してください。

**反応が遅い、画面が切り替わらないという理由だけで、同じ処理を繰り返し実行しないでください。** 画面への応答が失敗しても、処理自体は始まっている可能性があります。まず実行履歴や処理対象の状態を確認します。

画面を閉じたり別のページへ移動したりすることを、処理の停止として扱わないでください。

## 5. 状態と結果を確認する

### 実行状態を読む

画面や実行履歴には、次のような状態が表示されます。

| 状態 | 利用者が確認すること |
|---|---|
| 実行中 | 完了を待ちます。新しい実行を重ねず、状態を確認します。 |
| 成功 | 出力内容と、目的の業務結果が揃っているか確認します。 |
| 部分的成功 | どこまで完了したか、失敗・未完了の処理がないか確認します。 |
| 失敗 | エラーと完了済みの処理を確認し、再実行の可否を判断します。 |
| 停止 | 停止した時点までの結果を確認します。実行前の状態に戻ったとは限りません。 |

状態の詳しい原因は、表示されたエラーやステップの結果で確認します。「成功」であっても、生成された文章や集計値が業務上正しいことまで保証されるわけではありません。

### 出力内容を確認する

Appの結果画面や、Projectの実行画面の「結果」「ステップ」などを開いて確認します。

- 対象期間・顧客・レコードなどが、入力した条件と一致しているか。
- 期待した文章、数値、ファイルなどが出力されているか。
- 空欄、不自然な値、処理対象の抜けがないか。
- 必要な後続処理が完了しているか。

外部サービスへの登録・更新・送信を含む場合は、可能な範囲で対象サービスのレコードや送信履歴も確認します。結果が空の場合でも、「何も実行されていない」とは限りません。

### 結果を保存する

実行データをダウンロードできる場合は、Workflowが作成した業務用ファイルそのもののダウンロードとは別であることを確認します。

業務用のファイルや保存先が結果に示されている場合は、その案内に従って取得し、ファイルを開いて内容を確認します。すべてのWorkflowがファイルを生成するわけではありません。

取得したデータには入力内容や業務情報が含まれる可能性があります。保存先と共有相手は、組織のルールに従ってください。

## 6. 実行履歴から結果を見直す

1. 対象のWorkflowの「実行履歴」や「実行ログ」を開きます。
2. 開始時間、実行者、状態などで対象の実行を確認します。
3. 日付や状態などの絞り込みがある場合は、条件を調整します。
4. 「結果を開く」などから、その実行の内容を確認します。

同じWorkflowでも、別の人の実行や、異なる入力での実行が並ぶ場合があります。**一覧の先頭が自分の実行だと決めつけず、開始時間や実行者も照合してください。**

履歴や詳細の閲覧範囲は権限などによって異なります。結果が見つからない場合は、対象のApp・Project・Workflow、絞り込み条件、閲覧権限を確認します。結果のリンクを共有しただけで、相手に閲覧権限が付くわけではありません。

## 7. 再実行する前に確認する

再実行は、前回の表示を更新する操作とは異なります。新しく実行すると、登録や送信などが重複する可能性があります。

1. 前回の状態と、どこまで処理されたかを確認します。
2. 外部サービスや更新先に、すでに反映された内容がないか確認します。
3. 入力ミスや設定不足など、原因が解消されているか確認します。
4. 不明な場合は担当者に相談し、再実行してよいことを確認します。
5. 入力画面で値・ファイル・対象を見直してから実行します。

Appの結果画面の「再実行」は、入力・実行画面へ戻る入口です。戻っただけで完了とせず、入力内容と実行操作を確認してください。前回の入力がすべて引き継がれるとは限りません。

「実行状況を取得できませんでした」などの表示にある「再試行」は、状態の読み直しです。**状態取得の再試行と、Workflow自体の再実行を区別してください。**

## うまく進まないとき

| 状況 | 最初に確認すること |
|---|---|
| Workflowが見つからない | App・Project・Workflow名と、案内された入口を確認します。 |
| 無効化・権限不足と表示される | 自分で設定を変えず、担当者に有効状態や実行権限を確認します。 |
| 入力エラーになる | 必須項目、数値・URL・JSONなどの形式、添付条件を確認します。 |
| 接続や設定が必要と表示される | 管理者へ接続・シークレットなどの確認を依頼します。 |
| 状態やステップを取得できない | 表示の再試行を行います。処理自体が失敗・停止したとは断定しません。 |
| 失敗・部分的成功になる | エラーと完了済みの処理を確認し、重複の影響を確認してから再実行を検討します。 |
| 成功だが期待した結果ではない | 入力・出力・更新先を照合し、処理内容について作成者に相談します。 |

相談するときは、App・Project・Workflowの名前、実行日時、結果画面のURLや実行IDが分かればその情報、状態、エラー文、期待した結果を伝えます。スクリーンショットや入力例を共有する際は、秘密情報や不要な個人情報を除いてください。

## 完了の目安

- [ ] 正しいWorkflowと実行方法を選んだ。
- [ ] 必要な入力とファイルを確認した。
- [ ] 実行後の状態を確認した。
- [ ] 出力内容と、必要な登録・更新・送信の結果を確認した。
- [ ] 必要な成果物を取得し、未完了や不明点は担当者へ確認した。
