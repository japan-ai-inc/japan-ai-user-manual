# Storageのファイルを利用する

Storageは、Projectで利用する資料や成果物などのファイルを保存する場所です。この記事では、保存済みファイルを探して取得し、必要なファイルをアップロードして、Agentなどから参照するまでを説明します。

**「ファイルを保存する」「手元にダウンロードする」「Agentに読み取ってもらう」は別の操作です。** Storageに置いただけで、すべてのAgentが自動で内容を読み取ったり、Datasetの検索対象になったりするとは限りません。

フォルダ構成の設計、アクセス設定、API・SDKによる操作はこの記事の対象外です。既存の保存先を、許可された範囲で利用します。

## 始める前に

- 利用するProjectと保存先のフォルダを確認します。Appから利用する場合は、担当者が案内したファイルの入口を確認します。
- 取得・保存するファイルの名前、用途、対象期間や版を確認します。
- 業務で利用を許可された情報だけを扱います。共有先に見せてよい内容かも確認してください。
- 新規保存、既存ファイルの置き換え、取得のうち、どの操作を行ってよいか確認します。
- 操作できない場合の確認先を把握します。

利用先をまだ開けていない場合は、次の記事から始めます。

- [導入済みAppを開いて利用を始める](open-installed-app.md)
- [共有されたProjectで利用を始める](start-with-shared-project.md)

> 以下はPCのWebブラウザにある標準のStorage画面を中心に説明します。画面の表記や操作範囲は、設定・権限・Appの構成によって異なります。App独自のPage内にある添付・保存ボタンは、そのPageの案内に従ってください。

## 1. 保存先を開き、対象ファイルを探す

1. 対象のProjectを開き、「ストレージ」などの入口へ進みます。
2. フォルダを開いて、目的の保存先へ移動します。
3. 画面上部のフォルダの階層表示で、現在の場所を確認します。
4. 「ファイル名で検索」に名前の一部などを入力し、候補を絞ります。
5. ファイル名に加え、変更日・サイズ・アップロードしたユーザーなど、表示されている情報を確認します。
6. 件数が多い場合は、一覧のページを切り替えて確認します。

**検索して見つからない場合は、検索語だけでなく現在のフォルダも確認してください。** 標準の一覧は現在のフォルダを対象に取得するため、検索結果が空でもProject全体にファイルがないとは判断できません。検索語を消す、親フォルダへ戻る、案内された保存先を確認する、という順で探します。

同じ名前でも、保存先や内容が違う場合があります。特に顧客別・案件別の資料は、ファイル名だけで対象を判断しないでください。

AppにStorageの入口が見当たらない場合は、案内されたPageやリンクから利用します。すべてのAppに同じファイル一覧があるわけではありません。利用のためにAppの構成や権限を自分で変更する必要はありません。

## 2. 内容を確認し、必要ならダウンロードする

### プレビューで確認する

プレビュー操作が表示されている場合は、対象ファイルの内容を確認します。表示方法はファイル形式などによって異なります。

- プレビュー生成中なら、完了やエラーの表示を確認します。
- プレビュー非対応の場合は、ダウンロードして対応するアプリで開きます。
- 表示に失敗しても、それだけで元ファイルが消えた、または壊れたとは判断しません。
- 画像化された表示や一部の表示だけで内容を判断しにくい場合は、元ファイルを取得して確認します。

プレビュー画面で見えたことと、元のファイルを手元に保存したことは別です。

### 手元に保存する

1. 対象ファイルのダウンロード操作を選びます。
2. ブラウザのダウンロード結果を確認します。
3. 保存されたファイルを開き、必要な内容・対象期間・版であることを確認します。
4. 組織のルールに従って、手元の保存先や持ち出し可否を管理します。

フォルダや複数ファイルの選択時に「ZIPでダウンロード」が表示される場合は、まとめて取得できます。対象件数や容量などの制限・エラーは、画面の案内に従ってください。ZIPを取得できた場合も、中のファイルが目的のものか確認します。

取得できない場合は、対象がアップロード中ではないか、閲覧権限があるか、ブラウザ側でダウンロードが止められていないかを確認してください。以前に取得したダウンロード用URLは期限切れになる場合があります。その場合はStorageの画面から取得し直します。

## 3. ファイルをアップロードする

1. **保存先のProjectとフォルダを確認します。** ファイルの選択前に、保存先へ移動してください。
2. 「ファイルアップロード」を選びます。
3. アップロードするファイルを選択します。
4. 「選択されたファイル」の名前とサイズを見直します。
5. 「アップロード開始」を選びます。
6. 同名ファイルの確認が出た場合は、次の節を確認して判断します。
7. アップロードの進行状況と、各ファイルの完了・失敗を確認します。
8. 保存先の一覧で、意図した名前のファイルがあることを確認します。
9. 必要に応じてプレビューまたはダウンロードし、保存した内容を確認します。

ファイルをドロップできる画面もありますが、まず保存先を確認する点は同じです。

**ファイル選択画面が閉じても、アップロード完了とは限りません。** 標準画面ではアップロードの待ち行列に追加した時点でダイアログが閉じ、その後にファイル転送と保存の確定が行われます。「完了」の表示や完了通知まで確認してください。

複数ファイルを送った場合は、一部だけ失敗していないか確認します。失敗したファイルを再度アップロードするときも、先に保存先を確認し、すでに保存済みのものを重複登録しないようにします。

対応形式、ファイルサイズ、利用可能な容量などは画面の案内に従います。**プレビューの制限と、アップロードの制限は同じとは限りません。** エラーを避ける目的で拡張子だけを書き換えず、必要なら担当者に対応方法を確認してください。

## 4. 同じ名前のファイルがある場合を判断する

「ファイルが既に存在します」と表示されたら、既存のファイル名や変更日などを確認します。

| 選択肢 | 行うこと | 選ぶ前の確認 |
|---|---|---|
| 置き換え | 既存ファイルを新しいファイルで置き換える | 正しい保存先・対象か。既存資料を更新してよいか。参照している業務への影響はないか |
| 両方保持 | 新しいファイルに番号を付けて、既存ファイルと別に保存する | 別ファイルとして残す意図か。利用者がどちらを使うか判断できるか |
| キャンセル | 競合の判断を中止して見直す | 置き換えるべきか不明なときは、担当者へ確認する |

選択できる操作は権限によって異なります。「アップロード」を開けても、新規作成と置き換えの両方ができるとは限りません。

「両方保持」を選んだ後は、**実際に保存された名前**を一覧で確認します。元の名前を参照しているAgentや業務処理が、新しい別名ファイルを自動で使うとは限りません。

置き換えを行う場合は、必要な旧版を組織のルールに沿って保管するなど、事前に運用を確認してください。この操作だけで過去の内容へ戻せることは保証しません。

## 5. 保存したファイルをAgentなどから参照する

### パスをコピーして依頼する

標準画面には「パスをコピー（エージェントで使用可能）」という操作があります。対象ファイルのパスをコピーし、そのファイルへアクセスできるProjectの会話で、用途を添えて依頼します。

例えば、次のように依頼します。

> 次のStorageファイルを読み、契約更新の手続きを「必要な書類」「期限」「確認事項」に分けて要約してください。資料にないことは推測せず、要確認としてください。元ファイルの変更や外部への送信はしないでください。
>
> 対象：［Storageでコピーしたパスを貼り付ける］

ProjectのStorageでは、`project://`で始まる参照が使われます。手入力でパスを組み立てず、画面でコピーした値をそのまま使うと、名前や階層の取り違えを減らせます。

**パスはファイルを指定するための情報であり、閲覧権限を付与するものではありません。** Projectの文脈、Agentの利用可能な機能、ファイルへのアクセス条件などが合わなければ、読み取れない場合があります。別のProjectや関係のない会話へ貼り付けても、同じファイルを参照できるとは限りません。

読み取りを依頼した後は、対象ファイルを参照できたか、回答が内容に合っているかを確認します。ファイル名が回答に出ただけで、本文を読み取れたとは判断しないでください。

会話の進め方は、[Agentと会話して結果を確認する](chat-with-agents.md)を参照してください。

### 似た操作と区別する

| 操作 | 確認すること |
|---|---|
| Storageにアップロードする | Projectの意図した保存先にファイルが保存されたか |
| 会話にファイルを添付する | その会話で添付が完了し、依頼対象になっているか |
| Datasetで資料を検索する | 取り込み・同期・参照設定など、Dataset側の準備ができているか |
| PageやWorkflowでファイルを利用する | その画面・処理が求める入力や参照方法に従っているか |

Agentが成果物を作った場合も、会話にファイルが表示されたことだけで、ProjectのStorageへ保存されたとは判断しません。Storageへの保存が必要なら、保存先を明示して、一覧で保存結果を確認してください。

## 6. 名前変更・移動・削除は影響を確認してから行う

ファイルの整理は、取得・保存とは別の操作です。名前や場所を変更すると、以前のパスを使っている会話・Page・Workflowなどで参照できなくなる可能性があります。

- 業務で使用中のファイルは、参照元と担当者を確認してから整理します。
- フォルダを操作するときは、配下のファイルへの影響も確認します。
- Appが管理するファイルなど、変更操作が制限されるものがあります。通常のアップロードファイルと同じ扱いにしないでください。
- 読み取り専用の制限を回避するために、Appの更新・削除やアクセス設定変更を行わないでください。

この記事では、名前変更・移動・削除を利用開始の必須手順には含めません。取得・参照だけが目的なら、元ファイルを変更する必要はありません。

## うまくいかないとき

| 状況 | 最初に確認すること |
|---|---|
| ファイルが見つからない | Project、現在のフォルダ、検索語、一覧のページ、閲覧権限 |
| ファイルアップロードを選べない | 新規保存・更新の権限、画面に表示された制限理由 |
| ダイアログが閉じたが保存されていない | 待機中・アップロード中・失敗の状態。閉じたことを完了とみなさない |
| 同名ファイルの確認が出る | 保存先と既存ファイルの版。置き換えと別名保存のどちらが必要か |
| プレビューが表示されない | 対応形式・生成状態。取得権限があればダウンロードして確認 |
| ダウンロードできない | アップロードの完了、閲覧権限、ブラウザの動作。古いURLではなく画面から取得し直す |
| Agentが資料を読めない | コピーしたパス、会話のProject、Agentの機能・権限。Storage保存とDataset参照を混同していないか |

解決しない場合は、Project名、フォルダ、ファイル名、操作した日時、表示されたエラー、行いたかった操作を担当者へ伝えます。機密資料や一時的なダウンロードURLを、不必要に広い範囲へ共有しないでください。

## 完了チェック

- [ ] 対象のProject・フォルダ・ファイルを確認した
- [ ] 取得したファイル、または保存したファイルの内容を確認した
- [ ] アップロードの待機中・失敗を完了と取り違えていない
- [ ] 同名ファイルは意図した方法で処理し、保存後の名前を確認した
- [ ] Agentなどで使う場合は、参照先と読み取り結果を確認した
- [ ] 関係のないファイルや権限設定を変更していない
