# Pageのビルド・起動・更新

Pageを更新する開発者は、ローカルでブラウザ向けの成果物をビルドしてZIPにし、既存Pageへ新しいバージョンとしてアップロードします。登録時のビルドや依存関係の導入に依存せず、完成済みの成果物を用意してください。アップロード完了の表示だけでは、利用者の環境で動作することまでは保証されません。

この記事では、公開済みPageの更新、適用中の版とロールバック、アクセス設定との関係、稼働確認、ビルド・表示に失敗したときに確認できる範囲を説明します。初回の登録・公開操作は[画面からPageを登録・公開する](../build/register-and-publish-pages.md)、ZIPの構成と上限は[Pageの仕様・制限](../build/page-specs-and-limits.md)を参照してください。

## 始める前に

- 対象の組織、Project、Page名と、現在「適用中」の版を確認します。Pageカードの `Ver.` 表示は確認の補助になりますが、「バージョン履歴」の「適用中」を正として確認します。
- ローカルで成果物を作り、HTML、JavaScript、CSS、画像など、ブラウザへ配るファイルだけをZIPのルートに配置します。ZIP内の `node_modules` や、ルートの `dist`、`build` などは配信対象から除外され得ます。
- 更新する画面、入力、データ取得、登録・更新、外部送信などから、公開後に実施する代表操作を決めます。影響する利用者と切替時刻も関係者と確認してください。
- 更新は対象Pageを編集できる利用者が行います。メニューや操作が表示されない、または選択できない場合は、対象Project・Page・権限を確認します。

> ブラウザへ配信するZIPには、APIキー、パスワード、トークン、Project Secretの値を含めないでください。画面を公開していない場合でも、利用者のブラウザへ届く値は取得され得ます。

## ビルド・デプロイ状態を確認する

Pageには「新しいバージョンをアップロード」、「適用中」、「バージョンの切り替えに失敗しました」などの表示があります。Page単位のビルド・デプロイ状態やログを一覧・履歴で追跡する画面は確認できません。

アップロード直後に状態名だけで稼働を判断せず、次の3点を組み合わせて確認します。

| 確認対象 | 確認方法 | 判断できること |
|---|---|---|
| 版の適用 | 「バージョン履歴」で意図した版に「適用中」があることを確認します。 | 現在参照する版が想定どおりであること |
| 配信開始 | 利用者と同じ入口からPageを開きます。 | Pageを開く処理と画面の初期表示 |
| 業務動作 | 変更した代表操作を実行し、画面・保存結果・外部処理を確認します。 | 実際の利用に必要な処理の成否 |

> 「アップロードしました」または更新完了の通知は、代表操作まで成功した証明ではありません。特に認証、データ更新、外部送信を含むPageは、対象の利用条件で確認してから案内してください。

## 1. 新しいZIPを同じPageへ適用する

この操作は新規Pageを作るものではありません。対象Pageの「新しいバージョンをアップロード」からZIPを登録すると、同じPage IDのまま新しい版が作られ、版番号は既存の最大値より増えます。Pageの名前を同じにした別の新規アップロードと取り違えないよう、必ず既存Pageのメニューから開始します。

1. 対象Pageのメニューから「新しいバージョンをアップロード」を選択します。
2. 完成済みのZIPを1件選び、ファイル名とサイズを確認します。ZIPは100MB以下です。
3. 「アップロード」を選択し、処理中はダイアログを閉じたり、同じ更新を重ねたりせず、完了またはエラー表示を待ちます。
4. 完了後、Pageカードの `Ver.` と「バージョン履歴」を開きます。新しい履歴が増え、意図した版が「適用中」であることを確認します。
5. Pageを開き、初期表示と、あらかじめ決めた代表操作・結果を確認します。

更新時には新しい成果物が配信対象へ反映され、新しい成果物に含まれない以前のファイルは残さない扱いです。古いアセットへの参照やキャッシュに見える問題を避けるため、HTML、JavaScript、CSS、画像など必要な一式を毎回ZIPへ含めます。

## 2. 適用中の版を確認し、必要なら戻す

「バージョン履歴」には版の作成日時、名前、説明、アップロードした人が表示され、適用中の版には「適用中」と表示されます。番号が最も大きい版と適用中の版が一致するとは限りません。過去版へ戻した後も、より新しい番号の履歴は残ります。

1. 対象Pageのメニューから「バージョン履歴」を開きます。
2. 「適用中」の表示、版の日時、名前、説明、アップロードした人を確認します。
3. 問題があるときは、戻したい過去版のメニューから「復元して適用」を選択します。
4. 「〜に切り替えました」と表示されたら履歴を開き直し、選んだ版が「適用中」になったことを確認します。
5. Pageを再度開き、戻したかった表示だけでなく、代表操作と結果も確認します。

「復元して適用」は過去のファイルを現在のPageコンテンツとして再適用し、適用中の版を切り替える操作です。新しい版番号を作るロールバックではありません。また、適用中の版は削除できません。

> 切替や表示に問題が起きたとき、原因が未確定のままアップロードと復元を連続して行わないでください。現在「適用中」の版、直前の操作、発生日時、表示メッセージ、再現手順を記録します。

## 3. アクセス設定を変更するときの確認

「アクセス設定」で変更するのは、Pageを開く際の認証・公開条件です。変更できる選択肢には「サインイン必須」「サインイン任意」「匿名アクセス」があり、組織・Pageの条件によっては「外部顧客認証」も扱います。アクセス設定の保存は、Page IDやバージョンを新規作成・切替する操作ではありません。

1. Pageのメニューから「アクセス設定」を開きます。
2. 「アクセスモード」と対象Pageを確認し、必要な設定を選びます。
3. 保存後に「アクセス設定を保存しました。」を確認します。
4. 「バージョン履歴」で「適用中」の版が意図せず変わっていないことを確認します。
5. 変更後のアクセス条件で、想定した利用者がPageを開けることを確認します。公開URLが表示される場合も、表示データと実行できる操作を確認してから共有します。

> アクセス設定を緩めても、Page内のデータ操作が安全になるわけではありません。サインイン任意・匿名アクセスで公開する前に、画面に表示する情報と利用者が実行できる処理を個別に確認してください。

## 稼働を確認するチェックリスト

- [ ] Pageカードの `Ver.` と「バージョン履歴」の「適用中」が、意図した版を示している
- [ ] 利用者と同じ入口・アクセス設定でPageを開ける
- [ ] 初期表示で必要なHTML、JavaScript、CSS、画像が読み込める
- [ ] 変更した閲覧、入力、検索、実行などの代表操作と結果を確認した
- [ ] データ更新・外部送信がある場合、許可された検証方法で結果を確認した
- [ ] 版、切替時刻、変更内容、確認結果、未確認項目を関係者へ共有した

## うまくいかない場合

### ビルド失敗の状態やログを見たい

Pageの詳細なビルド・デプロイ状況や、利用者が開くビルドログを表示する画面は確認できません。アップロードまたは切替で表示されたエラー、ブラウザのネットワーク上の失敗、対象Page・Project、適用中の版、ZIP名、発生日時、再現手順を記録してください。秘密値、認証情報、個人情報をZIP・スクリーンショット・問い合わせに含めないでください。

Pageが開かない、白い画面になる、または更新後の動作を確認できない場合は、ZIPを展開して成果物の配置と参照パスを確認し、[Pageの仕様・制限](../build/page-specs-and-limits.md)を確認します。失敗の切り分けは[Pageのビルド・起動・表示に失敗する](../troubleshooting/page-build-start-display-failures.md)で扱います。

### アップロードや切替に失敗する

ZIP以外、複数ファイル、100MBを超えるZIPは登録できません。処理中であることを示すメッセージが出る場合は、直ちに再試行せず、時間をおいて「バージョン履歴」の「適用中」と実際のPageを確認します。操作が表示されない場合は、対象の組織・Project・Pageと編集権限を確認します。エントリ数、展開後サイズ、ZIP構造は[Pageの仕様・制限](../build/page-specs-and-limits.md)を確認してください。
