# Agentがデータを参照しない

このページは、Agentに資料やObjectを参照させたいのに、回答に資料の内容が出ない、古い内容が出る、または利用者によって結果が異なるときの切り分け手順です。対象はAgentの利用者と作成者です。まず「資料をDatasetとして参照させる問題」と「Objectや外部サービスをツールで読む問題」を分けてください。資料名を会話や指示に書いただけでは、Agentの参照設定・接続・権限は完了しません。

## 始める前に

- 対象の組織・Project・Agent名、質問した利用者、確認したい資料またはObjectを特定します。
- 資料の原文で答えを確認できる短い質問を1件用意します。更新日、見出し、固有の用語を含めると確認しやすくなります。
- 正しい回答がない質問も1件用意します。根拠のない内容を「参照できた」と判断しないためです。
- 外部更新、メール送信、レコード更新を含むツールは、この切り分けで実行しません。まず読み取りだけ、またはテスト用データで確認します。

> Datasetの選択、Agent設定の保存、データの取り込み完了、利用者の参照可否は別々の条件です。いずれかが未確認のまま、資料を再登録したり、共有範囲を広げたりしないでください。

## まず確認すること

- [ ] 対象Agentの「データ連携」に、正しいDatasetが選ばれている
- [ ] 選択画面で「適用」し、Agentを開き直しても設定が残っている
- [ ] Dataset内の対象データの「ステータス」が「完了」である
- [ ] 資料の現行版が取り込まれ、古い版・類似資料との重複がない
- [ ] 利用者、Agent、Dataset、必要なツール・接続の共有範囲と権限が合っている
- [ ] Agentの指示が、資料を参照して根拠のない補完をしないよう求めている

## 1. Datasetの状態から確認する

1. 対象Datasetを開き、資料の名前、取得元、更新日、版が正しいことを確認します。
2. データ一覧で対象データの「ステータス」を確認します。「保留中」「進行中」「更新」の間は処理中です。「失敗」「コンテンツなし」「読み取り不能」は、期待どおりに参照できない可能性があります。
3. 資料を更新した場合は、更新方法を確認します。PCから追加したファイルは更新後のファイルを改めて取り込む必要があります。外部のWebまたは外部APIを取得元とする場合は、同期・再読み込みの結果を確認します。
4. 現行版だけを残すか、旧版を残すかを判断します。同じ内容や旧版を重複して入れた状態では、回答の根拠を追いにくくなります。
5. 「完了」になった後、原文に答えがある短い質問で参照結果を確認します。

## 2. Agentの参照設定と指示を確認する

1. 作成者はAgent設定の「データ連携」を開きます。
2. 「データセットを選択」で対象Datasetにチェックを付け、不要なDatasetの選択を外します。
3. 「適用」を選び、Agentの「データ連携」欄と保存状態を確認します。選択画面を閉じただけでは適用されません。
4. 指示に、対象資料を参照すること、根拠がなければ未確認と答えること、参照できない資料を読んだことにしないことを明記します。
5. 作成者と想定利用者の両方で、同じ小さな質問を試し、資料の原文と回答を照合します。

> Datasetは、質問に関連する情報を探して回答する用途に向きます。契約書・マニュアルなどから全項目を漏れなく確認する用途では、Datasetを選んだことだけで全文を確認したとは扱いません。対象ファイルを明示し、取得・確認できた範囲を検証する別の手順を用意してください。

## よくある誤解

### 資料名を指示に書けばDatasetを選ばなくてよい

指示は回答の方針を伝えるものです。資料をAgentの参照情報として設定する操作は「データ連携」で行い、「適用」と保存結果を確認します。

### Datasetに入れれば、毎回すべての資料が回答に使われる

Datasetは全文を順番に読むことを保証するものではありません。質問との対応、資料の状態、Agentの指示、回答の根拠を確認します。

### ツールを追加すればObjectや外部サービスを必ず読める

ツールの追加、認証、外部サービス側の権限、Objectのレコードアクセスルールは別です。読み取りが必要な対象と範囲を確認してからテストします。

## 管理者・サポートに相談する前に

次を、秘密情報や資料本文を含めずに記録します。Agent名、組織・Project、DatasetまたはObject名、対象データの識別情報、利用者の種別、操作日時、質問、期待結果と実際の結果、データのステータス、確認済みの「データ連携」・共有範囲・接続状態、表示メッセージです。問い合わせ情報のまとめ方は[問い合わせに必要な情報を集める](collect-info-for-support.md)を参照してください。
