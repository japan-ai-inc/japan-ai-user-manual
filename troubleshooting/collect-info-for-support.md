# 問い合わせに必要な情報を集める

このページは、JAPAN AIの管理者・サポートへ不具合や確認依頼を送る前に、調査に必要な情報を秘密情報なしでそろえるための手順です。対象は全員です。画面で失敗した、Appが使えない、Workflowの結果が分からない、SDK／APIやCLIが失敗した場合に使います。原因を推測して認証情報や業務データを送るのではなく、対象、時刻、再現条件、表示結果、実施済みの確認を対応付けます。

## 始める前に

問い合わせは、同じ対象で何が起きたかを第三者が追える状態にするためのものです。エラーが出た直後に操作を連続して繰り返すと、状態や実行履歴が変わり、重複した外部送信・更新が起きる可能性があります。まず現在の状態を確認し、影響がある処理は必要最小限で止めます。

> APIキー、パスワード、Secret、トークン、Cookie、認証ヘッダー、MFAコードは、問い合わせ・画面キャプチャ・ログ・コード断片へ絶対に含めません。氏名、メールアドレス、電話番号、住所、顧客データ、会話本文、ファイル本文などの個人情報・業務データも、調査に不要な形で送らないでください。値を伏せるだけで安全か判断できない場合は、送信せず担当者へ相談します。

## まず確認すること

- [ ] 対象の組織、Project、App、Page、Agent、Workflowなどを取り違えていない
- [ ] 発生日時とタイムゾーン、実行者または影響を受けた利用者を記録した
- [ ] 実行ID・run ID・エラーID・対象ID・URLなど、画面に表示された識別情報を控えた
- [ ] 期待した結果と実際の結果、表示されたエラー全文または安全な要約を分けた
- [ ] SDK／CLIなら、SDK版、CLI版、Node.js版、実行モード、HTTPステータスまたは終了コードを控えた
- [ ] 再試行、更新、削除、再デプロイの有無と、その結果を記録した
- [ ] 認証情報、Secret、トークン、個人情報、業務データを含まないことを送信前に確認した

| 削除・アンインストール・引き継ぎの結果が分からない | 受付済み・処理中・完了・失敗、または対象操作を取り違えている | 対象、操作種別、日時、実行者、削除前後の状態、影響範囲、監査ログまたは実行履歴を確認した期間・絞り込み条件を記録します。 | [削除・引き継ぎと監査記録を確認する](../operations/deletion-handover-and-audit-logs.md) |

## 集める情報を段階ごとに整理する

### 1. 対象と発生時点を特定する

組織名、Project名、App名、Page名、Agent名、Workflow名など、該当する対象を記録します。可能なら画面に表示されるID、実行ID（run ID）、エラーID、公開URLまたは画面URLを控えます。URLにトークン、個人情報、検索語、機密のパラメーターが含まれる場合は、その部分を送信しません。

次に、発生日時をタイムゾーン付きで記録します。開始・終了が分かる処理では両方を記録し、単発か継続中か、影響を受ける利用者・業務範囲も要約します。再現できる場合は、通常の利用手順を必要最小限で記録します。外部サービスの更新、送信、削除を伴う操作を調査目的で繰り返しません。

### 2. 結果と確認済み事項を分ける

期待結果と実際の結果を別々に書きます。画面に出たエラー文は、キー・トークン・個人情報・業務データがないことを確認してから記録します。スクリーンショットは、ブラウザのアドレスバー、通知、入力欄、ログに秘密情報が写り込んでいないかを確認します。

実施済みの確認も順序付きで記録します。たとえば「対象Projectを確認した」「実行履歴でrun IDを探した」「導入先の設定状態を確認した」「429の待機案内に従った」「タイムアウト後に結果を照会した」のように記載します。原因を推測で断定せず、確認できた事実と未確認事項を分けます。

### 3. SDK／API／CLIでは環境情報を追加する

SDK／APIの問い合わせでは、パッケージ名とSDKバージョン、Node.jsバージョン、実行モード（ローカルNode.js、PRSブラウザ、PRSサーバー）、使用したAPI・SDKメソッド、HTTPの`statusCode`、タイムアウトの設定・発生有無を控えます。CLIではCLIバージョン、コマンド、終了コード、プロファイル名・環境名、標準エラー出力の安全な要約を追加します。

認証そのものの値は不要です。「対象Project用のキーを安全な環境変数から渡した」「PRSブラウザではキーを設定していない」のように、設定方法と確認結果だけを書きます。`baseUrl`やURLも、秘密のクエリ文字列・トークンを除いた範囲で、実行モードに合う接続先か確認します。

> ログや`responseBody`には入力値が含まれることがあります。エラー全文をそのまま送る前に、APIキー、Authorization、Cookie、Secret、個人情報、本文・添付内容を除去してください。安全に編集できない場合は、エラーID、時刻、対象、ステータスだけを送り、元ログはアクセス制御した場所に保持します。

## 問い合わせテンプレート

次のブロックを複製し、不要な項目は「該当なし」とします。角かっこ内に秘密情報を書かないでください。

```text
件名: [対象機能] の [症状] を確認したい

■ 対象
組織 / Project / App・リソース名: [名称と共有可能なID]
URL: [トークン・個人情報を除いたURL]
実行ID（run ID）/ エラーID: [表示されている場合のみ]

■ 発生状況
発生日時（タイムゾーン）: [YYYY-MM-DD HH:MM TZ]
実行者・影響範囲: [役割・人数・業務影響の要約]
期待結果: [期待した状態]
実際の結果: [表示・状態・安全に伏せたエラー文]

■ 再現手順と実施済み確認
1. [操作]
2. [操作]
再試行・状態照会の有無と結果: [内容]

■ 開発・CLIの場合
SDK / CLI / Node.jsの版: [値]
実行モード: [ローカルNode.js / PRSブラウザ / PRSサーバー]
API・SDKメソッドまたはコマンド: [秘密値を除いた内容]
HTTP statusCode / CLI終了コード: [値]

■ 含めていない情報
APIキー、Secret、トークン、Cookie、認証ヘッダー、個人情報、業務データ: 含めていません
```

## 送ってはいけない情報

| 種類 | 送らないもの | 代わりに記録するもの |
|---|---|---|
| 認証情報 | APIキー、Secret、パスワード、トークン、Cookie、MFAコード、`Authorization`・`x-api-key`の値 | キーを使ったか、対象Project、設定方法、有効性・スコープを確認した結果 |
| 個人情報・業務データ | 氏名、メール、電話番号、住所、顧客情報、会話本文、入力値、ファイル本文・添付内容 | 件数、データ種別、影響範囲、再現用の安全なダミー情報 |
| URL・ログ | 署名付きURL、クエリのトークン、完全なリクエスト・レスポンス、未加工の画面キャプチャ | トークンを除いたURL、エラーID、時刻、ステータス、伏せた要約 |

## 管理者・サポートに相談する前に

問い合わせを送る直前に、対象・時刻・ID・期待と実際・再現手順・実施済み確認がそろっているか、秘密情報と個人情報がないかを再確認します。削除・引き継ぎでは、対象操作、実行者、影響範囲、監査ログまたは実行履歴の確認条件も追加します。詳細は[削除・引き継ぎと監査記録を確認する](../operations/deletion-handover-and-audit-logs.md)を参照してください。
