# Workflowが起動しない・失敗する

このページは、Workflowを手動実行できない、イベントやタスクのスケジュールで起動しない、または起動後に失敗する場合の切り分け手順です。対象は作成者・運用担当です。最初に、下書きのテスト、公開済みWorkflowの手動実行、トリガー、「タスク」で管理するスケジュールを区別してください。下書きの変更は公開するまで通常の利用・トリガー・スケジュール実行に反映されません。

## 始める前に

- どの開始方法かを特定します。編集画面のテスト、利用者の手動実行、イベントトリガー、「タスク」で管理するスケジュールでは確認場所が異なります。
- 対象の組織・Project・Workflow名、公開状態、開始ノード、発生日時、実行者またはイベントを記録します。
- メール送信、Objectの作成・更新、外部サービスの更新を行うWorkflowは、失敗時にも途中まで処理済みの場合があります。原因が不明なまま「実行を開始」や再実行を繰り返しません。
- テストは、できるだけ外部更新のない構成、または許可されたテスト用の接続先・データで行います。

> 通知が届かないことと、Workflowが起動していないことは同じではありません。まず「実行履歴」またはタスクの「実行履歴」に記録があるかを確認し、実行、結果、通知を分けて切り分けます。

## まず確認すること

- [ ] 対象が下書きか「公開済み」か、開始方法は何かを確認した
- [ ] 変更後の下書きを「一時保存」し、必要なら「公開」した
- [ ] 開始ノード、必須入力、変数参照、未接続・未設定のノードを確認した
- [ ] トリガーならイベント条件・接続・公開状態を、スケジュールなら有効状態・次回実行・作成者を確認した
- [ ] 実行履歴で対象実行のステータス、結果、ステップ、最初に異常になったノードを確認した
- [ ] 再実行による外部送信・レコード重複の影響を確認した

## 1. 起動経路を分けて確認する

1. 編集画面から試した場合は、下書きの「実行履歴」を確認します。これは公開前のテスト用です。
2. 公開後に利用者・トリガーが起動した場合は、対象Workflowの実行ログを確認します。組織の「タスク」を使える場合は、「作る」で対象Workflowを確認し、利用できる「実行履歴」を開きます。編集画面でのテスト実行はここには表示されません。
3. イベントトリガーの場合は、Workflowが「公開済み」か、開始ノードのイベント条件と接続が正しいかを確認します。公開後に実際のイベントで1回確認します。
4. 定期実行の場合は、「タスク」の「使っているもの」から対象タスクを開き、状態、「次回実行」、終了日、実行履歴を確認します。Workflowを編集した場合も、公開版だけが実行対象です。

## 2. 入力と公開前の設定を確認する

実行できないときは、表示されたメッセージのノード名と理由を記録し、次の順に確認します。

1. 手動入力の必須項目、URL・JSON・数値など入力形式を確認します。
2. 開始ノードが想定の開始方法に合うかを確認します。
3. 「チェックリスト」の未接続ノード、設定不正、必須のプロンプト・モデル・変数・Dataset・ツールを確認します。
4. 参照している変数が削除・名称変更された出力を指していないか、分岐ごとの値と型が合うかを確認します。
5. 修正後は「一時保存」し、代表的な入力とエラーになる入力をテストします。通常利用または自動起動へ反映するには、テスト後に「公開」します。

## 3. 失敗したノードを実行履歴で確認する

実行詳細の「結果」でステータス・エラー・経過時間を確認し、「ステップ」で各ノードの入力・出力を開始ノードから順に見ます。入力が空、想定外の分岐、出力形式の不一致、接続・権限・相手先のエラーを分けます。成功は業務結果が正しいことの保証ではないため、送信先・更新先・最終出力も確認してください。

失敗したイベント実行で「再実行」が表示される場合でも、保存された入力で実行されます。失敗前にObjectなどへの書き込みが完了していたときは、再実行で重複する可能性があります。原因、既存レコード、外部送信の状況を確認してから実行します。手動実行の失敗は、通常の実行画面から入力を確認してやり直します。

> 接続が「認証済み」と見えても、対象フォルダー・送信先・レコードへの権限や、外部サービス側の制限が変われば失敗します。接続だけを原因と決めず、実行履歴の失敗ノードと入力・出力を先に確認してください。

## 管理者・サポートに相談する前に

秘密情報、メール本文、トークン、Webhook URL、個人情報を除き、次を記録します。Workflow名と組織・Project、開始方法、公開状態、発生日時、実行IDまたはタスク名、ステータス、表示メッセージ、失敗ノード、入力・出力のうち共有可能な要約、接続状態、実行済みの外部処理、再実行の有無、確認済みの対処です。実行データをJSONで保存する場合は入力・出力を含むため、保存先と共有相手を制限します。詳しくは[問い合わせに必要な情報を集める](collect-info-for-support.md)を参照してください。
