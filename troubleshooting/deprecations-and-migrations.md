# 非推奨機能・移行のお知らせ

既存の操作やコードの更新が必要な変更について、期限、影響、移行先を確認するページです。利用者は日常操作への影響を、SDK・CLIやAPIを利用する開発者は更新前のコード・自動化・Pageを確認します。

ここに掲載するのは、確認済みの一次情報で明示された変更だけです。SDK／CLIの `CHANGELOG.md` にある0.2.0〜0.11.0の破壊的変更・互換性上の注意を掲載します。Studio画面について、非推奨化・終了日・移行が必要な変更履歴は確認できていないため、作成しません。

## この記事の範囲

対象範囲を次の4つに分けて読みます。

| 対象 | このページで確認すること |
|---|---|
| Studio UI | 画面操作の廃止、表示・権限・導線の変更、利用者が行う移行。現在は確認済みエントリーなしです。 |
| SDK／CLI | npmパッケージ `@japan-ai-inc/studio-sdk`、`jai-studio`、公開メソッド・型・コマンド引数の変更。 |
| 公開API | SDKが利用する経路、応答、書き込み動作との互換性。SDK更新と接続先の対応状況は別に確認します。 |
| Page runtime | Studio Page内ブラウザまたはサーバー側で使えるSDK機能、セッション、認証、対応する実行環境。 |

「非推奨」は、単に古い版があることではなく、旧機能・引数・運用が使えなくなる、または移行が必要と一次情報で示された状態です。SDKは1.0未満のため、minor版にも破壊的変更が含まれ得ます。期限・終了日が示されていないものを、独自に「廃止予定」とは扱いません。

> Project APIキー、Cookie、認証ヘッダー、Secret値、トークンを、移行メモ、ソースコード、Pageのブラウザ側、問い合わせへ含めないでください。認証情報の発行・管理は[Project APIキーを管理する](../operations/manage-project-api-keys.md)を参照してください。

## まず確認すること

- SDK／CLI版、Node.js、ロックファイル、実行しているCLIの版を確認します。
- 変更対象がStudio UI、SDK／CLI、公開API、Page runtimeのどれかを分けます。
- 現在版から更新先までの項目を読み、使用中のメソッド、型、CLI、テスト・モック、Pageを検索します。
- 期限、影響、移行先が未記載の項目は、勝手な期日を設けず、互換性確認と検証を先に行います。
- 更新前の動作を記録し、検証環境で変更・失敗時・競合時を確認します。

```bash
node --version
npm ls @japan-ai-inc/studio-sdk
jai-studio --version
```

SDK 0.11.0とCLIにはNode.js **22以上**が必要です。SDKとCLIを使う構成では、同じ完全な版にそろえます。版の確認方法は[開発環境・バージョン・互換性](../development/dev-environment-and-versions.md)を参照してください。

## お知らせエントリーの形式

非推奨・移行のお知らせは、次の形式で記載します。未確認の期限や移行先を推測で補完しません。

| 項目 | 記載する内容 |
|---|---|
| 対象／状態 | Studio UI、SDK／CLI、公開API、Page runtimeの別と、非推奨・破壊的変更・終了予定などの状態 |
| 期限 | 一次情報にある日付・版・終了条件。記載がなければ「期限未記載」 |
| 影響 | 使えなくなる操作、変更されるデータ・型・表示、影響する利用者・実行環境 |
| 移行先・対応 | 新しい引数・形式・操作、検証方法、関連手順 |
| 根拠・問い合わせ先 | 一次情報、関連する移行記事、担当窓口。認証情報は含めない |

## 現在確認できるSDK／CLIの移行項目

### Object更新の完全ペイロード化（SDK 0.2.0）

| 項目 | 内容 |
|---|---|
| 対象／状態 | SDK／CLI・公開API。Custom Objectのレコード更新は完全な型付きペイロードを送る前提へ変更されました。 |
| 期限 | 0.2.0で変更済み。別の終了期限は記載されていません。 |
| 影響 | 一部フィールドだけを送る旧来の更新では、省略した通常フィールドが残る前提にできません。省略したフィールドは削除されます。 |
| 移行先・対応 | 更新前に最新レコードと必要な全フィールドを確認し、完全な型付きペイロードを組み立てます。更新後の値を再取得して検証します。 |

更新処理、バッチ、テストデータ、Pageからの書き込みを対象にします。意図が不明なフィールドを空値で上書きしません。

### Workflow待機入力の名称・単位変更（SDK 0.2.0）

| 項目 | 内容 |
|---|---|
| 対象／状態 | SDK／CLI。`RunAndWaitInput.timeout` は `timeoutMs` へ名称変更されました。 |
| 期限 | 0.2.0で変更済み。別の終了期限は記載されていません。 |
| 影響 | 旧`timeout`を参照・指定するコード、独自の型、設定ファイル、テストが影響します。新しい値の単位はミリ秒です。 |
| 移行先・対応 | `timeoutMs` へ置き換え、値をミリ秒として見直します。待機の成否、タイムアウト、再実行時の重複処理を検証します。 |

CLIの `workflows run-and-wait --timeout <seconds>` は、サーバー側の実行時間に適用されるよう修正されています。SDKの入力とCLIフラグの単位を同じものと仮定せず、利用している入口ごとに確認してください。

### Node.js実行要件（SDK 0.2.0）

| 項目 | 内容 |
|---|---|
| 対象／状態 | SDK／CLI。Node SDKとCLIはNode.js 22以上を要求します。 |
| 期限 | 0.2.0で要件として記載。旧Node.jsの猶予・終了日は記載されていません。 |
| 影響 | 開発端末、CI、コンテナ、Node.jsで動かすPageサーバー側の環境が22未満の場合、対象外です。 |
| 移行先・対応 | Node.js 22以上へそろえ、SDK、CLI、ロックファイルと代表操作を検証します。SDKだけを下げて回避する前に、利用する版の対応範囲を確認します。 |

### 非公開ルーム取得のアクセス制限（SDK 0.4.0）

| 項目 | 内容 |
|---|---|
| 対象／状態 | SDK・公開API。対応する接続先では、`agents.getMessages()` とCanvas読み取りが、所有者以外には非公開ルームを返さなくなりました。Project APIキーはその作成者として扱われます。 |
| 期限 | 0.4.0で挙動変更済み。別の終了期限は記載されていません。 |
| 影響 | 所有者以外の利用者・自動化が非公開ルームを読み取ろうとすると404になります。権限不足を共有範囲の拡大で回避してはいけません。 |
| 移行先・対応 | 読み取りが必要な主体、ルームの共有範囲、キーの作成者、処理の目的を確認します。想定外の404は、対象IDや実行主体を記録して権限設計を見直します。 |

### Canvas公開の引数追加（SDK 0.7.0）

| 項目 | 内容 |
|---|---|
| 対象／状態 | SDK、Page runtime。`agents.publishCanvasArtifact()`は、room IDとCanvas IDに加え、公開範囲を指定する第3引数を必要とする形へ変更されました。 |
| 期限 | 0.7.0で変更済み。別の終了期限は記載されていません。 |
| 影響 | 0.6.0の2引数呼出しは使えません。公開処理、ラッパー、モック、同梱skillを確認します。 |
| 移行先・対応 | `"PUBLIC"`または`"ORGANIZATION"`を第3引数に指定します。対応する接続先で公開・解除を確認します。 |

未対応の接続先では新しい公開経路が404になる場合があります。公開範囲を推測して処理を継続しません。手順は[SDK／APIのバージョン移行](../development/sdk-api-version-migration.md)を参照してください。

### 同梱skillの削除済みオプション（SDK 0.6.0）

| 項目 | 内容 |
|---|---|
| 対象／状態 | SDK／CLIに同梱されるskillのPageデプロイ準備。`--no-inject-base`と`--allow-root-assets`は削除されました。 |
| 期限 | 0.6.0で変更済み。別の終了期限は記載されていません。 |
| 影響 | 指定するスクリプトや自動化は実行できません。 |
| 移行先・対応 | 削除済みのオプションを外し、Pageを確認します。 |

### 回答比較の型・エラー文言の変更（SDK 0.10.0〜0.11.0）

| 項目 | 内容 |
|---|---|
| 対象／状態 | SDK、Page runtime。回答比較（`compare()`）の型と、拒否時のメッセージが変わりました。 |
| 期限 | 0.10.0、0.11.0で変更済み。別の終了期限は記載されていません。 |
| 影響 | `getTurns()`のターンには`attachments`、候補には`references`、`tools`、`effort`が加わりました。これらの型を手で組み立てているコードやテスト・モックは、新しい項目が必要です。同じモデルを重ねた比較を拒否するメッセージは「models must be distinct」から「models must differ in model or effort」へ変わりました。文言で判定している処理は影響を受けます。 |
| 移行先・対応 | 手書きの`Turn`・`TurnCandidate`に新しい項目を追加し、エラーは文言ではなくエラーコードで扱います。同じモデルを並べる場合は、`CompareChoice`でeffortを変えて指定します。 |

比較機能はPRSブラウザ用です。対応するPRS／agent-service経路がない接続先では、`listCompareModels()`は経路不足で失敗し、添付は空、effortは無視されます。Project APIキーを使う直接SDK呼出しで代替できるとは扱いません。

### キーのスコープが必要な新しいAPI（SDK 0.8.0〜0.10.0）

| 項目 | 内容 |
|---|---|
| 対象／状態 | SDK／CLI、公開API。スケジュールタスク、Agent定義の作成・更新、Objectのレコードアクセスルール、Objectの一括削除が追加されました。 |
| 期限 | 追加機能のため終了期限はありません。 |
| 影響 | スケジュールタスクは`task:read`、`task:write`（加えて`workflow:execute`）、`task:delete`、Agent定義は`agent:write`、レコードルールは一覧に`object:read`と`object:policy`、作成・削除に`object:write`と`object:policy`を要します。`bulkDelete`は`object:delete`を要しますが、SDKの存在だけで直接公開APIでも使えるとはいえません。スケジュールタスク、Agent定義、レコードルールのスコープはAppのリリースマニフェストに宣言できません。キーの作成者にも対応する権限が必要です。 |
| 移行先・対応 | 利用する経路と操作に必要なスコープだけを確認します。現行productionではレコードルールの公開APIはあります。一方、`bulkDelete`の公開API用`DELETE /api/v1/objects/:objectId/records/bulk`は確認できないため、直接Project APIキー用として案内せず、PRSブラウザ経路か利用環境の対応を確認します。発行と管理は[Project APIキーを管理する](../operations/manage-project-api-keys.md)を参照してください。 |

### 新機能の接続先・Page runtime依存（SDK 0.3.0〜0.11.0）

0.3.0のPageセッションログアウト、0.4.0のCanvas読み取り・Workflow作成編集、0.5.0以降のPage内ブラウザでの回答候補比較、0.6.0のStorageファイル添付・Canvas書込み、0.7.0の利用量確認・App設定、0.8.0のデータセット検索、0.10.0の回答比較の拡張、0.11.0の候補ごとのeffort指定は、SDKを導入しただけでは利用できるとは限りません。データセットは`project`スコープをProject APIキーで、`organization`スコープをPRSブラウザのサインイン利用者で使うという認証差があります。比較はPRSブラウザ経路・組織設定・利用者権限に依存します。対応する公開APIまたはPage runtimeがない場合、404、拒否、または機能未提供となる場合があります。

これは機能の「廃止期限」ではなく、新しいSDKだけを先行導入する際の互換性上の注意です。対応する接続先・実行環境で、利用するメソッド、対象Page、失敗時の表示を検証します。詳細は[SDK／APIのバージョン移行](../development/sdk-api-version-migration.md)を参照してください。

## Studio UIの非推奨・移行（追記待ち）

Studio画面の非推奨化、終了日、移行先について、本記事に掲載できる確認済みのエントリーはありません。ドキュメント担当者は、一次情報を確認できた場合だけ、前掲の形式で期限・影響・移行先・問い合わせ先を追記します。画面に表示されない操作を推測したり、根拠のない終了日を案内したりしません。

## Appリビジョンの実行サポート終了を案内する場合

Appの旧リビジョンの実行サポート終了は、SDKの版更新とは別の運用です。終了後も旧ルームの履歴は閲覧できますが、その旧リビジョンで新しいメッセージ実行はできません。後継の現在版で新しいルームを開始する場合も、旧ルームの会話内容が自動で引き継がれるとは扱いません。

利用者へのお知らせには、対象App・対象業務・終了する旧リビジョン、実行できなくなること、後継版または新しいルームという移行先、必要な再設定、問い合わせ先を明記します。終了操作、影響確認、未完了処理の扱いは[リビジョンの実行サポートを終了する](../distribution/end-revision-runtime-support.md)を参照してください。終了予定の予約や自動通知の仕組みは確認できないため、画面上の操作だけで告知期間を管理しません。

## よくある誤解

- **期限未記載は、ずっと安全に使えるという意味である**：期限が書かれていないだけです。更新時は対象版までのCHANGELOGを確認し、検証します。
- **SDKを更新したので接続先も対応している**：SDK、公開API、Page runtimeは別に確認します。未対応の経路は利用できない場合があります。
- **404なら対象リソースが削除された**：0.4.0以降の非公開ルーム取得では、所有者以外へのアクセス制限でも404になります。対象と実行主体を確認します。

## 確認できない場合

対象の組織・Project・Pageまたはアプリ、SDK／CLI／Node.jsの版、接続先、変更前後の結果、発生日時、実行したコマンドまたはメソッド、表示メッセージ・HTTP状態、確認済み事項をまとめます。APIキー、Cookie、認証ヘッダー、Secret値、トークン、顧客の機密データを含めません。SDK・APIの段階的な更新は[SDK／APIのバージョン移行](../development/sdk-api-version-migration.md)、Appリビジョンの終了運用は[リビジョンの実行サポートを終了する](../distribution/end-revision-runtime-support.md)を確認してください。
