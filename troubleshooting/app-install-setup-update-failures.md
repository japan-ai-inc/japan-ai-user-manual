# App導入・初期設定・更新に失敗する

このページは、Appを導入できない、導入後に「セットアップ」が終わらない、または更新後に期待どおり使えないときの切り分け手順です。対象はApp管理者です。まず、Marketplaceからの導入、作成者による組織内self-install、導入後の設定、更新の反映を別の段階として扱ってください。導入の受付、App専用Projectの作成、接続・Secretの設定、利用者の動作確認は同じ完了条件ではありません。

## 要点：誰が何をできるか

| 項目 | 決まり |
|---|---|
| インストール・アンインストール、「組織のアプリ」タブ | 組織の管理者、またはAppのインストール権限（`jai.studioapp.install`）を持つ人が操作できます。 |
| インストールした人 | 自動でApp管理者になります（有料Appでは1シートを使います）。 |
| 共有接続・Secret・メンバーの設定 | App管理者だけが設定できます。 |
| 一般メンバーの利用開始 | App管理者にメンバーとして追加してもらう、または「組織の全メンバーに公開」（無料App）が有効なAppを初めて開くと、メンバーとして参加します。 |
| プリインストール待ちのApp | 最初に「開く」を押したときにインストールされます。「削除」もできます。 |
| 更新 | Marketplace経由とプリインストールのAppは、新しい正式版の公開後に自動で更新されます。更新の選択やロールバックはできません。現在の版はAppヘッダーの「v… ・ インストール状態」で確認します。 |
| 接続の使われ方 | Agentは「実行者の個人接続 → Projectの共有接続 → 組織共通の接続」の順に使います。Workflowは共有接続だけを使います。Appで個人用として宣言された接続は、実行する人がいない場合に共有接続へフォールバックしません。 |

## 始める前に

導入対象の組織、App名、導入方式、操作した管理者、画面に表示された状態、発生日時を記録します。開発元Projectと導入済みAppのProjectは別物です。開発元で動作したこと、または「インストール中」と表示されたことだけで、導入先で利用可能とは判断しません。

> 接続ID、Project APIキー、Secret、トークン、Cookie、外部サービスの認証情報を、設定欄、画面キャプチャ、問い合わせに含めないでください。値を再入力して解決を試す前に、どの設定が必要なのかをApp固有の案内で確認します。

## まず確認すること

- [ ] 正しい組織と対象Appを開いており、Marketplace導入か組織内self-installかを確認した
- [ ] 導入の状態と、App専用の導入先Projectが作られたかを確認した
- [ ] 「インストール中」や結果不明のとき、同じ導入操作を連続で実行していない
- [ ] Appの案内にある接続、Project Secret、メンバー、App固有の準備を分けて確認した
- [ ] 更新では、提供元の変更内容、導入先に反映された版、利用者の実際の動作を分けた
- [ ] 再試行または再インストールが、既存の設定・データ・利用者へ与える影響を確認した

## 症状別の切り分け

| 症状・表示されるメッセージ | 主な原因 | 確認・対処 | 詳しい記事 |
|---|---|---|---|
| 「インストール」を選べない、または導入できない旨が表示される | 組織が違う、インストール権限（組織の管理者または`jai.studioapp.install`）がない、提供・購入条件を満たさない、問い合わせ型のAppである | 組織、App名、表示される導入方法、自分のインストール権限を確認します。表示させるために別アカウントや権限変更で回避しません。 | [MarketplaceからAppをインストールする](../use/install-marketplace-app.md) |
| 「インストール中」のまま、通信エラーで結果が分からない | 導入処理中、画面離脱または通信失敗。導入済みか未導入かを画面だけで断定できない | 同じAppの最新の導入状態を開き直し、導入先Projectと状態を確認します。結果が不明な間は操作を重ねません。画面に「再試行」が案内される場合だけ、対象と内容を確認して実行します。Marketplaceの有料Appでは、画面に表示される請求額と次回更新日を確認し、購入への同意を求められた場合は内容を確認してから進めます。有料Appの月額は単価×有効メンバー数です。 | [MarketplaceからAppをインストールする](../use/install-marketplace-app.md) ／ [作成者が組織内self-installする](../distribution/self-install-in-organization.md) |
| 組織内導入で「App公開」「組織内のアプリ」または「この組織にインストール」が表示されない | 正しい開発元Project・組織ではない、操作権限または利用条件が不足している | 開発元Project、組織、対象版、リソース確認の完了状況を確認します。導入先Projectを開発元として扱ったり、権限を自己判断で広げたりしません。 | [作成者が組織内self-installする](../distribution/self-install-in-organization.md) ／ [Appの組織内導入](../labs/deploy-app-in-organization.md) |
| リソース確認が失敗する、または導入後に必要な機能がない | 未解決の参照、選択漏れ、固定ID・配布元固有URL、接続・Secretの扱いが導入先と合わない | 依存リソース、配布先固有ではない設定、導入後に設定する認証情報を作成者と確認します。固定IDに見える値で止まり、導入先で問題がないと確認できた場合は「確認済みとして再チェック」で通せます。秘密値を配布物や初期データへ含めて解決しません。 | [作成者が組織内self-installする](../distribution/self-install-in-organization.md) |
| 「セットアップ」を完了できない、状況を確認できない、または設定を変更できない | 共有コネクタ・個人接続・Project Secret・メンバー・App固有準備が未完了、確認処理の失敗、App管理者ではない（共有接続・Secret・メンバーを設定できるのはApp管理者だけ） | Appを開き、どの設定が未確認かを特定します。導入または更新で追加・変更されたコネクタ要件も確認します。再読み込み後も確認できなければ、要件なしとは判断せず設定担当者へ依頼します。 | [Appの初期設定を完了する](../use/complete-app-setup.md) |
| セットアップが完了しても処理に失敗する／管理者だけ使える | 利用者がAppのメンバーでない、利用者本人の接続がない、外部サービス側の対象データ権限、App固有条件が不足している。Workflowや自動実行は共有接続だけを使い、個人用として宣言された接続は共有接続へフォールバックしない | 管理者と影響利用者で、許可されたテスト操作を比べます。App共通接続と個人接続、App内のメンバーと外部サービス側の権限を分けて確認します。自動実行で使う接続は、共有接続として設定します。 | [Appの初期設定を完了する](../use/complete-app-setup.md) |
| Appを開くと「全員には公開されていません」「プランでは利用できません」「メンバー数が上限」「アンインストールされています」などを含むメッセージが表示される | それぞれ、Appが組織の全メンバーに公開されておらず利用者がメンバーでない、組織のプランでは使えない、Appのメンバー数が上限に達している、Appがアンインストールされている | App管理者は、メンバー追加または「組織の全メンバーに公開」（無料App）、プラン、メンバー数、インストール状態を確認します。「初回のみ30秒ほど」と表示された場合は、初回の準備が終わるまで待ちます。 | [導入済みAppを開いて利用を始める](../use/open-installed-app.md) |
| 更新案内はあるが導入先に反映されない、または導入先の版が異なる | 新しい正式版がまだ公開されていない、提供元の版と導入先の版、導入方式を取り違えている | Marketplace経由とプリインストールのAppは、新しい正式版の公開後に自動で更新され、更新の選択やロールバックはできません。現在の版はAppヘッダーの「v… ・ インストール状態」で確認します（Marketplaceの詳細画面は「常に最新版（自動更新）」と表示されます）。原因が分からないまま再インストールせず、Appの提供元へ反映状況を確認します。 | [App更新の変更点と再設定を確認する](../use/check-app-updates.md) |
| 更新後に設定の不足が示される、接続停止、または一部利用者だけ失敗する | 更新で接続・Secret・入力形式・アクセス権・業務手順が変わった | 変更案内から、共通接続、個人接続、Project Secret、メンバー、データ・通知を確認対象として抽出します。管理者の成功だけで完了にせず、代表利用者で動作確認します。 | [App更新の変更点と再設定を確認する](../use/check-app-updates.md) |

## 段階別に確認する

1. **導入前・導入中**：組織、App、導入方式、導入権限、料金・提供条件を確認します。導入結果が不明なら、まず最新状態を再取得します。
2. **導入直後**：導入先のApp専用ProjectとAppを確認します。開発元Project、同名の別App、過去の導入と取り違えないようにします。
3. **初期設定**：Appの案内を基に、共通コネクタ、利用者本人の接続、Project Secret、メンバー・アクセス権、App固有準備を担当ごとに確認します。
4. **利用確認**：外部更新を避けられる代表操作で、管理者だけでなく想定利用者が開く・実行する・結果を確認する流れを試します。
5. **更新後**：変更内容、導入先の状態、再設定、実際の業務操作を順に確認します。Marketplace経由とプリインストールのAppは自動で更新されるため、更新後も接続や出力が期待どおりかを確認します。

> 「インストール済み」と表示され、「開く」ことができても、すべての接続・Secret・メンバー設定が済んだ意味ではありません。反対に、設定画面が見つからないことも設定不要の証拠ではありません。対象Appの案内と現在の状態を照合してください。

## よくある誤解

### 再インストールすれば設定の問題も直る

導入済みAppへのアクセス、初期設定、更新の反映は別問題です。再インストールを先に行うと、原因追跡や既存データ・利用者への影響確認が難しくなります。状態と表示メッセージを記録してから必要な手順へ進みます。

### 管理者が動かせたので利用開始できる

個人接続、Appへの参加、外部サービス側の権限は利用者ごとに異なります。一般メンバーは、App管理者による追加または「組織の全メンバーに公開」で参加します。App共通設定と利用者固有設定を分け、代表利用者で確認します。

## 管理者・サポートに相談する前に

秘密情報を除き、組織、App名、導入方式、導入先Projectの識別情報、発生日時とタイムゾーン、操作した画面・操作、表示された状態またはエラー、導入・設定・更新のどの段階か、影響利用者、確認済みの接続・Secret・メンバー状態、更新案内、再試行の有無を集めます。問い合わせのテンプレートと送ってはいけない情報は[問い合わせに必要な情報を集める](collect-info-for-support.md)を参照してください。
