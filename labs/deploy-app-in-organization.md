# Appの組織内導入

この実習では、[タスク管理アプリ](task-management-app.md)の実習用Object、Page、Agentを、同じ組織内の別ProjectへAppとして導入します。開発元Projectを直接共有せず、導入後に利用者として表示・回答を確認し、最後にアンインストールします。Marketplaceへの掲載や審査は行いません。

## 始める前に

- [タスク管理アプリ](task-management-app.md)の開発元Projectを開け、Appの作成・導入を行える担当者と、確認用の実習メンバーを決めます。機能が表示されない場合は、権限・提供条件を[制限・提供条件の索引](../operations/limits-and-availability-index.md)で確認します。
- Pageが配布元固有のURL、ID、Secret値、接続IDを固定していないことを確認します。設計上の確認は[配布可能なPageの設定設計](../development/design-distributable-page-config.md)を参照してください。
- 実在の業務データ、接続、Secret、スケジュール、トリガー、APIキー、公開リンクは使いません。導入先で確認するのは[タスク管理アプリ](task-management-app.md)の架空タスクだけです。
- 開発元とインストール先は別Projectです。開発元で動くことだけでは、導入先のアクセスや設定を確認したことになりません。

## この実習で使うサンプル

| 項目 | 値 |
|---|---|
| App名 | タスク管理実習App |
| 含めるもの | [タスク管理アプリ](task-management-app.md)の実習用Object、Page、Agent |
| 確認用Page | タスク管理（実習用） |
| 確認用Agent | タスク案内Agent（実習用） |
| 利用者の質問 | デモ画面のレビューのステータスを教えてください。 |
| 更新時の変更 | Page見出しへ「組織内導入の確認用」を追加 |

## Step 1. Appに含めるリソースを確認する

**目標：** 実習に必要なものだけをAppとして準備します。

1. 開発元Projectで、実習用Object、`タスク管理（実習用）`Page、`タスク案内Agent（実習用）`を開きます。
2. PageとAgentが実習外の接続、Dataset、固定URL、Secretを使っていないことを確認します。
3. Projectの**「App公開」**を開き、公開先で**「組織内」**を選び、App名を`タスク管理実習App`として作成します。
4. 公開対象リソースで実習用のものだけを選び、**「アプリのリソースを確認」**を実行します。
5. 未解決の参照や警告がないことを確認します。あれば導入へ進まず、依存関係と設計を見直します。

リソース選択と確認の詳細は[作成者が組織内self-installする](../distribution/self-install-in-organization.md)を参照してください。**確認ポイント：** App名と選択リソースが実習用だけで、配布元固有の値を含めません。

## Step 2. 別Projectへインストールする

**目標：** 開発元とは分離されたインストール先Projectを作ります。

1. **「組織内のアプリ」**で`タスク管理実習App`を確認します。
2. 準備した版、含まれるリソース、アクセス設定、認証情報の要件を確認します。
3. **「この組織にインストール」**を選び、対象と変更内容を確認して確定します。
4. 処理中は同じ操作を繰り返さず、**「インストール済みバージョン」**と**「インストール済みアプリを開く」**が表示されたことを確認します。
5. **「インストール済みアプリを開く」**から、開発元とは別のインストール先Projectを開きます。

導入の詳細と状態確認は[作成者が組織内self-installする](../distribution/self-install-in-organization.md)を参照してください。**確認ポイント：** 開発元Projectへ戻らず、導入先Projectを開いています。結果が不明でも再実行せず、状態を確認します。

## Step 3. 初期設定と利用者を確認する

**目標：** 導入状態、設定、利用者のアクセスを分けて確認します。

1. **「セットアップを完了」**が表示される場合は、残っている設定を確認します。この実習では接続・Secretを追加しません。
2. 未設定、確認中、読み込み失敗を、設定不要・設定済みと取り違えません。必要な設定が表示された場合は、値を推測して入力せず担当者に確認します。
3. 実習メンバーが対象Appを開けるよう、必要最小限のアクセスを設定します。
4. 管理者だけでなく実習メンバーのアカウントで、Appの入口を開けることを確認します。

初期設定は[Appの初期設定を完了する](../use/complete-app-setup.md)、メンバーの扱いは[Project・Appのメンバーを管理する](../operations/manage-project-and-app-members.md)を参照してください。**確認ポイント：** 「設定済み」の表示だけで、利用者のアクセスまで完了としません。

## Step 4. 利用者としてPageとAgentを確認する

**目標：** 導入先の実習メンバーが、実習データを利用できることを確かめます。

1. 実習メンバーのアカウントで`タスク管理実習App`を開きます。
2. `タスク管理（実習用）`Pageで、架空のタスクを表示できることを確認します。
3. `タスク案内Agent（実習用）`に、サンプルの質問を送ります。
4. 回答をPageまたはObjectのレコードと照合し、推測ではなく実習データに基づく内容か確認します。

App利用と確認の考え方は[Appの初期設定を完了する](../use/complete-app-setup.md)、Page・Agentの作りを戻って確認する場合は[タスク管理アプリ](task-management-app.md)を参照してください。**確認ポイント：** 開発者の権限でなく、実習メンバーが導入先で表示・回答を確認しました。

## Step 5. 小さな変更を更新として適用する

**目標：** 開発元の変更と、導入先へ反映された状態を分けて確認します。

1. 開発元Projectで実習用Pageの見出しに「組織内導入の確認用」を追加します。
2. App公開の画面でリソースを再確認し、新しい版を準備します。
3. 変更内容、アクセス設定、認証情報の要件を確認し、インストール済みAppの更新操作を行います。
4. 導入先でインストール済みの版を確認してから、実習メンバーが変更後の見出しと代表質問を確認します。

更新後の設定と利用確認は[App更新の変更点と再設定を確認する](../use/check-app-updates.md)を参照してください。**確認ポイント：** 開発元で編集しただけで完了にせず、導入先の利用者が変更後の状態を確認します。

## よくある誤解

| 誤解 | 確認すること |
|---|---|
| 組織内導入は開発元Projectへの部品追加 | 別のインストール先Projectを使います。 |
| インストール済みなら全利用者が使える | メンバー、アクセス、個人の設定を確認します。 |
| 開発元を更新すれば導入先にも反映される | 新しい版の準備・適用と、導入先での確認が必要です。 |
| セットアップ完了表示で業務利用も確認済み | 利用者の入口、接続、代表操作を別に確認します。 |

## うまくいかない場合

| 状況 | 最初に確認すること |
|---|---|
| **「App公開」**や**「組織内のアプリ」**がない | 対象組織、開発元Project、権限、提供条件を確認します。[制限・提供条件の索引](../operations/limits-and-availability-index.md)を参照します。 |
| リソース確認で未解決の参照が出る | 固定ID、配布元固有のURL、依存リソース、接続・Secretの扱いを確認します。[配布可能なPageの設定設計](../development/design-distributable-page-config.md)を参照します。 |
| インストール結果が分からない | 同じ操作を連続実行せず、版と状態を[作成者が組織内self-installする](../distribution/self-install-in-organization.md)で確認します。 |
| 利用者が開けない・回答が一致しない | 導入先Project、メンバー、App設定、対象リソースを確認します。開発元の権限を広げて回避しません。 |
| 更新後に表示が変わらない | 開発元の変更、準備した版、導入先の版、利用者の結果を分けて確認します。[App更新の変更点と再設定を確認する](../use/check-app-updates.md)を参照します。 |

## 後片付け

1. 実習メンバーに終了を連絡し、保存・引き継ぎが必要な実習成果物がないことを確認します。
2. インストール先のAppを対象に、**「アプリをアンインストール」**を選び、App名と案内を確認して確定します。開発元Projectは削除しません。
3. 完了後、Appが利用できない状態であることを確認します。結果が不明でも、連続したアンインストールや再インストールは行いません。
4. 開発元のObject、Page、Agentを残すか削除するか決め、他の実習で使われていないことを確認して整理します。

アンインストールの詳細は[Appをアンインストールする](../use/uninstall-app.md)を参照してください。この実習で追加していない接続、Secret、自動実行、APIキーを途中で作成した場合は、影響を確認して停止・削除の担当を決めます。
