# 外部サービス連携アプリ

この実習では、組織で利用を承認された外部サービスへ、架空の日報要約を1件だけ送る検証用Pageを準備します。接続、Secret、Pageの実行環境、送信結果は別々に確認します。実在の顧客名、売上、個人情報、認証情報、業務用の送信先は使いません。

Secret値を画面、ソース、配布物、公開用環境変数、問い合わせに入れてはいけません。Pageで利用できるサーバー処理とSecret参照の条件は環境により異なるため、この実習を始める前に必ず確認します。

## 始める前に

- Projectを編集でき、接続と**「プロジェクトシークレット」**を管理する担当者を決めます。権限や対象サービスが表示されない場合は、代替サービスを勝手に選ばず[制限・提供条件の索引](../operations/limits-and-availability-index.md)を確認します。
- 外部サービス側に、検証専用の送信先と最小限の権限を持つアカウントを用意します。送信の停止・失効を行う担当者も決めます。
- 対象のPage実行環境で、サーバー処理とProject Secret参照を利用できることを[Pageのサーバー処理・環境変数・Secret参照](../development/page-server-env-and-secrets.md)で確認します。ZIPを登録できるだけでは、任意のサーバー処理が利用できるとは限りません。
- 実習で追加するものは検証用接続、検証用Secret、検証用Pageだけです。スケジュール、トリガー、自動再送、公開リンクは追加しません。

## この実習で使うサンプル

| 項目 | 実習で使う値 |
|---|---|
| Page名 | 日報送信（検証用） |
| 接続名 | 日報送信_検証用 |
| Secret名 | `lab005_service_token` |
| 送信先 | 外部サービスの検証用送信先 |
| 送る内容 | 日付、担当、活動、次の対応だけを含む架空の日報要約 |

入力には次を使います。

```text
日付: 2026-10-03
担当: 研修担当
活動: 提案資料の構成を確認
次の対応: 検証手順を記録
```

Secret名と値の制約・作成・更新・削除は[Project Secretを登録・更新・削除する](../operations/manage-project-secrets.md)を正本とします。トークンの実値はこの資料、画面共有、チャット、ソースに記録しません。

## Step 1. 接続の所有者と検証先を決める

**目標：** 誰の認証情報で、どの送信先へ、誰の責任で送るかを固定します。

1. 今回の送信が個人用か、複数の利用者・自動処理で共有するものかを整理します。
2. 実習では検証用アカウントと送信先を使う共有接続として、`日報送信_検証用`を管理する担当者を決めます。
3. 投稿者、接続の所有者、停止・失効の担当者、送信先を記録します。値そのものは記録しません。

接続とSecretの選び方は[個人接続・共有接続・Secretを選ぶ](../operations/choose-personal-shared-connections-and-secrets.md)を参照してください。**確認ポイント：** 個人アカウントをチーム用接続へ転用せず、実習用送信先と停止担当を説明できます。

## Step 2. 共有接続を作成して確認する

**目標：** 外部サービスの認証と、Projectで使う接続を確認します。

1. Projectの設定から**「コネクタ設定」**を開き、**「プロジェクトのコネクタ」**を確認します。
2. **「新しいコネクタ」**から、表示される対象サービスと**「プロジェクト用コネクタ」**を選びます。共有設定が表示される場合は**「共有接続」**であることを確認します。
3. 接続名に`日報送信_検証用`を入力し、外部サービスの認証画面では検証用アカウントを選びます。要求される権限と送信先を確認します。
4. 作成後、一覧で接続名、対象サービス、共有範囲を照合します。ここでは投稿を行いません。

詳細は[Project・Appの共有接続を設定する](../operations/configure-shared-connections.md)を参照してください。**確認ポイント：** 名前だけではなく、認証アカウントと送信先も検証用です。

## Step 3. 検証用のSecretを登録する

**目標：** 外部サービスの秘密値を、Pageの成果物と分離して管理します。

1. Project設定の**「プロジェクトシークレット」**を開きます。
2. **「シークレットを作成」**を選び、名前に`lab005_service_token`、値に安全な方法で取得した検証用の値を入力します。
3. 作成後、一覧で名前と更新状態を確認します。値を確認のためにコピー、表示、共有しません。
4. 同名の既存Secretがある場合は上書きせず、対象と所有者を確認します。

Secretの操作は[Project Secretを登録・更新・削除する](../operations/manage-project-secrets.md)を参照してください。**確認ポイント：** Secretは接続の代替ではありません。接続、Secret、Page側の参照を別々に確認します。

## Step 4. Pageの送信処理を実装・登録する

**目標：** 入力値だけを検証用送信先へ渡す処理を作ります。

1. `日報送信（検証用）`に、サンプルの4項目を入力し、検証投稿を開始する画面を作ります。
2. サーバー処理とSecret参照は、[Pageのサーバー処理・環境変数・Secret参照](../development/page-server-env-and-secrets.md)の対象環境向けの方法だけを使います。
3. 実装では、Secret値・認証ヘッダーをブラウザへ返さず、画面・エラー・ログに出力しないようにします。値を含む応答や画面表示を作りません。
4. 入力の必須項目と送信先をサーバー側で確認し、承認された方式で要約を1件送信する処理に限定します。
5. Pageを登録する前に、成果物、設定ファイル、ソースマップ、画面表示にSecret実値が含まれないことを確認します。

Page登録とアクセス設定は[画面からPageを登録・公開する](../build/register-and-publish-pages.md)を参照してください。**確認ポイント：** ブラウザから外部APIへ直接送信する構成、Secret実値を含む構成、再送を自動化する構成にはしません。Secret非露出の実装条件は環境依存のため、[Pageのサーバー処理・環境変数・Secret参照](../development/page-server-env-and-secrets.md)の範囲外をこの実習だけで保証しません。

## Step 5. 1件を送信し、結果を照合する

**目標：** 送信内容、送信先、値を表示しないことを分けて確認します。

1. 実習を許可された利用者でPageを開き、対象名を確認します。
2. サンプルの入力で検証投稿を一度だけ行います。処理中・結果不明の場合は連続実行しません。
3. 外部サービスの検証用送信先に、4項目だけを含む投稿が1件あることを確認します。
4. Pageの画面、許可された実行記録、ブラウザで確認できる応答に、Secret値や認証ヘッダーを表示する設計がないことを確認します。

Pageの利用時の注意は[Pageから業務を進める](../use/work-with-pages.md)を参照してください。**確認ポイント：** 接続成功だけでなく、送信先・内容・件数を確認します。Secret実値が露出した可能性がある場合は、次の表の対応を優先します。

## よくある誤解

| 誤解 | 確認すること |
|---|---|
| 接続を作ればSecretは不要 | 接続とSecretの必要性はサービス・実装ごとに異なります。 |
| Secretを保存すればPageから自動で使える | Page側の参照設定と実行環境を確認します。 |
| 成功表示なら正しい送信先へ届いた | 外部サービス側で送信先、内容、件数を確認します。 |
| Secretを画面に出さなければ問題ない | ソース、配布物、公開用設定、ログ、応答にも置きません。 |

## うまくいかない場合

| 状況 | 最初に確認すること |
|---|---|
| コネクタ設定や対象サービスが表示されない | Project、権限、組織の提供条件、承認状況を確認します。[Project・Appの共有接続を設定する](../operations/configure-shared-connections.md)を参照します。 |
| Secretを作成・参照できない | 正しいProject、名前、権限、Page実行環境の対応を確認します。[Project Secretを登録・更新・削除する](../operations/manage-project-secrets.md)と[Pageのサーバー処理・環境変数・Secret参照](../development/page-server-env-and-secrets.md)を参照します。 |
| 送信に失敗する | 接続の認証状態、外部側の権限、送信先、入力、Page処理を確認します。値をエラー報告へ添付しません。 |
| 値が画面・成果物・ログに現れた | 送信を止め、URLを共有せず、値を外部サービス側で失効・再発行します。影響範囲を担当者へ連絡し、安全な状態を確認するまで再開しません。 |

## 後片付け

1. Pageを非公開または削除し、共有したURLがあれば利用停止を連絡します。
2. 接続を使うPage、App、Workflowがないことを確認してから、外部サービス側で検証用アカウントまたは認証を失効し、Projectの接続を整理します。詳細は[接続の失効・担当者変更に対応する](../operations/handle-expired-connections-and-owner-changes.md)を参照してください。
3. 依存する処理が停止したことを確認してから、`lab005_service_token`を削除します。Secretを先に消すと依存する機能が実行時に失敗する可能性があります。
4. 実習用送信先の投稿を、組織のルールに従って削除・保管します。
