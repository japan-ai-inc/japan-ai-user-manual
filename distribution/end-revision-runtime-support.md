# リビジョンの実行サポートを終了する

JAI Adminの「リビジョンの実行サポート終了」は、すでに現在版ではないAppランタイムのリビジョンについて、**そのリビジョンに固定されたルームでの新しい実行を恒久的に止める**緊急時の操作です。通常のリリース、Stable昇格、顧客への更新、アンインストールの代わりではありません。

ここでいうリビジョンは、Appをある顧客組織・Projectへ導入または更新した時点の実行計画です。既存ルームはその時点のリビジョンに固定され得ます。後継の現在リビジョンがある場合でも、旧リビジョンのルームが自動更新されるわけではありません。実行サポートを終了すると履歴は残りますが、旧リビジョンで新しいメッセージを実行できなくなります。

通常の互換性判断・顧客更新は[リリースの互換性を管理する](manage-release-compatibility.md)と[JAI Adminで顧客へ配布・更新確認する](admin-distribute-and-check-updates.md)を参照してください。旧リビジョンで必要だったコネクタやSecretが後継版でも必要なら、更新後のApp設定を確認します。利用者向けの期限・影響・移行先の案内は[非推奨機能・移行のお知らせ](../troubleshooting/deprecations-and-migrations.md)で扱います。

## 始める前に

この記事の対象は配布担当者です。ただし、この操作を実行できるのは、画面の注意書きどおり**デフォルトRealmのJAIスーパー管理者**に限られます。「Studioアプリ配布」を開けても、このタブが表示されること、影響確認や終了操作を実行できることは別です。タブが表示されない、または操作が拒否される場合は、URLや権限を推測して回避せず、権限を持つ担当者へ確認してください。

次を確認してから開始します。

- 対象App、顧客組織、導入先Project、対象リビジョンID、後継となる現在リビジョンを特定していること。
- 通常の更新で解決できない理由を確認していること。後継版への顧客更新は[JAI Adminで顧客へ配布・更新確認する](admin-distribute-and-check-updates.md)に従い、旧リビジョンを終える前に完了させます。
- 影響を受ける利用者、ルーム、実行中・一時停止中の処理、顧客窓口、案内文、移行先を整理していること。
- 終了後に旧ルームへ戻せないこと、履歴は残してよいこと、現在版で新しいルームを始める方法を関係者と確認していること。

> この操作は取り消せません。リビジョンの再有効化、終了日時の予約、猶予期間の設定、終了理由の後編集は、この画面では確認できません。顧客更新や通知を後回しにして、旧リビジョンだけを先に終了しないでください。

## 影響範囲を正しく読む

「影響をプレビュー」は、入力したリビジョンが属する**組織**と**プロジェクト**を表示します。AppインストールはProjectごとにランタイムを持つため、これは「どの顧客のどのインストール先か」を確認するための重要な手掛かりです。一方、このタブは顧客組織全体のインストール一覧や、同じ版を使う全顧客の一覧を出す画面ではありません。顧客ごとの現在版・更新状況は[JAI Adminで顧客へ配布・更新確認する](admin-distribute-and-check-updates.md)の「インストール管理」で別に確認します。

プレビューには次が表示されます。

| 表示 | 確認すること |
|---|---|
| 「組織」「プロジェクト」 | 対象の顧客組織と導入先Projectであること。IDだけで判断せず、配布記録と照合します。 |
| 「現在のリビジョン」 | 旧リビジョンの代わりに使える現在リビジョンです。「なし」の場合、利用者を現在版へ移す前提にせず、終了を保留します。 |
| 「プランスキーマ」 | 影響確認用の情報です。値だけから互換性や移行可否を判断しません。 |
| 「影響を受けるルーム」 | 旧リビジョンに固定されている、削除されていないルーム数です。対象の利用者・業務・顧客窓口を個別に確認します。 |
| 「ルームのサンプル（最大20件）」 | 影響調査の入口です。全件一覧ではないため、表示件数が少なくても影響がないと断定しません。 |
| 「未完了ワークフロー」「タスク」 | 完了していない実行の数です。実行中だけでなく、一時停止中なども含めて停止・完了・引継ぎを既存の操作で行います。 |

> 「影響を受けるルーム」が0件でも、顧客の現在版、後継版の利用可否、別のインストールへの影響まで確認済みとは限りません。対象Appの顧客展開・インストール状況を[JAI Adminで顧客へ配布・更新確認する](admin-distribute-and-check-updates.md)で照合してから判断してください。

## 1. 終了前の移行・通知を準備する

1. [リリースの互換性を管理する](manage-release-compatibility.md)に従い、後継リリースとの互換性、必要な接続・Secret・権限・データ・手順変更を確認します。
2. [JAI Adminで顧客へ配布・更新確認する](admin-distribute-and-check-updates.md)に従い、対象顧客組織のインストールを後継の安定版へ更新し、対象組織・リリース・デプロイ状態を確認します。旧リビジョンを終了しても、顧客インストールを更新する処理は実行されません。
3. 影響する利用者へ、対象App・対象業務・旧ルームで実行できなくなること・移行先・必要な再設定・問い合わせ先を案内します。期限、変更内容、移行先を利用者へ伝える文面と継続的な非推奨案内は[非推奨機能・移行のお知らせ](../troubleshooting/deprecations-and-migrations.md)で管理します。
4. 旧ルームの会話内容を新しいルームへ自動移行できるとは扱いません。現在版で新しいルームを開始する場合、確認画面には会話内容を引き継がない旨が表示されます。必要な情報を利用者・顧客担当者が確認できる形で引き継ぎます。
5. 実行中または一時停止中のWorkflow・タスクがないことを確認します。未完了の件数が残る場合、終了ボタンは有効になりません。

本実装で確認できるのは即時・恒久的な終了だけです。終了予定日を登録して自動終了する仕組み、終了前の自動通知、画面上の警告だけで実行を継続できる猶予期間は確認できません。したがって、必要な告知期間はこのタブで予約するのではなく、顧客との合意と[非推奨機能・移行のお知らせ](../troubleshooting/deprecations-and-migrations.md)の案内で管理し、移行・未完了実行の解消後に終了してください。

## 2. 「影響をプレビュー」で終了可否を確認する

1. JAI Adminで「Studioアプリ配布」を開き、表示されている場合は「リビジョンの実行サポート終了」を選びます。
2. 「リビジョンID」に、終了候補のIDを入力します。現在リビジョンや別の顧客組織のIDを入力しないでください。
3. 「影響をプレビュー」を選び、組織、プロジェクト、現在のリビジョン、ルーム数、サンプル、未完了ワークフロー・タスクを確認します。
4. 未完了または一時停止中の実行が表示された場合は、既存の運用操作で終了または引継ぎます。このタブで実行をキャンセル・更新・移行することはできません。
5. 組織・Project・現在リビジョン・ルーム数が想定と異なる場合は、終了を確定せず、対象IDと配布状況を再調査します。

プレビューは一度確認すれば使い続けられるものではありません。「プレビューの有効期限」に達した場合、またはルーム数・現在リビジョンなどの影響範囲が変わった場合は、再度「影響をプレビュー」を実行します。終了時にもサーバー側で影響範囲を再確認するため、古いプレビューでは確定できません。

## 3. 実行サポートを終了する

1. 未完了ワークフロー・タスクが0件であり、後継版への配布、利用者への案内、ルームの引継ぎ方針を確認します。
2. 「実行サポートを終了する理由」に、終了判断、対象、移行・通知の確認先が分かる理由を入力します。理由は空欄にできず、2,000文字以内です。Secret値、APIキー、パスワード、トークン、顧客の機密データは書きません。
3. 「この操作は取り消せないことを理解し、影響を受けるルームを確認しました。」へチェックを入れます。
4. 対象リビジョン、顧客組織・Project、後継の現在リビジョン、影響ルーム、理由を最後に確認し、「このリビジョンの実行サポートを永久に終了」を選びます。
5. 完了メッセージと対象リビジョンを記録します。終了日時、実行者、理由、確認時の影響範囲は保持されます。

終了は、選択した非アクティブなリビジョンだけが対象です。現在リビジョンは終了できません。また、ルームの更新、後継版への切替、履歴の削除、顧客インストールの無効化・アンインストールは行いません。

## 終了後の利用者への影響

終了後も旧ルームの履歴は保持されます。しかし、旧リビジョンでの新しいメッセージ実行はブロックされます。旧ルームを複製して同じ旧リビジョンで続ける操作も拒否されます。単に警告を表示して旧版の実行を許可する動作ではありません。

旧ルームを開いた利用者には、アプリバージョンが廃止されたこと、履歴は閲覧できるが新しいメッセージを実行できないことが警告として表示されます。現在リビジョンが利用可能でランタイムが有効なら、「現在のバージョンで新しいルームを開始」を選べます。これは新しいルームを作る操作であり、旧ルームの会話内容は引き継がれません。現在版が使えない場合は、この選択肢も出ないため、顧客更新・ランタイム状態を先に確認します。

## うまくいかない場合

| 状況 | 確認・対応 |
|---|---|
| タブが表示されない、または「影響をプレビュー」ができない | 機能の利用条件と、デフォルトRealmのJAIスーパー管理者であることを確認します。権限や設定を自己判断で変更しません。 |
| 現在リビジョンである、または既に終了済みである | 現在リビジョンは終了できません。対象ID、配布・更新状況を確認し、別の旧リビジョンを取り違えていないか調べます。 |
| 未完了ワークフロー・タスクがある | 既存の操作で実行を終了・引継ぎし、改めて影響をプレビューします。強制終了やこの画面での削除は行いません。 |
| プレビューが期限切れ、または終了時に拒否された | ルーム、現在リビジョン、未完了実行が変化した可能性があります。新しいプレビューで影響を再確認します。 |
| 終了後に顧客が旧ルームを続けられない | 想定どおり新規実行はブロックされます。現在版への顧客更新、利用者の再設定、現在版での新しいルーム開始を確認します。 |

問い合わせ・引継ぎには、App名、顧客組織、Project、対象リビジョン、後継リビジョン、影響ルーム数、未完了実行数、終了理由、通知・移行の状況、実施日時を記録します。認証情報や顧客の機密データは含めません。
