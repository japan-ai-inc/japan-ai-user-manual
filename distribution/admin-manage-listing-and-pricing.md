# JAI Adminで掲載・価格を管理する

JAI Adminの「Marketplace掲載情報」と「アプリID」では、配布担当者が、顧客に見せる掲載条件、導入の入口、Appの課金方式を管理します。ここでの保存は、Studioで公開申請者が作成する申請や、顧客が実施するメンバー追加とは別の操作です。掲載の文章・素材は次のリリース用の共有下書きとして扱われ、リリース作成時に固定されます。一方、掲載可否と「表示順」は別に保存されます。

利用人数・料金・契約上限の顧客への影響と確認手順は、[Appの利用人数・料金・契約上限を確認する](../operations/check-app-seats-pricing-and-limits.md)を正本とします。公開申請者が行う掲載情報の作成と審査提出は、[Marketplaceへ公開申請する](submit-to-marketplace.md)を参照してください。

## 始める前に

この記事の対象者は**配布担当**です。JAI Adminの「Studioアプリ配布」で対象Appを選び、「Marketplace掲載情報」または「アプリID」を開けることを確認します。画面を閲覧できても、保存・掲載停止・料金変更を実行できるとは限りません。必要なJAI Admin権限を持つ担当者だけが変更できます。必要な権限を自分で増やしたり、顧客にJAI Adminの操作を依頼したりしないでください。

操作前に、対象App、現在の安定版、顧客への導入方法、課金方式、影響する顧客組織を記録します。下書きの未保存変更がある状態でAppやタブを切り替えると、破棄を確認する画面が表示されます。

> 「掲載情報を保存」は、掲載を即時に公開する操作ではありません。掲載文・画像・動画は、次のリリースを作成した時点でそのリリースに固定され、当該リリースの公開時にMarketplaceへ反映されます。現在公開中の内容を急いで書き換える手段として扱わないでください。

## 1. 掲載情報の下書きと導入条件を管理する

1. 「Marketplace掲載情報」を開き、「アプリID」で対象を選びます。
2. 顧客向けプレビューで、現在の安定版に含まれるリソース、必要な認証情報、説明、タグ、変更内容を確認します。プレビューは掲載内容の確認用であり、顧客環境での導入・動作完了を示すものではありません。
3. 掲載文・タグ・画像・動画を確認または編集します。説明には、対象者、用途、必要な権限・外部接続、利用前の注意を記載し、パスワード、APIキー、トークン、個人情報、顧客データを入れません。
4. 必要に応じて「表示順」、「インストール方法」、「公式表示」、「検証済み表示」を設定します。「インストール方法」で**「セルフサービス」**を選ぶと、権限を持つ顧客ユーザーが導入できます。**「JAPAN AIに問い合わせる」**を選ぶと、掲載は維持しつつ顧客からの直接インストールを無効にします。
5. 内容と顧客向けプレビューを確認して「掲載情報を保存」を選び、「Marketplace掲載情報を保存しました」を確認します。

アイコンは、正規リリースの成果物からMarketplace用の場所へシステムがコピーするため、この画面で掲載用アイコンだけを別管理するものではありません。掲載情報の保存と、リリースの作成・承認・公開は別工程です。次のリリースに反映する掲載内容と、現在の安定版、顧客影響を混同しないでください。

## 2. Marketplaceへの表示を制御する

掲載状態には、通常の自動掲載と、配布担当による掲載停止があります。「自動掲載：Marketplaceに表示されています。」なら、掲載条件を満たすAppとして表示されています。「自動掲載：掲載情報の入力と、有効なアプリの承認済みSTABLEリリース（更新内容あり）を待っています。」と表示される場合は、不足している条件を満たすまで掲載されません。

掲載を止める場合は、次の順で操作します。

1. 対象App、現在の掲載状態、既存顧客への影響、新規導入を止める必要性を確認します。
2. 「Marketplaceへの掲載を停止」を選び、結果を確認します。
3. **Marketplaceには表示されず、新規インストールはできません。既存の利用者は引き続きAppを利用できます。** 既存顧客のAppを削除・停止する操作ではないため、必要な対応は別途検討します。
4. 再開可能な状態になった場合だけ「自動掲載を再開」を選び、掲載条件と表示状態を再確認します。

> 掲載停止は緊急の修正配布、顧客インストールの削除、料金停止を自動で実行しません。顧客環境の変更や更新確認は[JAI Adminで顧客へ配布・更新確認する](admin-distribute-and-check-updates.md)、アンインストール時の影響は[Appをアンインストールする](../use/uninstall-app.md)を参照してください。

## 3. 課金方式とシート料金を設定する

「アプリID」の一覧で対象Appの「課金設定」を開きます。選べる「課金方式」は**「無料」**と**「月額シート課金」**です。月額シート課金では「クレジット / シート / 月」の単価を入力します。料金は顧客組織や他のAppから推測せず、対象Appの設定として確認します。

1. 対象App、対象顧客組織、利用人数、既存の導入数、契約・承認状況を確認します。
2. 「課金設定」で「無料」または「月額シート課金」を選びます。
3. 月額シート課金を選ぶ場合は、正の金額を「クレジット / シート / 月」として入力し、対象と単価を再確認して保存します。
4. 初回インストール後は「課金方式」を変更できません。変更が必要と判明した場合は、画面上の値を強引に変更せず、配布・契約の責任者へエスカレーションします。
5. 顧客への導入・人数変更に進む場合は、[Appの利用人数・料金・契約上限を確認する](../operations/check-app-seats-pricing-and-limits.md)に従って、現在の利用者、契約上限、購入済み・使用中・空きシート、今回の料金、次回更新を分けて確認します。

月額シート課金のAppでは、利用者数と料金確認は顧客側のAppメンバーシップに連動します。Marketplaceで導入・シート変更を確認する画面では、シート数、今回のクレジット請求額（必要に応じて日割り）、次回更新日、月額料金、導入者自身が使用するシートが表示されます。導入または購入の確定前に、これらと明示的な同意を確認します。「アプリ利用ユーザー数上限」で契約上限を手入力して管理する対象ではありません。無料のAppでは、「アプリ利用ユーザー数上限」から顧客組織ごとの上限を保存または解除できます。解除後は組織全体のProjectメンバー上限が適用されます。上限の保存・解除は監査ログに記録されます。

## 4. 無料AppのPre-installを設定する

「Pre-install」は、顧客がMarketplaceで導入する前に、対象組織のプラン利用者へ無料Appをあらかじめ導入する管理操作です。対象にできるのは、**有効な無料App**で、**Stableリリースが存在する**場合です。月額シート課金のApp、候補版・ベータ版だけのApp、無効なAppをPre-install対象として扱いません。

1. 「Pre-install」を開き、対象App、現在のStableリリース、対象組織・プランを確認します。
2. 導入対象のティアを選びます。`NONE` はPre-installを行わない、`ADMINS` は対象プランの管理者、`ALL_MEMBERS` は対象プランの全メンバーを対象とする設定です。保存前のプレビューで、対象となるプラン・利用者範囲を確認します。
3. 導入方式を選びます。`EAGER` は対象者へ先行して導入を開始し、`ON_OPEN` は対象者がAppを開く契機で導入します。いずれも、導入後の接続・Secret・利用者権限の設定を自動完了するものではありません。
4. App、Stableリリース、ティア、方式、プレビューした対象を再確認して保存します。結果はおよそ20秒間隔で更新される進捗で確認し、開始直後に完了と判断しません。
5. 失敗またはスキップされた導入は件数だけで済ませず、理由と対象を確認します。再試行できる失敗は、原因を解消してから対象を確認して再試行します。再試行回数を使い切った失敗だけを、画面の案内に従って再試行します。

> Pre-installはMarketplace掲載、顧客の課金同意、既存導入の更新、セットアップ完了の代わりではありません。`ON_OPEN`の対象者がまだAppを開いていない場合や、コネクタ・Project Secretの準備が必要な場合は、利用可能な状態になっているかを別に確認してください。

## よくある誤解

| 誤解 | 正しい確認 |
|---|---|
| 下書きを保存すれば、すぐMarketplaceの説明が変わる | 次のリリースの作成時に内容が固定され、そのリリースの公開時に反映されます。現在公開中の掲載内容と下書きを分けて確認します。 |
| 掲載停止すると既存顧客も利用できなくなる | 新規インストールとMarketplace表示を止める操作です。既存利用者は継続利用できます。停止・削除が必要なら別の運用を確認します。 |
| メンバーを外せば料金・購入数も下がる | [Appの利用人数・料金・契約上限を確認する](../operations/check-app-seats-pricing-and-limits.md)のとおり、メンバー削除と購入シート数の変更は別の操作です。削除だけで更新料金は下がりません。 |
| 初回導入後でも無料と月額シート課金を切り替えられる | 初回インストール後は課金方式を変更できません。導入前に契約・価格・導入条件を確認します。 |
| 表示順や「JAPAN AIに問い合わせる」は掲載文の下書きと同時に公開される | 掲載可否・表示順・導入方法は掲載下書きとは別に保存されます。各保存結果と顧客への見え方を確認します。 |

## 確認できない場合

次の場合は保存、掲載停止、課金変更、顧客への案内を確定しません。

- 「Marketplace掲載情報」または「課金設定」が表示されない、保存できない、または権限がない。
- 自動掲載の待機理由、現在の安定版、掲載内容、導入方法のどれかを確認できない。
- 課金方式がロックされている、単価・対象顧客・契約承認を確認できない。
- 利用人数、契約上限、料金確認、次回更新のいずれかが[Appの利用人数・料金・契約上限を確認する](../operations/check-app-seats-pricing-and-limits.md)の確認と一致しない。
- 掲載停止後の既存顧客の対応、更新・アンインストールの影響を判断できない。

対象App、顧客組織、現在の掲載状態、安定版、予定する変更、表示されたメッセージ、操作日時、承認状況を記録して配布・契約の責任者へ確認します。認証情報、顧客データ、支払い情報は問い合わせに含めません。
