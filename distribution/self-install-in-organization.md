# 作成者が組織内self-installする

この記事では、作成者が開発元ProjectのリソースをAppとしてまとめ、同じ組織内の**開発元とは別のインストール先Project**へ導入する手順を説明します。組織内self-installでは、JAPAN AIの審査やMarketplaceへの掲載は必要ありません。導入後の利用者・アクセス権は、開発元Projectとは分けて管理します。

これは作成者が配布内容を確認するための操作です。Marketplaceで選定済みのAppを導入する手順は[MarketplaceからAppをインストールする](../use/install-marketplace-app.md)を参照してください。インストール後に必要な接続、Secret、利用者ごとの準備は[Appの初期設定を完了する](../use/complete-app-setup.md)で扱います。

## 始める前に

次を確認してから開始します。

- 正しい組織と、配布元となる開発元Projectを開いていること。
- Appに含めるリソース、初期データ、ホーム画面を決めていること。リソースの依存、固定ID、配布元固有のURL、外部接続、Secretの扱いは、事前に[配布対象・依存・認証設定の制約](distribution-scope-dependencies-auth.md)および[配布可能なPageの設定設計](../development/design-distributable-page-config.md)で確認します。
- 操作する人が、対象Projectを編集でき、組織内導入を実行できること。画面を閲覧できても、準備やインストールを実行できるとは限りません。
- 導入後に接続・Secretを設定する担当者と、利用者を追加する担当者を決めていること。
- 開発元とは別に、導入結果を確認する利用者を決めていること。実データや認証情報ではなく、許可された確認用データを使います。

> 組織内self-installは、開発元Projectへ部品を追加する操作ではありません。専用のインストール先Projectが作成され、開発元Projectは分離されたまま残ります。開発元で動いたことだけで、導入先の接続、アクセス、業務操作まで確認済みとは判断しません。

## 1. 開発元ProjectからAppを作成する

1. 開発元Projectで「プロジェクト設定」を開き、「App公開」を選びます。
2. 「公開先」で「組織内」を選びます。「マーケットプレイス」は選びません。
3. 「App情報」の「App名」を入力し、「Appを作成」を選びます。既存のAppを使う場合は、対象Appが今回の開発元Projectのものであることを確認します。
4. 作成後、App名と開発元Projectを照合します。誤った組織・Project・App名なら、この時点で先へ進まず、対象を切り替えて確認します。

App名は、導入先の利用者が識別できる名称にします。Appの作成と、実際にリソースを導入できる版の準備は別の操作です。

## 2. 配布するリソースを選び、確認する

1. 「公開対象リソース」で、Appへ含めるリソースを選びます。必要に応じて「ストレージ初期データ」も選びます。
2. Pageを最初に開かせる場合は、「ホームページ」で「最初に表示する画面」と対象ページを確認します。ページナビゲーションを使う場合は、利用者が閲覧できるページだけを対象にします。
3. 「アプリのリソースを確認」を実行します。この操作は、選択したリソースを組織にインストールできるかを確認するものであり、Marketplaceの審査提出ではありません。
4. 「リソースの確認が完了しました。」と表示されたら、選択内容を再確認します。未解決の参照、警告、読み込み失敗がある場合は、原因を修正してから再確認します。

> 「すべて含める」を選ぶ前に、不要なリソース、確認用データ、配布元だけで使う設定が含まれないか確認してください。Secret値、APIキー、トークン、Cookie、接続IDを配布物や初期データへ含めません。接続やSecretが必要なAppは、導入先で設定する前提で準備します。

## 3. インストールする版を準備する

リソースの確認後、「この組織にインストール」を選びます。初回は、選択した内容からインストール用の版が準備されます。既に同じ内容が導入済みの場合は「最新の状態です」と表示されることがあります。

準備後、確認画面で少なくとも次を確認します。

| 確認項目 | 確認する内容 |
|---|---|
| インストールするバージョン | 今回の開発元Projectから準備した版であること |
| 含まれるコンポーネント数 | 想定したリソース数と大きく異ならないこと |
| リソースの変更 | 追加・削除・変更の対象に不要なものがないこと |
| アクセス設定 | ロール、アクセス方針、レコードアクセスの変更がないか、影響を理解できること |
| 認証情報・コネクタ | 共有で設定するものと利用者ごとに設定するもの、追加・変更・削除されるコネクタ、導入後の担当者を確認したこと |

確認画面では、リソースの追加・更新・削除、コネクタの変更、認証情報への影響、アクセス設定が区分して表示される場合があります。件数だけで確定せず、展開して対象名を確認します。認証情報の要件が表示される場合、値そのものは確認画面へ表示・入力しません。導入後、必要なコネクタやSecretを設定します。内容に不明点があれば「キャンセル」で戻り、リソース選択や配布設計を見直します。

## 4. 組織内へインストールする

1. 確認画面で、App名、版、変更内容、アクセス設定、認証情報の要件をもう一度確認します。
2. 内容に問題がなければ「この組織にインストール」を確定します。
3. 「インストールまたは更新中です。この画面で状態を自動確認します。」と表示されている間は、同じ操作を繰り返しません。
4. 「インストール済みバージョン」と「インストール済みアプリを開く」が表示されたことを確認します。
5. 「インストール済みアプリを開く」を選び、開発元とは別のインストール先Projectを開けることを確認します。

> 通信エラー、画面離脱、応答なしなどで結果が不明でも、すぐに再実行しないでください。「インストール状況を再確認」で現在の版と状態を確認します。処理の受付表示は、導入完了や設定完了を意味しません。

## 5. 初期設定、メンバー、利用を確認する

インストール先Projectを開いたら、導入の確認と業務利用の準備を分けて進めます。

1. 「セットアップを完了」が表示される場合は選び、残っている接続、Secret、App固有の設定を確認します。詳しい手順は[Appの初期設定を完了する](../use/complete-app-setup.md)に従います。
2. 接続やSecretが不要と表示されない限り、開発元の認証状態を引き継げるとは判断しません。導入先用に承認された接続・値を設定します。
3. インストール先Projectの「設定」から「メンバー」を開き、利用者を追加して必要最小限の「ロール」を設定します。詳細は[Project・Appのメンバーを管理する](../operations/manage-project-and-app-members.md)を参照してください。
4. 管理者だけでなく、想定利用者のアカウントでAppを開きます。ホーム画面、主要なリソース、必要な接続、代表的な業務操作の結果を確認します。
5. 確認した版、設定済みの項目、利用開始してよい機能、未対応の作業、問い合わせ先を利用者と運用担当者へ共有します。

組織に所属していることと、インストール先Projectを利用できることは別です。また、セットアップの完了表示だけで、各利用者の個人接続や業務操作まで成功したとは扱いません。

## 完了チェックリスト

- [ ] 正しい組織と開発元ProjectからAppを作成した
- [ ] 必要なリソース、初期データ、ホーム画面だけを選び、確認を完了した
- [ ] インストール前に、版、変更内容、アクセス設定、認証情報の要件を確認した
- [ ] 「インストール済みアプリを開く」から、別のインストール先Projectを開けた
- [ ] 必要な初期設定を確認し、Secret値や認証情報を共有していない
- [ ] 想定利用者を追加し、必要最小限の役割を設定した
- [ ] 利用者の立場で代表操作と結果を確認した

## うまくいかない場合

| 状況 | 確認・対応 |
|---|---|
| 「App公開」または「組織内のアプリ」が表示されない | 正しい組織・開発元Project・操作権限・組織の利用条件を確認します。表示させるために権限や設定を自己判断で変更しません。 |
| 「この組織にインストール」を選べない | リソース確認が完了しているか、対象Projectを編集できるか、Appと版が利用可能かを確認します。 |
| リソース確認が失敗する | 未解決の参照、選択漏れ、固定ID、配布元固有のURL、認証情報の扱いを確認します。設計は[配布可能なPageの設定設計](../development/design-distributable-page-config.md)を参照します。 |
| インストール結果が不明 | 「インストール状況を再確認」で版と状態を確認してから対応します。同じ操作を連続で実行しません。 |
| インストール後に開けない、または利用者だけ開けない | インストール先Projectを開いているか、メンバー・ロール・利用者本人の接続を確認します。開発元Projectの権限を広げて回避しません。 |
| 接続やSecretの設定が分からない | 要件を推測して値を入力せず、[Appの初期設定を完了する](../use/complete-app-setup.md)とApp固有の案内を確認します。 |

問い合わせる場合は、組織名、App名、開発元／インストール先Project、表示された版と状態、操作日時、確認済みの内容を伝えます。Secret値、APIキー、トークン、Cookie、実データを送らないでください。
