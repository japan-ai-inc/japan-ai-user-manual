# 配布対象・依存・認証設定の制約

Appとして公開する操作は、開発用Projectをそのまま複製する操作ではありません。リリースには、選んだリソースの定義、初期化用に明示した一部のデータ、リソース間の参照、および導入先で設定すべき認証情報の**要件**が含まれます。一方、日々の業務データ、利用者が追加したデータ、外部サービスの認証状態、Secretやトークンの実値は持ち運びません。

この記事は作成者向けに、何を公開対象にできるか、何を導入先で準備するか、依存がどのように導入先の実体へ解決されるかを説明します。組織内への導入操作は[作成者が組織内self-installする](self-install-in-organization.md)、利用者・管理者が行う導入後の設定は[Appの初期設定を完了する](../use/complete-app-setup.md)を参照してください。

## この記事の範囲

ここでいう「配布対象」は、Appのリリースに含めることを選んだProjectリソースです。公開画面の**「公開対象リソース」**では、対象種別ごとに**「すべて含める」**、**「個別に選択」**、**「含めない」**を選べます。選択できることは、導入先のデータ、認証情報、外部サービスの利用許可まで自動で揃うことを意味しません。

通常のリソース上限、契約条件、利用人数、料金は扱いません。[制限・提供条件の索引](../operations/limits-and-availability-index.md)を確認してください。公開申請・審査の進め方も対象外です。

> 配布元のProject ID、リソースID、PageのURL、外部接続ID、APIキー、Cookie、アクセストークン、Secretの値を、Pageのソース、環境変数、Storageの初期ファイル、説明文、ログへ書き込まないでください。導入先では同じIDになりません。

## リリースに含めるもの、含めないもの

公開対象に選んだ内容は、導入先用の管理対象リソースとして用意されます。次表の「初期データ」は、業務データ全体を移す意味ではありません。

| 対象 | リリースで扱う内容 | 持ち運ばない・導入先で確認すること |
|---|---|---|
| エージェント、スキル | 指定した版と、リリース内で必要な参照 | 配布元Projectの個別設定や利用履歴。導入先でも利用可能な版かを確認します。 |
| ワークフロー | ワークフロー定義と、宣言済みリソースへの参照 | 実行履歴、実行中の処理、外部サービスの認証状態。 |
| Page | Pageの成果物、表示設定、宣言したリソース参照 | 配布元のPage ID・URL・利用者のセッション。固定IDを埋め込まない設計は[配布可能なPageの設定設計](../development/design-distributable-page-config.md)を参照してください。 |
| カスタムオブジェクト | スキーマ（Object・フィールド・関係・アクセスの定義）。必要なら明示した初期レコード | 通常の業務レコード全体、利用者が導入後に追加・更新したレコード。初期レコードを含める必要性を個別に判断します。 |
| Storage | 明示的に選んだ初期ファイルと保存先の論理的な範囲（Project Storageのシードを含む） | Project内の全ファイル、利用者が導入後に追加したファイル、配布元のファイルID。保存先参照が利用不可になっても、選択から明示的に外すまでは保存済みの選択として残る場合があります。 |
| Dataset | Datasetとして必要な導入先の入れ物・表示情報 | 配布元のDatasetに蓄積された本文、検索結果、利用履歴をそのまま複製する前提。必要な知識データは導入後に用意・登録します。 |
| カスタムロール | Appに含めるロール定義 | 導入先メンバーへの自動的な割当て。ロール変更の影響は導入・更新時に確認します。 |
| 自動実行 | スケジュールまたはイベントを契機にする自動実行の定義、対象リソースへの論理参照 | 過去の実行結果、外部接続の認証状態。実行前に接続・送信先・更新先を確認します。 |
| 接続・Secret・APIキー | 必要な認証の種類、利用範囲、導入先で満たすべき要件 | 接続ID、OAuthトークン、パスワード、Secret値、APIキーの実値。導入先の担当者が設定します。 |

Storageやカスタムオブジェクトの初期データを含めても、検証用に使った個人情報、顧客情報、認証情報、運用中のファイルを混ぜないでください。初期状態を作るために本当に必要な最小限だけを選びます。

## コネクタとリソース選択の考え方

公開画面でコネクタを選べる場合、候補には配布元から導出されたコネクタと追加選択できるコネクタがあり、検索、アイコン、個人用／共有用の表示で確認できます。Appが要求する外部アカウント・コネクタを見つけたら、配布元の接続を移すのではなく、導入先で誰がどの方式で設定するかを決めます。

リソースを個別選択する場合は、Agent、Workflow、Page、Skill、自動実行、Dataset、カスタムオブジェクト、カスタムロール、Project Storageを対象ごとに確認します。個別選択やStorageシードには対象ごとの件数・データ量の制限があるため、公開画面と検証結果で確認します。選択画面で検索結果に表示されない、または保存済みのStorage参照が利用不可になった場合も、名称・保存先・必要性を確認してから明示的に選択を外します。

## 1. 公開対象と依存を棚卸しする

1. Appで利用するエージェント、スキル、ワークフロー、Page、カスタムオブジェクト、Dataset、Storage、自動実行を列挙します。
2. 各項目について、配布する「定義」、初期化時だけ必要な「初期データ」、導入先で作る「業務データ・認証情報」に分けます。
3. **「公開対象リソース」**で必要な種別を選びます。Pageが呼ぶワークフロー、ワークフローが使うエージェントやDatasetなど、画面に直接表示されない依存も外さないでください。
4. 初期ファイルまたは初期レコードを含める場合は、導入先で同名のデータと衝突しても安全か、更新時にどの内容を維持したいかを確認します。
5. 公開前に、導入先で再設定する接続・Secret・利用者ごとの接続を一覧にします。

> 「すべて含める」は、認証情報や実データを含める指定ではありません。ただし、不要な定義や初期データまで配布しないよう、Appの機能に必要な範囲へ絞ることを推奨します。

## 2. 論理名で依存を解決できるようにする

配布処理は、配布元の内部IDを導入先へコピーするのではなく、リリース内で宣言された論理名を使って導入先のリソースへ対応付けます。たとえばPageが参照するワークフロー、エージェント、カスタムオブジェクト、Storageのルートは、同じリリースで提供する対象として解決可能である必要があります。

Pageの参照は、配布用の参照ファイルで論理名として宣言します。記述方法と、固定IDを避けるPage設計は[配布可能なPageの設定設計](../development/design-distributable-page-config.md)を参照してください。任意の文章、ビルド済みJavaScript、URL、外部サービスの設定値に入れたIDまで自動で置換されるものではありません。

| 依存の状態 | 作成者が行うこと |
|---|---|
| PageがWorkflow、Agent、Object、Storageを使う | Pageの論理参照と、公開対象側の論理名を一致させます。 |
| Workflow・自動実行がDatasetや他のリソースを使う | 必要な対象を公開対象に含め、導入先でデータを準備する作業を分けて記載します。 |
| スキル・Agentが特定の版に依存する | 任意の「最新」ではなく、利用可能な特定の版を確認します。 |
| 外部サービス・任意のURL・固定IDを使う | 配布時の自動解決対象と決めつけず、導入先で設定する値として設計・案内します。 |

導入先では新しいリソース識別子が作られるため、IDを固定した実装は配布後に参照先を失うおそれがあります。導入先の実体を論理名から解決する設計と、依存の宣言漏れがないかを公開前に確認してください。

## 3. 認証情報は「要件」だけを配布する

リリースは、必要な認証情報の要件を導入先へ示せますが、配布元の認証情報そのものを複製しません。共有で使う認証と、利用者ごとに設定する認証は区別して設計します。

1. 外部サービスごとに、共有接続、個人接続、Project Secretのどれが必要かを決めます。選び方は[個人接続・共有接続・Secretを選ぶ](../operations/choose-personal-shared-connections-and-secrets.md)を参照してください。
2. 共有接続が必要な場合は、導入先の業務用アカウント、最小権限、再認証の担当者を決めます。作成・Appへの割り当ては[Project・Appの共有接続を設定する](../operations/configure-shared-connections.md)に従います。
3. APIキーやトークンなどの値が必要な場合は、導入先でProject Secretを作成または選択し、Appが求める項目へ紐づけます。値の管理は[Project Secretを登録・更新・削除する](../operations/manage-project-secrets.md)を参照してください。
4. 利用者本人の接続が必要な機能は、各利用者が自分のアカウントで設定できるよう案内します。管理者の個人接続で代用しません。
5. 導入後は、Appの**「設定」**で**「コネクタ」**と**「シークレット管理」**の状態を確認し、許可されたテストデータで代表操作を実行します。全体の確認順は[Appの初期設定を完了する](../use/complete-app-setup.md)を参照してください。

> 接続またはSecretが「設定済み」と表示されても、外部サービス側の権限、対象データ、送信先、利用者本人の接続まで検証済みとは限りません。自動実行を含むAppでは、実行者がいない場合に使われる共有接続も確認してください。

## 公開前チェックと表示されるエラー

公開画面では、**「公開前チェック」**で選択内容と依存を確認します。Pageの未解決参照、配布元のIDを含む参照、宣言されていないDataset参照、固定されていない依存先の版、初期データの参照不整合などがある場合、チェックまたはリリース作成を完了できません。画面には**「公開前チェックを完了できませんでした。内容を確認して再実行してください。」**または**「リリースを作成できませんでした。内容を確認して再実行してください。」**と表示される場合があります。

その場合は、次の順で修正します。

1. 対象のリソース名と、選択した公開対象を確認します。Pageが参照する対象を外していないか、論理名が一致するかを確認します。
2. 配布元のUUID、ID、URL、期限のない依存先の指定を、論理参照または導入先設定へ置き換えます。
3. Dataset、Storage、カスタムオブジェクトのデータについて、配布できる定義・初期データと、導入後に準備するデータを分けます。
4. 認証情報の値を成果物へ追加して回避せず、必要な接続・Secretの要件と導入手順を見直します。
5. 修正後に**「公開前チェックを再実行」**します。選択後にリソースが削除・変更された場合は、選択を更新してから確認します。

## よくある誤解

| 誤解 | 確認すること |
|---|---|
| Appを配布すれば、配布元の顧客データも使える | 業務データは配布対象ではありません。必要な初期データだけを明示し、導入先のデータ準備を別に行います。 |
| 接続を公開対象にしたので、導入先で認証不要である | 配布されるのは要件です。接続、Secret、利用者本人の接続は導入先で設定します。 |
| Resource IDをPageに書けば確実に参照できる | 導入先のIDは異なります。論理名を使い、[配布可能なPageの設定設計](../development/design-distributable-page-config.md)の設計に従います。 |
| Storageを選べばProject内のすべてのファイルが移る | 明示した初期ファイルだけを扱います。業務ファイルや導入後の利用者ファイルは別です。 |

## 確認できない場合

**「公開対象リソース」**を読み込めない、対象が選択から外れた、公開前チェックが失敗する、または導入後に接続・Secretの状態を確認できない場合は、IDや認証情報を直接埋め込んで回避しないでください。対象の組織・Project・App、選択したリソース、依存する論理名、表示されたメッセージ、操作日時、確認済みの設定を記録して担当者へ確認します。Secret値、APIキー、パスワード、トークン、Cookieは問い合わせに含めません。
