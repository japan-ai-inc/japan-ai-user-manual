# JAI Adminで顧客へ配布・更新確認する

配布担当者は、承認済みの安定版リリースを顧客組織へ初回インストールし、既存インストールを必要な範囲で更新して、結果を確認します。JAI Adminでの「公開」「安定版へ昇格」「顧客展開」は別の操作です。候補の公開は顧客組織を変更せず、安定版への昇格では準備済みの既存インストールに自動更新が予定されます。初回導入、対象を絞った更新、失敗の確認と対応は、配布担当者が「顧客展開」と「インストール管理」で行います。

顧客側が更新内容、再設定、業務上の確認を行う手順は[App更新の変更点と再設定を確認する](../use/check-app-updates.md)を参照してください。変更の互換性と展開方針の整理は[リリースの互換性を管理する](manage-release-compatibility.md)で扱います。

## この記事の範囲

対象は、JAI Adminの「Studioアプリ配布」で顧客組織への配布を担当する方です。顧客向けMarketplaceからのセルフサービス導入、顧客の接続・Secret・利用者ごとの準備、リリースの審査と安定版への昇格の詳しい操作は対象外です。

操作できる項目はJAI Adminへのアクセス権限によって異なります。画面を開けない、操作が実行できない場合は、URLを推測したり別の権限で回避したりせず、管理担当者へ確認してください。

## 始める前に

- 対象App、配布する「安定版リリース」、対象顧客組織、顧客窓口を確認します。
- 変更内容、必要な再設定、顧客への案内、配布後に確認する代表操作を整理します。未確認の変更を全顧客へ一括展開しません。
- 初回インストールでは、対象組織の有効なメンバーから「ランタイム所有者」を確認します。このユーザーは、インストールで作られるリソースの実行者として使われます。
- 顧客側の利用者・管理者へ、対象App、版、変更点、必要な作業、確認依頼先を連絡できる状態にします。認証情報の値を配布記録や連絡本文に含めません。

> 「デプロイを開始しました」は顧客での業務確認完了を示しません。また「インストールが完了しました」と表示されても、インストール一覧の再読み込みに失敗する場合があります。対象組織・リリース・状態を一覧で改めて確認してから、完了と案内してください。

## 1. 配布する版と既存導入の状況を確認する

1. JAI Adminで「Studioアプリ配布」を開き、「リリースフロー」の「顧客展開」を選びます。
2. 「顧客展開リリース」で「安定版リリース」を選び、App名と「リリース」を確認します。顧客へのインストール・更新に選べるのは安定版リリースです。
3. 表示される「選択中アプリの統計」で、導入済み組織、アクティブ、無効、失敗、デプロイ中の件数を確認します。件数は対象を検討する補助情報であり、配布完了の根拠にはしません。
4. 対象組織に同じAppの既存インストールがあるか確認します。ある場合に「初回インストール」を重ねず、「既存インストールを更新」を使います。

既存インストールの現在版、状態、直近のデプロイ結果は「インストール管理」の「インストール済みアプリ」で確認できます。表の「アプリ」「組織」「ステータス」「リリース」「デプロイ」を組み合わせて読み、対象組織と対象版を取り違えないでください。

## 2. 新しい顧客組織へ初回インストールする

対象組織に一致するインストールがない場合だけ、「初回インストール」を使います。

1. 「顧客組織」を検索して、配布先を1組織選びます。初回インストールは、組織ごとに実行します。
2. 「ランタイム所有者」で、その組織の有効なメンバーを選びます。
3. 表示される「認証情報バインディング」や「機能の表示設定」がある場合は、顧客の合意済みの内容と照合します。機能の設定は初回インストールで表示する機能を選ぶものであり、インストールの有効・無効とは別です。
4. App、安定版リリース、顧客組織、ランタイム所有者、設定内容を再確認し、「インストールを作成」または「顧客へインストール」を実行します。
5. 「インストールが完了しました」と表示されたら、一覧を更新し、対象組織の行でリリースとデプロイの状態を確認します。

初回インストール後の機能設定に失敗した場合は、初回インストール自体が完了した可能性があります。「インストール管理」で対象行を確認し、失敗した機能だけを確認・再試行します。初回インストールを重ねて作成しません。

## 3. 既存インストールを更新する

通常の更新では、選択した安定版リリースに対する「準備済みインストールへ一括デプロイ」を使用します。「準備完了」は、インストールがアクティブで、選択したリリースに未更新であり、デプロイ中ではない状態です。開始直前にサーバー側でも対象が再確認されます。

1. 「準備済みインストールへ一括デプロイ」で、準備完了とブロックの件数、ブロック理由を確認します。
2. 対象の変更が顧客一律で安全か、顧客への連絡・再設定の準備が済んでいるかを確認します。
3. 「準備済みインストールへ一括デプロイ」を選び、確認内容を読んで開始します。
4. 結果を記録し、「インストール済みアプリ」で各組織の「リリース」と「デプロイ」を再確認します。

一部の顧客だけに適用する場合、または段階展開する場合は「詳細: 選択したインストールへデプロイ」を使います。「デプロイ対象組織」を選び、一致する既存インストールから対象行だけを選択して「選択したインストールへデプロイ」を実行します。対象外の組織にも反映される前提で操作しないでください。

> 「ブロック理由」がある行を、一覧に出ないからといって更新済みと扱わないでください。「既にこのリリースです」「デプロイ中です」「インストールがアクティブではありません」「組織がアクティブではありません」「ランタイム所有者の準備ができていません」など、表示された理由ごとに対象・状態を確認します。

## 4. 結果・更新失敗を確認し、顧客へ引き継ぐ

配布結果では、少なくともApp名、安定版リリース、顧客組織、実施日時、実行した方法、一括または個別の対象、一覧の「ステータス」「リリース」「デプロイ」、表示されたエラーを記録します。自動更新が予定される昇格と、手動デプロイの結果は区別します。

デプロイに失敗したときは、失敗件数だけで済ませず、各結果を確認して対象組織・既存版・エラーを特定します。同じインストールでデプロイ中の間は、重ねて更新、無効化、アンインストールを実行しません。失敗原因を確認後、対象を絞って再試行するか、顧客への案内とともに保留します。

顧客側には、更新済みと確認できた組織だけへ、対象版、変更点、必要な再設定、確認を依頼する業務操作、問い合わせ先を連絡します。更新後の顧客の具体的な確認は[App更新の変更点と再設定を確認する](../use/check-app-updates.md)へ案内してください。

## うまくいかない場合

| 状況 | 確認・対応 |
|---|---|
| 安定版リリースを選べない | 審査・昇格状況を確認します。候補リリースを顧客展開の対象として扱いません。 |
| 初回インストールが作成できない | 対象組織、既存インストールの有無、ランタイム所有者が対象組織の有効なメンバーかを確認します。有料Appでは初回インストールや失敗後の再試行でシート購入の確認が必要な場合があります。 |
| 一括デプロイの対象が少ない、またはない | ブロック理由を確認します。未更新・アクティブ・デプロイ中でないことだけでなく、組織とランタイム所有者の状態を確認します。 |
| デプロイ失敗、または結果が不明 | 一覧を更新して対象行のリリース・デプロイ・表示エラーを確認します。重複実行せず、個別結果を添えて問い合わせます。 |
| 更新後に顧客が使えない | 配布完了だけで解決とせず、顧客側の再設定、権限、接続、代表業務の確認を[App更新の変更点と再設定を確認する](../use/check-app-updates.md)に沿って切り分けます。 |

問い合わせには、App名、リリース、顧客組織、インストールの状態、実施日時、実行方法、エラー表示、再試行の有無を添えます。パスワード、APIキー、トークン、Secret値は添付しません。
