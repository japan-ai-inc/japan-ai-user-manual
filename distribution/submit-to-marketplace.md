# Marketplaceへ公開申請する

Marketplaceへ出すAppは、リリースの中身だけでなく、利用者がMarketplaceで読む掲載情報も整えてから審査へ提出します。この操作は、Appをその場で掲載・販売開始する操作ではありません。審査中は、提出したリリースと掲載情報を変更できず、承認後の提供開始・掲載はJAPAN AIが管理します。

配布物に含めるリソース、依存関係、認証情報を先に確認することが重要です。[配布対象・依存・認証設定の制約](distribution-scope-dependencies-auth.md)を確認し、利用者に見せる内容と実際の利用条件が一致する状態で申請してください。Marketplaceでの見え方、導入前の確認事項は[MarketplaceでAppを選ぶ](../use/choose-marketplace-app.md)も参照してください。

## 始める前に

この記事の対象者は**公開申請者**です。Studioの対象Projectで「App公開」を開き、公開先として**「マーケットプレイス」**を選べる人が行います。申請には、次の条件を満たす必要があります。

- 対象組織でApp公開とMarketplace公開が利用できること
- 対象Projectを閲覧・更新でき、App公開を実行する権限があること
- App名、掲載情報、公開対象リソース、ホームページ、バージョン、リリースノートを準備できること
- 公開前チェックを完了できること

画面を開けても、「マーケットプレイス」が表示されない、または「審査へ提出」を実行できない場合があります。自分で権限や組織の利用設定を変更せず、組織の管理担当者へ確認してください。

> 申請者が使うのはStudioの「App公開」です。JAI Adminは配布担当が審査・承認・掲載を扱う画面です。申請者がJAI Adminで「承認する」や「掲載情報を反映」を操作して提出するものではありません。

## 提出前に整える情報

「マーケットプレイス掲載情報」では、掲載用の内容を下書きとして保存します。App名は組織内利用とMarketplaceで共通です。掲載情報には、少なくとも次を分かりやすく記載します。

| 項目 | 入力・確認する内容 | 確認済みの制約 |
|---|---|---|
| App名 | 用途を識別できる名称 | 1〜255文字。審査中または承認後は変更できません。 |
| アプリアイコン | Marketplaceで表示する画像。必要に応じて「プロジェクトのアイコンを使用」します。 | PNG、JPEG、WebP、GIFのいずれかで、2MB以下です。 |
| コネクタ要件 | 共有・個人のどちらのコネクタを誰が設定するか、外部アカウントと必要権限 | 接続の実値や認証済み状態は配布されません。利用開始前または更新後の設定手順・担当を掲載情報と案内に明記します。 |
| 「サブタイトル」 | App名の下に表示する短い紹介文 | 120文字までです。 |
| 「説明」 | 目的、対象ユーザー、主な機能、基本的な使い方、利用前の注意点 | 公開申請者が入力する説明は1〜4,000文字です。リリースごとの差分はここではなく「リリースノート」に書きます。 |
| 「タグ」 | 検索・理解を補助する語 | 最大10件、各1〜32文字。カンマで区切って入力します。同じタグを重複させないでください。 |
| 「画像・動画」 | 利用者が画面・利用イメージを理解できる素材 | 画面に表示される対応形式、件数、容量の範囲で追加します。画像はPNG、JPEG、WebP、GIF、動画はMP4、WebM、QuickTimeが対応候補ですが、実際に追加できる種類・件数・容量は画面の案内を確認します。 |

説明は文字どおりのテキストとして表示されます。HTMLやMarkdownで見栄えを変える前提にせず、改行と通常の文章で読みやすくしてください。画像・動画には、顧客情報、個人情報、パスワード、APIキー、トークン、検証環境のURLなどを写さないでください。

> Studioの公開申請画面には、申請者がMarketplace向けの価格、シート料金、料金体系を入力・申請する項目は確認できません。料金を決めたり、料金が表示されるAppの利用人数・契約上限を判断したりする場合は、本申請で補完せず[Appの利用人数・料金・契約上限を確認する](../operations/check-app-seats-pricing-and-limits.md)に従ってください。

## 1. App情報と掲載情報を保存する

1. 正しい組織・Projectで**「App公開」**を開き、公開先の**「マーケットプレイス」**を選びます。
2. **「App情報」**で「App名」とアイコンを確認し、変更した場合は保存します。
3. **「マーケットプレイス掲載情報」**で「サブタイトル」、「説明」、「タグ」、「画像・動画」を入力します。
4. 必要に応じて**「掲載プレビュー」**を開き、App名、説明、素材の順序、誤字、写り込んだ情報を確認します。
5. **「下書きを保存」**を選び、「保存しました」を確認します。

掲載情報が未保存のまま、または上限を超えたままでは申請できません。入力を保存しても、承認前にMarketplaceへ公開されるわけではありません。

## 2. リリース内容を確認して公開前チェックを実行する

1. **「公開対象リソース」**と「ストレージ初期データ」で、Appに含めるものを確認します。個別選択は種類ごとに最大1,000件です。必要なリソースを漏らさず、不要なデータを含めないでください。
2. **「ホームページ」**で、利用者がAppを開いたときの最初の画面を選びます。
3. **「バージョンとリリースノート」**で、未使用の `x.y.z` 形式のバージョンと、この版の変更内容を入力します。
4. **「公開前チェック」**で**「チェックを実行」**を選びます。エラーや警告があれば、対象Project・リソースを修正してから**「再チェック」**します。
5. 「公開前チェックが完了しました。審査へ提出できます。」と表示されることを確認します。

公開前チェックは、掲載の文章を承認する操作ではなく、選択したリソースを安全に公開できるかを確認するものです。Page、外部接続、Secret、固定IDの可能性がある値などの警告を、表示だけで問題なしと判断しないでください。配布上の前提は[配布対象・依存・認証設定の制約](distribution-scope-dependencies-auth.md)で再確認します。

## 3. リリースと掲載情報をまとめて申請する

1. **「審査へ提出」**を選びます。
2. 確認画面でApp名、含めるリソース数、リリースノート、バージョンを確認します。
3. 掲載情報の下書きがある場合は、**「リリースと掲載情報を審査に提出します。」**と表示されます。これは、申請者のStudio画面から、リリースとその掲載情報を同じ申請として提出する意味です。
4. 内容が正しい場合だけ、もう一度**「審査へ提出」**を選びます。
5. 「審査へ提出しました。」が表示され、**「公開・掲載状況」**が「審査中」、審査状況に対象バージョンが表示されることを確認します。

提出後、そのリリース内容と掲載情報は変更できません。修正が必要になった場合は、新しいバージョンを作成して申請します。提出時点では現在の掲載状態は変わらず、承認が即時にMarketplaceへの掲載を意味するわけでもありません。

## 審査中・却下時の対応

審査中は、同じAppから新しいリリースを提出できません。画面の「審査状況」で提出日時、対象バージョン、現在公開中のバージョンを確認し、JAPAN AIによる確認を待ちます。申請を止める必要がある場合は、審査中に**「提出をキャンセル」**を選べます。リリースとキャンセル履歴は残ります。

却下された場合は、表示される**「却下理由」**を確認し、リリース内容と掲載情報のどちらに対応が必要かを分けます。掲載情報の画面では理由が表示され、**「編集を再開」**から下書きを作り直せます。次の順で対応してください。

1. 却下理由を関係者と確認し、推測で文言や設定を変えないようにします。
2. Projectのリソース、依存関係、認証条件、掲載文、画像・動画を修正します。Secret値や認証情報を掲載情報へ書き込まないでください。
3. 新しいバージョンとリリースノートを作成し、掲載情報を保存します。
4. 公開前チェックを再実行し、問題を解消してから再申請します。

## うまくいかない場合

| 状況 | 確認・対応 |
|---|---|
| 「マーケットプレイス」または「審査へ提出」が表示されない | 組織の提供状態、対象Project、公開申請の権限を確認し、管理担当者へ依頼します。 |
| 掲載情報を保存できない | 必須項目、文字数、タグの件数・重複、画像・動画の対応形式・件数・容量、通信状態を確認します。入力は保持される場合があるため、消さずに内容を確認します。 |
| 公開前チェックで止まる | 表示された対象リソースを修正し、保存後に再チェックします。依存関係や認証条件は[配布対象・依存・認証設定の制約](distribution-scope-dependencies-auth.md)を確認します。 |
| 審査中で新しい版を提出できない | 同一Appで進行中の審査がないか確認します。必要なら提出をキャンセルするか、審査完了を待ちます。 |
| 却下理由が理解できない | App名、バージョン、却下理由、表示日時、公開対象、実施済みの修正を添えてJAPAN AIの窓口へ確認します。認証情報や機密データは送らないでください。 |

## 完了チェック

- [ ] App名、アイコン、サブタイトル、説明、タグ、画像・動画を利用者目線で確認した
- [ ] 説明と素材に機密情報・認証情報を含めていない
- [ ] 配布対象・依存関係・認証条件を[配布対象・依存・認証設定の制約](distribution-scope-dependencies-auth.md)で確認した
- [ ] 公開対象リソース、ホームページ、バージョン、リリースノートを確認した
- [ ] 公開前チェックを完了し、警告・エラーを確認した
- [ ] 確認画面で、リリースと掲載情報をまとめて提出することを確認した
- [ ] 提出後は審査状況を確認し、修正が必要なら新しいバージョンで対応することを理解した
